# 작업 구조 — 두 도구·두 자리를 오가며 일하는 법
- 날짜: 2026-10-31   - 결정자: 운영자   - 상태: 확정 (적용 PR 과 함께)

## 배경
- 운영자 1명이 Claude 와 Codex 를 함께 쓰고, 로컬(컴퓨터 앞)과 클라우드(폰·다른 PC)를 오가며 일한다. 한쪽 사용량이 바닥나면 다른 쪽이 같은 일을 그 자리에서 이어받아야 한다.
- 10-30 까지의 세팅은 클라우드 환경에 전부를 넣는 방향이었다(네트워크 허용목록, setup script, 한쪽 도구가 다른 쪽을 부르는 브리지, 보조 명령). 각각 이유가 있었지만 합치면 혼자 유지할 수 없는 크기가 됐고, 한 도구에만 있어 다른 도구로 옮기면 따라가지 않았다.
- Claude 메모리·클라우드 세션 기록·Codex 세션은 서로 넘어가지 않는다. 네 자리(두 도구 × 두 장소)가 공통으로 보는 것은 저장소 하나뿐이다.

## 결정
1. **두 도구는 동등한 동료다.** 어느 도구도 다른 도구를 일꾼으로 부르지 않는다. 전환은 운영자가 한다("정리해 둬" → "이어서 해"). 10-30 카드의 서비스별 주 플랫폼은 기본값으로 남고 금지가 아니다.
2. **클라우드 환경은 기본값, 비밀값 0.** 편집·테스트·푸시까지 하고, 화면은 Vercel Preview 로 본다. `.env.local`·브라우저·운영 데이터·모바일 빌드가 필요한 일(AI QA·마이그레이션 적용 등)은 `[로컬에서]` 로 표시하고 로컬이 한다.
3. **브랜치 하나 = 일 하나 = `HANDOFF.md` 하나.** 멈출 때마다 갱신해 같은 브랜치에 푸시한다. 끝나면 마지막 커밋에서 지우고 PR. "자리" 줄이 잠금이다(한 브랜치는 한 번에 한 자리).
4. **`ROADMAP.md` 는 세 칸(다음·나중·끝남).** "지금"은 파일에 없다 — 아직 합쳐지지 않은 브랜치와 그 `HANDOFF.md` 가 정본이고, `scripts/agent/start.sh` 가 둘을 함께 찍는다. 로드맵만 고치는 PR 은 없다.
5. **PR 은 일이 끝났을 때 한 번.** 에이전트는 기본 브랜치에 직접 푸시하지 않는다. `.github/workflows/handoff-guard.yml` 이 `HANDOFF.md` 가 남은 PR 을 막는다.
6. **시작·종료·옮기기는 `scripts/agent/{start,stop,init}.sh`** 로 두 도구가 같은 명령을 돈다. `init.sh` 는 비밀값이 없는 트리에서도 통과한다.
7. **리뷰는 10-30 카드 그대로**(PR 을 만든 쪽의 반대편). Codex 자동 리뷰의 검출력은 결함을 심은 시험 PR 로 한 번 측정한다.
8. 결정은 `docs/decisions/` 에 결정을 내린 세션이 그 브랜치에 쓰고, 일을 끝내는 PR 에 함께 실린다.

## 근거
- 클라우드에 비밀값을 넣어 얻는 것(dev 서버·QA·캡처)은 실제 카카오 로그인·결제·모바일을 확인하지 못해 가치의 일부고, Vercel Preview 가 그 일부를 이미 준다. 반면 비밀값·허용목록·토큰 회전은 평일 저녁 폰으로 못 고치는 조용한 고장 지점이다.
- 유닛 테스트·타입 검사·빌드는 env 없이 돈다(10-30 실측). 그래서 "편집·테스트·푸시"는 양쪽 도구가 아무 설정 없이 똑같이 할 수 있다.
- 로드맵 "지금" 칸을 파일에 두면 에이전트가 기본 브랜치에 직접 쓰지 않는 한 PR 이 합쳐질 때까지 보이지 않는다. 합쳐지지 않은 브랜치 목록이 그 역할을 더 정확히 한다.

## 되돌리지 말 것 / 다시 꺼내는 조건
- 한 도구가 다른 도구를 부르는 브리지를 다시 만들지 않는다.
- 클라우드 환경에 비밀값을 다시 넣는 조건: Preview 를 대상으로 한 AI QA 가 평일에 반복해서 필요해질 때. 그때는 두 도구의 환경에 같이 넣는다.
- `HANDOFF.md` 를 기본 브랜치에 들이지 않는다(가드가 막는다).
- 공통 규칙 절은 모든 서비스 저장소가 같은 글이다 — 고칠 땐 함께 고친다.
