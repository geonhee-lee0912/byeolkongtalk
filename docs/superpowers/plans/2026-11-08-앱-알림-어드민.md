# 앱 알림 성과 어드민 Implementation Plan

> 운영자 지시(2026-11-08): "어드민까지 진행하자". 승인을 기다리지 않고 바로 구현.

**Goal:** 설계 `docs/superpowers/specs/2026-11-06-앱-알림-design.md` §1 '잴 것'을 한 화면(`/admin/push`)에서 본다.

| 잴 것(§1) | 화면 블록 | 원천 |
|---|---|---|
| 알림 허용률(묻는 순간별) | 묻는 순간별 답 — 받아들임/나중에/휴대폰 거부, 허용률 | `push_asks` |
| 광고 수신 동의율(묻는 순간별) | 광고 동의·철회 — 어디서 | `ad_consent_events` + `push_asks` |
| 다시 볼 날 설정·그날 돌아온 비율 | 다시 볼 날(예약·보낸 비율) + 종류별 표의 '다시 볼 날' 열람률 | `push_schedules`, `push_sends.opened_at` |
| 알림 종류별 열람률·수신거부율 | 보낸 알림 — 종류 × 정보성/광고, 날짜별 | `push_sends` |
| 지금 상태 | 알림 받는 회원·기기, 광고 동의 중/철회, 최근 7일 앱 연 회원, 칸을 끈 회원 | 각 표 |

- 앱 사용자의 14일 내 재방문(상위 설계 §6)은 이 화면에 넣지 않았다 — 앱 출시 뒤 코호트가 생기면 따로.

## 구조

- 마이그레이션 `20261108020000_admin_push_stats.sql`(PR 따로, 3단계 마이그레이션 위) — 집계 RPC 5개(`admin_push_summary`·`_asks`·`_consent`·`_sends_daily`·`_revisit`). 원본 행을 앱으로 끌어오지 않는다(AGENTS.md '어드민 집계'). SECURITY DEFINER + REVOKE 3종 + service_role. 날짜는 KST 식.
- `app/api/admin/push/route.ts` — `requireAdmin` + RPC 5개, 블록별 error 플래그. 창 30일(오늘 포함, 다른 어드민 추세표와 같음). 어드민 계정 제외.
- `lib/admin/push-stats.ts` — RPC 행 → 표(비율은 `pct1`, 분모 0 → '—'). 라벨에 없는 키는 원본 그대로.
- `app/admin/push/page.tsx` — 서버 컴포넌트, 라우트 셀프 호출(별마루 어드민과 같은 관행). 실패 블록은 `LoadFailed`.
- 메뉴: 분석·성과 → '앱 알림 🔔'.
