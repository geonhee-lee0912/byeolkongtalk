# 앱 화면 손보기 3단계 — 나머지 시트·팝업 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 남은 시트·팝업 27개를 2단계의 공통 틀(`Sheet`·`Dialog`)과 같은 겹창 스택 위로 옮긴다. 웹 모양은 그대로다.

**Architecture:**
- 2단계 틀을 먼저 보강한다.
  - 판·배경막 모양을 넘겨받는 prop
  - 아래 고정 변형
  - ESC 와 '닫을 수 없음'을 스택 하나에서 처리
  - 부모가 닫기를 거절했을 때 되살리기
- 그다음 겹창을 모양별 묶음으로 옮긴다: 반응형 시트 → 아래 고정 시트 → 확인창 → 틀에 안 맞는 4개.
- 틀에 안 맞는 4개는 모양은 그대로 두고 스택만 쓴다.
- 마지막에 "컴포넌트가 직접 `body.style.overflow` 를 만지지 않는다"를 계약 테스트로 잠근다.

**Tech Stack:** Next.js 16 · React 19 · Tailwind v4 · node:test

**Spec:** `docs/superpowers/specs/2026-11-07-앱-화면-design.md` §8(공통 시트 틀 — 3단계 = 나머지 이전) · §11(3단계 확인 = "시트마다 열기·닫기 한 번씩")

## Global Constraints

- **웹(브라우저) 모양:** 지금과 같아야 한다(§8 "둘 다"). 판·배경막·폭·여백이 지금과 다르면 prop 으로 지금 값을 그대로 넘긴다. 앱 전용 꾸밈은 `app-only` 또는 `useAppInfo` 로만 붙인다.
- **옮기기만 한다.** 안의 문구·버튼·결제/별/저장 로직·`history` 연동(뒤로가기로 닫기)은 바꾸지 않는다.
  - 예외는 스택으로 옮기면 저절로 생기는 것만이다: ESC 통일, 겹칠 때 스크롤 잠금 순서.
- **앱↔웹 메시지(`ui.overlay`·`ui.back`)는 4단계 몫이다.** 이번에 보내지 않는다.
- **z 값은 지금 값을 그대로 넘긴다.** 겹치는 순서: 75 < 80 < 90 < 100, 그리고 50 < 60.
- **판정 보호 화면:** `RechargeSheet`·`WelcomeStarsModal` 은 dev 에서만 옮긴다(§8). 운영 배포는 앱 출시 때 운영자 "go" 뒤에만 한다.
- **반복 규칙:**
  - 테스트는 `node --import tsx --test …`.
  - 패키지 설치 금지.
  - 커밋은 `git commit -F <파일> -- <경로>`.
  - 공개 저장소라 키·풀 UUID·사업 숫자를 쓰지 않는다.

## Review Focus

- **부모가 닫기를 거절함**(`if (saving) return` 같은 onClose): 앱에서 Sheet 가 내려가는 움직임을 끝낸 뒤에도 사라지지 않는다. 그러면 보이지 않는 배경막이 화면 전체 누르기를 삼킨다. 내려간 뒤에도 남아 있으면 다시 올라와 누를 수 있어야 한다 → Task 1 `onceClose().reset` 테스트 + Task 5 헤드리스 "거절 뒤 되살아남"
- **겹창 위 겹창**(PassSheet 위 PassConfirm, Acquaintance 목록 위 삭제 확인, tarot/draw 의 StarConfirm 위 RechargeSheet): 순서가 지켜져야 한다.
  - ESC·바깥 누르기는 맨 위 하나만 닫는다.
  - 스크롤 잠금은 마지막 창이 닫힐 때만 풀린다.
  - → Task 1 스택 테스트 + Task 5 헤드리스
- **처리 중 상태가 바뀌는 순간**(busy 가 켜졌다 꺼짐): 스택 순서가 바뀌면 안 된다. 다시 올리면 아래 창이 맨 위가 된다 → Task 1 `useOverlayEntry` 는 한 번만 올리고 dismissible 은 ref 로 읽는다(테스트: `closeTop` 이 닫을 수 없는 항목을 소비만 함)
- **웹 모양:** prop 으로 넘긴 판·배경막이 지금과 같아야 한다. 폰 폭과 PC 폭 모두다(`sm:` 변형) → Task 1 Step 0 전 사진 + Task 5 후 사진 나란히

### Task 1: 틀 보강 (스택 ESC·닫을 수 없음·되살리기, 모양 prop)

**Files:**

- Create: `components/common/use-overlay-entry.ts`

- Modify: `components/common/Dialog.tsx`

**Interfaces:**
- Consumes: 2단계의 `createOverlayStack` · `overlayStack` · `shouldDismissSheet` · `onceClose`
- Produces:
  - 스택 항목 모양을 `push(entry: { close: () => void; canDismiss: () => boolean }): () => void` 로 바꾼다.
    - `closeTop(): boolean` — 맨 위가 `canDismiss()` 면 `close()` 를 부른다. 아니면 아무것도 안 부른다. 둘 다 true 다(소비). 비었으면 false.
  - `handleKey(key: string): boolean` — `"Escape"` 면 `closeTop()` 결과, 아니면 false.
    - 기본 인스턴스 `overlayStack` 은 첫 push 때 `document` 에 keydown 리스너를 한 번 단다. 마지막 제거 때 뗀다. 처리했으면 `preventDefault`.
  - `onceClose(fn)` 이 돌려주는 함수에 `.reset(): void` 를 붙인다(다시 한 번 부를 수 있게).
  - `useOverlayEntry(close: () => void, dismissible: boolean): void`(`components/common/use-overlay-entry.ts`)
    - 마운트 때 한 번만 push 하고 언마운트 때 뺀다.
    - `close`·`dismissible` 은 ref 로 최신값을 읽는다. 바뀌어도 다시 push 하지 않는다.
  - `Sheet` 새 prop(전부 선택):
    - `align?: "responsive" | "bottom"` — 기본 `responsive` = 지금 `items-end sm:items-center`. `bottom` = `items-end` 만.
    - `panelClassName?: string` — 주면 판의 기본 모양 클래스(`bg-cream rounded-t-3xl sm:rounded-3xl p-6 pb-[…] sm:pb-6 max-h-[88vh] overflow-y-auto overscroll-contain`)를 통째로 바꾼다. `relative w-full max-w-md mx-auto` 와 `sheet-panel` 은 늘 붙는다.
    - `backdropClassName?: string` — 주면 배경막의 `bg-night/50 backdrop-blur-sm` 을 바꾼다.
    - `panelClassName` 이 있으면 앱 손잡이 띠가 음수 여백(`-mx-6 -mt-6`)을 쓰지 않는다. 판에 패딩이 없다고 본다.
  - `Dialog` 새 prop(전부 선택):
    - `backdropClassName?: string` — 기본 `bg-night/45 backdrop-blur-[2px]`
    - `widthClassName?: string` — 기본 `max-w-sm`
    - `gutterClassName?: string` — 기본 `px-6`
  - Sheet·Dialog 둘 다 `overlayStack.push` 대신 `useOverlayEntry(requestClose, dismissible)` 를 쓴다.
  - Sheet 되살리기: 앱에서 내려가는 움직임 뒤 `onClose` 를 부른다. 그 뒤 다음 틱에도 아직 마운트돼 있으면 부모가 거절한 것이다. 그때는 `closing=false` 로 되돌리고 `requestClose.reset()`.
