# 앱 알림 단계 1 — 뼈대 + 다시 볼 날 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱 회원이 리딩 결과 화면에서 '다시 볼 날'(3일·1주·2주 뒤)을 고르면, 그날 아침 알림이 한 번 오고, 누르면 그 리딩이 열린다.

**Architecture:** 웹(결과 화면)이 앱에 알림 권한을 묻고(새 브리지 메시지), 앱이 OS 권한·Expo 푸시 토큰을 받아 Bearer 로 서버에 등록한다. 웹은 쿠키 세션으로 예약을 만든다. 15분마다 도는 cron 이 오늘 보낼 예약을 순수 판정 함수로 거른 뒤 Expo 푸시 서비스로 보내고, 기록·영수증으로 중복과 죽은 토큰을 정리한다.

**Tech Stack:** Next.js 16 App Router(서버·웹), Supabase(Postgres), Expo SDK 58 + `expo-notifications`(앱), Expo Push API(HTTP), node:test + tsx(테스트)

**Spec:** `docs/superpowers/specs/2026-11-06-앱-알림-design.md` (§7 단계 1). 상위 설계 `docs/superpowers/specs/2026-10-12-앱-전환-design.md`.

## Global Constraints

- 테스트: `node --import tsx --test <파일들>` (vitest 아님). 타입: `npx tsc --noEmit --incremental false`. 빌드: `npx next build` — 라우트 표에 `ƒ Proxy` 가 있어야 한다.
- 커밋은 `git commit -F <파일> -- <경로>`, 제목 다음 줄 비우기, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `git add -A`·`--amend` 금지.
- 🔴 마이그레이션 커밋을 **먼저 혼자** 푸시하고 Supabase 체크 success 를 본 뒤, 그걸 읽는 코드를 올린다.
- 🔴 새 테이블: 같은 마이그레이션에 `ENABLE ROW LEVEL SECURITY` + `GRANT SELECT, INSERT, UPDATE, DELETE ON public.<표> TO service_role;`, 시퀀스는 `GRANT USAGE, SELECT, UPDATE ON SEQUENCE … TO service_role;`. anon·authenticated 에는 주지 않는다. `users(id)` FK 는 `ON DELETE CASCADE`.
- 🔴 `lib/app-bridge/protocol.ts` 의 `BRIDGE_VERSION` 은 올리지 않는다. 새 type 만 더한다. 앱 토큰·푸시 토큰은 어떤 메시지로도 웹에 넘기지 않는다.
- 🔴 `mobile/src` 의 순수 모듈(테스트 대상)은 `react-native`·`expo*` 를 import 하지 않는다(루트 CI 에 mobile/node_modules 가 없다).
- 날짜는 KST: `(created_at at time zone 'UTC' + interval '9 hours')::date` / JS 는 `lib/admin-time.ts` 의 `kstDate`.
- 알림 시각: 다시 볼 날은 고른 날 **08:30 KST 이후, 21:00 KST 전**에 보낸다. 그날 못 보내면 다음 날로 미루지 않고 **건너뛴다**(spec §3 A "미뤄지지도 않는다").
- 문구(정보성 틀, spec §3 A): 제목 `다시 볼 날이야`, 본문 `그때 그 리딩, 오늘 다시 펼쳐 볼래?`. 고민 내용·별·충전·할인·체험·출석·다른 상품 언급 금지.
- 시트 문구(spec §4-2, 단계 1 은 광고 체크칸 없음): `이 고민, 언제 다시 볼까?` / 칩 `3일 뒤` `1주 뒤` `2주 뒤` / `그날 별콩이가 알려줄게. 알림을 켜 줘.` / 버튼 `알림 받을래` · `나중에`.
- 이 개발용 앱에서 결제 버튼을 누르지 않는다. 운영(main) 배포 금지 — 입구 판정 뒤 운영자 허락.
- 의존성: `mobile/` 안에서만 `EXPO_NO_TELEMETRY=1 npx expo install expo-notifications expo-device < /dev/null` (앱 ① 계획의 선례). 루트 `npm install` 금지. 실행 전에 운영자에게 한 줄로 알린다.

- [ ] **Step 1: 마이그레이션 작성**

```sql
create table public.push_devices (
  token text primary key,                       -- Expo 푸시 토큰
  user_id uuid not null references public.users(id) on delete cascade,
  platform text not null check (platform in ('ios','android')),
  app_version text,
  created_at timestamptz not null default now(),
  last_seen_at timestamptz not null default now(),
  disabled_at timestamptz                         -- Expo 가 '등록 안 된 기기'라고 하면 채운다
);
create index push_devices_user_idx on public.push_devices(user_id) where disabled_at is null;

create table public.push_preferences (
  user_id uuid primary key references public.users(id) on delete cascade,
  revisit boolean not null default true,
  updated_at timestamptz not null default now()
);

create table public.push_asks (
  id bigserial primary key,
  user_id uuid not null references public.users(id) on delete cascade,
  moment text not null check (moment in ('first_reading_end','second_launch','reading_end','byeolmaru_first','birthday')),
  answer text not null check (answer in ('accepted','later','os_denied')),
  created_at timestamptz not null default now()
);
create index push_asks_user_idx on public.push_asks(user_id);

create table public.push_schedules (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.users(id) on delete cascade,
  kind text not null check (kind in ('revisit')),
  reading_id uuid not null references public.readings(id) on delete cascade,
  send_on date not null,                          -- KST 날짜
  status text not null default 'pending' check (status in ('pending','sent','skipped')),
  created_at timestamptz not null default now(),
  unique (reading_id, kind)
);
create index push_schedules_due_idx on public.push_schedules(send_on) where status = 'pending';

create table public.push_sends (
  id bigserial primary key,
  user_id uuid not null references public.users(id) on delete cascade,
  kind text not null,
  class text not null check (class in ('info','ad')),
  ref_id text not null,                           -- 다시 볼 날은 schedule id
  send_date date not null,                        -- KST
  device_count int not null default 0,
  expo_tickets jsonb not null default '[]',       -- [{ "id": 티켓, "token": 기기 }]
  sent_at timestamptz not null default now(),
  receipt_checked_at timestamptz,
  opened_at timestamptz,
  unique (user_id, kind, ref_id, send_date)
);
```
