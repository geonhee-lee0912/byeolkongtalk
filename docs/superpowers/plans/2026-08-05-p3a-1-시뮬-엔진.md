# P3a 시뮬레이션 엔진 (백엔드) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** "연애 시뮬레이션" 한 판(상황 선택 → 밤 무대 3화자 대화 → 디브리핑)을 **API + QA 하네스만으로** 돌릴 수 있는 백엔드/엔진을 만든다 — 프론트 화면은 Plan 2.

**Architecture:** 제네릭 3화자 엔진 = **인형(별콩이 아님, `doll_partner.md`)** 과 **별콩이(코어+`byeolkong_sim.md`)** 를 **서로 다른 페르소나·별도 Claude 호출**로 격리(스펙 §5). 상황은 코드 상수(`situations.ts`)로 seed 하고, 판은 기존 `reading`/`messages` 에 저장(신규 `consultation_type='relationship_sim'`). 결제는 판 고정가 `SIM_COST` 1회(세션 생성 시 `lib/stars`), 대화 턴은 판에 포함(무료). 안전은 `lib/sensitive` 상시 게이트 → high 면 인형 내려놓고 별콩이 복귀 + hotline. Claude 호출은 전부 기존 `lib/claude` 래퍼(`streamChat`/`generateOnce`, 모델·`cache_control`·재시도 내장) 경유 — SDK 직접 호출 금지.

**Tech Stack:** Next.js 16 (App Router, `runtime=nodejs`, SSE `ReadableStream`), React 19, TypeScript strict, Supabase(service role), Claude API(`claude-sonnet-5` via `streamChat`/`generateOnce`), `node:test` + `tsx` 유닛 테스트, QA 하네스(`qa/`, dev 서버 대상 fetch).

> **분할 메모(하나로 유지 결정):** 백엔드만으로 10개 태스크 — 한 플랜으로 관리 가능. 병렬화가 필요하면 **T1~T7(데이터·상수·마이그레이션·페르소나·순수 헬퍼·빌더)** 을 먼저 끝내고 **T8~T10(라우트 3종)** 을 한 배치로, **T11(QA)** 을 마지막에 두면 자연스러운 3구획이 된다. 그래도 순서 의존이 강해(§헬퍼→빌더→라우트) 단일 세션 실행을 권장.

## 디브리핑 (정리하기 / 인형 내려놓기)

유저가 정리하기를 누르거나 판이 충분히 무르익으면, 별콩이는 **인형을 내려놓고** 유저 곁으로 돌아와 밤 톤에서 따뜻한 톤으로 바뀌어. 유료 판이라도 **반드시** 이 디브리핑까지 해줘(인형 침묵으로 끝나면 최악). 3블록:

1. **통찰(관찰형, 예측 금지)** — 이번 판에서 본 것 2~3개. 걔(인형)의 성향 + 너의 반응 패턴을, 무대에서 실제 오간 말에 근거해. "네가 ~할 때 걔가 ~하더라" 식.
2. **💌 보낼 말** — 실제 상대에게 보낼 **한 문장**을 제안해. 자연스럽고 그 사람한테 정말 보낼 수 있는 톤으로(유저가 고쳐 쓸 수 있어). 그리고 응답 맨 끝에 그 한 문장을 `[SEND:여기에 보낼 말 한 문장]` 마커로 **한 줄 단독** 붙여 — 화면엔 안 보이고 저장·복사용이야.
3. **따뜻한 마무리** — 오늘 연습 자체를 응원하며 닫아. "완벽하게 안 해도 돼, 이렇게 미리 마음을 만져본 것만으로 한 걸음이야." 스레드로 더 얘기하고 싶으면 이어갈 수 있다는 결로.

## 인형 내려놓기 — 위기 신호 (코어 §위기 최우선)

무대 중 위기 신호가 감지되면 별콩이는 **인형을 내려놓고 곧바로 곁으로** 돌아와. 이땐 연습·디브리핑을 멈추고 공통 코어 §위기 그대로 — 판단·재촉 없이 수용하고 정확한 hotline 을 얹어. `[SEND:]` 마커·3블록 쓰지 말고, 곁에 머물러(먼저 작별하지 마).

  if (args.hasSensitive) return false;
  return args.dollTurns >= SIM_TURN_CAP;

const SIM_SEND_RE = /\[SEND:([^\]]+)\]/;

/** 디브리핑 응답에서 보낼 말 한 문장 추출([SEND:...] 마커). 없으면 null. */
export function extractSendLine(text: string): string | null {
  const m = text.match(SIM_SEND_RE);
  return m ? m[1].trim() : null;
}

export function stripSimMarkers(text: string): string {
  return text.replace(/\[SEND:[^\]]*\]/g, "").replace(/\n{3,}/g, "\n\n").trim();
}

  return convo.map((m) => `${m.role === "user" ? "유저" : "인형"}: ${m.content}`).join("\n");
}

  if (p.personality?.trim()) lines.push(`한 줄 성격: ${p.personality.trim()}`);
  return lines.join("\n");
}

/** 판 로드 + 소유권 + 상황/관계/프로필 컨텍스트를 한 번에 준비. */

    .from("readings")
    .select("id, user_id, relationship_id, consultation_type, saju_data, has_sensitive")
    .eq("id", simReadingId)

  const { userId } = await getSession();
  if (!userId) return NextResponse.json({ error: "Login required" }, { status: 401 });

  maybeSweepExpired();
  const ip = getClientIp(request);
  const bySession = checkRateLimit({ namespace: "sim_chat_session", key: userId, max: 20, windowMs: 60_000 });
  const byIp = checkRateLimit({ namespace: "sim_chat_ip", key: ip, max: 60, windowMs: 60_000 });
  if (!bySession.ok || !byIp.ok)
    return NextResponse.json({ error: "rate_limited" }, { status: 429, headers: { "Retry-After": "60" } });

  let body: Body;
  try { body = (await request.json()) as Body; }
  catch { return NextResponse.json({ error: "invalid_json" }, { status: 400 }); }
  if (!body.simReadingId) return NextResponse.json({ error: "invalid_input" }, { status: 400 });

  const loaded = await loadSim(userId, body.simReadingId);
  if (!loaded) return NextResponse.json({ error: "not_found" }, { status: 404 });
  const { supabase, reading, meta, situation, rel, statusLabel, mbti, personality } = loaded;
  if (meta.phase === "debriefed") return NextResponse.json({ error: "sim_done" }, { status: 409 });

  const action: Action = body.action ?? "say";
  const encoder = new TextEncoder();
  const logCtx = { route: "/api/relationship/sim/chat", userId, extra: { simReadingId: reading.id, action } };

  // ── note (온디맨드 💭 / 자동): 별콩이 노트 — 인형 대화 컨텍스트를 텍스트로 주입, 별도 호출 ──

    const convo = await loadDollConversation(supabase, reading.id);
    const system = buildSimByeolkongMessage({
      mode: "note", situation, partnerName: rel.label, statusLabel,
      userContext: meta.userContext, convoBlock: buildSimContextBlock(convo),
    });
    return streamAndSave(supabase, encoder, system, [{ role: "user", content: "지금 무대를 보고 노트를 남겨줘." }],
      NOTE_MAX_TOKENS, reading.id, "sim_note", logCtx, request, userId);

  // ── say (인형 대사) ──
  if (typeof body.message !== "string" || body.message.length < 1 || body.message.length > MAX_MESSAGE_LEN)
    return NextResponse.json({ error: "invalid_input" }, { status: 400 });

  // 민감 게이트 — high 는 regex 즉시, 회색지대는 haiku 2차(await). 감지되면 인형 내려놓고 별콩이 복귀+hotline.

  const system = buildDollSystemMessage({
    situation, partnerName: rel.label, statusLabel,
    profileLine: formatPartnerForDoll({ statusLabel, mbti, personality }), userContext: meta.userContext,

  const respHeaders: Record<string, string> = {
    "Content-Type": "text/plain; charset=utf-8", "Cache-Control": "no-cache, no-transform", "X-Accel-Buffering": "no",
    "X-Sim-Turn": String(nextDollTurns),

  let dollText = "";
  const stream = new ReadableStream({
    async start(controller) {
      try {
        for await (const chunk of streamChat(system, split.apiMessages, DOLL_MAX_TOKENS, logCtx)) {
          dollText += chunk; controller.enqueue(encoder.encode(chunk));

          { reading_id: reading.id, role: "user", content: userMessage, skill_key: null, created_at: new Date(ts).toISOString() },
          { reading_id: reading.id, role: "assistant", content: dollText, skill_key: null, created_at: new Date(ts + 1).toISOString() },

        controller.close();

        await logError(err, ctxFromRequest(request, { ...logCtx, extra: { ...logCtx.extra, partialCharsShown: dollText.length } }));
        controller.error(err);
      }
    },
  });
  return new Response(stream, { headers: respHeaders });
}

  const text = await res.text();
  const headers: Record<string, string> = {};
  res.headers.forEach((v, k) => (headers[k] = v));

3. **판 메타 저장 위치** — `saju_data` JSONB 재사용(§8 "saju_data 패턴 참고")을 택함. 어드민 별-소모 집계(`20260731050000`)가 `consultation_type IN ('saju','tarot')` 로 그룹하므로 `relationship_sim` 은 자연히 'other' 로 빠진다(연애 스레드와 동일 취급) — 별도 컬럼이 필요하면 T3 마이그레이션에 `sim_meta JSONB` 추가로 전환 가능. 현 설계는 무해 — **확인만.**
4. **onesided-decide 재라우팅**(결정형 → 별콩이 스레드, §4·§11) — 본 플랜은 리허설 seed 로 무대에 태우기만 함. 재라우팅은 프론트 동선(Plan 2) 또는 후속 — **범위 밖으로 이월 확인.**
