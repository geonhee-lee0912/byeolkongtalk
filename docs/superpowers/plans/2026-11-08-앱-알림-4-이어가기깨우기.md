# 앱 알림 단계 4 — 이어가기 + 깨우기 Implementation Plan

> 운영자 사전 허락(2026-11-08): 승인을 기다리지 않고 바로 구현. 설계에 없는 결정은 `HANDOFF.md`·PR 의 "결정 필요"에 적고 계속한다.

**Goal:** 광고에 동의한 회원에게 ① 대화 도중 나간 다음 날 저녁 '하던 이야기 이어가기' 한 번, ② 7일 미접속에 한 번·14일에 한 번 더 '깨우기'. 둘 다 누르면 홈.

**Spec:** `docs/superpowers/specs/2026-11-06-앱-알림-design.md` §3 C, §5-2, §5-3, §7(단계 4). 단계 2(판정·광고 틀·수신거부 표)·단계 3(판정 재료 로더·앱 연 시각) 위에 쌓는다. **DB 변경 없음** — 마이그레이션 PR 이 없다.

**끝났다는 기준(spec §7):** 빈도 상한과 위기 신호 제외가 지켜진다(`lib/push/comeback.test.ts`·`comeback-job.test.ts`).

## 규칙 (`lib/push/comeback.ts`, 순수)

### 이어가기 `decideResume`
- 대상: 가장 최근의 (운세가 아닌) 타로 상담 — 홈 이어가기 버튼(`app/page.tsx`)과 같은 대상
- 끝나지 않았고(`[END]` 없음), 사용자가 한 마디 이상 했고, **마지막 사용자 말이 어제(KST)** — 오늘 다시 왔으면 안 보낸다
- 19:00 이상(§5-2 저녁 19:00), 광고 창이 닫히는 20:30 미만
- 공통 판정(kind "resume", 저녁 칸) — 동의·하루 2·위기 신호 30일·기기
- 표식 = 그 상담 id → 상담 하나에 한 번(마지막 말이 '어제'인 날은 하루뿐이라 저절로 1회)

### 깨우기 `decideWake`
- 앱을 마지막으로 연 날(KST)로부터 7일 → 1회, 14일 → 1회 더. 표식 `{마지막으로 연 날}:{7|14}` — 앱을 다시 열면 새 미접속으로 다시 센다
- cron 이 밀려도 단계마다 7일까지는 늦게 보내고, 그 뒤엔 안 보낸다. 7일을 놓친 채 14일이 되면 14일 것 하나만
- **아침 별 흐름을 받는 사람에겐 안 간다**(§5-3) — 아침 칸이 켜져 있고 생일이 있고 (유료 구독 또는 광고 동의)인 사람
- 공통 판정(kind "wake", **아침 칸**) — 같은 실행에서 아침 흐름이 먼저 돌아 아침 칸을 쓴 회원은 걸러진다

## 문구 (`lib/push/ad-templates.ts`, 광고 틀)

| 종류 | 제목 | 본문 |
|---|---|---|
| 이어가기 | (광고) 어제 하던 이야기, 이어서 할래? | (광고) 별콩이랑 나누던 이야기가 남아 있어. 편할 때 이어서 들려줘. |
| 깨우기 7일 | (광고) 요즘 어떻게 지내? | (광고) 별콩이가 네 생각 하고 있었어. 잠깐 들러 줄래? |
| 깨우기 14일 | (광고) 오랜만이야 | (광고) 마음에 걸리는 일이 생기면 언제든 별콩이한테 들려줘. |

모두 끝에 무료 수신거부·고객센터 줄. 고민 내용은 넣지 않는다(잠금화면). 탓하거나 겁주지 않는다(페르소나 원칙).

## 결정 필요 (설계에 없는 값 — 기본값으로 구현하고 운영자 확인을 받는다)

- **깨우기 시각** — 설계는 '아침 칸'(§5-3 깨우기는 아침 흐름을 안 받는 사람에게만)까지만 말한다. 아침 08:30~11:00 으로 했다.
- **이어가기를 누르면 홈** — 설계 그대로다. 다만 홈의 이어가기 버튼은 같은 상담에 3번까지만 보인다(`RESUME_BANNER_MAX_VIEWS`). 홈을 이미 3번 본 회원은 알림을 눌러도 버튼이 없다. 버튼이 가는 `/readings`(내 고민톡)로 바로 보낼지 정해 줘.
