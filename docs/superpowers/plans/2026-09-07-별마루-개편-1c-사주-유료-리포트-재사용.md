# 별마루 개편 1C-사주(유료) — 기존 daily 리포트 재사용 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`).

**Goal:** 별마루 유료 오늘 사주를 **기존 `/fortune/daily`(오늘의 운세) 리포트 그대로** 재사용해 렌더한다 — 같은 프롬프트·같은 파서·같은 `DailyReportCard`. 구독 게이트 + 오늘 1회 생성-캐시.

**스코프 결정(today-only):** "기존 오늘의 사주를 그대로"(사용자) = **오늘 하루 리포트**. 30일 아무 날이나 리포트 생성은 **범위 밖**(그건 날짜 파라미터화된 프롬프트가 필요 — 이 플랜은 기존 프롬프트를 손 안 대고 그대로 씀). 30일 캘린더는 무료 룰 등급 브라우저로 유지. 무료 오늘 사주 ~400~500자 정적 뱅크는 **별도 후속(1C-사주-무료)**.

**Architecture:** 기존 daily 생성 스택은 재사용률이 매우 높다(연구 지도 `plans/` 세션 참조):
- **그대로 재사용**: `lib/fortune/daily-report.ts`(`parseDailyReportJson`·`buildDailyReport`·`DailyReport` 타입) · `components/fortune/DailyReportCard.tsx`(`{report, dateLabel}`, 결합도 0) · `lib/fortune/prompt.ts`의 `buildFortuneSystem("daily", {saju})` · `lib/fortune/model.ts`의 `fortuneModel("daily")`(=gpt-5-nano) · `lib/fortune/response-format.ts`의 `fortuneResponseFormat("daily")`(=undefined) · `generateOnce`.
- **신규**: 캐시 테이블 `byeolmaru_daily_report`(user×date, `byeolmaru_daily_card` 미러) + 얇은 래퍼 `lib/byeolmaru/daily-report.ts` + 라우트 `app/api/byeolmaru/daily-report/route.ts`(구독 게이트 선행) + `SajuTodayView` 배선.
- 🔴 현 `narrative` 라우트는 **캐시 없이 매 로드 재생성** → 캐시 도입은 순수 원가 개선.

**Tech Stack:** Next.js 16 route handler · OpenAI nano(generateOnce) · Supabase(migration) · React client.

**검증 모델:** 캐시 래퍼 로직은 가능한 단위 테스트, 라우트/UI/마이그레이션은 `tsc`+`next build`+**브라우저 라이브**(세션 주입). daily 파서 계약은 기존 `lib/fortune/*.test.ts`가 이미 지킴(무변경).

- [ ] **Step 1: 마이그레이션 작성.** `byeolmaru_daily_card` 마이그레이션을 그대로 미러하되 이름/컬럼만 바꾼다:
```sql
-- byeolmaru_daily_report — 유료 오늘 사주(기존 daily 리포트 재사용)의 (유저, 날짜)별 1회 생성 캐시.
create table if not exists public.byeolmaru_daily_report (
  user_id uuid not null references public.users(id) on delete cascade,
  report_date date not null,
  report jsonb not null,           -- lib/fortune/daily-report.ts 의 DailyReport(v:1) 객체
  created_at timestamptz not null default now(),
  primary key (user_id, report_date)
);
create index if not exists idx_byeolmaru_daily_report_user_date
  on public.byeolmaru_daily_report (user_id, report_date desc);

alter table public.byeolmaru_daily_report enable row level security;
revoke all on public.byeolmaru_daily_report from public, anon, authenticated;
grant all on public.byeolmaru_daily_report to service_role;
```
⚠️ 실제 `byeolmaru_daily_card.sql`을 열어 RLS/REVOKE/GRANT 문구를 **정확히 그 형식으로** 맞출 것(정책 코멘트 포함). 컬럼 타입·PK만 위와 같이.

- [ ] **Step 2: 래퍼 작성.** `lib/byeolmaru/daily-report.ts` — `daily-card.ts`의 조회/저장 패턴을 미러:
```ts
// lib/byeolmaru/daily-report.ts — 유료 오늘 사주 리포트 캐시 래퍼((유저,날짜)별 1회 생성).
import { getServiceSupabase } from "@/lib/supabase";
import type { DailyReport } from "@/lib/fortune/daily-report";

/** 캐시된 리포트 조회. 없으면 null. */
export async function getCachedDailyReport(userId: string, dateStr: string): Promise<DailyReport | null> {
  const { data, error } = await getServiceSupabase()
    .from("byeolmaru_daily_report")
    .select("report")
    .eq("user_id", userId)
    .eq("report_date", dateStr)
    .maybeSingle();
  if (error || !data) return null;
  return data.report as DailyReport;
}

/** 리포트 저장. 이미 있으면(동시 생성) 덮지 않는다(23505 무시). */
export async function saveDailyReport(userId: string, dateStr: string, report: DailyReport): Promise<void> {
  const { error } = await getServiceSupabase()
    .from("byeolmaru_daily_report")
    .insert({ user_id: userId, report_date: dateStr, report });
  if (error && (error as { code?: string }).code !== "23505") {
    throw error;
  }
}
```
⚠️ `daily-card.ts`가 다른 시그니처/헬퍼(예: KST 날짜 계산 위치)를 쓰면 그 관행에 맞출 것.
