# 별마루 ④ 계측 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 별마루에 트래픽이 흐르기 전에 기준선 계측을 심는다 — 진입·**D1~D7 재방문**·인터랙션 깊이·퍼널 이탈 지점. 나중에 붙이면 첫 7일이 영구히 빈다.

**Architecture:** 새 인프라를 만들지 않는다. 방문은 기존 `page_views`(PageViewBeacon 자동)로 이미 쌓이므로 **집계 RPC만** 얹고, 클릭류는 기존 `trackUiEvent` → `/api/event` → `ui_events` 경로에 이벤트 4종을 추가한다. 어드민은 `app/admin/free/{byeoljari,saju-mbti}` 와 같은 자리에 화면 하나.

**Tech Stack:** Next.js 16 · Supabase(PostgreSQL) · `node:test`

**스펙:** `docs/superpowers/specs/2026-08-31-별마루-리텐션허브-design.md` §8

### Task 2: 어드민 집계 RPC

**Files:**
- Create: `supabase/migrations/<timestamp>_admin_byeolmaru_aggregates.sql`

🔴 **AGENTS.md 필수 규칙 3가지** — 어기면 조용히 틀리거나 보안이 열린다:
1. 날짜식은 반드시 `(created_at at time zone 'UTC' + interval '9 hours')::date` — `at time zone 'UTC'` 를 빼면 캐스트가 세션 TimeZone 에 좌우된다
2. **NULL 3값 논리** — `page_views.user_id` 는 비로그인이면 NULL 이다. `NOT (col = ANY(...))` 는 NULL 행을 통째로 버린다. 제외 필터는 `col IS NULL OR NOT (...)` 로 감쌀 것
3. 새 `SECURITY DEFINER` RPC 는 `REVOKE EXECUTE … FROM PUBLIC, anon, authenticated` **셋 다** 쓰고 `GRANT … TO service_role`

기존 `supabase/migrations/20260829000000_admin_saju_mbti_aggregates.sql` 을 **먼저 읽고** 그 형식(파라미터 `p_exclude UUID[]`, `SET search_path = public`, REVOKE/GRANT 블록)을 그대로 따를 것.

- [ ] **Step 1: 마이그레이션 파일을 만든다**

파일명은 `<YYYYMMDDHHMMSS>_admin_byeolmaru_aggregates.sql`(기존 최신 타임스탬프보다 큰 값).

함수 3개:

**(a) `admin_byeolmaru_summary(p_exclude UUID[])`** — 누적 요약
`page_views` 에서 `path = '/byeolmaru'` 의 PV·UV(=`coalesce(user_id::text, anon_id)` distinct), `ui_events` 에서 별마루 4종 각각의 건수·인원.

**(b) `admin_byeolmaru_trend(p_since TIMESTAMPTZ, p_exclude UUID[])`** — 일별 추세
KST 날짜별 PV·UV·날짜클릭·슬롯클릭.

**(c) `admin_byeolmaru_retention(p_exclude UUID[])`** — 🔴 **이 계획의 핵심**
`/byeolmaru` 를 처음 본 날을 코호트로 잡고, 그 뒤 1~7일차에 다시 온 **실인원**을 센다.

```sql
-- 재방문은 로그인 유저만 센다(anon_id 는 쿠키 삭제·기기 변경에 취약해 코호트가 오염된다).
-- 🔴 퍼센트가 아니라 실인원을 함께 반환한다 — 분자가 1~3명일 때 퍼센트는 오독을 부른다(AGENTS.md).
with v as (
  select pv.user_id,
         (pv.created_at at time zone 'UTC' + interval '9 hours')::date d
  from page_views pv
  where pv.path = '/byeolmaru'
    and pv.user_id is not null
    and not (pv.user_id = ANY(p_exclude))
  group by 1, 2
),
first_seen as (select user_id, min(d) d0 from v group by 1)
select f.d0 as cohort_date,
       count(distinct f.user_id) as cohort_users,
       g.offset_day,
       count(distinct v2.user_id) as returned_users
from first_seen f
cross join generate_series(1, 7) as g(offset_day)
left join v v2 on v2.user_id = f.user_id and v2.d = f.d0 + g.offset_day
group by f.d0, g.offset_day
order by f.d0 desc, g.offset_day;
```

⚠️ 위 SQL 은 **뼈대**다. 그대로 붙여넣지 말고 실행해 보고 컬럼·집계가 맞는지 확인할 것. `cohort_users` 가 offset 마다 반복되는 형태가 맞다(long format).
