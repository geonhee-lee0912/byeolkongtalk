# 어드민 앱/웹 구분 + 실제 결제자 줄 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 대시보드·트래픽에서 방문·가입·결제를 앱/웹으로 나눠 보이고, 결제율 아래 그 기간 실제 결제자 전체를 보인다.

**Architecture:** 새 집계 RPC 3개(마이그레이션 PR 먼저) → 순수 변환 함수(`lib/admin/platform.ts`) → 대시보드 로더·트래픽 API 가 RPC 를 부르고 화면이 표·선을 그린다. 기존 RPC 는 건드리지 않는다.

**Tech Stack:** Next.js 16 · Supabase Postgres(SQL RPC) · `node:test`

**Spec:** `docs/superpowers/specs/2026-11-28-어드민-앱웹-구분-design.md`

## Global Constraints

- 날짜식은 전부 `(created_at AT TIME ZONE 'UTC' + INTERVAL '9 hours')::date`.
- 새 함수마다 `SECURITY DEFINER` · `SET search_path = public` · `REVOKE EXECUTE … FROM PUBLIC, anon, authenticated` · `GRANT EXECUTE … TO service_role`.
- 어드민 제외: 방문은 `(user_id IS NULL OR user_id <> ALL(p_exclude))`, 회원은 `id <> ALL(p_exclude)`, 결제는 `(p.user_id IS NULL OR p.user_id <> ALL(p_exclude))`. `p_exclude` 는 `COALESCE(p_exclude, '{}')`.
- 앱 방문 = `browser_env = 'app'`, 웹 = 그 외 전부(NULL 포함). 봇(`is_bot`) 제외.
- 가입 앱/웹 = 가입 시각 이후 24시간 안 그 회원의 첫 방문 기록(봇 제외)의 `browser_env`; 없으면 모름.
- 결제 = `status = 'completed'`(환불 제외), 수단 `pg_provider` ∈ `tosspayments`·`apple`·`google`.
- 원본 행을 앱으로 끌어오지 않는다(집계는 RPC).
- 마이그레이션 PR 과 화면 PR 은 따로. 화면 PR 은 마이그레이션이 dev 에 적용된 뒤.
- 공개 저장소: 커밋·문서·PR 에 운영 숫자·UUID 금지.

## Review Focus

- 한 날에 가입·방문·결제가 전혀 없는 날 → 표는 0 으로 그 날짜를 보여야 한다(트래픽 일별 표는 기존 추세 축에 맞춰 채운다). → Task 2 테스트 `platformDailyRows 빈 날 채움`.
- 실제 결제자 RPC 가 어떤 분류를 0행으로 안 줄 때 → 화면은 5줄을 늘 같은 순서로, 없는 분류는 0. → Task 2 테스트 `periodPayerLines 누락 분류 0`.
- 탈퇴(사람 구분 불가) 줄 → 사람 칸은 "—", 합계 사람 수에 더하지 않는다. → Task 2 테스트 `periodPayerLines 탈퇴는 사람 합계 제외`.
- 세 수단 밖의 `pg_provider`(지금은 없음) → 앱/웹 결제 칸 어디에도 안 잡힌다(세 수단만 FILTER). 실제 결제자 표는 수단을 안 보므로 거기엔 잡힌다. Task 1 Step 3 ④ 대조가 어긋나면 이것부터 의심.
- RPC 하나 실패 → 그 칸만 `LoadFailed`, 다른 칸은 정상. → Task 3 수동 확인(잘못된 함수명으로 일시 교체해 확인 후 원복).

### Task 1: 집계 RPC 3개 (마이그레이션)

**Files:**
- Create: `supabase/migrations/20261128000000_admin_platform_split.sql`

**Interfaces:**
- Produces:
  - `admin_platform_daily(p_since TIMESTAMPTZ, p_exclude UUID[])` → `TABLE(d DATE, uv_app BIGINT, uv_web BIGINT, pv_app BIGINT, pv_web BIGINT, signups_app BIGINT, signups_web BIGINT, signups_unknown BIGINT, pay_toss BIGINT, pay_apple BIGINT, pay_google BIGINT, won_toss BIGINT, won_apple BIGINT, won_google BIGINT)` — 방문·가입·결제 중 하나라도 있는 날만 행.
  - `admin_platform_summary(p_since TIMESTAMPTZ, p_until TIMESTAMPTZ, p_exclude UUID[])` → 위와 같은 열에서 `d` 를 뺀 **한 행**(값이 없으면 0). `p_until` NULL = 지금까지. UV 는 기간 안 서로 다른 `anon_id`.
  - `admin_period_payers(p_since TIMESTAMPTZ, p_until TIMESTAMPTZ, p_exclude UUID[])` → `TABLE(segment TEXT, people BIGINT, payments BIGINT, won BIGINT)`; segment ∈ `new_48h`·`new_later`·`existing_first`·`repeat`·`withdrawn`; `withdrawn` 의 people 은 NULL.

분류 규칙(`admin_period_payers`): 창 안 completed 결제를 사람별로 묶고, 가입 `u.created_at`·평생 첫 completed 결제 `fp` 로 — 가입이 창 안이면 `fp < created_at + 48h` → `new_48h`, 아니면 `new_later`; 가입이 창 전이면 `fp >= p_since` → `existing_first`, 아니면 `repeat`; `user_id IS NULL` → `withdrawn`. `users` 행이 없는데 `user_id` 가 있으면(이론상 없음) `withdrawn` 에 합친다.

- [ ] **Step 1: SQL 파일 작성** — 위 세 함수 + REVOKE/GRANT. 가입 판정은 `LEFT JOIN LATERAL (SELECT browser_env FROM page_views pv WHERE pv.user_id = u.id AND NOT pv.is_bot AND pv.created_at >= u.created_at AND pv.created_at < u.created_at + interval '24 hours' ORDER BY pv.created_at LIMIT 1)`. 가입 버킷은 가입 시각 KST 날짜, 결제 버킷은 결제 시각 KST 날짜.

- [ ] **Step 2: 운영에서 본문 인라인 실행(읽기 전용)** — 세 함수 본문을 파라미터를 리터럴로 바꿔 `node scripts/run-prod-query.mjs <파일>` (env 는 메인 체크아웃 `.env.local`). 세 개 모두 오류 없이 결과가 나와야 한다.

- [ ] **Step 3: 운영 대조** — 같은 스냅샷에서 독립 쿼리와 비교:
  - ① 최근 14일 날짜별 `signups_app + signups_web + signups_unknown` = 그날 `users` 가입 수(제외 없이).
  - ② 창 `2026-11-20 00:00+09` ~ `2026-11-27 00:00+09` 의 `new_48h` 사람 수와 같은 날짜 `admin_pay_rate` 결제자 합의 차이를 사람 단위로 뽑아, 전부 "창 끝 가입·창 뒤 결제" 또는 "창 직전 가입·창 첫날 결제"인지.
  - ③ 같은 창에서 분류별 `payments` 합 = 창 안 completed 결제 건수, `won` 합 = 금액 합.
  - ④ `pay_toss + pay_apple + pay_google` 날짜별 = 그날 completed 결제 건수.
  결과는 커밋하지 않는다(숫자) — HANDOFF 에 "대조 통과"만.

- [ ] **Step 4: 커밋** — `git commit -F <메시지파일> -- supabase/migrations/20261128000000_admin_platform_split.sql`

- [ ] **Step 5: 마이그레이션 PR** — `origin/dev` 에서 `claude/admin-app-web-rpc` 를 따 이 커밋만 cherry-pick → push → PR(base `dev`, 본문 "어디에 영향": 새 읽기 전용 RPC 3개, 기존 함수·표 무변경) → `@codex review` 댓글 + Claude `/code-review <PR>`(DB 영역). 머지는 운영자. 머지 뒤 Supabase dev 체크 success 확인.

### Task 2: 행 변환 순수 함수

**Files:**

**Interfaces:**
- Consumes: Task 1 의 RPC 행 모양.
- Produces:

  - `platformCounts(row: Record<string, unknown> | undefined): PlatformCounts` — snake_case → camelCase, `Number()`, 없으면 전부 0.
  - `platformDailyRows(rows: Record<string, unknown>[], dates: string[]): ({ date: string } & PlatformCounts)[]` — `dates` 순서대로, 없는 날은 0.
  - `type PeriodPayerLine = { segment: string; label: string; people: number | null; payments: number; won: number }`
  - `PAYER_SEGMENTS` = `[["new_48h","신규 · 가입 48시간 안 첫 결제"],["new_later","신규 · 48시간 뒤 첫 결제"],["existing_first","기존 가입자 · 첫 결제"],["repeat","재결제"],["withdrawn","탈퇴(사람 구분 불가)"]]`
  - `periodPayerLines(rows: Record<string, unknown>[]): { rows: PeriodPayerLine[]; total: { people: number; payments: number; won: number } }`

- [ ] **Step 1: 실패하는 테스트 작성** — `lib/admin/platform.test.ts`:
  - `platformCounts 문자열 숫자 변환·빈 행 0`: `platformCounts({ uv_app: "3", won_toss: "4900" })` → `uvApp === 3`, `wonToss === 4900`, `uvWeb === 0`; `platformCounts(undefined).payApple === 0`.
  - `platformDailyRows 빈 날 채움`: rows 에 `2026-11-02` 만, dates `["2026-11-01","2026-11-02"]` → 길이 2, 첫 줄 전부 0, 둘째 줄 값 유지.

  - `periodPayerLines 탈퇴는 사람 합계 제외`: `withdrawn` people NULL·payments 2 → 그 줄 `people === null`, `total.people` 는 나머지 합, `total.payments` 에는 2 포함.
  - `periodPayerLines 모르는 분류 무시`: `segment:"weird"` → 결과 5줄, 합계에 안 들어감.
