# 타로톡 연속 기억 (크로스-리딩 유저 기억) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fresh 타로 리딩에서 별콩이가 그 유저의 최근 타로 상담(요약)을 자동·무음으로 기억해 이번 고민에 자연스럽게 참조한다.

**Architecture:** 유저×종목 롤링 요약 1개를 신규 테이블 `consultation_memory`에 보관. **다음 fresh 리딩 생성 시**(리딩 종료가 아니라) 직전 리딩(들)을 haiku로 압축해 요약에 누적하고, 매 chat 턴에 그 요약을 system dynamicPart에 주입한다. 순수 로직(`lib/tarot/memory.ts`)과 DB 오케스트레이션(`lib/tarot/memory-fold.ts`)을 분리해 순수부는 단위 테스트한다.

**Tech Stack:** Next.js 16 route handlers · Supabase(service_role) · Anthropic haiku(요약) · `node:test`+`tsx`(테스트).

**Spec:** `docs/superpowers/specs/2026-09-06-타로톡-연속기억-design.md`

// lib/tarot/memory.ts — 타로톡 연속 기억(크로스-리딩 유저 기억)의 순수 헬퍼.
// DB 접근은 lib/tarot/memory-fold.ts / 라우트가 담당하고, 이 파일은 순수 함수만(테스트 가능).
// 스펙: docs/superpowers/specs/2026-09-06-타로톡-연속기억-design.md

/** 롤링 요약 최대 길이(자). 데이터: 재방문 90%가 직전 1개, 최대 21회 고래도 상한 안에서 압축. */
export const TAROT_MEMORY_CAP = 800;
/** 접기 창(일) — 이보다 오래된 리딩은 요약에 넣지 않는다. 데이터: 재방문 100%가 60일 내. */
export const MEMORY_FOLD_WINDOW_DAYS = 60;
/** 주입 신선도(일) — folded_upto 가 이보다 오래면 낡은 요약이라 주입하지 않는다. */
export const MEMORY_INJECT_STALE_DAYS = 90;

const DAY_MS = 86_400_000;

/** 마커 제거 — 접기 입력에서 [CARD:n]/[END]/[RECO:...] 를 지운다. */
export function stripMarkers(s: string): string {
  return s.replace(/\[CARD:\d+\]|\[END\]|\[RECO:[^\]]*\]/g, "").trim();
}

/** 요약 상한 절단 — 줄바꿈(불릿)을 보존하며 max 자 이내로. 줄 경계 우선, 없으면 말줄임표. */
export function capSummary(raw: string, max = TAROT_MEMORY_CAP): string {
  const s = raw.trim();
  if (s.length <= max) return s;
  const head = s.slice(0, max);
  const nl = head.lastIndexOf("\n");
  if (nl >= max * 0.5) return head.slice(0, nl).trimEnd();
  return head.trimEnd() + "…";
}

/** system dynamicPart 에 넣을 "지난 상담 기억" 블록. summary 가 있을 때만 호출. */
export function buildTarotMemoryBlock(summary: string): string {
  return `\n\n## 지난 상담 기억 (이 유저와 나눈 과거 타로 상담 요약)
${summary.trim()}
- 이번 고민과 자연스럽게 이어지는 대목이 있으면 가볍게 참조해. 억지로 다 끌어오지 말 것.
- 관련 없으면 언급하지 않는다.
- 과거는 요약이라 세부가 흐릿할 수 있으니 단정하지 말고 부드럽게 확인하듯.`;
}

export interface PriorReading {
  id: string;
  created_at: string; // ISO
  has_sensitive: boolean;
}

export interface FoldSelection {
  /** 실제로 haiku 요약에 넣을 리딩 id — 민감 제외 + 60일 창 내. */
  toFoldIds: string[];
  /** 커서 전진 목표 — 계산 대상(민감·오래된 것 포함) 중 가장 최근 created_at. 없으면 null. */
  cursorAdvanceTo: string | null;
}

/**
 * "계산 대상"(folded_upto 이후 & 새 리딩 이전, 오름차순) → 요약 대상/커서 분리.
 * 커서는 접기 여부와 무관하게 계산 대상 최댓값으로 전진 → 스킵된 민감·오래된 리딩 재스캔 방지.
 */
export function selectFoldTargets(
  prior: PriorReading[],
  nowMs: number,
  windowDays = MEMORY_FOLD_WINDOW_DAYS
): FoldSelection {
  if (prior.length === 0) return { toFoldIds: [], cursorAdvanceTo: null };
  const cutoff = nowMs - windowDays * DAY_MS;
  const toFoldIds = prior
    .filter((r) => !r.has_sensitive && Date.parse(r.created_at) >= cutoff)
    .map((r) => r.id);
  const cursorAdvanceTo = prior
    .map((r) => r.created_at)
    .reduce((a, b) => (Date.parse(b) > Date.parse(a) ? b : a));
  return { toFoldIds, cursorAdvanceTo };
}

/** 주입 게이트 — 요약이 있고 folded_upto 가 stale 하지 않을 때만 주입. */
export function shouldInjectMemory(
  mem: { summary: string | null; folded_upto: string | null } | null,
  nowMs: number,
  staleDays = MEMORY_INJECT_STALE_DAYS
): boolean {
  if (!mem || !mem.summary || !mem.summary.trim()) return false;
  if (!mem.folded_upto) return false;
  return Date.parse(mem.folded_upto) >= nowMs - staleDays * DAY_MS;
}

/** haiku 요약 프롬프트 조립 — 순수(테스트 가능). 네트워크는 lib/claude.ts 가 담당. */
export function buildMemorySummaryPrompt(
  prevSummary: string | null,
  blocks: string[]
): { system: string; user: string } {
  const system = `너는 타로 상담 기록 요약가야. [이전 요약]과 [이번에 끝난 상담들]을 합쳐, 이 유저가 어떤 고민들을 다뤄왔는지 한국어 불릿으로 압축해.
- 각 항목은 [날짜] + 고민 요지. 예: "- 9/1: 이직 고민 — 아직 결정 못함, 상사와 갈등".
- 가장 최근 1~2개는 또렷이, 그보다 오래된 건 짧은 한 줄로 더 압축(버리지 말 것).
- 전체 ${TAROT_MEMORY_CAP}자 이내. 넘으면 오래된 항목부터 더 줄여.
- 사실·중립. 위기/자해/민감한 세부는 담지 마. 별콩이 말투를 흉내내지 말 것(이건 상담이 아니라 기록).`;
  const user = `[이전 요약]\n${prevSummary?.trim() || "(없음)"}\n\n[이번에 끝난 상담들]\n${blocks.join("\n\n")}`;
  return { system, user };
}

/** 타로 크로스-리딩 기억 접기 — 이전 요약 + 이번에 끝난 상담들 → 갱신 요약(haiku, 상한 컷). */
export async function summarizeReadingsForMemory(
  prevSummary: string | null,
  blocks: string[]
): Promise<string> {
  if (blocks.length === 0) return prevSummary ?? "";
  const { system, user } = buildMemorySummaryPrompt(prevSummary, blocks);
  const resp = await anthropic.messages.create({
    model: "claude-haiku-4-5-20251001",
    max_tokens: 700,
    system,
    messages: [{ role: "user", content: user }],
  });
  const text = resp.content.find((b) => b.type === "text");
  const out = text && text.type === "text" ? text.text.trim() : (prevSummary ?? "");
  return capSummary(out, TAROT_MEMORY_CAP);
}
```

// lib/tarot/memory-fold.ts — 타로 연속 기억 접기(DB 오케스트레이션).
// 다음 fresh 리딩 생성 시 호출: 직전 리딩(들)을 요약해 유저 기억에 누적. best-effort.
// 스펙: docs/superpowers/specs/2026-09-06-타로톡-연속기억-design.md §6
import type { SupabaseClient } from "@supabase/supabase-js";
import { kstDate } from "@/lib/admin-time";
import { summarizeReadingsForMemory } from "@/lib/claude";
import { selectFoldTargets, stripMarkers, type PriorReading } from "@/lib/tarot/memory";

interface PriorRow extends PriorReading {
  question: string | null;
}

/**
 * 유저의 타로 기억을 접는다. newReadingCreatedAt = 방금 만든 리딩의 created_at(상한, 배타).
 * 계산 대상(folded_upto < created_at < 새 리딩)이 없으면 아무것도 안 한다.
 */
export async function foldTarotMemory(
  supabase: SupabaseClient,
  userId: string,
  newReadingCreatedAt: string
): Promise<void> {
  const { data: mem } = await supabase
    .from("consultation_memory")
    .select("summary, folded_upto")
    .eq("user_id", userId)
    .eq("consultation_type", "tarot")
    .maybeSingle();

  const foldedUpto = (mem?.folded_upto as string | null) ?? null;

  let q = supabase
    .from("readings")
    .select("id, question, created_at, has_sensitive")
    .eq("user_id", userId)
    .eq("consultation_type", "tarot")
    .lt("created_at", newReadingCreatedAt)
    .order("created_at", { ascending: true });
  if (foldedUpto) q = q.gt("created_at", foldedUpto);

  const { data: priorData } = await q;
  const prior = (priorData ?? []) as PriorRow[];
  if (prior.length === 0) return; // 계산 대상 없음 → upsert도 안 함

  const { toFoldIds, cursorAdvanceTo } = selectFoldTargets(prior, Date.now());

  let newSummary = (mem?.summary as string | null) ?? null;

  if (toFoldIds.length > 0) {
    const { data: msgs } = await supabase
      .from("messages")
      .select("reading_id, role, content, created_at")
      .in("reading_id", toFoldIds)
      .order("created_at", { ascending: true });

    const byReading = new Map<string, { role: string; content: string }[]>();
    for (const m of (msgs ?? []) as { reading_id: string; role: string; content: string }[]) {
      const arr = byReading.get(m.reading_id) ?? [];
      arr.push({ role: m.role, content: m.content });
      byReading.set(m.reading_id, arr);
    }

    const blocks: string[] = [];
    for (const r of prior) {
      const rows = byReading.get(r.id);
      if (!rows || rows.length === 0) continue; // 빈 리딩 제외
      const convo = rows
        .map((m) => `${m.role === "user" ? "유저" : "별콩이"}: ${stripMarkers(m.content)}`)
        .filter((l) => l.length > 4)
        .join("\n");
      if (!convo) continue;
      blocks.push(`[${kstDate(r.created_at)}] 고민: ${r.question ?? "(없음)"}\n${convo}`);
    }

    if (blocks.length > 0) {
      newSummary = await summarizeReadingsForMemory((mem?.summary as string | null) ?? null, blocks);
    }
  }

  await supabase.from("consultation_memory").upsert(
    {
      user_id: userId,
      consultation_type: "tarot",
      summary: newSummary,
      folded_upto: cursorAdvanceTo,
      updated_at: new Date().toISOString(),
    },
    { onConflict: "user_id,consultation_type" }
  );
}
```
