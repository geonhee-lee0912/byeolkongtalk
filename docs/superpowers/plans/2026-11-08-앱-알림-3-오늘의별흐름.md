# 앱 알림 단계 3 — 오늘의 별 흐름 Implementation Plan

> 운영자 사전 허락(2026-11-08): 승인을 기다리지 않고 바로 구현. 설계에 없는 결정은 `HANDOFF.md` "결정 필요"에 적고 계속한다.

**Goal:** 매일 아침 08:30 이후, 별마루 '오늘'의 하루 이름과 풀이를 알림으로 보낸다. 유료 구독자는 정보성 틀, 광고에 동의한 비구독자(체험 포함)는 광고 틀. 아침 알림을 받는데 14일 동안 앱을 열지 않으면 멈추고, 다시 열면 재개한다.

**Spec:** `docs/superpowers/specs/2026-11-06-앱-알림-design.md` §3 B·C, §4-6, §5-2, §5-3, §7(단계 3). 단계 2 계획 `2026-11-08-앱-알림-2-광고동의.md` 위에 쌓는다(판정 `decidePush`·광고 틀·수신거부 표를 그대로 쓴다).

**끝났다는 기준(spec §7):** 같은 시각에 구독자와 비구독 동의자가 다른 틀을 받는다. 비동의 비구독자는 받지 않는다(`lib/push/morning.test.ts`·`morning-job.test.ts`).

## 내용 — LLM 없이

별마루 달력과 같은 규칙 계산(`calcSaju` → 오늘 일진 → `buildCalendar`)으로 오늘의 십신을 구하고, 이미 있는 문구를 쓴다.

| 틀 | 제목 | 본문 |
|---|---|---|
| 정보성(구독자) `templates.ts` `morningInfoMessage` | `오늘은 {하루 이름}` (예: 오늘은 차곡차곡 쌓는 날) | `DAY_LINE` 두 문장 |
| 광고(비구독 동의자) `ad-templates.ts` `morningAdMessage` | `(광고) 오늘은 {하루 이름}` | `(광고) {DAY_LINE 첫 문장} 별마루에서 오늘 흐름을 더 볼 수 있어.` + 수신거부·고객센터 줄 |

- 정보성 제목에 "오늘의 별 흐름"을 쓰지 않는다 — '별'이 판촉 단어(재화)라 계약 테스트가 막는다. 판촉 단어 검사는 '별콩톡·별콩이·별마루' 같은 이름을 지우고 한다(`promoWordsIn`).
- 누르면 `/byeolmaru/day`(별마루 오늘 상세).
- 생일이 없는 회원은 계산할 수 없어 보내지 않는다.

## 규칙 (`lib/push/morning.ts` `decideMorning`, 순수)

1. 오늘 이미 보냄 → 안 보냄
2. 아침 창 **08:30 이상 11:00 미만**(KST) — 08:30 은 설계 §5-2, **11:00 은 설계에 없는 값** — 운영자가 2026-11-08 '지금대로' 확정
3. 공통 판정 `decidePush(kind "morning")` — 기기·아침 칸·분류·광고 동의·도착 창·빈도(아침 칸)·위기 신호
4. 앱을 마지막으로 연 지 14일 넘음 → 멈춤(다시 열면 다음 아침부터 재개)
5. 생일 없음 → 안 보냄

| `lib/push/dispatch.ts` `withPushHash` | 모든 알림 경로 끝에 `#bkp=<발송 번호>`(광고는 `&bku=<표>`) |
| `app/mypage/notifications/page.tsx` | '아침 별 흐름' 칸. 비구독자는 광고 동의도 켜야 받는다는 안내 |

## 알려진 한계

- 발송은 회원마다 Expo 호출 한 번이다. 실행당 45초 예산 × 아침 창 10번 실행이라 앱 사용자가 수천 명을 넘으면 여러 회원을 한 호출(100건)로 묶어야 한다. 지금은 앱 출시 전이라 단순한 쪽으로 둔다.
