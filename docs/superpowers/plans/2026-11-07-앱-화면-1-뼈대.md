# 앱 화면 1단계(뼈대) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱 안에서만 앱식 헤더·푸터 정리·작은 동작·화면 전환을 켜고, 웹(브라우저) 화면은 한 픽셀도 바꾸지 않는다.

**Architecture:**
- 루트 레이아웃 맨 앞 인라인 스크립트가 `<html data-app data-platform>` 를 붙인다.
- 웹·앱이 다른 부분은 둘 다 그려 두고 CSS(`web-only`/`app-only`)로 하나를 숨긴다.
- 화면 전환은 Next 16 `experimental.viewTransition` 으로 켠다. 방향은 `<html data-nav>` 속성으로 정하고, 그 속성이 없으면 애니메이션이 없다.

**Tech Stack:** Next.js 16.2 App Router · React 19.2 `<ViewTransition>` · Tailwind v4 · node:test(`node --import tsx --test`)

**Spec:** `docs/superpowers/specs/2026-11-07-앱-화면-design.md` (§3·§4·§5 ①③⑤⑦·§6·§9) · 시안 `docs/superpowers/specs/assets/2026-11-07-앱-화면-시안.html`

**범위:**
- 2~4단계(시트 틀·나머지 시트·앱 쪽 묶음)는 이 계획에 없다. 1단계를 실기기로 확인한 뒤 각자 계획을 쓴다.
- 1단계 결과(§6 미확인 2개)가 그 설계를 바꿀 수 있어서다.

## Global Constraints

**배포·작업 규칙**
- 운영 배포 금지. 이 단계 변경은 dev 에만 들어간다.
- 판정 창(2026-11-10 18:57 KST) 동안 로그인·첫 화면·타로 첫 구매의 **운영** 코드를 바꾸지 않는다. 홈·로그인 시트 손질은 dev 에서만, 앱에서만 달라진다.
- 패키지 설치 명령을 직접 돌리지 않는다. 이 단계는 새 의존성이 없다.
- 공유 워킹 트리에서 `git add -A`·`--amend` 를 쓰지 않는다. 커밋은 `git commit -F <파일> -- <경로>` 로 한다.
- 키·풀 UUID·사업 숫자를 코드·문서·PR 에 쓰지 않는다.

**앱 판단과 웹 보존**
- 앱 판단 규칙은 `lib/app-context.ts` `getAppInfo` 와 같다.
  - 1차: `window.__BYEOLKONG_APP__` 가 `isAppInfo` 를 통과하면 앱
  - 2차: UA 가 `/ByeolkongApp\/([0-9A-Za-z._-]{1,32}) \((ios|android)\)/` 에 맞으면 앱
- 웹 화면은 바뀌지 않는다. 바꾸는 화면마다 웹 모드 스크린샷을 작업 전후로 찍어 비교한다.

**헤더 값**
- 앱 헤더 높이는 `h-14`(56px)로 한다. 웹 헤더와 같아야 하는 이유: `saju/reading` 의 `top-[3.5rem]` 처럼 이 높이에 기대는 화면이 있다.
- 탭 첫 화면 5개와 제목: `/` 타로톡 · `/fortune` 사주 운세 · `/byeolmaru` 별마루 · `/shop` 별콩 상점 · `/mypage` 마이

**화면 전환 시간**
- 아이폰: 0.35초. 새 화면이 오른쪽에서 들어오고, 옛 화면은 왼쪽 30% 로 밀리며 어두워진다.
- 안드로이드: 0.3초. 새 화면이 아래 8% 에서 떠오르며 나타난다.

## Review Focus

1. **입력칸 (앱 모드):** 글자 선택 막기를 켜도 `input`·`textarea`·`[contenteditable]` 는 입력·선택이 그대로 돼야 한다. 아이폰은 `user-select:none` 을 입력칸에 걸면 타이핑이 안 된다. → Task 6 확인 단계
2. **웹 모드:** 모든 화면이 작업 전과 같아야 한다. 헤더 높이, 푸터, 자체 뒤로 줄, 애니메이션 없음. → Task 3~7 의 전후 스크린샷
3. **딥링크·알림으로 하위 화면이 바로 열렸을 때:** `‹` 가 죽지 않고 그 탭 첫 화면으로 가야 한다. → Task 2 테스트 + Task 3 확인
4. **화면 이동이 아닌 React 트랜지션**(페이지 안 `useTransition`·Suspense): 미끄러지면 안 된다. → Task 7 테스트 + 확인
5. **콘솔:** 앱 모드에서 `<html>` 속성 때문에 하이드레이션 경고가 나지 않아야 한다. → Task 1 확인
