# W1 사이클 3 — 통합 QA → 연애 상담 페르소나 → prod 일괄 배포 → 광고 교체 (로드맵)

> **성격:** 이건 태스크 단위 TDD 실행 플랜이 아니라 **사이클 3 전체 시퀀스 로드맵**이다.
> 각 단계는 게이트로 연결되며, `3c`(페르소나)·`3f`(광고)의 상세 설계는 **착수 시 별도 spec+plan(브레인스토밍 경유)** 으로 채운다 — 프로젝트 컨벤션(한 종목/화면 = 자체 spec+plan) 준수.

**배경:** 사이클 1(구조 전환)·사이클 2(연애 상담=구 "우리 사이" v1)·후속 폴리시(리네임/리디자인)가 전부 **dev 완료**. 배포 정책상 사이클 1~3 전부 dev+QA 후 **prod 1회 일괄**. 사이클 3은 그 일괄 배포를 안전하게 넘기기 위한 **통합 QA + 신규 페르소나 정식화 + (배포 후) 광고 교체**까지 포함한다.

⚠️ **배포 정책 (불변):** 중간 prod 금지. `3e`에서 사이클 1~3 전체를 main으로 **1회 일괄** 배포. 그 전(3a~3d)은 전부 dev 전용 커밋/푸시.

**참조:**
- 사이클 1 플랜 `docs/superpowers/plans/2026-07-17-w1-cycle1-structure.md`
- 사이클 2 플랜 `docs/superpowers/plans/2026-07-18-w1-cycle2-우리사이.md`
- 리네임/리디자인 플랜 `docs/superpowers/plans/2026-07-18-연애상담-리네임-리디자인.md`
- QA 하네스 `docs/superpowers/plans/2026-06-28-conversation-qa-harness.md` (`npm run qa`) + `scripts/qa-cycle2-api.mjs`
- 광고 소재 믹스 `docs/superpowers/specs/2026-07-17-w1-love-restructure-w6-ads-design.md` §8
- 페르소나 파일 `data/persona/byeolkong_{core,saju,tarot,fortune,verdict,relationship}.md`

## 시퀀스 (게이트로 연결)

```
3a 코어 QA ──▶ 3b 사용자 화면 QA ──▶ 3c 연애상담 페르소나 신설 ──▶ 3d 전체 페르소나 QA ──▶ 3e prod 일괄 ──▶ 3f 광고 교체
  (dev)          (dev, 반복)             (dev, 브레인스토밍)          (dev)                (main 1회)     (prod 이후)
```

### 3a. 사이클 3 코어 — **prod 배포 직전까지**

**목표:** dev에 쌓인 사이클 1~3 전부가 "언제든 prod로 올려도 되는" 상태.

- [ ] **QA 하네스에 연애 상담 시나리오 추가** — 관계 스레드(지속 대화·패스 게이트·소프트캡·연장) + 스킬 4종(체크인/속마음/궁합/판정) + verdict 수렴. 기존 `scripts/qa-cycle2-api.mjs`(API 41케이스) 위에 대화형 시나리오 확장.
- [ ] **전체 회귀 (골든패스 자체 QA):** 사주 / 타로 / 궁합 / 운세 리포트 / 연애 상담. 각 종목 정상턴 + 종료(수렴 [END] 또는 소프트캡) 경로.
- [ ] **dev 잔여 부채 정리 (prod 전 필수):**
  - 등록실패 **진단 계측 raw `detail` 제거** — 클라 에러코드 표시 + 라우트 응답 raw `detail`이 dev 잔존(사이클 2 등록 thread_failed 디버깅용). prod 노출 금지 → 제거/축약.
  - **Toss 로컬 `.env.local` 위젯키 스테일** 확인 — dev/prod Vercel env는 정상, 로컬만 스테일. 로컬 결제 검증 필요 시 갱신(코드 무관).
  - (범위 밖 부채: `middleware→proxy` rename, admin 콘솔, legal 페이지 톤 — 별도. 이 사이클에서 건드리지 않음.)
- [ ] **빌드/타입/헬스 그린**

**검증:** `npm run build` EXIT 0 · 유닛 전부 PASS(`node --import tsx --test lib/**/*.test.ts`) · qa 하네스 시나리오 PASS · dev `/api/health` 200.
**게이트 → 3b:** 사용자에게 "화면 단위 QA 시작해도 됨" 신호.

### 3b. 사용자 화면 단위 QA → 수정 (반복)

**목표:** 사용자가 dev에서 화면별로 훑고 어색한 부분 지적 → 내가 수정. (사용자 주도)

- 대상 화면(연애 상담 신설·구조 전환으로 영향받은 표면):
  - 홈 연애존 / `/concern` / `/tarot`·`/tarot/draw`·`/tarot/reading`
  - `/fortune` 운세 진열대 / `/relationship` **S1 미등록·S2 패스없음·S3 활성·S4 캡도달** / 스킬 시트 · verdict
  - `/mypage`·보관함 / `/shop` / result·공유 · OG
- **사이클:** 지적 → 코드 수정 → 빌드/타입 그린 → dev push → 사용자 새로고침 검증 (화면당 1~3 사이클).

**검증:** 사용자 승인. 수정분 빌드/타입 그린 유지.
**게이트 → 3c:** 사용자가 "화면 OK".

### 3c. 연애 상담 페르소나 신설 (착수 시 브레인스토밍)

**목표:** 연애 상담(지속 대화형)을 위한 **정식 페르소나** 확립.

- ⚠️ **스코프는 착수 시 브레인스토밍으로 확정** — 사이클 2 v1(`data/persona/byeolkong_relationship.md`)을
  - (a) 완전 신규 설계로 대체 / (b) 정식 승격·리파인 / (c) 부분 보강 중 택.
- **근거:** 사주/타로/운세/판정은 W4에서 v3 페르소나로 정립됐지만(공통 코어 + 도메인), **연애 상담은 성격이 근본적으로 다름** — 수렴/[END] 없는 지속 스레드, 파일+요약 기억 기반, 관계 상담. v1은 사이클 2에서 기능과 함께 급조된 상태 → **정식 설계 1패스** 필요.
- **산출 후보:** `byeolkong_relationship.md`(또는 신규 파일) + `lib/claude`의 `buildRelationshipSystemMessage` 조정 + (필요 시) 요약/기억(`lib/relationship/memory.ts`) 튜닝.
- ⚠️ **페르소나/데이터 파일 수정 후 dev 서버 재시작 필수**(모듈 캐시 — `qa-harness-usage` 메모리).

**상세 플랜:** 착수 시 `docs/superpowers/{specs,plans}/<date>-연애상담-페르소나-*.md`.
**게이트 → 3d.**

### 3d. 전체 페르소나 QA (1회 전수)

**목표:** 전 페르소나 회귀 — 신규 연애 상담 페르소나 **정상** + 기존 v3(사주/타로/운세/판정) **무회귀** 확인.

- QA 하네스로 도메인별 시나리오 + judge 루브릭(W4에서 v3 갱신).
- **위기 시그널 안전망(SafetyBanner)** 전 종목 패리티 확인 — 사주·타로·관계 스레드·verdict.
- 회귀 발견 시 → **3c로 되돌아 수정** 후 재실행.

**검증:** 하네스 어서션 PASS + judge 핵심(소신·훅·완곡·회피구·위기) 통과.
**게이트 → 3e.**

### 3e. prod 일괄 배포 (사이클 1~3 전체)

**목표:** dev의 사이클 1~3 전부를 main으로 **1회 일괄**.

- [ ] main ff/merge, **마이그레이션 적용 순서 확인** — Supabase main Workflow logs SUCCESS (baseline drift 시 `Phase 4 (a) 운영 노트` 절차).
- [ ] 배포 후: prod `/api/health` 200 · 골든패스 스팟체크(로그인→각 종목→별 차감→SSE→결과) · 카카오 공유 OG(prod 보호 없음 → 정상).
- [ ] ⚠️ **페르소나 배포 = 이탈지표 새 경계 커밋 기록** — `persona-tuning-baseline` 패턴(W4 `eee051f` 선례). 배포 커밋 SHA를 전후 비교 기준으로 메모리에 남김.
- [ ] AGENTS.md 진행 상황(Phase) + 스테일 정리(admin 완료·legal 존재 등 비차단 부채) 반영.

**게이트 → 3f:** prod 그린.

### 3f. 광고 소재 제작 + 교체 (W6, **prod 이후**)

**목표:** 연애 중심 소재로 광고 교체.

- ⚠️ **착수 시 소재 브레인스토밍** — 문구·이미지·영상 형태까지 확정(스펙 §8 하단 기록대로 "세세 브레인스토밍 후 확정").
- **소재 믹스 미확정분 확정:** tarot 대조군 + **범용 연애**('그 사람의 마음이 궁금해?' 캐치올) + **연애 상담**(신상품 수요테스트 = 패스/리텐션 측정) — 재회/연락 특정 소재 대신 갈지 여부(스펙 §8: tarot 대조군이 이미 연애 broad 훅이면 슬롯 겹침 → 각도 조정).
- Meta 교체 + utm 파라미터 규약(`v` 우선, `utm_content`=어트리뷰션 전용) 준수.
