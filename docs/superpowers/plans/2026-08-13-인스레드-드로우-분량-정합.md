# 인-스레드 드로우 분량 정합 (Phase C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 인-스레드 드로우(`checkin_6`·`deep_feelings_5`) 첫 풀이 분량을 동일 스프레드·동일 별값 타로 프리미엄 밴드(5장 3,100~3,700 / 6장 3,500~4,200)에 정합시킨다. 현재 luna 실측 2,024/1,961 → 밴드 도달.

**Architecture:** 코드 게이트(`WRAP_THRESHOLDS`) 이식 없이 **페르소나 프롬프트에 밴드·자리당 밀도 지침**만 부여(Phase B가 타로 페르소나에 밴드 넣은 방식). 검증은 `smoke-draw-inthread.ts`(dev 서버 + luna 실호출)의 `drawLen` 밴드 하한으로. `[CARD:n]` 자리 분할·마커 규칙·톤은 전부 불변.

**Tech Stack:** 페르소나 md(`data/persona/`), 수동 smoke 스크립트(tsx, untracked), `PROMPT_VERSION` 라벨.

**전제 조건 (실행 전 확인):**
- dev 서버가 `http://localhost:3000`에 떠 있어야 함 (`.claude/launch.json`의 `byeolkong-dev`). smoke가 여기로 POST.
- `.env.local`에 `CLAUDE_API_KEY`·`OPENAI_API_KEY`(luna) 존재. `CHAT_MODEL="gpt-5.6-luna"`가 기본 배선이라 별도 오버라이드 불필요.
- smoke 1회 = 관계 등록→패스→드로우→grace 턴, luna 실호출 ~1.5분/스킬.

**커밋 대상:** `data/persona/byeolkong_relationship_draw.md` + `lib/prompt-version.ts` **둘뿐**. `scripts/smoke-draw-inthread.ts`는 untracked 검증 도구라 커밋하지 않는다(수정만).

### Task 2: 드로우 페르소나에 밴드·자리당 밀도 부여 (GREEN)

**Files:**
- Modify: `data/persona/byeolkong_relationship_draw.md`

두 곳을 바꾼다. 마커 규칙·`[END]` 금지·물음표 금지·단정 금지는 **건드리지 않는다**(불변).

- [ ] **Step 1: 자리별 해석(1번 항목)에 밀도 지침**

`## 이 순서로 써` 아래 **1번 항목 전체**를 교체.

찾을 것(정확히):
```
1. **자리별 해석** — 카드마다, 해석 문단 **직전에 `[CARD:n]` 을 한 줄 단독으로** 놓아(n = [뽑은 카드] 목록의 번호). 그 자리 이름과 카드가 어떻게 맞물리는지 읽어줘. 카드 뜻만 나열하지 말고 "이 자리에 이 카드가 온 의미"로.
```
바꿀 것:
```
1. **자리별 해석** — 카드마다, 해석 문단 **직전에 `[CARD:n]` 을 한 줄 단독으로** 놓아(n = [뽑은 카드] 목록의 번호). 각 자리를 **5~6문장 이상**으로 두껍게 읽어줘:
   - 카드 이름과 정/역방향의 결을 먼저 한두 문장 (카드 뜻만 나열하지 말고).
   - **"이 자리에 이 카드가 온 의미"를 관계 파일(호칭·상태·지난 기록·이번 대화의 구체 사건)과 엮어 세 문장 이상** — 이 파트가 가장 두꺼워야 해. 한 문장으로 뭉뚱그리지 말고 "자리 → 카드 → 지금 이 관계"로 차근차근.
   - 앞 자리 카드와 어떻게 이어지는지 한 문장.
   한 자리가 3문장 이하로 얇게 끝났으면 관계 맥락 연결을 한 겹 더 얹어 다시 늘려.
```

- [ ] **Step 2: 분량 라인을 카드수별 밴드로 교체**

`## 이 스레드니까 지킬 것` 아래 **분량 불릿 한 줄**을 교체.

찾을 것(정확히):
```
- 분량: 자리 수만큼의 문단 + 흐름 + 처방까지 촘촘하게. 평소 한 턴보다 확실히 길게 — 유저가 값을 치른 풀이야.
```
바꿀 것:
```
- 분량 (유료 풀이 — 낸 별에 맞는 밀도를 자리마다 보장): 위 자리당 5~6문장을 지켜서 총 목표 분량에 닿아 —
  - **5장(걔 속마음): 3,100~3,700자**
  - **6장(관계 체크인): 3,500~4,200자**
  - 카드가 많을수록 총량은 카드 수에 비례해 늘고, 자리당 밀도는 일정하게 유지해. 밀도로 채워 — 같은 말 반복이나 공허한 미사여구로 부풀리지 말고, 관계 파일·이번 대화와의 구체적 연결을 한 겹씩 더 얹어서 길게.
```

- [ ] **Step 3: dev 서버 재시작 (모듈 캐시 무효화 — 필수)**
