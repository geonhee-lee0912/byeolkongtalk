# 타로톡 질문 메뉴판 + 별 경제 — 구현 계획 (반반 A/B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 타로톡에 질문 메뉴판(맛보기 → 3장 → 깊게 → 끝까지)과 새 별 가격·패키지를 넣되, **가입자를 user_id 로 반반 나눠** 옛 타로톡(지금 prod 그대로)과 같은 기간에 비교한다. 맛보기가 끝나면 같은 질문의 깊게 상품을 정가로 이어 보게 한다(메뉴판 그룹만).

**Architecture:** 그룹은 `lib/tarot/menu-ab.ts` 의 `menuArmOf(userId)` 하나로 계산하고(끝 글자 짝수 = 메뉴판), 클라이언트는 `/api/stars/balance` 의 `menuArm` 으로 받는다. 타로 가격은 `lib/tarot/pricing.ts` 의 `tarotPrice(spread, arm)` 하나가 서버 차감·이어가기·화면 표시를 모두 맡는다 — `SPREAD_INFO.starCost` 는 **옛 그룹(prod) 값으로 되돌려** 그룹을 모르는 코드가 남아도 prod 와 같게 보이게 한다. 패키지는 판매 목록(두 그룹 합집합)으로 결제를 검증하고 진열만 그룹별로 가른다. 상품 32개는 `lib/tarot/menu.ts` 데이터(기존 스프레드 재포장). DB 마이그레이션 없음.

**Tech Stack:** Next.js 16 App Router(클라이언트 컴포넌트) · TypeScript strict · Tailwind v4 · node:test + tsx · Supabase(service role)

**스펙:** `docs/superpowers/specs/2026-10-05-타로톡-메뉴판-별경제-design.md` — §9(반반 판정)·§9-1(나누는 범위)이 이 계획의 기준이다.

**prod:** 사용자가 명시적으로 go 하기 전엔 배포하지 않는다. 배포 시각(KST)을 반드시 기록한다(판정 창 시작).

## 반반(A/B) 구조 — 이 계획의 뼈대

- **그룹**: `menuArmOf(userId)` — user_id 마지막 글자가 `0 2 4 6 8 a c e` 면 `"menu"`, 아니면 `"legacy"`. 비로그인 = `"legacy"`. 스위치 `MENU_AB = "split" | "menu" | "legacy"`. 판정 SQL·감시 쿼리(`scripts/menu-ab-daily-check.sql`)와 같은 규칙.
- 🔴 **구현 중엔 `MENU_AB = "legacy"` 로 잠가 둔다**(Task 4 리뷰 반영) — 화면이 덜 된 중간 커밋이 dev→main 으로 나가도 전원 prod 그대로 동작하게. **Task 15 에서 `split` 으로 켠다.**
- **원칙: 옛 그룹 = 지금 prod 그대로.** 옛 화면·흐름은 지우지 않고(스프레드 고르기 → `components/tarot/SpreadPicker.tsx` 로 옮길 뿐) 판정 뒤 정리 배포에서 진 쪽을 지운다.
- **가격 하나**: `tarotPrice(spread, arm)` — 옛 = `SPREAD_INFO.starCost`(prod 값), 메뉴판 = 카드 수 사다리 15·15·25·55·55·70. 서버 차감(`/api/consultations/tarot`)·이어가기(`fullCostFor`)·화면 표시가 모두 이 함수를 쓴다. `SPREAD_INFO.starCost` 를 prod 값으로 두는 이유: 그룹을 모르는 코드가 하나 남아도 prod 와 같은 값을 보여 옛 그룹이 깨지지 않는다.
- **패키지**: `STAR_PACKAGES` = 판매 목록 전체 7종(두 그룹 합집합) — 결제 준비·승인 검증용(id 마다 별·가격 고정이라 안전). 진열은 `shopPackages(arm)`·`sheetPackages(arm)`.
- **클라이언트의 그룹**: `/api/stars/balance` → `{ balance, isGuest, giftUnused, menuArm }`. 파서 `parseWallet`(→ `Wallet {balance, giftUnused, menuArm, isGuest}`), 조회 `fetchWallet`(실패 시 `wallet_fetch_failed` 이벤트), 훅 `useWallet`(실패 시 `parseWallet(null)` = 잔액 0·게스트·스위치가 정한 비로그인 그룹(반반 중엔 옛 그룹) — 화면이 멈추지 않게).
- **앱 코드는 `menuArmOf(userId)` 만** 쓴다(스위치 `MENU_AB` 를 따른다). 규칙 본체 `armForMode(userId, mode)` 는 테스트·QA 픽스처 전용 — 앱에서 직접 부르면 스위치를 돌려도 그 지점만 반반으로 남는다.

// 타로톡 메뉴판 반반 비교(A/B) — 그룹 계산의 단일 원천. 순수 함수(클라 안전).
// 그룹은 저장하지 않고 user_id 로 계산한다. 판정 SQL·감시 쿼리(scripts/menu-ab-daily-check.sql)와 같은 규칙:
//   position(right(id::text,1) in '02468ace') > 0  → 메뉴판
// 스펙: docs/superpowers/specs/2026-10-05-타로톡-메뉴판-별경제-design.md §9 · §9-1

export type MenuArm = "menu" | "legacy";
export type MenuAbMode = "split" | MenuArm;

/** 판정 스위치 — 'split' = 반반 · 'menu'·'legacy' = 전원 한쪽(판정 뒤·고장 시). 상수라 바꾸면 재배포(prod 는 사용자 go). */
export const MENU_AB: MenuAbMode = "split";

/** 메뉴판 그룹의 user_id 끝 글자 */
const MENU_LAST_CHARS = "02468ace";

/** 이 유저의 그룹. 비로그인(그룹을 모름)은 옛 그룹 — 지금 prod 그대로 보인다. mode 는 테스트용(앱은 MENU_AB). */
export function menuArmOf(userId: string | null | undefined, mode: MenuAbMode = MENU_AB): MenuArm {
  if (mode !== "split") return mode;
  const last = (userId ?? "").trim().slice(-1).toLowerCase();
  return last !== "" && MENU_LAST_CHARS.includes(last) ? "menu" : "legacy";
}

// /api/stars/balance 응답 → 화면이 쓰는 지갑 값(잔액·선물 미사용·반반 그룹). 표시·분기용 — 서버가 권위다.
import type { MenuArm } from "./tarot/menu-ab.ts";

export interface Wallet {
  balance: number;
  /** 별을 한 번도 쓴 적 없음 — 메뉴판 "선물로 무료" 조건 */
  giftUnused: boolean;
  /** 반반 비교 그룹 — 서버가 user_id 로 계산(lib/tarot/menu-ab.ts) */
  menuArm: MenuArm;
}

/** 응답 JSON → Wallet. 모양이 이상하면 안전한 쪽(잔액 0 · 선물 약속 없음 · 옛 그룹 = 지금 prod) */
export function parseWallet(d: unknown): Wallet {
  const o = (d && typeof d === "object" ? d : {}) as Record<string, unknown>;
  return {
    balance: typeof o.balance === "number" ? o.balance : 0,
    giftUnused: o.giftUnused === true,
    menuArm: o.menuArm === "menu" ? "menu" : "legacy",
  };
}

/** 지갑 조회 — 실패면 null(호출부가 안전한 기본값 parseWallet(null) 을 고른다) */
export async function fetchWallet(): Promise<Wallet | null> {
  try {
    const r = await fetch("/api/stars/balance", { cache: "no-store" });
    if (!r.ok) return null;
    return parseWallet(await r.json());
  } catch {
    return null;
  }
}

"use client";

import { useEffect, useState } from "react";
import { fetchWallet, parseWallet, type Wallet } from "./wallet";

/**
 * 지갑(잔액·선물 미사용·반반 그룹)을 마운트 때 한 번 읽는다. 읽는 중 = null.
 * 실패하면 안전한 기본값(잔액 0 · 선물 약속 없음 · 옛 그룹 = 지금 prod)으로 채운다 — 화면이 "잠시만…"에 멈추지 않게.
 * 결제 직전처럼 최신 잔액이 필요한 곳은 그 자리에서 fetchWallet 을 다시 부른다.
 */
export function useWallet(): Wallet | null {
  const [wallet, setWallet] = useState<Wallet | null>(null);
  useEffect(() => {
    let alive = true;
    void fetchWallet().then((w) => {
      if (alive) setWallet(w ?? parseWallet(null));
    });
    return () => {
      alive = false;
    };
  }, []);
  return wallet;
}

  const price = productPrice(p);

      ? { main: "선물로 무료", sub: null, free: true }
      : { main: `⭐${price}`, sub: null, free: false };
  }
  const short = price - w.balance;
  if (short <= 0) return { main: `⭐${price}`, sub: "지금 잔액으로 바로", free: false };
  return {
    main: `⭐${price}`,
    sub: w.giftUnused ? `선물 쓰면 ⭐${short}만 더` : `⭐${short}만 더`,

export const CONTINUATION_KEY = "byeolkong:continuation";

type Store = Pick<Storage, "setItem">;

/** 메뉴판에서 고른 상품 → /tarot/draw 가 읽는 선택값(가격 동의 포함). */
export function menuSelection(p: MenuProduct, concern: string): TarotSpreadSelection {
  return {
    spreadType: p.spreadType,
    spreadCategory: EMOTION_TO_CATEGORY[p.tag],
    emotion: p.tag,
    concern,
    consented: true,
  };
}

export function saveMenuSelection(store: Store, p: MenuProduct, concern: string): void {
  store.setItem(TAROT_SPREAD_KEY, JSON.stringify(menuSelection(p, concern)));
}

/**
 * 맛보기 끝 "이어서 깊게" — 기존 tarot-fresh 이어가기 계약 그대로 + 깊게 상품 선택(동의). 호출부가 /tarot/draw 로 보낸다.

 */
export function saveDeepContinuation(
  store: Store,
  o: { parentReadingId: string; deep: MenuProduct; concern: string }
): void {
  store.setItem(CONTINUATION_KEY, JSON.stringify({ previousReadingId: o.parentReadingId, mode: "fresh" }));
  const pending: PendingConsultation = { emotion: o.deep.tag, concern: o.concern, type: "tarot" };
  store.setItem(PENDING_KEY, JSON.stringify(pending));
  saveMenuSelection(store, o.deep, o.concern);
}

export function spendConsent(store: Store, selection: TarotSpreadSelection): void {

 * 가격은 정가(이어가기 할인 없음 — 맛보기 뒤 이어가기가 처음부터 깊게보다 싸면 우회로가 된다, 사용자 확정).

 * 노출 조건(메뉴판 그룹·맛보기 리딩·[END]·비민감·소유자)은 호출부가 판단한다. 스펙 2026-10-05-타로톡-메뉴판-별경제 §6 · §9-1.
 */
export default function TeaserUpsellCard({
  parentReadingId,
  emotion,
  concern,
  surface,
}: {
  parentReadingId: string;
  emotion: string | null;
  concern: string;
  surface: TeaserSurface;
}) {
  const router = useRouter();
  const deep = getDeepProduct(emotion);
  const deepKey = deep?.key ?? null;
  const shownRef = useRef(false);

  useEffect(() => {

    shownRef.current = true;

      readingId: parentReadingId,
      meta: { surface, deepProduct: deepKey },
    });
  }, [deepKey, parentReadingId, surface]);

  const locked = productPositions(deep).slice(1);

    trackUiEvent("teaser_upsell_clicked", {
      readingId: parentReadingId,
      meta: { surface, deepProduct: deep.key },
    });
    saveDeepContinuation(sessionStorage, { parentReadingId, deep, concern });
    router.push("/tarot/draw");

      >
        이 고민 이어서 {count}으로 · ⭐{productPrice(deep)}
      </button>
    </div>
  );
}

  from ui_events
  where event = 'wallet_fetch_failed' and user_id is not null
    and created_at >= timestamptz '<배포 시각>'

- 광고 구조 동결 조항은 없다(반반이라 광고가 두 그룹에 똑같이 섞인다). 어드민 화면 숫자는 두 그룹이 섞여 나온다 — 판독은 SQL 로.
- **판정 뒤 정리 배포**: 진 쪽 코드(`SpreadPicker` 또는 메뉴판 묶음 — 메뉴판 묶음엔 홈 `app/page.tsx` 의 `useWallet`·알약·import 3개와 대화·결과 화면의 `TeaserUpsellCard`·`useWallet` 도 들어간다) · `MENU_AB` · 진 쪽 전용 패키지 · `tarotPrice` 를 이긴 값 하나로. 진 쪽 패키지는 **진열에서 먼저 빼고 결제 승인에선 한동안 받는다**(또는 스위치를 먼저 돌리고 다음 배포에서 삭제) — 결제창을 연 채 배포를 맞은 주문이 "Amount mismatch" 로 실패하지 않게.
  - 메뉴판이 이겨 `MENU_AB = "menu"` 로 돌리면: 지갑 조회에 실패한 로그인 유저에게도 폴백 지갑(`parseWallet(null)` — 잔액 0·게스트)으로 메뉴판이 그려진다 → `priceLine` 이 없는 부족분("⭐55만 더")을 보이고 선물 유저의 "선물로 무료"가 사라진다. 돈은 안전하다(뽑기가 지갑을 다시 읽는다 — 화면이 덜 약속하는 쪽으로만 틀린다). 정리 배포 때 `priceLine` 이 `w.isGuest`(= 잔액 모름)면 `sub: null` 로 두거나 `/tarot` 갈림길에서 `isGuest` 를 확인한다(Task 7 리뷰 — 반반 기간엔 폴백이 옛 그룹이라 이 경로가 없다). ⚠️ 잔액 조회 오류로 **잔액만 0 으로 오는 정상 응답**(`getStarBalance` 가 오류를 던지지 않고 0 을 준다 · `isGuest:false`)은 이 가드로 안 잡힌다 — 그 경우 유료 줄 숫자가 0 기준으로 틀리는 건 기존 결함(돈은 안전).

## 알고 가는 것

- **동의는 가격에 묶여 있지 않다**(`consented` = 단순 boolean, Task 8 리뷰). 지금은 안전하다 — 판정 뒤 어느 쪽으로 전환해도 메뉴판 유저 가격은 같거나 내려가고(32개 전부 옛 ≤ 메뉴판), 지갑 조회 실패면 잔액 0 → 팝업. **메뉴판 가격을 올리는 배포 전엔** 보여 준 가격을 `consentedCost` 로 같이 저장하고 `consentedCost === tarotPrice(spread, w.menuArm)` 일 때만 팝업을 건너뛰게 바꿀 것. ⚠️ 다른 곳 #14(`expectedCost` 서버 대조)는 이걸 **대신하지 못한다**(정정 — 처음엔 대신한다고 잘못 적었다): 팝업을 건너뛰는 경로의 `expectedCost` 는 메뉴판이 보여 준 값이 아니라 **뽑기 화면 번들이 그 자리에서 계산한 값**이라, 동의와 뽑기 사이에 가격을 올리는 배포가 끼고 뽑기 화면이 새 번들로 뜨면(하드 내비게이션·탭 새로고침·모바일 탭 복원 — sessionStorage 의 동의는 남는다) 새 가격이 팝업 없이 대조를 통과한다. 지금 예정된 배포(split 켜기·판정 전환·깊은 상품 가격 인하)는 동의한 유저의 가격을 올리지 않아 급하지 않다(구현자 지적, `lib/tarot/pricing.ts` 주석).
