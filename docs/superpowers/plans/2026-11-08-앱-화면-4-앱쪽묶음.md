# 앱 화면 손보기 4단계 — 앱 쪽 묶음 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 앱과 웹이 서로 아는 화면 동작을 넣는다. 범위는 아래와 같다.
- 안드로이드 뒤로 버튼으로 시트를 닫는다
- 진동
- 당겨서 새로고침
- 링크 길게 누르기 미리보기를 끈다
- 앱 아이콘·상태바 아이콘

다음 EAS 빌드 한 번에 실을 수 있게 준비하는 것까지가 이 일이다.

**Architecture:**
- 메시지는 `lib/app-bridge/protocol.ts` 에 더한다. 웹과 앱이 같이 쓰는 단일 원천이다.
- 웹은 앱이 `caps` 에 `ui` 를 실었을 때만 보낸다.
- 웹 쪽:
  - 겹창 스택(3단계)이 열림·닫힘을 앱에 알리고, 앱의 `ui.back` 을 받아 맨 위 창을 닫는다.
  - 진동·새로고침 요청은 `lib/app-context.ts` 의 작은 함수로 보낸다.
- 앱 쪽:
  - `mobile/src/WebScreen.tsx` 가 메시지를 받는다.
  - 판단은 순수 모듈(`mobile/src/ui.ts`)로 빼서 루트 CI 의 테스트로 잠근다. react-native·expo import 는 하지 않는다.

**Tech Stack:** Next.js 16 · React 19 · Expo SDK 58(`react-native-webview` 14) · node:test

**Spec:** `docs/superpowers/specs/2026-11-07-앱-화면-design.md` §5(②④⑥) · §7(웹↔앱 메시지) · §8("둘 다" — `ui.overlay`·`ui.back`) · §10(아이콘) · §11(4단계)

## Global Constraints

- **메시지 규칙:**
  - 웹 → 앱은 `postToApp`, 앱 → 웹은 `byeolkong:app` CustomEvent 로 보낸다.
  - **토큰은 절대 싣지 않는다.**
  - `BRIDGE_VERSION` 은 올리지 않는다(새 type 을 더한다).
  - 파싱은 허용 목록으로 하고, 모르는 값은 버린다(§7).
- **옛 앱 대비:**
  - 이 메시지들을 아는 앱만 `AppInfo.caps` 에 `ui` 를 싣는다.
  - 웹은 `hasCap(app, "ui")` 일 때만 보낸다.
  - 지금 깔린 개발용 앱(caps `push` 뿐)에서는 아무것도 달라지지 않아야 한다(§7).
- **안드로이드 뒤로 버튼:** 앱 `BackHandler` 는 바로 답해야 해서 웹에 물어볼 수 없다. 웹이 미리 알린 `ui.overlay` 상태로 정한다.
  - 열려 있으면 `ui.back` 을 보내고 소비한다.
  - 닫혀 있으면 지금처럼 웹뷰 뒤로 가거나 앱을 닫는다.
  - 로그인 덮개 중엔 무시한다(§7).
- **당겨서 새로고침은 탭 첫 화면 5개에서만 한다**(§5 ④).
  - 아이폰: 웹뷰 기본 기능(`pullToRefreshEnabled`)을 앱이 현재 주소를 보고 켜고 끈다.
  - 안드로이드: 웹이 당김 표시를 그리고 `ui.refresh` 로 청한다(이 라이브러리의 `pullToRefreshEnabled` 는 `@platform ios` — 2026-11-08 `react-native-webview` 14 타입 확인).
- **진동은 세 순간만, 가볍게 울린다:** 탭 전환, 카드 뽑기, 결제 완료(§5 ⑥).
- **`expo-haptics` 는 새 의존성이다.** 에이전트가 설치하지 않는다(AGENTS.md). 운영자가 설치 명령을 돌린다(Task 0).
- **아이콘:**
  - 앱 아이콘은 별콩이 얼굴이다. 아이폰은 1024×1024 불투명 PNG, 안드로이드 adaptive 전경은 1024px 에 얼굴을 지름 66% 안에 두고 배경은 night 계열로 한다.
  - 상태바 아이콘은 4꼭지 별 흰 실루엣·투명 배경 96×96 이다. 알림 색 `#5A3E8C` 는 그대로 둔다.
  - **그림 생성 전에 대상·스타일·프롬프트를 운영자와 먼저 맞춘다**(§10).
  - 웹 파비콘(`app/icon.png`)은 바꾸지 않는다.
- **빌드는 이 일에서 뽑지 않는다.** 운영자 결정(11-08): 4단계 → 전체 디자인 다듬기 → 빌드 1회 → 실기기·알림 확인. 실기기 확인표는 이 계획 끝에 둔다.
- **반복 규칙:**
  - 테스트는 `node --import tsx --test …`.
  - 앱 타입 검사는 `cd mobile && npm run typecheck`.
  - 패키지 설치는 운영자 손으로 한다.
  - 커밋은 `git commit -F <파일> -- <경로>`.
  - 공개 저장소라 키·풀 UUID·사업 숫자를 쓰지 않는다.
  - 운영 배포는 앱 출시 때 한다.

## 정해 둔 것 (스펙이 비워 둔 값)

| 항목 | 값 | 이유 |
|---|---|---|
| 메시지 모양 | 웹→앱 `ui.overlay` `{open: boolean}` · `ui.haptic` `{kind: "light" \| "success"}` · `ui.refresh` `{}` / 앱→웹 `ui.back` | §7 표. 값을 싣는 첫 메시지라 type 별 payload 를 허용 목록으로 다시 만든다(받은 객체를 그대로 쓰지 않는다) |
| 탭 첫 화면 목록 | `protocol.ts` 의 `APP_TAB_ROOTS = ["/", "/fortune", "/byeolmaru", "/shop", "/mypage"]` 하나. `lib/app-shell/screens.ts` 의 `TABS` 도 이걸 쓴다 | 앱은 `lib/app-bridge` 만 가져갈 수 있다. 두 목록이 갈라지면 새로고침이 엉뚱한 화면에서 켜진다 |
| 뒤로 버튼이 닫는 창 | **z 가 가장 높은 창**, 같으면 나중에 연 창 | 3단계 최종 리뷰 Minor("ESC 가 마지막 연 창을 닫음")를 여기서 맞춘다. 스택 항목에 `z` 를 싣는다. ESC 도 같은 규칙을 쓴다 |
| 앱의 '열림' 상태 초기화 | 웹뷰가 새 문서를 읽기 시작하면(`onLoadStart`) 닫힘으로 본다 | 새 문서는 겹창이 없다. 웹이 `closed` 를 못 보내고 떠난 경우에 뒤로 버튼이 먹통이 되지 않게 |
| 진동 위치 | ① 하단 탭: **다른** 탭을 누를 때 `light` ② 카드 뽑기: `CardDrawRitual` 의 `confirmPick` 이 카드를 자리에 놓을 때 `light` ③ 결제: `app/shop/page.tsx` 승인 성공(`setConfirmTone("success")`) 때 `success` | §5 ⑥ 의 세 순간. 결제 승인 호출은 상점 한 곳뿐이다(2026-11-08 grep) |
| 안드로이드 당김 | 탭 첫 화면에서 `scrollY===0` 일 때 손가락을 아래로 끌면 위에 둥근 표시가 따라 내려온다. **72px** 를 넘겨 놓으면 `ui.refresh` 를 보낸다. 표시는 앱 안드로이드·`caps ui` 일 때만 그린다 | 안드로이드 기본 SwipeRefresh 와 비슷한 거리 |
| 앱의 새로고침 | `ui.refresh` → `webRef.reload()` | 기록·주소 그대로 다시 읽는다(콘텐츠 프로세스 회복과 같은 방식) |
| 안드로이드 adaptive 배경색 | `#1F1735`(night 토큰) | §10 "night 계열" |

## Review Focus

- **옛 앱(caps 에 `ui` 없음):** 웹이 `ui.*` 를 하나도 보내지 않아야 하고, 당김 표시도 그리지 않는다. 지금 깔린 개발용 앱이 이 상태다 → Task 2·3·4 테스트("cap 없으면 안 보냄")
- **뒤로 버튼을 눌렀는데 맨 위가 닫을 수 없는 창**(탈퇴 확인·삭제 확인·동의 결과 안내): 앱은 소비하고(화면이 뒤로 가지 않음) 창도 그대로다 → Task 2 테스트(closeTop 이 소비만) + Task 5 `decideAndroidBack` 테스트
- **겹창이 열린 채 다른 문서로 이동**(결제창으로 나감, 로그인 리다이렉트): 앱의 '열림' 상태가 남으면 다음 화면에서 뒤로 버튼이 먹지 않는다 → Task 5 `onLoadStart` 초기화 + 테스트
- **기록으로 닫는 시트**(보조 카드·별 충전·카드 뽑기): `ui.back` 으로 닫으면 `history.back()` 이 한 번 불린다. 앱의 웹뷰 뒤로 가기와 겹쳐 두 칸 뒤로 가면 안 된다 → Task 5 "열려 있으면 goBack 하지 않음" 테스트 + Task 7 헤드리스(가짜 앱이 `ui.back` 을 쏘고 주소가 한 칸만 바뀌는지)
- **당김과 스크롤 다툼**(안드로이드): 맨 위가 아니거나 위로 끄는 손가락에서는 표시가 나오지 않는다. 겹창이 열려 있을 때도 마찬가지다 → Task 4 `pullDistance` 테스트
