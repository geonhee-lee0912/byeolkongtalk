# 별마루 개편 Phase 4-a — 관계 유형 캡처 + 판정/서술 주입 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 우리 오늘에서 상대를 담을 때 **관계 유형(썸/연애/짝사랑/헤어진)**을 캡처하고, 그 상태를 오늘 둘 사이 **룰 판정(무료 정적 한 줄)**과 **LLM 서술(유료)**에 주입한다 → "짝사랑의 오늘 ≠ 연애 중의 오늘". 스펙 §8(관계 유형).

**Architecture:** 인물 데이터는 `user_profiles` 단일원천, `byeolmaru_watch`는 "이 상대를 우리 오늘에서 본다"는 얇은 링크(현재 `(user_id, profile_id)` PK, status 없음). 관계 유형은 **링크의 성질**이라 `byeolmaru_watch.status` 컬럼으로 추가(마이그). enum·라벨·칩은 전부 `lib/relationship/types.ts`(`RelationshipStatus`) 재사용 — 새 enum 안 만든다. 판정 주입은 **문구만 분기**(score/tone 가중은 측정 후 — Phase 4 heavy라 저위험 우선). 인형색(DOLL_COLORS)은 순수 시각이라 Phase 5 UI 개편으로 미룸.

**Tech Stack:** Supabase 마이그(ALTER TABLE ADD COLUMN, Git-sync 자동적용), TypeScript strict, `node:test`.

## 결정 (승인 시 확정)
- **D1. status 컬럼 NULL 허용** — 기존 행(status 없이 담긴 상대)은 NULL. 판정/서술/UI는 NULL을 기본값(`dating` 또는 "관계 미지정")으로 폴백. 백필 안 함(무해).
- **D2. 판정 주입 = 문구만** — `getPairStaticLine`이 status로 문구 분기(짧은 관계 프레이밍), score/tone/tags 무변경. `pair-day.test.ts` 회귀 최소.
- **D3. 서술 주입 = 프롬프트 라벨 한 줄** — `buildPairNarrativeSystem`에 "지금 둘은 <라벨> 사이" 주입 → LLM이 톤 반영.
- **D4. 캡처 기본값 = `dating`** (ProfileEditModal 선례). 미선택 방지로 항상 하나 선택된 상태.
- **D5. 인형색·혼자/같이 기본값 = 이 플랜 밖** — 인형색은 Phase 5(시각), 혼자/같이 분기는 4-b(초대).

## Self-Review (완료)
- **스펙 §8 관계 유형:** enum 재사용(신규 0)·`watch.status` 캡처·판정(문구)·서술(라벨) 주입 = Task 1~3. "쓰이는 곳 3" 중 ①판정·서술 tone 완료. ②혼자/같이 기본값=4-b, ③인형색=Phase5(결정 D5).
- **위험:** 마이그는 NULL 허용 컬럼 추가라 기존 행·구클라 무회귀. 판정은 문구만(score 무변경)이라 pair-day 회귀 최소. status read 실패 시 null 폴백.
- **보안:** 컬럼 추가는 ACL/REVOKE 무관(새 RPC/테이블 아님). CHECK로 enum 강제. status는 비-PII.
