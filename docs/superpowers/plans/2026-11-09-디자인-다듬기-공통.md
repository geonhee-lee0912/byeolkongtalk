# 디자인 다듬기 공통 규칙 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 스펙의 공통 규칙(A 아이콘 · B 글자·모서리·그림자·글자색·버튼·카드·간격 · C 장식)을 웹·앱 사용자 화면 전체에 한 번에 옮기고, 다시 흩어지지 않게 계약 테스트로 잠근다.

**Architecture:** 값은 `app/globals.css` 의 `@theme` 토큰과 `@utility` 부품 클래스 한 곳에 둔다. 기계적으로 바꿀 수 있는 것(글자 크기·모서리·그림자·투명 글자)은 이 브랜치 전용 변환 스크립트(`scripts/design-polish/`, 마지막에 지움)로 바꾸고, 역할 판단이 필요한 것(16·18 글자, 카드 종류, 버튼 종류, 장식)은 스크립트가 뽑아 준 목록을 사람이 처리한다. 규칙마다 `lib/design-rules.test.ts` 에 위반 목록 테스트를 먼저 넣고(RED) 옮겨서 통과시킨다(GREEN).

**Tech Stack:** Next.js 16 · React 19 · Tailwind CSS v4(`@theme`·`@utility`) · node:test + tsx · 헤드리스 Edge(CDP) 화면 찍기

**Spec:** `docs/superpowers/specs/2026-11-09-디자인-다듬기-공통-design.md` (시안·정본 데이터: `docs/superpowers/specs/assets/2026-11-09-디자인-다듬기/`)

## Review Focus

1. **밤 배경 위 글자**: `text-lilac-deep` → `text-accent` 일괄 변환이 밤 바탕(night·밤 카드) 위 글자에도 먹으면 대비가 떨어진다(#775CB0 은 밤 위에서 더 어둡다). 기대: 밤 바탕 안의 연보라 글자는 바뀌지 않는다 → Task 6 테스트 `밤 바탕 파일의 lilac 글자는 변환 대상에서 빠진다`.
2. **11px 로 커진 좁은 자리 넘침**: 9~10px 이던 관계 전환 탭 이름(`HubSwitcher`)·타로 작은 카드 이름(`CardSpreadView` xs)이 11 로 커져 잘린다. 기대: 화면 넘침 수가 옮기기 전보다 늘지 않는다 → Task 3 마지막 단계의 넘침 비교 0 증가.
3. **조건부·조립 클래스**: `${cond ? "text-[13px]" : ""}`·크기 표 객체(`{ name: "text-[10px]" }`)·`text-[${n}px]` 처럼 조립된 클래스는 정규식 변환이 놓친다. 기대: 리터럴은 계약 테스트가 잡고, 조립식은 0곳 → Task 1 테스트 `조립식 임의값 클래스가 없다`.
4. **아이폰 입력칸 확대 방지**: 글자 토큰을 바꾼 뒤에도 폰에서 입력칸은 16 이어야 한다(`@media (pointer: coarse)` 규칙이 레이어 밖에 남아 있어야 함). 기대: 입력칸을 눌러도 화면이 확대되지 않는다 → Task 1 테스트 `입력칸 16 규칙이 레이어 밖에 있다`.
5. **회사 규정 버튼·위험 버튼**: 버튼 일괄 정리 때 카카오 노랑(#FEE500)·애플 검정·탈퇴/삭제 위험 버튼까지 `btn-primary` 로 바뀌면 안 된다 → Task 7 테스트 `카카오·애플 버튼은 규정 색을 유지한다`.
