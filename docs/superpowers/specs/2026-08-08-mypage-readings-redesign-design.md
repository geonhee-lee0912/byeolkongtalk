# 마이 탭 + 보관함 재설계 (T1)

> 2026-08-08 브레인스토밍 확정. T1 IA 재설계의 마지막 화면이자 **prod 배포 전 필수 게이트**.
> 관련: [[t1-ia-session-progress]] · 상위 로드맵 `plans/2026-08-01-roadmap-t1-t2-t3.md`

## Goal

상품이 타로·사주·시뮬·우리 사이로 다양해졌는데, 마이 화면은 여전히 **사주 프로필 관리가 대부분**이고 보관함(`/readings`)은 2탭(고민톡=타로 / 사주=운세)뿐이라 **시뮬·우리 사이 기록이 아예 안 보인다**. 마이를 "내 것들 허브"로 재구성하고 보관함을 종목·상태별로 세분화한다.

## 현황

- **마이(`app/mypage/page.tsx`)**: 별 잔액 카드 / 보관함 단일 링크 / 내 명식(`SajuBoard`)·지인 사주(`ProfileForm` 인라인·페이지네이션·케밥 수정/삭제) / 계정(고객센터·탈퇴) / 로그아웃. 사주 프로필 관리가 화면 대부분.
- **보관함(`app/readings/page.tsx`)**: 2탭 — `consult`(타로 상담) / `fortune`(운세 리포트). 분류는 `fortuneTypeFromTag(emotionTag)`. 시뮬(`relationship_sim`)·우리 사이 스레드(`relationship`) 미노출.
- **데이터**: `/api/readings`가 현재 타로+운세만 반환.

## 확정 결정 (브레인스토밍)

1. **마이도 재구성** (골격 유지 아님)
2. **사주 프로필 = 요약 + 모달 편집** (인라인 펼침 제거, P2 `ProfileEditModal` 패턴과 통일)
3. **마이 보관함 진입 = 종목별 요약 4카드** (개수 표시, 탭 → 딥링크)
4. **보관함 = 종목 칩 4개 + 상태 배지** (상태 필터 별도 줄은 안 함)
5. **우리 사이 공존** — 파일 허브(우리 사이 탭)=상대별 실행 / 보관함=시간순 열람

## 마이 화면 구조 (`app/mypage/page.tsx` 재구성)

위→아래 블록:

1. **프로필 헤더 카드** — 프사 · 닉네임 · 별 잔액 · 충전 버튼. (기존 별잔액 카드 + 프로필 정보 통합.)
2. **내 보관함** — 종목별 요약 4카드, 2×2 그리드:
   - 🔮 타로 `N` · 📜 사주·운세 `N` · 🎭 시뮬 `N` · 💬 우리 사이 `N`
   - 각 카드 탭 → `/readings?tab=<종목>` (해당 칩 선택된 채 진입)
   - 개수는 `/api/readings` 집계에서.
3. **내 사주** — 요약 카드만: 내 명식 일주(있으면) 또는 "생일 미입력" + 지인 `N`명. "관리" 탭 → **모달**(내 명식 편집 + 지인 목록 추가/수정/삭제). 기존 인라인 `SajuBoard`+`ProfileForm` 펼침·페이지네이션·케밥은 모달 안으로 이동.
4. **계정** — 결제·별 내역 / 고객센터(안읽음 뱃지 유지) / 로그아웃 / 회원 탈퇴.
5. Footer (홈·마이만 노출 규칙 유지).

## 보관함 구조 (`app/readings/page.tsx` 재구성)

- **종목 칩 4개**: 타로 / 사주·운세 / 시뮬 / 우리 사이. 가로 스크롤. `?tab=` URL 파라미터로 마이 카드 딥링크(기본 첫 칩).
- **상태 배지**(항목별): 완료 / 이어하기 / 진행중.
- 종목별 목록:
  - **타로** — 현행(완료/이어하기/후속 상담·프로필 칩·민감 표시).
  - **사주·운세** — 현행(리포트, 생성 중 폴링).
  - **시뮬** — `relationship_sim`. 완료(`saju_data.phase==='debriefed'`) 판은 탭 → 디브리핑 다시 보기. 진행 중(`phase==='stage'`) 판은 "이어하기" → 무대(`/relationship/sim?rel=`)로.
  - **우리 사이** — `relationship` 스레드. 관계별 1항목, 시간순(최근 방문). 탭 → 우리 사이 스레드.

## 데이터 / API

- `/api/readings` 확장: 기존 반환 + `relationship_sim`(시뮬 판, `saju_data.phase`) + 우리 사이 스레드(`relationships` + `thread_reading_id`).
  - 종목 분류 키: `consultationType`(`tarot`/`saju`/`relationship`/`relationship_sim`) + 운세는 기존 `emotionTag`(`fortuneTypeFromTag`) 유지.
  - 마이 종목 카드 개수 = 종목별 count (같은 응답에서 파생하거나 경량 count 엔드포인트).
- ⚠️ 구현 시 실제 `consultation_type` 값·필터를 코드에서 확인(추정 금지). 시뮬 진행 중 판이 보관함/개수에 어떻게 잡히는지 정의.

## 컴포넌트

- **재사용**: `ProfileEditModal`(P2, 사주 프로필 편집 모달로) · `ContinuationModal`(후속 상담) · 기존 보관함 카드 렌더 로직 · `SajuBoard`(모달 내부).
- **신규**: 마이 종목 요약 카드(그리드) · 보관함 종목 칩 바 · 시뮬 보관함 항목 · 우리 사이 보관함 항목.
- 마이 `page.tsx`는 블록 단위로 재구성 — 사주 프로필 관리 로직(추가/수정/삭제·페이지네이션·케밥·삭제확인)은 모달 컴포넌트로 이동해 `page.tsx` 축소.

## 스코프 밖 (이번 안 함)

- 설문(별도 브레인스토밍) · 1탭 잔여(시뮬 카드 위치·설문 배선) · 전체 가격 비교(백로그 4번) · 인형 실에셋 · 카톡 프사 OAuth.

## 열린 세부 (구현 플랜에서 확정)

- `/api/readings` 확장을 단일 응답 확장 vs 별도 count 엔드포인트.
- 사주 프로필 편집 모달을 P2 `ProfileEditModal` 그대로 재사용 vs 지인(acquaintance) 지원 위해 확장/신규.
- 우리 사이 스레드 "시간순" 기준(생성 vs 최근 방문 `last_visited_at`).
