# 시뮬 무료 런웨이 + 초상화 축적 payoff — 리텐션 설계 (2026-08-14)

연애 시뮬(P3a, dev)의 리텐션 공백을 메우는 설계. 로드맵 ②(시뮬 무료 이벤트), 어드민 ③보다 앞서 실행(시뮬 결정이 어드민 시뮬 지표 설계에 선행).

## 0. 배경 — #4 문제

시뮬의 가치는 **여러 판을 돌려 초상화가 두꺼워질 때** 나오는데(P3b 축적), 현재는:
- 판당 15별 유료(첫 판만 웰컴 20 흡수). 축적 전에 **유료벽**.
- 설령 결제해도 초반 1~2판은 초상화가 얇아 **무의미하게 느껴짐** → 되돌아올 이유가 없음.

원가는 병목 아님(luna 티어링으로 판당 원가 무시가능, [[cost-unit-economics-2026-08-10]]). 병목은 **"값을 느낄 만큼 쌓이기 전의 유료벽"**. 해법 = 무료 런웨이(축적 시작) + 리텐션 훅(축적 지속) + **눈에 보이는 축적 표면**(초상화).

## 1. 목표 & 비스코프

**목표:** ①신규가 유료벽 없이 시뮬을 시작해 초상화를 채우기 시작 ②재방문마다 계속 쌓게 ③"쌓이는 맛"을 눈으로 확인 → **런웨이 소진 지점(투자 절정)에서 15별 자기 전환**.

**수익 경계(사용자 확정):** 시뮬 **자체 유료 전환**(로스리더 아님). 무료는 온램프일 뿐, 그 뒤는 판당 15별.

**비스코프 (의도적 제외):**
- **풀 P3b 대종합**(판 가로지른 grand synthesis + "너의 패턴" 정식 축) — 실플레이 데이터 쌓인 뒤 후속.
- **패스/스킬·연애상담 가격·턴 구조** 변경 — 무관.
- **프로액티브 훅 넛지**(홈·데일리에서 "이번 주 무료 판 있어") — E3(운세 캘린더 재방문 훅) 합류 시 후속. 이번 MVP는 시뮬 진입 지점의 정직한 가격 표기까지.

## 2. 초상화 (축적 payoff)

**3개 통로로 채워지고, 하나의 저장소(`user_profiles.personality`, 상대 프로필)에 누적:**

| 통로 | 시점 | 필수 | 설명 |
|---|---|---|---|
| ① 패시브 관찰 | 디브리핑(자동) | — | 별콩이가 그 판 대화에서 관찰 1~2개 추출 → append. **판만 끝내면 두꺼워짐**(주 동력, 유저 노력 무의존) |
| ② 라인 교정 👍👎 | 플레이 중 | 선택 | 기존(`/sim/feedback` → `appendPersonalityNote`). 특정 인형 대사 즉시 보정 |
| ③ 성향 입력창 (신규) | 디브리핑 | 선택 | "걔는 사실 이런 사람이야" 자유 입력. **"적을수록 인형이 더 걔처럼 돼"** 설명 부착 = 입력이 곧 보상 |

**표시:** 디브리핑에 **읽을 수 있는 초상화 카드** — 누적 관찰이 판마다 한 줄씩 쌓여 "별콩이가 걔를 이만큼 알아가는 중"이 보임. (지금은 저장만 되고 유저에겐 안 보이던 `personality`를 처음으로 노출.)

**전파(의도된 교차 가치):** 초상화 = 인형 정확도(`formatPartnerForDoll` → 다음 판) + **연애상담·궁합에 이미 전파되는 그 필드**. 즉 시뮬을 돌릴수록 연애상담 품질도 같이 오름.

**순환 방지(설계 확정):** 인형은 애초 유저 설명으로 빚어지므로, 인형 대사만 되읊으면 순환이다. 패시브 추출 프롬프트는 **유저 쪽 신호**(어떻게 반응했나·어떤 상황을 반복하나)와 대화에서 실제로 드러난 역학을 우선한다 = "너와 그 사람을 알아가는".

**🔴 저장소 결정(스펙 리뷰 포인트):** 패시브 관찰을 `personality`에 바로 누적하면 **연애상담·궁합(유료)에도 전파**된다 — 사용자가 원한 교차 가치지만, 저품질 관찰이 유료 품질을 오염시킬 위험이 있다. 완화 = **보수적 추출**(판당 1~2개, 고신호만, 일회성 사건 아닌 지속 성향으로 서술) + **기존값 대비 근접 중복 dedup**(무한 증식·반복 방지). 배포 후 연애상담 품질 관찰. (대안: 패시브는 별도 portrait 필드로 격리하고 상담엔 안 먹임 — 교차 가치를 잃어 기각. 사용자 리뷰에서 재확인.)

## 3. 무료 예산 (런웨이 + 훅)

**서버 권위 게이트 — `POST /api/relationship/sim` 세션 생성 시 `spendStars` 앞에서 funding 판별:**

```
1) runwayUsed = count(관계의 sim 판 where funding='runway')
   runwayUsed < SIM_FREE_RUNWAY(3)  →  funding='runway' (무료, 차감 skip)
2) else hookLast = 유저의 가장 최근 funding='hook' 판 created_at
        hookLast 없음 or now - hookLast >= SIM_HOOK_INTERVAL_DAYS(7)  →  funding='hook' (무료)
3) else  →  funding='paid'  →  spendStars(SIM_COST) (기존 경로·실패 402)
```

- **런웨이 = 관계당 3판.** 초상화는 사람마다 따로 차오르니(#4는 사람별 문제) 런웨이도 사람별. 대부분 1~2명이라 페이월 희석 미미. 근거: 1판 인형 만남(얇음)→2판 인형이 1판 관찰 반영("걔 같아지네" 클릭)→3판 관찰 3+줄 모멘텀 최고조 **바로 여기서 페이월**.
- **훅 = 유저당 7일 롤링 1판.** 주간 리텐션 케이던스로 끌어오되 주중 추가 판은 결제 = 페이월 유지. 헤비유저 훅 상한 ~월 4판. 롤링(마지막 hook 판 기준 7일)이라 주 경계 버스트 없음.
- **funding 저장** = `SimMeta.funding: 'runway'|'hook'|'paid'` (saju_data JSONB, 마이그레이션 불필요). `stars_spent`도 funding 에 맞춰(무료=0). 게이팅 count 는 `saju_data->>'funding'` 필터(시뮬 저볼륨이라 무해).
- **레거시 판**(funding 태그 없음)은 'paid'로 간주 → 런웨이 소비 안 함(기존 유저도 런웨이 3판 새로 받음, 관대·dev only·prod sim_plays=0). 웰컴 흡수 로직은 런웨이로 대체돼 사문화(SIM_COST<WELCOME 불변식은 무해하게 유지, 테스트 그대로).

## 4. 진열 · 전환

- **정직한 가격 표기:** 시뮬 진입 시 다음 판 funding·비용을 반환하는 신규 쿼트 `GET /api/relationship/sim/quote?relationshipId=`(§5) → 진입 UI 가 "무료(런웨이 N/3)" / "이번 주 무료 판" / "15별" 을 정직하게 표기. 현행 `StarConfirmModal`+`SIM_COST` 하드코딩 대체.
- **전환 동력 = 초상화 카드:** 런웨이 소진 페이월 순간 "초상화 이만큼 찼어, 더 채우려면 15별" → 콜드 결제 아닌 **투자 이어가기**.
- **답변추천 5별은 항상 유료**(무료 판에서도) — 무료 판에도 결제 접점 1개 유지(사용자 확정).
- 원가 가드레일 불필요(luna 판당 원가 무시가능). 유일한 절제 = 런웨이(3/관계)+훅(주1) 캡.

## 5. 데이터 모델 & 통합 지점 (파일별)

**상수 (`lib/relationship/types.ts`):** `SIM_FREE_RUNWAY = 3` · `SIM_HOOK_INTERVAL_DAYS = 7`. 서버 권위(클라 신뢰 X).

**게이트 (`app/api/relationship/sim/route.ts`):** §3 로직. 무료면 `spendStars` skip + `stars_spent:0` + `SimMeta.funding`. 판별용 count 쿼리 2개(runway per-relationship, hook per-user).

**순수 헬퍼 (`lib/relationship/sim.ts`):** `resolveFunding({runwayUsed, hookLastAt, now})` 결정 함수(TDD 대상) + `SimMeta.funding` 타입 추가. 패시브 관찰 추출 `extractPortraitObservations(debriefRaw)`([PORTRAIT:...] 마커) + 근접중복 dedup 헬퍼.

**쿼트 (`GET /api/relationship/sim/quote`):** funding·cost·runwayRemaining 반환(읽기 전용, 차감 없음).

**초상화 저장 (`lib/relationship/sim.ts` `appendPersonalityNote` 재사용):**
- 패시브: 디브리핑 응답(chat `action:"debrief"`, `buildSimByeolkongMessage(mode:"debrief")`)에 `[PORTRAIT:관찰]` 마커 1~2개 방출하도록 `SIM_DEBRIEF_GUIDE`/`byeolkong_sim.md` 확장 → 파싱 → dedup → 상대 `personality` append. **기존 디브리핑 LLM 콜 재활용(추가 콜 없음).**
- 성향 입력(③): `POST /api/relationship/sim/feedback` 확장(또는 신규 액션) → `appendPersonalityNote` → 확인 응답. 기존 👍👎 경로와 동일 저장소.

**표시 (`components/relationship/sim/SimDebrief.tsx`):** 초상화 카드(상대 personality 불릿 렌더) + 성향 입력창(마이크로카피 "적을수록 인형이 더 걔처럼 돼").

**페르소나:** 디브리핑 프롬프트 변경 → **새 `PROMPT_VERSION` 코호트**. 코어 무편집(byeolkong_sim.md 도메인 파일만).

## 6. 측정 (→ 어드민 ③ 연결)

funding 태그가 곧 지표 소스: **무료 판 → 유료 판 전환율** · 초상화 채움(관찰 수) vs 전환 상관 · 훅이 끌어온 재방문 · 런웨이 소진율. 이 지표들이 다음 단계 **어드민 시뮬 화면 스펙**의 입력(시뮬을 어드민보다 먼저 한 이유).

## 7. 판정 & 검증

- **TDD**: `resolveFunding`(런웨이/훅/유료 경계·7일 롤링·레거시 paid 취급) · `extractPortraitObservations`(마커 파싱·최대 2·dedup) — node:test.
- **QA 하네스**(`qa:sim`): 디브리핑이 [PORTRAIT:] 방출 + 화면 마커 누출 0 + 관찰이 순환(인형 대사 되읊기) 아닌 유저-신호 기반인지 육안. 페르소나 수정 후 dev 서버 재시작([[qa-harness-usage]]).
- **가드레일:** 초상화 관찰이 연애상담 품질 오염 안 하는지(배포 후 관찰) · funding 게이트 우회 불가(서버 권위) · 무료 판도 환불 로직 무관(차감 자체를 skip).
- **판정 지표:** 시뮬 재플레이율 · 무료→유료 전환율 · 재방문(훅 소비).

## 8. 배포

roadmap ④(dev 누적분 한 판 → prod)에 포함. 마이그레이션 없음(funding=JSONB, personality=기존 컬럼). 새 `PROMPT_VERSION` 슬러그. prod 는 P3a 시뮬 자체가 이 배포에서 처음 나가므로 sim_plays=0 = 깨끗한 시작.

## 9. 구현 단계 (writing-plans 에서 상세)

독립 배포 가능하나 한 판으로: (1) funding 게이트 + 상수 + 쿼트 + resolveFunding TDD · (2) 초상화 패시브 추출([PORTRAIT:] 마커 + dedup + 디브리핑 프롬프트) · (3) 성향 입력창 + 초상화 카드 UI · (4) 정직한 가격 표기(진입 UI). 각 단계 QA/유닛 게이트.
