# 기능 1: 설문 컨택 선호 문항

## 목적

기존 정성 이탈조사 설문(`/survey`, dev-only)에 **"앞으로 알림을 제공한다면 어떤 채널이 편할지"** 선호를 파악하는 문항 1개 추가. 미래 리텐션 통로(E3 캘린더·E4 편지·알림톡 등) **어느 채널에 투자할지 결정하는 리서치 입력값**.

⚠️ **원 설문의 "아웃바운드 기각"과 충돌하지 않는다** — 기각된 것은 *발송 인프라를 지금 구축*하는 것(발송비·동의·시스템). 이 문항은 발송도 PII 수집도 아닌 **가정형 선호 조사**("제공한다면 뭐가 편해?"). 실제 엔드포인트(이메일 주소 등)나 동의는 수집하지 않는다. 설문의 정성 리서치 성격과 동일.

## 문항

- **id**: `contact` · **배치**: `freeform`(마지막 말) **앞** = Q6, freeform 이 Q7 (클로저 유지)
- **텍스트**: "앞으로 별콩이가 좋은 소식이나 그날의 운세를 알려준다면, 어떤 방법이 편할 것 같아? (편한 거 다 골라도 돼)"
- **형식**: **복수 선택(체크박스)** · **필수**(최소 1개)
- **옵션 5개**:

| id | 라벨 | 부가입력 |
|---|---|---|
| `kakao` | 카카오톡 알림 | — |
| `email` | 이메일 | — |
| `sms` | 문자 메시지 | — |
| `calendar` | 내 캘린더에 좋은 날 자동 등록 | 체크 시 텍스트 입력 "어떤 캘린더 써? (예: 구글·애플·네이버)" |
| `etc` | 기타 | 체크 시 텍스트 입력 "어떤 방법이 편해?" |

- **검증**: 최소 1개 선택 · `calendar`/`etc` 체크 시 각 입력 비어있지 않음.

## 데이터 모델 확장 (`lib/survey/questions.ts`)

현재 `SURVEY_QUESTIONS` 는 `{id, text}`(전부 자유서술)이고 `validateSurveyAnswers(string[])` 가 각 ≥`SURVEY_MIN_CHARS`(=20) 검사 후 `[{q,a}]` 정규화. 이를 문항 타입 인지로 확장:

```ts
type SurveyQuestion =
  | { id: string; text: string; type?: "text" }              // 기본(생략 시 text)
  | { id: string; text: string; type: "multi"; options: MultiOption[] };
type MultiOption = { id: string; label: string; input?: { prompt: string } };
```

- 기존 6문항은 `type` 생략(=text). 신규 `contact` 만 `type:"multi"`.
- **저장 포맷 `[{q,a}]` 불변** — multi 의 `a` 는 선택 라벨을 ` · ` 로 조합한 문자열.
  - 예: `"카카오톡 알림 · 이메일 · 내 캘린더에 좋은 날 자동 등록 (구글) · 기타 (인스타 DM)"`
  - 부가입력 있는 옵션: `"{label} ({sanitized 입력})"`. 부가입력은 조합 전 **` · `·개행 제거 + trim + 40자 캡**(세그먼트 파싱 안전).
- **조합 헬퍼**: `composeMultiAnswer(question, { checked: string[], inputs: Record<string,string> }): string` — 옵션 정의 순서로 선택된 것만 세그먼트 생성 후 ` · ` join. 단일 원천.

## 검증 (서버·클라 분리, 둘 다 questions.ts 원천)

- **서버 `validateSurveyAnswers(answers: string[])`**: 문항 타입별 분기 —
  - `text`: `trim().length >= SURVEY_MIN_CHARS`
  - `multi`: `trim().length >= 1`(비어있지 않음). 클라가 조합해 보낸 문자열은 ≥1개 선택일 때만 non-empty 이므로 이 경량 검사로 충분(기존 위협 모델과 동일 — 완벽 어뷰징 방어 아님, 보상 게이트만). 정규화 `[{q,a}]` 는 기존과 동일(q=문항 텍스트 스냅샷, a=받은 문자열).
- **클라 `page.tsx`**: multi 는 조합 문자열이 아니라 **리치 상태**(checked Set + inputs)로 유효성 판정 = 최소 1개 + calendar/etc 체크 시 입력 non-empty. text 는 기존대로 ≥20자. 제출 시 `answers[contactIdx] = composeMultiAnswer(...)`.

## 페이지 렌더 (`app/survey/page.tsx`)

- `SURVEY_QUESTIONS.map` 에서 `type === "multi"` 면 `<textarea>` 대신 **체크박스 그룹** 렌더:
  - 각 옵션 체크박스 + 라벨. `calendar`/`etc` 체크 시 그 아래 조건부 `<input type="text">`(placeholder=prompt).
  - multi 상태는 별도 state(`contactChecked: Set<string>`, `contactInputs: Record<string,string>`). 변경 시 `answers[contactIdx]` 를 `composeMultiAnswer` 로 갱신.
  - 유효성 표시: 미선택 시 "하나 이상 골라줘", calendar/etc 체크했는데 입력 비면 그 입력에 경고.
- `allValid` = text 전부 ≥20자 **AND** contact 리치 상태 유효.
- 나머지 흐름(로그인 가드·제출·done/already)은 무변경.

## 어드민 집계 (`app/admin/survey/page.tsx`)

- 기존 원문 리스트 **위에** 이 문항 옵션별 카운트 한 줄 추가: `"카톡 12 · 이메일 8 · 문자 3 · 캘린더 5 · 기타 2 (응답 N명)"`.
- **이미 fetch 한 응답 데이터로 계산**(추가 쿼리 0). 각 응답의 `answers` 배열에서 `q === CONTACT 문항 텍스트` 인 항목을 찾아 `a` 를 ` · ` 로 split → 세그먼트별로 옵션 매칭(단순 옵션=라벨 정확 일치, calendar/etc=라벨 prefix). 옵션별 카운트 누적.
- 복수 선택이라 카운트 합 > 응답자 수(정상). 캘린더 종류·기타 내용은 원문 리스트에서 그대로 읽힘.
- 매칭은 현재 문항 텍스트 기준 — 문항 텍스트를 나중에 바꾸면 옛 응답은 집계에서 빠진다(dev-only 짧은 조사라 허용, 원문은 항상 보존).

## 변경 범위 (기능 1)

`lib/survey/questions.ts`(모델+검증+조합 헬퍼) · `app/survey/page.tsx`(체크박스+조건부입력) · `app/admin/survey/page.tsx`(집계 한 줄). **마이그레이션 0 · API route 0 · 저장 포맷 불변**(`answers` jsonb `[{q,a}]`).

# 기능 2: 별콩이 사용법 페이지

## 목적

홈 캐러셀 첫 카드 `intro`("별콩이는 처음이지?")가 지금 `/concern`(상담 흐름)으로 바로 던진다 — 신규 유저에게 사용법을 안 알려준다. **공개 온보딩 페이지**를 만들어 첫 카드를 거기로 연결한다.

## 라우트·성격

- **`/how-to-use`** (신규). `/guide` 는 `app/(content)/guide` = SEO 타로 콘텐츠 허브라 충돌 → 별도 경로.
- **공개**(로그인 게이트 없음 — 캐러셀이 비로그인 홈에 노출). 서버 컴포넌트 정적.
- `layout.tsx` = `noindexMetadata()`(다른 상품 페이지와 동일, SEO 스코프 확장 안 함).

## 구조 (풀 온보딩)

`AppShell` 이 Header/BottomTab 자동 부착. 디자인 시스템(cream/lilac, `rounded-2xl`, 별콩이 톤) 준수. 신규 이미지 0(기존 `byeolkong-main.png` + 이모지).

1. **별콩이 소개** — `byeolkong-main.png` + 한 줄: "별콩이는 별의 수호자, 타로와 사주로 네 마음의 흐름을 읽어주는 친구야."
2. **핵심 흐름 3단계** — ① 고민 고르기(감정·고민 적기) → ② 타로/상담으로 풀어보기 → ③ 결과 받고 이어가기. 번호 뱃지 + 한 줄 설명.
3. **뭘 할 수 있어 (상품 4종)** — 각 이모지 + 이름 + 한 줄:
   - 🃏 타로톡 — 고민을 타로로 풀어보기
   - 🔮 별콩 운세 — 사주로 보는 나의 흐름 리포트
   - 💬 연애 상담 — 그 사람과의 이야기를 계속 나누기
   - 🎭 연애 시뮬 — 그 사람과의 상황을 미리 연습
4. **별(재화) 간단 안내** — "처음 오면 별콩별 20개를 선물로 줘. 무료로 시작하고, 더 깊게 보고 싶으면 충전이나 패스로 이어갈 수 있어."
5. **시작하기 CTA** — 큰 버튼 → `/concern`.

문구는 별콩이 화법(반말·따뜻함·단정 안 함). 상품명·재화 숫자는 코드 정본(웰컴 `WELCOME_BONUS_STARS`=20)과 일치.

## 캐러셀 연결 (`components/common/HeroCarousel.tsx`)

- `CARDS` 의 `intro` 카드: `href: "/concern"` → `href: "/how-to-use"`, `cta: "시작하기"` → `cta: "사용법 보기"`.
- `intro` 카드 클릭 계측(`ui_events`의 `banner_clicked{slot:"intro"}`)은 `id` 불변이라 자동 유지(변경 불필요). (2026-08-14 정정: 과거 `?b=intro`(page_views) 서술은 미도달이었다 — `ui_events` 방식으로 교체됨.)
- 나머지 카드·로직 무변경.

## 변경 범위 (기능 2)

`app/how-to-use/page.tsx`(신설) · `app/how-to-use/layout.tsx`(noindex, 신설) · `components/common/HeroCarousel.tsx`(intro 카드 2필드). 마이그레이션·API 0.

# 비목표 (YAGNI)

- 설문: 캘린더 종류/기타를 객관식 하위선택으로(자유입력 유지) · PII·동의·아웃바운드 발송 인프라 · 정량 대시보드(집계는 이 한 문항 한 줄뿐).
- 사용법 페이지: 단계별 일러스트 신규 제작 · 인터랙티브 튜토리얼 · Footer/마이페이지 링크(캐러셀만) · SEO 색인.
