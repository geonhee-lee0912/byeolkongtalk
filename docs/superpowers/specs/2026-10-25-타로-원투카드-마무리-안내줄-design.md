# 옛 타로톡 분량 안내 줄 + 원·투카드 자연 마무리 되돌리기

- 날짜: 2026-10-25 · 상태: 사용자 승인(10-25) · 배포: 같은 날 prod 부분 배포 + 입구 반반 판정 창 재시작
- 관련: `2026-10-05-타로톡-메뉴판-별경제-design.md`(진 메뉴판) · `2026-10-04-타로톡-인챗결제-대화길이-design.md` §3-1(+3턴)·§3-3(keep-open) · `2026-10-11-타로-로그인전-맛보기-design.md`(입구 반반)

## 1. 배경

메뉴판 반반(10-09~10-25)이 지고 전원이 옛 타로톡으로 돌아갔다(`9018e929`). 사용자 결정: 가격과 무관한 메뉴판 요소만 옛 화면에 옮겨 심는다.

후보 4개 중 **스프레드 카드의 분량 안내 한 줄만** 옮긴다(사용자 10-25). 나머지를 뺀 근거 — 메뉴판 그룹 실측(판정 창 전체, 지인 제외):

| 요소 | 결과 |
|---|---|
| 비교 창 | 11명 열고 8명 '이걸로 볼래' → 깊게 리딩 0건(쓰리카드 4건) |
| 맛보기 끝 '이어서 깊게' | 노출 70명 → 클릭 3 → 이어진 리딩 0건 |
| 질문 이름 | 효과 근거 없음 · 옛 화면은 질문마다 스프레드 5개라 새 이름 18개가 필요 |

옛 그룹의 첫 리딩은 투카드 84%(163/194), 쓰리카드 이상 3%(6/194)였다 — 가입 선물 15별로 딱 덮이는 투카드에 몰린다. 안내 줄은 첫 리딩 전에 '별을 더 내면 무엇이 더 오는지'를 보여 주려는 것이다(효과는 가설).

문구를 다듬다가 원·투카드의 **실제 대화 길이를 줄이기로** 했다(§2-2). 화면 숫자만 낮추는 안은 기각.

## 2. 결정 (사용자 2026-10-25)

### 2-1. 안내 줄 문구 — `첫 풀이 ~{X}자 · 질문 {N}번 이상`

- **'첫 풀이'**: 글자 수는 첫 답 하나의 길이다. 리딩 전체 분량은 몇 번 더 묻느냐에 따라 달라지므로 '풀이 ~X자'만 쓰면 전체 분량으로 읽힌다(사용자 지적).
- **'질문 N번 이상'**: N = 자연 마무리선 답 번호(`hardCapTurn`) − 1. 첫 풀이가 1번째 답이라서다(메뉴판의 '대화 9턴'은 첫 풀이를 포함해 셌다). '이상'인 이유 — 자연 마무리선에서 유저가 아직 묻고 있으면 닫지 않고(keep-open) 강제 종료선까지 간다.
- 메뉴판 줄 앞의 '🃏 N장'은 뺀다. 옛 화면은 이름(투카드)·카드 그림·'· N카드'로 장 수를 이미 보여준다.
- 숫자는 손으로 적지 않고 설정(`FIRST_ANSWER_CHARS`·`WRAP_THRESHOLDS`)에서 계산한다 — 설정이 바뀌면 화면이 따라간다.

### 2-2. 원·투카드 자연 마무리선을 10-04 이전 자리로

- 원카드 8번째 → **5번째 답**, 투카드 9번째 → **6번째 답**. 쓰리카드 이상은 그대로.
- 정리 말투(converge)는 **마무리 한 턴 전부터만**(쓰리카드 이상과 같은 간격 1). 10-04 이전엔 간격 2였다 — 간격 1이어야 '카드 한 장 더' 제안이 나오는 자유 구간이 덜 준다(§3).
- **강제 종료선은 불변**(원 11·투 12). 계속 묻는 사람은 지금처럼 끝까지 간다.
- 10-04 '+3턴'(사용자 결정)을 원·투카드만 되돌리는 것이다. 그때의 이유(투카드 6번째 답에서 묻는 중에 닫힌 대화 49건)는 같은 배포에 들어간 keep-open 이 따로 막는다.
- 기각: 1·2·3장 숫자를 화면에서만 낮추기('이상'이라 거짓은 아님) — 가입 선물로 보는 투카드를 일부러 얇아 보이게 하면 입구 실험이 재는 가입률을 깎을 수 있고, 손으로 적은 숫자는 설정이 바뀔 때 화면에만 남는다.

### 2-3. 배포·실험

같은 날 prod 배포 + 입구 반반 판정 창을 이번 배포 시각으로 다시 시작한다(§7).

## 3. 근거 실측 (prod 읽기 전용 · 지인 6명 제외 · 원문 출력 없음)

- **첫 풀이 길이** — 2026-09-01~ 새 리딩(이어가기·위기·메뉴판 그룹 창 제외), 첫 assistant 메시지 글자 수 중앙값: 1장 812(276건) · 2장 1,208(927) · 3장 2,044(29) · 5장 3,101~3,606(30) · 6장 3,840(1건뿐) · 7장 4,707~4,748(23). 가운데 절반이 중앙값 ±10% 안 → 기존 표 800 / 1,200 / 2,000 / 3,500 / 3,800 / 4,700 그대로 쓴다.
- **'이상' 약속 검증** — 2026-10-06~(+3턴 뒤) 타로 리딩 505건: 자연 마무리선 전에 끝난 172건 중 170건 = 마무리 버튼·출구 칩, 1건 = 유저 마무리어, **1건(0.2%) = 별콩이가 먼저 닫음**.
- **영향받는 대화**(10-06~): 투카드 267건 중 6번째 답 이상 간 43%(114) · 원카드 221건 중 5번째 이상 37%(82).
- **'카드 한 장 더'**(후보 = 자유 구간 + 유저 질문): 제안이 나온 답 번호 — 원카드 65건 중 2~3번째 82% · 투카드 93건 중 2~4번째 86% = 바뀐 뒤에도 자유 구간인 자리. 원·투카드 구매 13건 중 12건이 바뀐 뒤에도 같은 자리(빠지는 1건 = 원카드 4번째 답). 강제 종료선 뒤 재개 구매(투카드 12·14번째)는 강제 종료선 불변이라 그대로.
- **결과 열람 하락**(10-12 판독): '결과 열람' 62→50% 의 원인 2개(+3턴 · 금색 마무리 버튼 제거) 중 +3턴이 원·투카드분 되돌아간다. 별콩이가 스스로 닫는 대화가 다시 생겨 결과 화면까지 가는 사람이 늘 것으로 본다(기대, 미측정).

## 10. 덧붙임 — 스프레드 카드 줄바꿈 다듬기 (사용자 2026-10-25 저녁)

배포 뒤 320px 화면에서 줄이 단어 중간에서 끊겼다("봐줄/게" · "깊/이 봐줄게" · "가입 선물 + ⭐10만 더 (1,000원부/터)"). 사용자 요청 = 최소한 가입 선물 줄의 "(X원부터)" 를 빼기.

- **가입 선물 줄**: `guestShortLine` 이 금액을 넣지 않는다 → "가입 선물 + ⭐10만 더". 금액은 카드를 뒤집은 뒤 로그인 창 줄(`guestSheetLine`)에 그대로 남는다(결정하는 자리). 쓰지 않게 된 `arm` 인자는 뺐다.
- **`SpreadPicker` 전체 `break-keep break-words text-pretty`**: 한글은 띄어쓰기에서만 끊고(앱의 기존 관례 — LoginSheet·CardReveal 등 4곳), 띄어쓰기 없는 긴 고민 글은 그래도 넘치지 않게, 마지막 줄에 단어 하나만 남지 않게(지원 안 하는 브라우저는 그냥 break-keep).
- **제목** `text-balance` — "너의 고민을 내가 해결해 / 줄게" → "너의 고민을 / 내가 해결해 줄게".
- **배지·가격** 각각 `whitespace-nowrap` + 줄 `flex-wrap` — 7장 카드에서 "가능성 스프레드 · / 7카드"·"⭐ / 55별" 로 쪼개지던 것을, 안 들어가면 가격이 통째로 다음 줄로.
- **자리 이름**은 이름 단위로만 줄바꿈(`whitespace-nowrap` 조각) + 가운뎃점 앞은 붙는 공백(U+00A0) — 줄이 "… ·" 로 끝나고 다음 줄은 이름으로 시작한다.
- 검증(dev): 질문 10종 × 320·375·414px = 30조합에서 단어 중간 끊김 0 · 가운뎃점으로 시작하는 줄 0 · 배지·가격 쪼개짐 0 · 가로 넘침 0.
- 입구 반반: 새 흐름 그룹의 로그인 전 화면 문구가 바뀌므로 이 배포 시각으로 판정 창을 한 번 더 다시 시작한다(결과 미열람).

## 11. 덧붙임 — 자리 이름 줄 빼고 설명 한 줄로 (사용자 2026-10-25 저녁)

사용자 질문 = 카드마다 자리 이름(의미)을 써 두는 게 큰 의미가 있나, 지워서 시각적 완성도를 높이는 게 낫나. 질문 10종 × 리딩 5종 = 50칸을 대조했다.

- **1~3장**: 자리 이름 줄이 설명 문장을 한 번 더 말한다(원카드는 10종 모두 "질문의 답", 투카드 "지금 상황과 조언…" 밑에 "현재 상황 · 상황에 대한 조언"). 지워도 잃는 내용이 없다.
- **5장 이상**: 자리 이름 줄이 '뭘 받는지'를 구체적으로 말하는 유일한 줄이었다(속마음 심층 설명은 "겉모습 뒤의 진심까지", 줄은 "망설이는 이유 · 나에 대한 진심 · 다가올 태도").
- **결정(사용자)**: 자리 이름 줄은 모든 카드에서 뺀다. 5장 이상은 설명 문장을 길게 써서 그 일을 맡긴다 — 카드 모양이 하나로 맞고, 문장은 일반 항목("둘러싼 상황 · 나 · 상대방 · 조언")을 빼고 그 고민에 맞는 자리만 앞세울 수 있다. 자리 이름은 뽑기 화면 칸마다 그대로 나온다.
- **문장 규칙**: ① 50자 이하(띄어쓰기 포함 — `spreads.test.ts` 가 잡는다) ② 실제 카드에 있는 자리만 말한다 ③ 별콩이 말투(반말 · 단정 금지 — "재회할 수 있는지"가 아니라 "다시 이어질 가능성").
- **어긋남 4곳 바로잡음**: 자리 이름을 질문·카테고리로 갈라 놓고 설명은 안 가른 곳 — 쓰리카드 × 연락 타이밍·재회·새 인연(카테고리 문장 "너와 상대, 둘 사이의 에너지"인데 실제 카드는 "지금의 흐름 · 전환점 · 다가올 신호" 등 — 새 인연엔 아직 상대가 없다) + 가능성 × 선택 고민(연애 문장 "이 관계가 어디까지"). 지금까지는 자리 이름 줄이 옆에서 가려 줬다. → `getSpreadDescription(spread, category, rawTag?)` 에 질문별 문장(`TAG_DESCRIPTION_OVERRIDES`, `TAG_LABEL_OVERRIDES` 의 짝) + `potential_7.decision`. 재발 방지 = "자리 이름이 갈라지는 곳은 설명도 갈라진다" 계약 테스트(고치기 전 실패 확인).
