# 추천 게이트웨이 A — 잠긴 문의 착지점 (2026-09-29 design)

현황 인벤토리: `2026-09-29-추천게이트웨이-인벤토리.md`

## 배경 — 결과 화면의 문이 전부 잠겨 있다

웰컴 별이 15다(`WELCOME_BONUS_STARS`, 2026-09-13 `3b4a7890`). 투카드(15별) 한 판이면 **잔액 0**,
원카드(10별)면 **5**. 그 잔액으로 결과 화면에 도착하면 거기 있는 문은 이렇다.

| 결과 화면의 문 | 값 | 잔액 0~5에서 | 9월 클릭 |
|---|---|---|---:|
| "이 고민 다시 뽑기" | 10★~ | 잠김 | 32 |
| 크로스셀 사주 카드 | 15~20★ | 잠김 | 31 |
| 크로스셀 별마루 | 무료 | **열림** | **55** |
| 첫충전 배너 | — | — | **1** |

유일하게 열린 문으로 제일 많이 나간다. `/shop` 도달은 37%인데 결제는 7.4%고,
투카드 후 잔액 5인 74명 중 8명(11%)만 샀다(`2026-09-19-페이월-재결제-소재-심층분석-findings.md`).

**문제는 게이트웨이의 유무가 아니라, 눌린 다음 끊긴다는 것이다.**

| 경로 | 잔액 부족하면 | 결제 후 |
|---|---|---|
| 대화 중(인챗) | `RechargeSheet` 가 그 자리에 뜸 | `returnTo` 복귀 + `pending_upsell` 재개 |
| 결과 화면 → 크로스셀 → 상품 | 텍스트 에러 + `/shop` **페이지 이동** | **돌아오는 길 없음** |

## 원칙

지면마다 **문 하나의 역할**만 준다. 이번 범위(A)는 유료 결과 2지면이고, 역할은 "지금 결제로 잇기"다.

🔴 **결과 화면의 카드·문구·배치는 건드리지 않는다.** 지금 눌리는 31~55 클릭이 유일한 구매 의사
신호라 잃으면 손해다. 바꾸는 것은 **눌린 뒤의 착지점**뿐이다.

## 변경 1 — 착지점 4곳을 시트로 교체

`router.push("/shop")` 를 그 자리 `RechargeSheet` 열기로 바꾼다. 시트는 이미 범용이라
(채팅을 모른다) 새 컴포넌트는 없다.

| 파일 | 지금 | 바꾼 뒤 |
|---|---|---|
| `app/tarot/draw/page.tsx` | `onCharge={() => router.push("/shop")}` | 시트 열기 (`returnTo` = 현재 URL) |
| `components/fortune/FortunePurchasePanel.tsx` | `onCharge` push + `/shop` 텍스트 링크 | 〃 |
| `components/fortune/compat/CompatInput.tsx` | 〃 | 〃 |
| `components/fortune/tarot/TarotInput.tsx` | 〃 | 〃 |

**복귀는 `returnTo` 만으로 충분하다** — 돌아오면 잔액이 차 있고 이미 그 상품 화면이라 버튼만
누르면 된다. `pendingUpsell`(원클릭 재개)은 **폼 상태가 있는 `FortunePurchasePanel` 에만** 쓴다
(프로필 선택 상태가 날아가면 재입력 마찰). 나머지 셋은 불필요하다.

`tarot/draw` 는 고른 스프레드를 URL 이 아니라 `sessionStorage`(`TAROT_SPREAD_KEY`)에 들고 있고,
없으면 `/tarot` 으로 되돌린다. **sessionStorage 는 토스 결제 왕복(외부 도메인 이탈 후 복귀)을
견딘다** — 같은 탭 세션에 묶이기 때문이고, `pending_upsell` 이 이미 그 방식으로 돌고 있는 것이
증거다. 따라서 `returnTo="/tarot/draw"` 로 돌아오면 선택이 그대로 복원된다. 별도 처리 불필요.

범위 밖: 연애(`ThreadChat`·`PassSheet`·`ThreadDrawModal` 등)·마이·헤더의 `/shop` 이동은 그대로 둔다.

## 변경 2 — 첫충전 배너 제거

결과 화면의 🎁 첫충전 +20% 배너는 9월 클릭 **1건**이다. 상품이 안 붙은 순수 충전 CTA라
"문 하나의 역할" 원칙과 어긋나고, 같은 +20% 안내를 `RechargeSheet` 가 안에서 이미 보여준다.
**혜택을 없애는 게 아니라 결정하는 자리로 옮기는 것이다.**

제거 대상과 그에 딸린 고아:

- `components/upsell/RechargeBlock.tsx` — 배너 블록 + `first-charge-status` fetch + `firstChargeEligible` state
- `components/upsell/ResultUpsell.tsx` — 같은 배너 + 같은 fetch/state + **`showBonus` prop**
  - `showBonus` 는 배너 전용 스위치라 배너가 사라지면 의미가 없다 → prop 삭제
  - 호출부 2곳(`tarot/result`·`saju/result`)의 `showBonus={false}` 인자도 같이 제거

## 변경 3 — `RechargeSheet` 의 `source` 를 파라미터로 (계측 보호)

🔴 **이걸 빼먹으면 로드맵 KPI 가 오염된다.** 시트는 `source: "inchat"` 을 세 이벤트에
하드코딩한다(`recharge_sheet_opened`·`recharge_payment_started`·`recharge_package_selected`).
그리고 `scripts/roadmap-kpi-snapshot.sql:31` 과 `20260921030000_admin_roadmap_kpi.sql:102` 가
`meta->>'source' = 'inchat'` 으로 **명시 필터**한다.

→ `source` prop 을 추가하고 **기본값을 `"inchat"`** 으로 둔다(기존 호출부 무변경 = 기존 지표 보존).
새 지면은 각자 다른 값을 넘긴다: `tarot_draw` · `fortune_purchase` · `compat` · `tarot_report`.

기존 `inchat` KPI 는 필터가 명시적이라 **새 값이 섞이지 않는다.** 새 지면의 성과는 같은 이벤트를
`source` 로 갈라 보면 된다.

## 안 하는 것

- **크로스셀 카드 추가·재배치 없음** — 화면에 문만 늘어난다
- **사주 리포트 결과에 재구매 CTA 신설 없음** — 리포트의 "또 하기"는 크로스셀 카드가 이미 그 역할
- **잠김 표시 없음** — 미리 막으면 지금 눌리는 클릭(유일한 구매 의사 신호)을 잃는다
- **가격·재화 불변** — 웰컴 15, 스프레드·상품 가격 그대로. 재화 변수를 새로 넣지 않는다

## 검증

1. 유닛 855+ · `tsc` 0 · `build` 0(`ƒ Proxy` 확인)
2. **실물**: dev 에서 잔액을 0으로 만든 계정으로 네 경로를 각각 눌러 ①시트가 그 자리에 뜨는지
   ②결제 시작 시 `returnTo` 가 그 화면인지 ③`source` 가 지면별로 갈려 찍히는지 DOM·이벤트로 단정
   (스크린샷은 인앱 캡처가 불안정 — `browser-e2e-session-injection` 규율)
3. 배너 제거 후 결과 화면 2곳에서 **레이아웃이 무너지지 않는지** 실렌더 확인
4. `recharge_sheet_opened{source:inchat}` 가 배포 전후로 **뛰지 않는지** 확인(오염 감시)

## 리스크

- **첫충전 +20% 노출이 줄어든다.** 배너는 죽어 있었지만(1클릭) 노출 자체는 있었다. 시트 안으로
  옮기면 시트를 연 사람만 본다. 되돌리기는 쉽다(블록 복원).
- **시트가 인챗 밖에서도 잘 도는지는 미검증.** 인챗은 목적이 확정된 자리("이 턴 이어가기")고
  여기는 상품 선택 직후라 맥락이 다르다. 실측으로 판정할 것.
