# 재화 분량·턴수·정합성 재정리 — luna 원가 기준 (2026-08-10)

"가격·분량·모델·페르소나 통합 재설계"의 **가격/분량 축**. 모델 축(luna 티어링)은 완료(`2026-08-10-model-tiering-routing-design.md`), 그 결과가 이 설계의 전제를 바꿨다.

## 0. 전제 — 티어링이 원가를 재앵커했다 (이 설계의 토대)

모델 티어링(chat→luna, 무료데일리→nano, 유료리포트→sonnet 유지) 배포로 원가 구조가 뒤집혔다. 실측·검증:

- **luna 자동 프리픽스 캐싱 = 대화 내부 99.6% 히트** (실호출 실측, `prompt_tokens_details.cached_tokens`). 첫 턴만 cold, 이후 warm. 상품별 실효 히트율 = `(총턴수−리딩수)/총턴수`.
- **luna 단가 확정** (OpenAI 문서): 입력 $0.20 · 캐시읽기 $0.02(0.1×) · 출력 $1.20 · 캐시write 1.25×. 캐시 경제가 sonnet과 동일 → 콘솔 검증(이론 ₩137.8k ≈ 실측 ₩137.5k) 유효.
- **재앵커 결과** (`scripts/tiering-cost-reanchor.mjs`, prod 토큰 × 티어 단가):

| | 이전(sonnet) | 티어링 후 |
|---|---|---|
| 주력 tarot two_card 별당원가 | ₩8.9 | **₩0.57** |
| API 콘솔 총액/30일 | ₩173,012 | **₩22,922** (9.0x↓) |
| 기여마진/유저 | ₩80 | **₩207** |
| 회수율 (vs CAC ₩392) | 20% | **~53%** |

**함의 (통념 4번째 반전):** 원가 레버(①무료별 ②입력축소)의 실익이 티어링에 먹혀 대부분 증발. 웰컴 20별을 타로 chat에 통째 태워도 원가 ₩11(이전 ₩178). 정가 마진 이미 99%. **손익분기 남은 격차(마진 ₩207→₩392, ~1.9배)는 이제 비용이 아니라 매출/전환 문제.** 그리고 **원가가 묶어두던 것 — 얇은 맛보기·짧은 턴 캡·플랫 리포트 분량 — 을 이제 풀 여력이 생겼다.**

## 1. 목표 & 비스코프

**1차 목표 (사용자 확정):** ③ **정합성**(체감·진열) + ④ **분량·턴수·가성비**(재구매 유도). 마진이 이미 99%라 "가격을 얼마로?"가 아니라 "별당 체감 가치를 일관·후하게"의 문제.

**접근 = A (깊이 사다리 + 균열 보정):** 가격 숫자는 유지(주력 가격선 안 흔듦 = 매출 리스크 0). 대신 분량/턴수/진열을 정합화. 유일한 의도적 가격 변경 = 첫 슬롯 인트로가(§5).

**비스코프 (의도적 제외):**
- **가격 숫자 변경** — 슬롯 인트로가(§5) 외 전부 유지.
- **전환/ARPU 전략** (교차이용·패키지·재구매 구조) — 다음 사이클(1차 목표에서 제외).
- **무료별 리사이징** (웰컴 20·설문 10) — luna로 원가 미미, 레버 아님 → 유지.
- **모델 변경·입력축소** — 티어링 완료 / 입력축소는 죽은 레버.

## 2. 운세 리포트 깊이 사다리 (분량 — 본체)

**문제:** 운세 페르소나(`byeolkong_fortune.md`)가 모든 리포트에 플랫 **"섹션당 2~4문장, 전체 600~900자"**. 실제 출력은 캡 무시하고 제각각(monthly 2,990자 > compat 1,778자) — **가격과 역전**(20별이 40별보다 길다). 타로엔 있는 티어 사다리가 운세엔 없다.

**설계 (타로톡 정합 — 2026-08-10 사용자 확정):** 타로톡 첫 풀이는 균일 **~63자/별**(설계 딜리버러블)이고 그 뒤 무료 대화가 붙어 총 산출량이 커진다(40별 5장 ≈ 총 3,450자). 운세는 **원샷(후속 대화 없음)**이라 공정 기준 = **같은 값 타로톡의 총 산출량 + 원샷 프리미엄 ~+20%**(같은 별 = 같은(+α) 총 별콩이 산출량). 밀도는 가격↑ 시 완만히↓(볼륨 디스카운트, 타로 총출력 곡선과 정합). 싼 궁합(1,778)을 끌어올려 역전 제거.

| 운세 리포트 | 정가 | 현재 실측 | 목표(총자) | 자/별 |
|---|---|---|---|---|
| 오늘의 운세 (무료) | 0 | ~1,700 | **1,200~1,700 유지(얇게·바닥)** | — |
| 이번달 | 20 | 2,990 | 3,000~3,400 | ~160 |
| 인간관계 궁합·좋은날 | 35 | ~1,600 | 3,600~4,000 | ~109 |
| 사랑 궁합 | 40 | 1,778 | 3,900~4,300 | ~103 |
| 2026 사주분석 | 60 | ~5,000 | 6,000~6,800 | ~107 |

**오늘의 운세(무료)는 사다리 제외 — 얇게 유지.** 이유: ①유료 사다리 바닥 방어(무료가 20별 이번달만큼 두꺼우면 결제 이유 소멸) ②매일 읽는 습관형이라 짧게 훑는 게 UX(긴 데일리 = 습관 역효과) ③nano 모델. 원가는 이유 아님(nano ₩1~3). "데일리를 리텐션 훅으로 확대"는 분량 아닌 **상품 구조** 문제 → 별도 사이클([[product-backlog]] #2·#3, W5).

**기전 (코드 실측 확인):** 리포트 길이는 `lib/fortune/prompt.ts`의 `SECTION_GUIDE[type]` **필드별 문장 수**가 유일하게 제어한다 — 페르소나 "600~900자"는 스키마와 모순돼 모델이 무시 중이고, `MAX_TOKENS_BY_FORTUNE`는 이미 넉넉(compat 7,800토큰 vs 실측 ~1,100), 파서엔 총길이 캡 없음. 따라서 **주 레버 = 필드별 문장 수·분석 깊이 상향(파서/렌더러/타입/스키마 무변경)** + 페르소나 모순 캡 정합화. QA 실측이 목표 미달 + 문장수로는 물타기뿐이면 **그 리포트에 분석 차원 1개 추가**(파서/타입/렌더러/테스트 동반 — 이때만 스키마 확장). **유료 리포트는 sonnet 유지**(품질) — 분량 확대 원가 무시가능(별당 ₩0.8~2).

**가독성 가드레일:** 섹션으로 끊어 "벽" 방지. 6,000자 리포트가 한 덩어리면 안 됨.

## 3. 타로 재정리 (luna 재튠 + 커버리지 + 관대함)

타로 첫 풀이 사다리는 **prod 라이브**(`byeolkong_tarot.md`, 2026-07-22 스펙 구현: 맛보기 2~4문장 / 프리미엄 6~7문장 + 티어별 목표분량). 단 **sonnet에서 튠됨** — 지금 chat=luna라 재검 필요. 4조각:

- **T-a. luna 길이 재검·재튜닝 (필수)** — QA 하네스로 스프레드별 첫 풀이 실측이 페르소나 목표(쓰리 1,300~1,700 ··· 7장 3,300~3,800)에 드는지 확인. luna 미달이면 페르소나 재튜닝(견인 숫자 상향 / 워크드 예시). ⚠️ 어차피 배포 전 검증 필수 항목.
- **T-b. 커버리지 갭** —
  - **관계 인-스레드 드로우** (`byeolkong_relationship_draw.md`): 현재 길이 지침이 "촘촘하게·확실히 길게"로 **모호 — 카드수별 사다리 없음**. 근데 스킬은 프리미엄 가격(체크인 45·걔속마음 40). → 타로와 정합하는 카드수별 목표분량(checkin_6=6장급, deep_feelings_5=5장급) 부여.
  - **이어가기(continuation)** 첫 풀이가 타로 사다리 상속하는지 확인.
- **T-c. 원가 여력 반영 (맛보기·후속)** — 마진 걱정에 얇게 눌러둔 곳을 luna로 재고: 원·투카드 맛보기 밀도, 후속 턴 분량. 재구매/체감에 기여하면 상향. **프리미엄 목표는 유지**(상한은 원가가 아니라 LLM 길이순응+가독성).
- **T-d. 턴 캡 재검 (턴수)** — `WRAP_THRESHOLDS`(convergeStartTurn/hardCapTurn/absTurnCap, 스프레드별). 캡이 부분적으로 원가를 묶던 장치(매 턴 정적블록 재전송)였고 luna로 그 이유 약화. **단 원가만의 문제 아님** — 수렴/[END]은 페르소나 품질과 얽힘([[persona-tuning-pendulum]]), 안전(has_sensitive absCap 억제)과 연결. 판단 기준 = "캡이 여전히 UX/수렴 품질에 기여하나", 무조건 늘림 아님. QA 게이트 필수.

## 4. 관계·시뮬 턴수 (턴수)

원가로 묶여 있던 무료/캡 예산 재검 — 역시 **원가만이 아니라 활성화/UX 기준**으로:

- `FREE_INTRO_TURNS`(3) — 무료 첫 대화 3턴. 원가 미미해진 지금, 활성화(과거 등록 14/15 무발화)에 더 후하게? (예: 4~5턴) — 재구매 아닌 **첫 발화 도달률**로 판정.
- `DAILY_TURN_CAP`(20) + `EXTEND`(5별→+5턴) · 스킬 `graceTurns` · `SIM_TURN_CAP`(12) — 캡 근거가 원가면 완화 여지, UX/수렴이면 유지.
- ⚠️ 전부 QA/실측 판정 — 캡 완화가 대화 늘어짐·심문피로로 역효과 안 나는지 감시.

## 5. 정합성 (진열·체감)

**재검 결과 "균열 3개" 중 2개는 이미 정합** — 손대는 게 리스크. 문서화만:
- **시뮬 15 vs 스킬 40~45:** 시뮬은 신상품, 낮은 가격 = **트라이얼 유도가 의도**(깊이-가격 아님). 유지 + 근거 문서화.
- **궁합 3곳:** 스킬 우리궁합 40 = 운세 사랑궁합 40 (**같은 값 정합**, 진입만 다름) · 인간관계궁합 35 < 사랑 40 (**소셜이 가벼움 정합**). 가격 유지, 진열에서 3개 구분만 명확히.

**남는 실제 결정 — 첫 슬롯 인트로가 (유일한 의도적 가격 변경):**
- 현재 `SLOT_COST=50` 플랫 → 웰컴 20 < 50이라 신규가 관계 시작에 무조건 충전(과거 14/15 무발화 지점).
- **설계: 첫 슬롯 = 인트로가(웰컴 20으로 덮이게, 권장 20), 2번째+ = 50.** 신규가 웰컴으로 첫 관계 등록 → 무료 인트로 3턴 → 이후 패스/스킬에서 결제. 등록 벽 제거하되 수익화는 패스/스킬 레이어 유지.
- ⚠️ 서버 권위 게이트 — `slotAllowance`/`SLOT_COST`(`lib/relationship/types.ts`) + `create_relationship` RPC. **1:N 슬롯 마이그레이션·drift 픽스(dev 미배포, [[relationship-slot-gate-drift-fix]])와 동반 확인 필수.** 첫-슬롯 판별 = 서버가 구매 슬롯 수로.

## 6. 판정 & 검증

- **새 `PROMPT_VERSION` 코호트** — 타로·운세·관계드로우 페르소나 동시 변경. 전후 비교.
- **운세:** 재구매율(운세) · 결과 열람율 · 실측 분량(역전 해소 확인).
- **타로:** 재구매율 · 결과 열람율 · luna 실측 첫 풀이 분량 · 대화 길이(턴).
- **슬롯:** 신규 관계 등록률 · 첫 발화 도달률(무발화 개선).
- **가드레일:** 증발률(너무 길어 읽기피로 이탈 감시) · `no_consecutive_question_close`(심문피로) · 안전(has_sensitive [END]억제 불변).
- **QA:** 하네스 `npm run qa`(dev), 페르소나 수정 후 **dev 서버 재시작 필수**([[qa-harness-usage]]). 길이 목표는 견인 숫자 — 도달 아닌 baseline 대비 증가율·재구매율로 판정([[reading-depth-and-value-tuning]]).

## 7. 배포

roadmap ④(dev 누적분 한 판 → prod)에 포함. 새 `PROMPT_VERSION` 슬러그. 페르소나(md)·config·프롬프트 변경이 주라 마이그레이션은 슬롯 인트로가(RPC)만.

## 8. 구현 단계 (writing-plans 에서 상세)

독립적이라 단계별 배포 가능: (P1) 운세 사다리 · (P2) 타로 luna 재검+커버리지+맛보기/후속 · (P3) 턴 캡(타로/관계/시뮬) · (P4) 슬롯 인트로가. 각 단계 QA 게이트.
