# 별마루 ⑤ — 오늘의 카드(원카드) + good_days·one_card 폐지 + 낙수 — 설계

> 상위 = `2026-08-31-별마루-리텐션허브-design.md` §3(블록4·9)·§6.2(낙수)·§12(원가). 가격 근거 = `deficit-diagnosis-pricing-grid-2026-08-29`(one_card 폐지 = 별마루 무료 대체와 동시). 브레인스토밍 2026-09-05. 사용자 결정: **풀 스코프(블록4 신설 포함)**.

## 1. 목표 & 스코프

별마루에 **오늘의 카드(무료 원카드)**를 신설하고, 그 무료 대체가 생기는 것과 동시에 **유료 타로 원카드(10별)를 폐지**한다. 죽은 **good_days(35별·구매0)**도 폐지(기능은 별마루 캘린더가 흡수). 낙수는 하단 CrossSell(②-b 완료)에 **블록4 인라인 낙수**를 더한다.

- 포함: ①블록4 오늘의 카드(뽑기·무료 정적·구독 LLM) ②good_days 폐지 ③유료 원카드 폐지 ④블록4 인라인 낙수
- 제외: `/fortune` 결과화면 낙수 CTA(별마루 밖 — 별건으로 미룸, 사용자 결정) · three_card 25→20·웰컴 20→15·star_10(전부 ⑤ 아님) · 풍부한 per-카드 별콩 정적 뱅크(⑥)

## 2. 블록4 — 오늘의 카드 (사용자 결정 반영)

### 뽑기 = 오늘의 카드(하루 1장) · 타로톡과 동일한 뽑기/정역
- **하루 1장**: KST 날짜당 1회. 첫 진입 시 "오늘의 카드 뽑기" → 뽑고 나면 **그날 고정**(축적·재방문). 다음 로드는 저장분 표시.
- **뽑기·정/역 = `components/tarot/CardDrawRitual` 재사용**(cardCount=1). 유저가 셔플 덱에서 직접 뽑고, 정/역도 타로톡과 동일하게 그 뽑기에서 결정된다(자동배정 ❌). 결제 모달은 부모에 있으므로 **무료 드로우로 재사용**(별 비용 0).
- 저장: 신규 `byeolmaru_daily_card`(user_id, card_date, card_id, reversed, created_at, PK(user_id,card_date)). 카드는 `lib/tarot/cards.ts`(78장, `getCard`/`getCardImagePath`) 재사용 — 새 카드 데이터 없음.

### 무료 / 구독
- **무료**: 카드 이미지(`getCardImagePath`) + 이름(name_kr) + 키워드(뽑힌 정/역에 따라 `card.upright[]`/`card.reversed[]`) + 짧은 정적 해석(⑤는 키워드 기반 템플릿, ⑥에서 별콩 톤 뱅크로 교체).
- **구독**: LLM 개인화 해석 — nano `generateOnce`, ②-a `narrative`·3-b `pair-narrative` 패턴 재사용. 카드+정/역+내 사주/오늘을 엮어 별콩 톤 서술. 비자격 = 블러+CTA(게이트 재사용).
- 🔴 원가: 무료는 정적(변동비 0). LLM은 구독 전용·비자격 미호출(원가 0) — 별마루 무료/구독 경계 원칙 유지.

### 구현 뼈대
- 테이블 `byeolmaru_daily_card` + `lib/byeolmaru/daily-card.ts`(순수 조회/기록 래퍼) + `POST /api/byeolmaru/daily-card`(뽑은 카드 저장, 하루 1회 멱등) + `GET`(오늘 카드 조회) + `app/api/byeolmaru/card-narrative`(구독 LLM, ②-a 미러) + `components/byeolmaru/DailyCardBlock`(뽑기 전=버튼/CardDrawRitual, 후=카드+무료정적+구독서술/블러) + `ByeolmaruView` 배선(블록4 위치).

## 3. good_days 폐지

- `lib/saju/products.ts` `SajuProduct`/`SAJU_PRODUCTS`/`SAJU_PRODUCT_INFO` 에서 `good_days` 제거 + /fortune 리포트 타입·목록·프롬프트·모델 분기에서 제거. 기능은 별마루 캘린더(잘 맞는 날/챙길 날 30일)가 이미 흡수.
- ⚠️ **제거 표면이 넓다** — grep `good_days` 로 전 참조(fortune types·hero·generic-report·response-format·model·prompt·saju/calc 등) 감사. **신규 노출만 차단**하고, 기존 readings·타입 데이터는 보존(0 구매라 결제 소급 이슈 없음). 계약 테스트(`types.test.ts` 등)·enum 폭 주의.

## 4. 유료 타로 원카드(one_card) 폐지

- `lib/tarot/spreads.ts` `TAG_SPREADS`(태그별 큐레이션 5) 목록에서 `one_card` 제거 → 신규 유료 뽑기로 노출 안 됨. **무료 별마루 오늘의 카드가 대체**(동시 조건 충족).
- ⚠️ `SpreadType` 타입·`SPREAD_INFO`·포지션 라벨·`continuation`(one_card deep=6별) 은 **보존**(기존 리딩 열람·이어가기 데이터 무결성). 제거는 "새 유료 제안"에서만. grep `one_card` 로 노출 지점만 정확히 골라낸다.

## 5. 낙수

- 별마루 하단 CrossSellCard(②-b, `crosssell.ts` 축 기반 → 타로/사주) = 블록9, **완료**. 그대로 유지.
- ⑤ 추가 = **블록4 오늘의 카드 결과의 인라인 낙수** — 무료 카드 아래 "이 카드, 타로로 더 깊게" CTA(→ `/`). (구독자는 이미 LLM 해석을 받으므로 인라인 낙수는 무료/비구독 대상.)

## 6. 미해결 / 리스크

- 🔴 good_days·one_card 제거 표면이 넓어 **조용한 회귀** 위험(enum·계약테스트·이어가기). 플랜에서 grep 감사 + tsc/build + 기존 리딩 열람 회귀 확인 필수.
- 오늘의 카드가 "매일 뽑는 습관"이 될지는 미검증(별마루 히어로 리스크와 동류) — 완화=무료라 변동비 0.
- ⑥ 정적 뱅크 전 무료 정적은 키워드 기반이라 다소 건조 — ⑥에서 별콩 톤으로 교체.

## 7. 플랜 분할(예정)

블록4(신설·테이블·드로우·LLM·컴포넌트)가 커서 ③처럼 분할:
- **5-a**: 오늘의 카드 블록(테이블 + daily-card 래퍼/API + DailyCardBlock[CardDrawRitual 재사용] + card-narrative LLM + ByeolmaruView 배선 + 인라인 낙수). = 무료 대체가 실재.
- **5-b**: good_days 폐지 + 유료 one_card 폐지(5-a로 무료 대체가 생긴 뒤 = 동시 조건). grep 감사 중심.
