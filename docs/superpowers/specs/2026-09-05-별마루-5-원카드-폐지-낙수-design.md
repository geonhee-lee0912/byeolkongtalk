# 별마루 ⑤ — 오늘의 카드(원카드) + good_days 폐지 + 낙수 — 설계

> 상위 = `2026-08-31-별마루-리텐션허브-design.md` §3(블록4·9)·§6.2(낙수)·§12(원가). 브레인스토밍 2026-09-05. 사용자 결정: **⑤-a 오늘의 카드 풀 스코프(완료) + ⑤-b good_days 폐지만 (유료 one_card 폐지는 2026-09-05 취소 — §4)**.

## 1. 목표 & 스코프

별마루에 **오늘의 카드(무료 원카드)**를 신설한다(⑤-a 완료). 죽은 **good_days(35별·구매0)** 진열을 폐지한다(기능은 별마루 캘린더가 흡수). 낙수는 하단 CrossSell(②-b 완료)에 **블록4 인라인 낙수**를 더한다(⑤-a 완료).

> 🔴 **2026-09-05 사용자 결정 — 스코프 축소**: **유료 타로 원카드(one_card)는 폐지하지 않고 유지**한다. 별마루 오늘의 카드(무료 데일리 오라클)와 타로톡 원카드(유료·고민 기반)는 **역할이 다른 상품**이므로 공존한다. 따라서 ⑤-b 는 **good_days 폐지만** 수행한다.

- 포함: ①블록4 오늘의 카드(뽑기·무료 정적·구독 LLM) — ⑤-a 완료 ②good_days **진열** 폐지 — ⑤-b ③블록4 인라인 낙수 — ⑤-a 완료
- 제외: **유료 타로 원카드 폐지(취소 — 유지)** · `/fortune` 결과화면 낙수 CTA(별마루 밖 — 별건으로 미룸) · three_card 25→20·웰컴 20→15·star_10(전부 ⑤ 아님) · 풍부한 per-카드 별콩 정적 뱅크(⑥)

## 2. 블록4 — 오늘의 카드 (사용자 결정 반영)

### 뽑기 = 오늘의 카드(하루 1장) · 타로톡과 동일한 뽑기/정역
- **하루 1장**: KST 날짜당 1회. 첫 진입 시 "오늘의 카드 뽑기" → 뽑고 나면 **그날 고정**(축적·재방문). 다음 로드는 저장분 표시.
- **뽑기·정/역 = `components/tarot/CardDrawRitual` 재사용**(cardCount=1). 유저가 셔플 덱에서 직접 뽑고, 정/역도 타로톡과 동일하게 그 뽑기에서 결정된다(자동배정 ❌). 결제 모달은 부모에 있으므로 **무료 드로우로 재사용**(별 비용 0).
- 저장: 신규 `byeolmaru_daily_card`(user_id, card_date, card_id, reversed, created_at, PK(user_id,card_date)). 카드는 `lib/tarot/cards.ts`(78장, `getCard`/`getCardImagePath`) 재사용 — 새 카드 데이터 없음.

### 무료 / 구독
- **무료**: 카드 이미지(`getCardImagePath`) + 이름(name_kr) + 키워드(뽑힌 정/역에 따라 `card.upright[]`/`card.reversed[]`) + 짧은 정적 해석(⑤는 키워드 기반 템플릿, ⑥에서 별콩 톤 뱅크로 교체).
- **구독**: LLM 개인화 해석 — nano `generateOnce`, ②-a `narrative`·3-b `pair-narrative` 패턴 재사용. 카드+정/역+내 사주/오늘을 엮어 별콩 톤 서술. 비자격 = 블러+CTA(게이트 재사용).
- 🔴 원가: 무료는 정적(변동비 0). LLM은 구독 전용·비자격 미호출(원가 0) — 별마루 무료/구독 경계 원칙 유지.

### 구현 뼈대
- 테이블 `byeolmaru_daily_card` + `lib/byeolmaru/daily-card.ts`(순수 조회/기록 래퍼) + `POST /api/byeolmaru/daily-card`(뽑은 카드 저장, 하루 1회 멱등) + `GET`(오늘 카드 조회) + `app/api/byeolmaru/card-narrative`(구독 LLM, ②-a 미러) + `components/byeolmaru/DailyCardBlock`(뽑기 전=버튼/CardDrawRitual, 후=카드+무료정적+구독서술/블러) + `ByeolmaruView` 배선(블록4 위치).

## 3. good_days 폐지 (⑤-b — 진열/추천 표면만, 데이터·생성·타입은 보존)

good_days 는 **두 시스템에 존재**한다(이름만 공유, 실체는 별개):
- **`/fortune` 좋은 날 리포트**(FortuneType, one-shot, 35별, 카탈로그 진열) — **사용자가 보는 "좋은날"의 본체.**
- **`/saju` 좋은 날 상담**(SajuProduct, 채팅형) — /select 진입이 닫혀 사실상 휴면. 타로톡 페르소나가 날짜 반복질문에 `[RECO:saju:good_days]` 로 가끔 유도.

### 제거(신규 노출/추천 차단) — 4곳
1. `lib/fortune/types.ts` — `FORTUNE_LIST` 배열에서 `FORTUNE_CONFIG.good_days` **한 줄 삭제** → 카탈로그·`timing` 카테고리·크로스셀 후보에서 사라짐.
2. `lib/fortune/types.ts` — `FORTUNE_CONFIG.good_days.active: true → false` (은퇴 주석 동반, 기존 tarot 타입 은퇴 선례와 동일 형태) → 직링크 `/fortune/good_days` 진입 시 `app/fortune/[type]/page.tsx:36` 의 `valid` 가드가 걸려 **`/fortune` 로 리다이렉트**(구매창 안 뜸).
3. `app/tarot/page.tsx` — "언제 연락 올까" 태그의 good_days 크로스링크 블록(`href="/fortune/good_days"`) 삭제.
4. `data/persona/byeolkong_tarot.md` — `[RECO:saju:good_days]` 유도 섹션(§달력 수준의 시점…) 삭제 → 타로톡이 더는 좋은날을 추천하지 않음.

### 보존(데이터·검증·생성 무결성) — 손대지 않음
- ⚠️ **`FORTUNE_CONFIG.good_days` 레코드 자체는 유지** — `FORTUNE_GRADIENTS`/`FORTUNE_HASHTAGS`/`FORTUNE_LENGTH_HINT`/`FORTUNE_CATEGORY` 는 `Record<FortuneType>` 라 키를 빼면 tsc 가 깨진다. `FortuneType` union 도 유지.
- ⚠️ **`SAJU_PRODUCTS`/`SAJU_PRODUCT_INFO`/`isSajuProduct` 의 good_days 는 유지** — `app/readings/page.tsx` 의 `sajuSubtext`(:131)·`sajuAvatar`(:160)가 `isSajuProduct` 로 옛 상담 리딩의 **상품 라벨·아이콘**을 결정한다(확인 완료). 빼면 옛 good_days 상담 리딩이 라벨·아이콘 fallback 으로 degrade(크래시는 아님). (원래 초안의 "SAJU_PRODUCTS 제거"는 §3 자신의 "기존 readings 보존" 원칙과 충돌 → 정정.)
- ⚠️ **생성 코드 전부 유지**: `lib/fortune/{hero,prompt,generic-report,existing-lookup,response-format,model}.ts`·`lib/claude.ts` 의 good_days 분기 → 기존 리포트 재열람이 정상 렌더.
- ⚠️ **reco enum `saju:good_days` 유지**: `RecoProduct`/`RECO_PRODUCTS`/`RECO_DISPLAY` 는 그대로(페르소나 유도가 사라져 **휴면**, 렌더 지점엔 `if (!display) return null` 가드 존재). 라우팅 대상(`/saju` + 보존된 SajuProduct)과 일관.
- ⚠️ **cross-cards `RELATED_SAJU.good_days` 유지**: 옛 good_days 리딩 재열람 시 크로스셀 소스. `pickValid` 의 `active` 가드가 good_days 를 후보에서 자동 제외하므로 무해.
- 계약 테스트(`types.test.ts`·`model.test.ts`·`response-format.test.ts`·`route-labels.test.ts`·`reco-utils.test.ts`·`cross-cards.test.ts`·`cases.test.ts`)는 **전부 그대로 GREEN** 이어야 한다(전부 config/카테고리/모델/포맷만 검사, `FORTUNE_LIST` 멤버십은 안 봄 — 확인 완료).

## 4. 유료 타로 원카드(one_card) — ~~폐지~~ **유지 (2026-09-05 결정)**

- 🔴 **폐지 취소.** 별마루 오늘의 카드(무료 데일리 오라클)와 타로톡 원카드(유료·고민 기반 뽑기)는 **역할이 다른 상품**이라 공존한다. `lib/tarot/spreads.ts` `TAG_SPREADS` 는 **손대지 않는다**. one_card 관련 코드·데이터 전부 현행 유지.

## 5. 낙수

- 별마루 하단 CrossSellCard(②-b, `crosssell.ts` 축 기반 → 타로/사주) = 블록9, **완료**. 그대로 유지.
- ⑤ 추가 = **블록4 오늘의 카드 결과의 인라인 낙수** — 무료 카드 아래 "이 카드, 타로로 더 깊게" CTA(→ `/`). (구독자는 이미 LLM 해석을 받으므로 인라인 낙수는 무료/비구독 대상.)

## 6. 미해결 / 리스크

- 🔴 good_days 제거 표면(진열 4곳)은 좁지만, **보존 표면이 넓어**(config 레코드·생성·SajuProduct·reco enum·계약테스트) "무심코 같이 지우면" tsc/테스트/옛리딩 열람이 조용히 깨진다. → §3 의 "보존 목록"을 그대로 지키고, 실행 후 **전체 테스트 + tsc + build + 옛 good_days 리딩 재열람**을 반드시 확인.
- 오늘의 카드가 "매일 뽑는 습관"이 될지는 미검증(별마루 히어로 리스크와 동류) — 완화=무료라 변동비 0.
- ⑥ 정적 뱅크 전 무료 정적은 키워드 기반이라 다소 건조 — ⑥에서 별콩 톤으로 교체.
