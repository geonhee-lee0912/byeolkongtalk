# 별마루 ⑥ — 정적 콘텐츠 뱅크(타로 156 · 골격 45) — 설계

> 상위 = `2026-08-31-별마루-리텐션허브-design.md` §6(정적 1회생성·검수)·§핵심법칙("LLM 1회 생성 + 검수 = 사전 작성"). 브레인스토밍 2026-09-05. ⑤-b 다음. 사용자 결정: 범위=타로156+캘린더골격 / 저장=정적 JSON / 생성=세션 내 직접 저작 / 골격키=tone×relation×3variant.

## 1. 목표 & 스코프

무료 티어의 **dry 한 룰/키워드 정적 텍스트**를 별콩 톤 **사전 생성 뱅크**로 교체한다(변동비 0 유지 — 1회 저작 후 굳힘). 노출 전 무료 화면 완성도를 올리는 게 목적.

- 포함: ①**타로 156**(오늘의 카드 정적 해석) ②**골격 45**(나 캘린더 상세 골격 문장) ③**티저 3줄 리파인**(별건 — 골격과 역할 분리, 아래 §3)
- 제외: 우리 오늘 서술(구독 LLM — ③-b 완료) · 캘린더 등급 라벨(이미 별콩 톤 "잘 맞는 날" 등, 무변경) · ⑦ 캐릭터 에셋 · per-카드 상세 SEO 문구(별건)

## 2. 뱅크 1 — 타로 156 (오늘의 카드)

- **키** = 카드 78 × 정/역 2 = **156**. 카드 id = `data/tarot_card_data.json`(0~77)과 정렬.
- **내용** = 카드별 정/역 각각 별콩 톤 **1~2문장**. 근거 = 그 카드의 `name_kr` + `upright[]`/`reversed[]` 키워드(정/역에 맞게). "오늘 하루" 프레임(오늘의 카드니까).
- **저장** = `data/byeolmaru/card-lines.json`:
  ```json
  { "0": { "upright": "…", "reversed": "…" }, "1": { … }, … "77": { … } }
  ```
- **조회** = `lib/byeolmaru/static-lines.ts` `getCardLine(cardId, reversed): string`. 폴백 = 현 키워드 템플릿(`buildStaticLine`) — 뱅크 미스 시 크래시 대신 degrade.
- **교체 지점** = `DailyCardBlock.buildStaticLine(keywords)` → `getCardLine(cardId, reversed)`(카드 id·정역을 이미 알고 있음).

## 3. 뱅크 2 — 골격 45 (나 캘린더 상세 + 티저)

- **키** = 등급 `tone(3: good/normal/caution)` × `relation(5: 생아/아극/비화/아생/극아)` = **15조합**, 각 **variant 3개 = 45문장**.
  - `tone` = 전반 결(잘 맞는/무난/살짝 챙길). `relation` = 그날 천간 오행이 내 일간 오행과 만나는 관계 = **"왜 그런 결인지"의 핵심 동인**(생아=날 살려줌 / 극아=날 누름 / 비화=같은 결 / 아극=내가 다룸 / 아생=내가 내줌).
- **내용** = 별콩 톤 골격 문장(1~2문장). tone 의 valence + relation 의 flavor 를 엮되 **단정 예언 금지**(흐름·가능성). 축(연애/돈/일 막대)은 이미 화면에 있으니 문장은 "전반 결 + 왜"에 집중.
- **반복 최소화** = 날짜 문자열 해시로 variant 로테이션(30일간 같은 tone×relation 이 반복돼도 다른 문장). `variantIndex = hash(date) % 3`.
- **저장** = `data/byeolmaru/skeleton-lines.json`:
  ```json
  { "good": { "생아": ["v0","v1","v2"], "아극": […], … }, "normal": {…}, "caution": {…} }
  ```
- **조회** = `lib/byeolmaru/static-lines.ts` `getSkeletonLine(tone, relation, date): string`.
- 🔴 **선행 코드 변경(additive 1줄)**: `DayCell` 에 `relation: ElementRelation` 노출. `buildCalendar` 가 이미 `f = dayFactors(...)` 로 계산 중 → `relation: f.relation` 추가. 이래야 상세카드·티저가 뱅크 키를 만든다. `DayCell` 은 `Record` 강제 대상이 아니라 tsc 파급 없음(소비처가 새 필드를 안 읽으면 무변).
- **교체 지점 = `DayDetailCard` 1곳** — 등급 라벨(`cell.grade.label`) 아래에 골격 문장 슬롯 추가(`getSkeletonLine(cell.grade.tone, cell.relation, cell.date)`).

### 티저 (별건, 골격 뱅크 아님)
- 🔴 **화면 배치상 `DayDetailCard`(골격 하루읽기)와 `PremiumBlock`(티저)이 인접 스택** → 티저를 골격 뱅크에서 파생하면 **같은 화면에 산문 2줄 중복**. 그래서 티저는 뱅크와 분리한다.
- **역할 분리**: 골격 = 무료 "오늘 전반 결 + 왜"(DayDetailCard). 티저 = 그 위에서 **개인화(월·시 기둥 겹침)로 유도하는 훅**(PremiumBlock 게이트) — 하루읽기의 복제가 아니라 "더 깊은 게 있다"는 앞당김.
- **작업** = `narrative-prompt.TEASER_BY_TONE` 3줄(tone별)을 별콩 톤 **개인화-forward 훅**으로 리파인(현행도 3줄 tone 기반). 뱅크·로테이션 없음. `buildTeaserLine` 시그니처 무변.

## 4. 생성 · 검수

- **생성 = 세션 내 직접 저작**(스펙 §핵심법칙의 "LLM"이 곧 나). 스크립트 200콜 blind 생성보다 톤·다양성·반복회피를 전체적으로 통제 가능하고 생성=검수가 한 번에. JSON 을 직접 Write.
- **톤 = 별콩 코어 단일 원천**(`data/persona/byeolkong_core.md`): 반말·1인칭 "별콩이는/나는"·흐름/가능성/선택 3키워드·**단정 예언 금지**·불안 자극/운명론 협박 금지·따뜻한 마무리·**마크다운 별표(**) 금지**(화면 그대로 노출). 장난기는 과하지 않게.
- **검수** = ①내 전수 통독 → 톤 위반(단정·별표·불안조장) 수정 ②사용자 표본 리뷰(타로 몇 장 + 골격 15키 훑기) ③**계약 테스트**로 완전성·정합 고정: card-lines 156칸 전부 존재(78×2) · skeleton 15조합×3 전부 존재 · relation/tone enum 정합 · 조회 함수 폴백.

## 5. 배선 요약 (2 뱅크배선 + 1 티저리파인 + 1 additive)

| 지점 | 현재 | ⑥ 후 |
|---|---|---|
| `DailyCardBlock.buildStaticLine` | 키워드 나열 템플릿 | `getCardLine(id, reversed)` (폴백=현 템플릿) |
| `DayDetailCard` | 등급 라벨 + 축 막대 | + 골격 문장 슬롯(`getSkeletonLine`) |
| `narrative-prompt.TEASER_BY_TONE` | tone별 3줄 룰 | 개인화-forward 훅 3줄 리파인(뱅크 아님) |
| `DayCell` (calendar.ts) | grade/axes/element/score | + `relation`(additive) |

## 6. 미해결 / 리스크

- **무료층 문장 반복 체감**(스펙 §리스크3) — 완화 = 타로는 156칸(카드 랜덤이라 겹침 드묾) · 골격은 variant 3 로테이션 + 날짜별 카드/등급/축이 매일 달라 문장만 정적. 잔여 반복은 v1 후 variant 증량으로.
- **톤 드리프트** — 201칸을 한 번에 저작하면 후반 품질 저하 위험. 완화 = 청크 저작(메이저22 → 마이너 수트별 → 골격) + 전수 통독.
- **골격 tone×relation 상관** — tone 이 relation 에서 부분 파생(생아→good 경향)이라 일부 조합(극아+good)은 드묾. 드문 조합도 저작(combo/scarcity 로 도달 가능). 저작 낭비는 15×3=45로 작음.
- DayCell.relation 추가는 소비처가 안 읽으면 무해하나, 직렬화/스냅샷에 DayCell 이 저장되는 경로가 있으면 확인(현재 캘린더는 런타임 계산·비저장 → 무관).
