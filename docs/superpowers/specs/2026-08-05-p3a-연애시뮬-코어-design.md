# P3a · 연애 시뮬레이션 코어 — 설계

**작성** 2026-08-05 · **상태** 브레인스토밍 확정 (구현 착수용)
**선행(확정 코어 계승)** `2026-08-03-우리사이-시뮬레이션-design.md` §1~10 — 정체(밤에 인형 안고 털어놓기·3화자)·뼈대·콜드스타트·1:N/슬롯·코호트·과금 틀은 그대로 계승. 이 문서는 그 위에서 **§11 미정 + 화면·엔진 구현 세부**를 확정한다.
**범위** P3a = **시뮬 "한 판"의 경험**(상황 선택 → 밤 무대 → 디브리핑). **P3b(초상화 종합 ⓑ)는 후속** — 판 데이터가 쌓인 뒤.
**⚠️ 선행 스펙에서 이번에 뒤집은 것 1건**: §7 과금 — **💭 코칭 별도 과금 폐지**(판 가격에 흡수). 근거는 §7.

## 0. 한 줄

유저가 그린 그 사람의 인형을 상대로 난감한 상황을 **미리 연습**하고, 곁의 별콩이가 통찰과 "보낼 말"을 건네는 한 판. 파는 것은 **연습 + 코칭 경험**(판 고정가).

## 1. 흐름

```
[파일 허브] 상대 선택 → [연애 시뮬레이션] 카드
   → ① 상황 선택 (라이트 톤)
   → ② 밤 무대 (3화자, 밤 톤)        ← 톤이 확 바뀌며 "무대 진입"
   → ③ 디브리핑 (별콩이 복귀, 따뜻한 톤) → 보낼 말 적립
   → [별콩이랑 더 얘기하기] 동선으로 스레드 연결
```

세 화면의 **톤 전환**(라이트 → 밤 → 따뜻한 복귀)이 곧 화자·모드 구분 장치다.

## 2. 밤 무대 화면 (핵심)

배경 = 스레드(크림)와 **확 다른 밤 톤**(`night`/`night-deep` + 금색 별). 화자 혼동(2화자 스레드 ↔ 3화자 시뮬)을 물리적으로 차단.

- **인형 = 접히는(collapsing) 방식** (확정):
  - **진입**: 인형 초상화가 상단에 **크게**(≈80px, 은은한 글로우) + 이름 + "🌙 마음이 그린 인형" 태그. "인형을 만나는 순간"의 무대 프레임.
  - **대화 시작 후**: 초상화가 상단에 **작은 상시 아바타로 접힘**(sticky, ≈30px). 항상 보이되 대화 공간을 내줌.
  - (기각: 큰 초상화 계속 고정=대화 답답 / 완전 스크롤로 사라짐=대화 중 스레드와 동일)
- **상대 = 인형으로 시각화**(관계별 색 프리셋, 사람 사진 ❌). **별콩이 = 노트🌙**(채팅 버블이 아니라 금색 노트 카드) = 지켜보는 이 신호.
- **프레임 고지**(제품 발화, 진입 시 별콩이 노트): *"별콩이가 민준이 인형을 데려왔어. 진짜 걔가 아니라 네 마음속 민준이야. 편하게 말 걸어봐."*
- **대화 = 자유 대화**(미연시식 A/B/C 선택지 ❌ = 승리목표형 게임화 기각).
- **하단**: 입력창 + `💭 도움`(코칭) + `정리하기`(디브리핑 트리거 = 언제든 빠져나오는 문, 위기 시 서버가 누르는 문도 동일).
- **턴 한도** = 고민톡(타로/사주 chat)과 동일 — 자연 수렴(`[END]`) + abs-cap 재사용(원가 경계).

## 3. 상황 선택 화면

- 상단 밤 톤 바 + 본문은 **라이트(크림) 톤**. 상황 고르면 밤 무대로 전환(진입감).
- **구체 상황 카드 + "✍️ 직접 쓰기"** — 카드가 주, 자유가 보조. 백지 입력이 무발화 원인이라 카드로 첫 마찰 제거.
- 카드 세트는 **관계별로 다름**(§4). "무게 분류(가벼움/무거움)"는 노출 ❌(내부 개념).

## 4. 상황 데이터 모델 + 스타터 세트

**아키텍처(확정)**: 제네릭 3화자 엔진(§5, 한 번 만들고 QA) + **상황별 seed** + **상황마다 QA**. "올바른 시뮬"은 데이터 구조가 아니라 **엔진 + seed + QA**가 보장한다. 얇은 라벨만으론 품질이 들쭉날쭉.

**저장소 = 코드 상수**(`lib/relationship/situations.ts`), **DB/어드민 없음.** 기존 `FORTUNE_CHIPS`·`RELATIONSHIP_SKILLS` 패턴. 상황 추가 = 이 파일에 객체 1개 + QA + 커밋. ("빠른 확장"의 병목은 배포가 아니라 QA이므로 무배포 어드민은 불필요.) — *상황 카탈로그만 코드; 실제 판 대화는 DB(`reading`/`messages`) 저장(§8).*

**seed 스키마**:
```ts
interface SimSituation {
  id: string;                 // "breakup-reconnect"
  relationship: RelationshipStatus | "any";  // crush|dating|onesided|breakup|any
  emoji: string;
  label: string;              // "재회 연락"
  desc: string;               // 카드 설명 한 줄
  dollStance: string;         // 인형 초기 태도(프롬프트 주입) ← "상황별 페르소나"의 본체
  opening: string;            // 무대 시작 상태/오프닝 방향
  safety?: "high" | "normal"; // 위기 민감 코호트 강화 플래그(이별·짝사랑)
}
```
`dollStance` + `opening` + 프로필(관계·사주·MBTI·성격) + 상대 이름이 제네릭 인형 프롬프트에 주입돼 "그 상황의 그 사람"이 된다.

**스타터 8개** (관계당 2, 반응 테스트용 — 초안 seed. 최종 톤은 QA로 확정):

| id | 관계 | 라벨 | 인형 초기 태도(dollStance) | 오프닝 | safety |
|---|---|---|---|---|---|
| crush-confess | 썸 | 고백하기 | 아직 마음 확신 없음, 놀람+호기심 | 평범히 대화 중, 유저가 마음 꺼내려는 긴장 | normal |
| crush-firsttext | 썸 | 먼저 연락 | 무심·바쁠 수 있음, 답이 짧을 수 있음 | 오랜만/조심스러운 첫 톡 | normal |
| dating-hurt | 연인 | 서운한 거 말하기 | 몰랐다는/방어적 반응 가능 | 유저가 쌓인 서운함을 꺼냄 | normal |
| dating-makeup | 연인 | 화해하기 | 아직 감정 안 풀림, 뾰족할 수 있음 | 싸운 직후, 먼저 손 내밀기 | normal |
| onesided-approach | 짝사랑 | 다가가기 | 유저를 친구/지인으로 인식, 거리감 | 자연스러운 접점에서 말 걸기 | high |
| onesided-decide | 짝사랑 | 고백할지 말지 | 유저 마음 모름 | 저부담 고백을 시험 삼아 해보며 마음 확인 | high |
| breakup-reconnect | 이별 | 재회 연락 | 이미 정리한/경계하는 전 애인, 뜨뜻미지근 | 오랜만의 연락 | high |
| breakup-closure | 이별 | 미련·후회 정리 | 전 애인, 못 한 말의 상대 | 마지막으로 털어놓기 | high |

⚠️ **결정형 vs 리허설형**: "고백할지 말지"(onesided-decide)는 대화 연습보다 **결정 고민**에 가깝다 → seed를 "저부담 고백 리허설로 마음 확인"으로 잡아 인형 무대에 태우되, 반응이 약하면 **별콩이 스레드 상담으로 재라우팅**을 §11에서 검토.

## 5. 3화자 엔진

**격리 원칙**(E6 리스크 해소의 핵심): 인형과 별콩이는 **서로 다른 페르소나·다른 LLM 호출**. 한 모델이 둘 다 하면 차가운 인형 톤이 별콩이 코어(따뜻함)에 번지고 안전이 흔들린다.

- **인형 대사** = 인형 페르소나 호출. 시스템 프롬프트 = 제네릭 인형 base + 상황 seed(`dollStance`/`opening`) + 상대 프로필. **차갑게·회피·현실적 OK / 유해·잔인·자해조장 금지**(가드레일). 스트리밍 = `lib/claude` SSE 재사용.
- **별콩이 노트🌙** = 별콩이 페르소나 호출(코어 그대로). **둘 다 제공**:
  - **온디맨드(💭)** — 유저가 "별콩이 도움" 누를 때. 말문 트기부터 통찰까지. 판에 포함(무료, §7).
  - **자동 노트(스로틀)** — 별콩이가 알아서 관찰 노트. **매 턴 ❌**, ≈몇 턴마다/걔 반응이 바뀌는 주요 순간에만(원가·소음 관리). 트리거 휴리스틱은 구현 시 튜닝.
- **입력 컨텍스트**: 관계 memory(최근창 + 롤링 요약) 재사용. 최근창은 user 발화로 시작(Anthropic 규칙).
- **안전** = `lib/sensitive` 상시. high → **인형 내려놓고 별콩이 복귀 + hotline**(기존 재사용). 위기 대화는 서버측 강제 종료 없음(안전 > 원가), abs-cap `[END]` 억제.

## 6. 디브리핑

`정리하기` 또는 자연 수렴(`[END]`) → 인형 내려놓고 별콩이 복귀(밤 → 따뜻한 톤). **유료 판이라도 반드시 포함**(인형 침묵 종료 = 최악). 3블록:

1. **별콩이 통찰**(관찰형, 예측 ❌) — 이번 판에서 본 것 2~3개(걔 성향 + 너의 반응 패턴).
2. **💌 보낼 말**(강조) — 실제 상대에게 보낼 **한 문장** 제안(유저가 고쳐 쓸 수 있음).
3. **적립** — 판(상황 + 보낼 말)이 그 사람 파일에 저장(§8).

**동선 CTA**: `[💌 보낼 말 저장·복사]` + `[별콩이랑 더 얘기하기 → 스레드]`. (시뮬 → 디브리핑 → 스레드로 깊이)

## 7. 과금 (B안 — 단순화)

| 대상 | 방식 |
|---|---|
| 연애 상담(스레드) | **패스**(기존, 무변경) |
| **시뮬레이션 한 판** | **판 고정가 X별** — 연습 + 💭 코칭 + 자동 노트 + 디브리핑 + 보낼 말 **전부 포함** |
| 관계 슬롯 | **별도 별**(첫 사람부터, `slotAllowance`) |

- 🔴 **💭 코칭 별도 과금 폐지**(선행 스펙 §8에서 뒤집음). 근거: 끝에 무료로 주는 "보낼 말"과 중간 유료 "문구 추천"이 유저 눈엔 같은 문구 추천 → **대체재로 서로 잠식** + 감정 리허설 중 결제 벽은 마찰. → 판 하나에 다 넣고, 늘어난 원가(💭·자동 노트)는 **판 가격 X별에 흡수**.
- **무료 첫 판 없음** → **웰컴 20별**(`WELCOME_BONUS_STARS`)이 흡수하도록 **X < 20**. (구체값 §11, 코드 상수가 정본)
- 별 잔액은 항상 `lib/stars` 래퍼 경유(트랜잭션).
- ⚠️ **무발화 완충 관측 지표**: 무료 판이 없어 첫 행동이 결제(웰컴 별 차감)로 바뀐다. 구매 비율이 배포 후 첫 관측 지표 — 무너지면 "명시적 무료 체험" 부활 검토.

## 8. 저장 / 데이터

- **시뮬 판 = `reading`**(신규 데이터 아님). 보관함엔 "시뮬" 종목, 파일 허브엔 "그 사람" 필터로 자동(E1 §5: 정본 하나·진입 슬롯 여럿).
- 🔴 **신규 `consultation_type` 값**(예: `relationship_sim`) → **컬럼 폭 확인 필수**(AGENTS.md: `'relationship'`이 `VARCHAR(10)` 넘어 22001로 죽은 사례). CHECK 값 + 폭 같이.
- 판 메타(상황 id·보낼 말)는 reading에 부속(기존 memo/saju_data 패턴 참고).

## 9. 페르소나 파일 + QA

- `data/persona/` **코어 + 도메인 오버레이** 구조 따름:
  - **`byeolkong_sim.md`**(신규) — 별콩이의 시뮬 오버레이(노트 화법·프레임 고지·디브리핑·인형 내려놓기). 코어(`byeolkong_core.md`) 화법·안전·금지표현은 계승(복사 ❌ = 드리프트 방지).
  - **`doll_partner.md`**(신규, 별콩이 아님) — 제네릭 인형 base(역할극 규칙·차가움 허용·유해 금지 가드레일). 상황 seed·프로필이 주입되는 틀.
- **QA** — 별콩이 검증처럼 **QA 하네스로 상황별 샘플 판을 돌려 읽고** 엔진·seed 튜닝. 스타터 8개 각각 통과가 "올바름"의 증명. ⚠️ 페르소나 수정 후 dev 서버 재시작(모듈 캐시).

## 10. 신규 vs 기존

- **신규**: 상황 선택 화면 · 밤 무대 화면(접히는 인형·노트·밤 톤) · 디브리핑 화면 · `situations.ts`(seed 상수+스타터) · 제네릭 3화자 엔진(인형/별콩이 분리 호출 + 자동노트 스로틀) · `doll_partner.md`·`byeolkong_sim.md` · 판 고정가 결제 · 신규 `consultation_type`(+컬럼 폭)
- **기존 재사용**: `lib/claude` SSE · 관계 memory · 턴 한도/수렴 · `lib/sensitive` · `lib/stars` · `reading`/`messages` 저장·보관함 · `user_profiles`(partner: 사주·MBTI·성격) · 파일 허브(P2) · 슬롯(P1)

## 11. 이월 (구현 시 / 후속)

- **판 가격 X별 구체값**(X<20) · 자동 노트 트리거 휴리스틱 · 인형 색/에셋(프리셋 vs 정교)
- **게임성 장치** — 형식만(판·"다시"·카드). 승리 목표 금지 유지
- **onesided-decide 재라우팅** 여부(결정형 → 별콩이 스레드)
- **초상화 종합(ⓑ) = P3b** — 판 가로지른 별콩이 종합. 판 데이터 쌓인 뒤 별도 스펙
- **명시적 무료 체험 부활** — 구매 비율 관측 후 판단
