# 잔액 맞춤 충전 기본값 (실행 순서 ② 최소 버전) — 설계

- 날짜: 2026-10-05
- 상태: 사용자 승인 (2026-10-05)
- 근원: 로드맵 v2 Phase 2-② "잔액 기반 shop 제안" (`plans/2026-09-19-흑자전환-로드맵-v2-별마루배포포함.md` §Phase 2)
- 성격: **작은 개선**. 큰 레버(타로톡 질문 메뉴판 구조)는 이 뒤에 별도 설계한다. 이 변경은 메뉴판 구조로 바뀐 뒤에도 그대로 쓰인다(잔액 < 가격 순간은 계속 생긴다).

## 1. 왜

prod 실측(2026-08-10~10-04, 결제 179건, 지인 6명 제외):

| 패키지 | 결제 | 결제 직전 잔액 중앙값 | 직후 2시간 첫 소모 중앙값 | 부족분 ≤10 |
|---|---|---|---|---|
| star_10 ₩1,000 | 84 | 10 | 15 | 72 (86%) |
| star_30 ₩2,800 | 63 | 20 | 40 | 4 |
| star_70 ₩5,900 | 32 | 20 | 55 | 0 |

- 결제는 거의 전부 **"지금 할 것 − 잔액" 을 덮는 최소 패키지**다. star_150·300 은 0건.
- 기본 선택은 사람을 움직인다: star_30 으로 충분했던 15명이 /shop 기본값(star_70 '추천')을 따라 star_70 을 샀다. 반대로 필요와 동떨어진 기본값은 사람이 직접 내려 고른다(/shop 에서 star_10 직접 선택 62회).
- 지금 코드는 부족분을 모른다: `StarConfirmModal` 은 `cost - balance` 를 계산해 **보여주기만** 하고 넘기지 않는다. `RechargeSheet` 기본값은 늘 star_30, /shop 은 늘 star_70.
- 10-02 부터 타로 뽑기·운세 구매의 잔액 부족은 /shop 이 아니라 `RechargeSheet` 로 간다. 따라서 가장 흔한 경우(부족 5~10)는 이 변경 후에도 기본값 star_30 으로 **같다**. 이 변경이 실제로 바꾸는 것은 ①부족 13~36 일 때 기본값 star_30→star_70 ②"충전 후 ⭐N 남아" 표시로 손으로 star_10 내려 고르기를 줄이는 것.

## 2. 기본 선택 규칙

순수 함수 하나로 둔다(시트·/shop 공용, 유닛 테스트 대상).

```
입력: need(하려는 것의 가격), balance, bonusEligible(첫 충전 보너스 자격), packages(그 화면의 패키지 목록)
shortfall = need - balance
received(p) = p.stars + (bonusEligible ? round(p.stars × FIRST_CHARGE_BONUS_RATE) : 0)
min = packages 중 received(p) ≥ shortfall 인 가장 작은 패키지
default = min 의 바로 위 패키지. 단 star_70 이 상한 — 그러나 min 보다 작아지지는 않는다
  - min 이 star_70 이면 → star_70 / min 이 star_70 보다 크면(/shop 에서만 가능) → min
  - 어느 패키지도 못 덮으면 → 목록의 가장 큰 패키지
반환 null(= 화면의 기존 기본값 유지) 조건: need 나 balance 를 모름 · shortfall ≤ 0
```

- 보너스 반올림은 기존 화면 표시와 같은 방식을 쓴다(구현 시 `RechargeSheet`·/shop 의 현행 계산을 재사용해 어긋나지 않게).
- 예: 부족 5 → min star_10 → **star_30** / 부족 20 → min star_30 → **star_70** / 부족 50 → min star_70 → **star_70**
- star_10 은 숨기지도 지우지도 않는다. 기본 선택이 아닐 뿐이다(₩1,000 제거는 08-31 실측으로 철회된 안 — 재등장 금지).

## 3. 화면 변경

### 3-1. RechargeSheet
- 새 optional prop `need?: number` (하려는 것의 가격). 열릴 때 규칙 결과가 있으면 그걸 기본 선택, 없으면 현행 star_30.
- **남는 별 표시**: `need` 와 잔액을 둘 다 알 때만, 각 패키지 줄에
  - 덮는 패키지: "충전 후 이번 판 하고도 ⭐N 남아" (N = balance + received − need, 0 이면 "딱 맞아")
  - 못 덮는 패키지: "⭐N 모자라" (흐린 색)
- '추천' 배지·금테는 **기본 선택된 패키지**를 따라간다(지금은 star_30 고정).

### 3-2. 호출부 배선 (`need` 전달)
- 시트를 여는 곳은 각자 가격을 넘긴다: 타로 뽑기(`app/tarot/draw/page.tsx`) · 운세 구매(`components/fortune/FortunePurchasePanel.tsx`) · 궁합(`components/fortune/compat/CompatInput.tsx`) · 타로 리포트(`components/fortune/tarot/TarotInput.tsx`) · 대화 중 연장·한 장 더(`app/tarot/reading/page.tsx`, `app/(consultations)/saju/reading/page.tsx`).
- /shop 으로 보내는 `StarConfirmModal.onCharge` 경로는 `?need=<cost>` 를 붙인다: `ThreadDrawModal` · `ThreadChat`(모달 경로) · `useByeolmaruSubscribe` · `relationship/sim/page.tsx` · `sim/NightStage.tsx`. 기존 `reason` 파라미터는 유지(공존).

### 3-3. /shop
- `?need=` 가 있고 잔액을 불러온 뒤 규칙 결과가 있으면 그걸 기본 선택. 없으면 현행 star_70.
- 사용자가 이미 직접 고른 뒤에는 덮어쓰지 않는다(잔액 응답이 늦게 와도).
- /shop 에는 남는 별 표시를 넣지 않는다(이번 범위 밖 — 들어오는 경로 대부분이 `need` 를 모른다).

### 3-4. 첫 충전 배너 문구 버그
- `app/shop/page.tsx` `FirstChargeBanner` 부제 "처음 충전하면 별을 1.5배로 드려요" 는 07-20 보너스 50%→20% 때 안 바뀐 문구다. 제목·부제의 퍼센트를 `FIRST_CHARGE_BONUS_RATE` 에서 계산해 다시 어긋나지 않게 한다 (예: "처음 충전하면 별을 20% 더 드려요 (딱 한 번)").

## 4. 계측

- `recharge_sheet_opened` meta 에 `need`·`balance`·`defaultPackageId` 를 추가한다(시트·/shop 둘 다. 모를 때는 null).
- ⚠️ `meta.source` 는 그대로 둔다 — Meta CAPI AddToCart(`rechargeCapiEventId`)와 로드맵 KPI SQL 이 `source` 로 필터한다.
- 판정: `need` 를 알았던 결제에서 ①star_10 비중 ②결제 1건당 금액을 배포 전후 비교. 하루 결제 2~3건이라 최소 2~3주 모은다. 배포 전 기준선은 `recharge_package_selected`/`recharge_payment_started` 의 `packageId` 와 시트 source 로 이미 있다.
