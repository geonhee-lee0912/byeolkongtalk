# 별마루 ② — 구독 게이트 · 3일 체험 · 블러 · 출석 · 크로스셀 (2026-09-04)

부모 스펙 = `docs/superpowers/specs/2026-08-31-별마루-리텐션허브-design.md`(§5 무료/구독 경계 · §6 구독 상품 · §8 계측). 이 문서는 그 위에서 **② 단계의 구현 가능한 결정**을 확정한다. §5·§6에서 이미 확정된 것(경계 표·20별/30일·자동갱신 없음·D-3 배너·`good_days`/`one_card` 흡수)은 재론하지 않고 인용만 한다.

계획 ①(판정엔진·캘린더·탭재편·슬롯)·④(계측)는 이미 dev 배포·검증 완료. ② 는 그 위에 얹는다.

---

## 1. 범위

이 문서가 확정하는 것:
1. **게이트 원칙** — 무엇이 잠기고, 서버가 어떻게 판정하고, 비구독자에게 LLM 을 안 태우는 구조
2. **3일 체험** — opt-in 버튼, 글로벌 1회
3. **블러/페이월 UX** — 시안 C(첫 줄 맛보기)
4. **구독 상품 & 구매 플로우** — 20별/30일 user-스코프 구독, star 인프라 재사용
5. **출석 & 보상** — 체크인 버튼(전 유저 습관) + 구독 연동 20/30 → 10별
6. **크로스셀 배너** — 위치·형태
7. **데이터 모델** — 신규 테이블 2 + `users` 컬럼 1

범위 밖(다른 단계): 우리 오늘 콘텐츠(③) · `good_days`/`one_card` 폐지(⑤) · 정적 콘텐츠 생성(⑥). 게이트는 **표면 무관(surface-agnostic)** 으로 짜서 ③의 우리 오늘·택일이 나중에 끼워지기만 하면 되게 한다.

---

## 2. 게이트 원칙

### 자격(entitlement) 정의

> **`entitled(user) = withinTrial(user) OR hasActiveSubscription(user)`**

- `withinTrial(user)` = `users.byeolmaru_trial_started_at IS NOT NULL AND now() < byeolmaru_trial_started_at + interval '3 days'`
- `hasActiveSubscription(user)` = `byeolmaru_subscriptions` 에 `expires_at > now()` 행 존재

### 🔴 비-자격자에게 LLM 을 태우지 않는다 (원가 0 유지 = §5 핵심)

- **자격자**(체험 중 or 구독 중): 개인화 LLM 서술을 실제 생성해 보여준다. 체험 3일의 LLM 원가는 §5가 수용한 "체감 필수 장치" 비용이다.
- **비-자격자**: 개인화 엔드포인트를 **호출하지 않는다.** 무료 정적 콘텐츠 + 블러(정적 티저) + CTA 만 렌더. 서버는 개인화 API 를 `gated` 플래그로 즉시 반환(LLM 미호출).

### 서버 권위

- 캘린더/데일리 API(그리고 나중의 우리오늘·택일 API)는 응답에 `entitled: boolean` 을 실어 보낸다. 클라는 이 플래그로 블러/CTA 를 렌더할 뿐, 자격을 스스로 판정하지 않는다.
- 개인화 서술 생성 라우트는 **진입 시 `entitled` 를 서버에서 재검증**한다(클라 우회 방지). 비-자격이면 402/`gated` 반환, LLM 미호출.
- 자격 판정은 공용 헬퍼 `lib/byeolmaru/entitlement.ts`(가칭) 단일 원천 — 표면마다 재구현 금지(drift 방지).

## 3. 3일 체험 — opt-in 버튼 · 글로벌 1회

### 트리거

- **명시 버튼 "3일 무료 체험 시작"** — 블러 영역의 CTA. 자동 시작 아님.
- 클릭 시 `users.byeolmaru_trial_started_at = now()` 1회 기록. 이미 값이 있으면(체험 소진) 버튼은 노출되지 않고 "구독 20별/30일" CTA 로 대체.
- **글로벌 1회**: 한 번의 체험이 모든 개인화 블록(서술·우리오늘·택일)을 3일간 전면 개방. 블록별 별도 체험 아님.
- **대상**: 신규·기존 147명 구분 없음. `byeolmaru_trial_started_at IS NULL` 이면 누구나 자격. (기존 유저 passive 소진 문제 없음 — 트리거가 클릭이라.)

### 선행 조건

- 개인화는 내 사주(primary)가 필요 → 비로그인·사주 없음이면 버튼이 **로그인/사주 입력으로 먼저 보낸다**(계획 ①의 `need_login`/`no_profile` 상태·라우트 재사용).

### 만료

- `trial_started_at + 3일` 경과 → 다시 블러, CTA 가 "구독"으로 교체. 재체험 없음(1회성).

## 4. 블러/페이월 UX — 시안 C (첫 줄 맛보기)

무료/유료가 한 카드 안에 위아래로 공존한다(오늘 상세 카드 기준):

1. **무료 정적 해석** — 전부 노출(등급·축·정적 카드 해석)
2. **개인화 잠금 영역**(비-자격 시):
   - 🔒 라벨 "별콩이의 개인화"
   - **선명한 첫 줄** = 일간×일진 룰 기반 **정적 문장 1줄**(LLM 아님, §5 일진 조각 뱅크). 예: "오늘 너의 일간(辛)으로 보면, 먼저 손 내미는 쪽이 흐름을 쥐는 하루야."
   - 이어지는 줄은 **fade-out**(mask-image 그라데이션) 처리 → "이어서 더" 호기심
   - 하단 CTA: 미체험 → "3일 무료 체험 시작" / 체험 소진 → "구독 20별 · 30일"
- **자격 시**: 잠금 영역이 실제 LLM 개인화 서술 전문으로 대체.

기각: 시안 B(가짜 문단 블러) — 별콩이 정직·따뜻 톤과 충돌 + devtools 로 가짜 노출. 시안 A(맛보기 없는 클린 잠금)는 최소안으로 보류.

⚠️ 첫 줄 정적 문장은 ⑥(정적 콘텐츠 생성)에서 일진 조각 뱅크로 함께 만든다. ② 구현 시엔 룰 폴백 문장으로 시작해도 된다.

## 5. 구독 상품 & 구매 플로우

§6 확정 인용: **20별 / 30일 · 별 결제 · 자동갱신 없음 · 만료 D-3 배너 + 재잠금.**

### 저장 = 전용 user-스코프 테이블 (relationship_passes 재사용 안 함)

- `relationship_passes` 는 relationship 스코프(`relationship_id` 필수, 활성 체크가 `WHERE relationship_id=?`)라 user-스코프 구독엔 부적합. "PASS_PLANS 패턴 확장"은 **패턴(별 결제·기간권·star 인프라)** 을 따르되 **테이블은 신규**로 간다(기존 관계 로직 오버로드 금지).
- 신규 테이블 `byeolmaru_subscriptions`(§8).
- 상수: `lib/constants.ts` 에 `BYEOLMARU_SUBSCRIPTION = { cost: 20, days: 30 }`.

### 구매 RPC

- 신규 `purchase_byeolmaru_subscription(p_user_id, p_cost, p_days)` — `purchase_relationship_pass` 패턴 그대로: `star_balances` `SELECT FOR UPDATE` → 잔액 검사 → 차감 → `star_transactions` audit(`source='byeolmaru_subscription'`) → `byeolmaru_subscriptions` 행 insert(`expires_at = now() + p_days`) → 활성 구독이 남아 있으면 그 `expires_at` 뒤에 이어붙임(관계 패스의 연장 로직과 동일).
- `SECURITY DEFINER` + `REVOKE … FROM PUBLIC, anon, authenticated` + `GRANT … TO service_role`(AGENTS.md 규칙). 앱은 `lib/stars` 계열 래퍼 경유.

### 구매 UI

- 기존 **`StarConfirmModal` 재사용**(20별 확인). 잔액 부족 시 기존 충전 시트(`RechargeSheet`)로 연결 — 신규 결제 UI 0.

### 갱신·만료

- 자동갱신 없음. `expires_at - 3일`부터 별마루 상단에 **D-3 배너**("구독 만료 D-3 · 지금 이어가면 흐름이 안 끊겨"). 만료 시 개인화 영역 재잠금(자격이 false 로 자연 전환).

## 6. 출석 & 보상

§6 확정 인용: **30일 출석 = 10별(구독료 절반). 보상 ≥ 구독료면 매출 붕괴.**

### 출석 버튼 (전 유저 · 습관 장치)

- 별마루 상단에 **명시 체크인 버튼**. 하루 1회, 그날 첫 클릭이 `byeolmaru_checkins`(user_id, checkin_date) 행 upsert.
- 진행 가시화: "12일째 · 20일 채우면 10별"(구독자) / 비구독자는 스트릭만("12일째") — 습관 표시는 전 유저, **10별 보상은 구독자에게만**.
- 출석 정의 = 버튼 클릭(방문 자체 아님). 데일리 습관 제품에선 탭 1회가 마찰이 아니라 리추얼.

### 보상 (A안 — 구독 연동, 제공형)

- **카운트 창 = 활성 구독 기간**. `byeolmaru_checkins` 중 `checkin_date` ∈ `[subscription.started_at, expires_at]` 인 distinct 일수.
- **구독 30일 중 20일 이상 출석 → 10별 지급**(임계 20/30 — 부모 스펙의 "30일 출석"을 달성 가능한 20/30 으로 구체화). 매일(30/30)은 대부분 실패 → 당근 사망. 2/3 은 습관 유저면 자연 달성.
- **지급 시점 = 만료 시, 무조건**(재구독 조건 아님). 이게 재구독 반값 쿠폰이 되어 **재결제배수(1.53→2.0)** 를 직접 때린다(2차 목표의 유일 경로).
- **지급 방식 = lazy grant**(크론 없음): 유저가 만료 후 다음 진입 시, 방금 만료된 구독이 20일 달성 & 미지급이면 `charge_stars(10, …)` 로 지급. 멱등 = `byeolmaru_subscriptions.reward_granted_at` 플래그(중복 지급 차단). `charge_stars` 자체도 reward 키로 멱등.
- free 유저에겐 별(=원가) 안 뿌림 → A안 유지.

## 7. 크로스셀 배너

3rd-party 광고는 붙이지 않는다(별도 판정: 퍼널 지면 · 원가경제 · 브랜드 · 웹 플랫폼 이유로 net-negative). 자사 크로스셀만 얹는다.

### 위치

- **하단 브라우즈 존** — `30일 흐름` 아래, `우리 사이 슬롯` 위. 핵심 전환 CTA(오늘 상세)와 **주목도 경쟁 없음** + "이왕 온 김에" 존.

### 형태 = 별콩이 컨텍스트 추천 카드 (정적 배너 아님)

- 오늘 흐름·시즌·미경험 상품 기반 **로테이션**. 룰 예: 관계 축 높은 날 → 타로/우리 궁합, 재물 축 → 사주 리포트, 10~11월 → 신년운세, 이미 산 상품은 제외.
- "이 흐름이면 이것도 봐"는 별콩이 안내자 톤 → 광고가 아니라 추천으로 읽힘 + 배너 블라인드니스 회피.
- 규칙은 `lib/byeolmaru/crosssell.ts`(가칭) 순수 함수(입력=오늘 판정·유저 보유 상품·날짜, 출력=추천 1개). 마이그레이션 0.

## 8. 데이터 모델

| 대상 | 스키마 | 용도 |
|---|---|---|
| `byeolmaru_subscriptions` (신규) | `id · user_id(FK ON DELETE CASCADE) · started_at · expires_at · stars_spent · reward_granted_at NULL · created_at` | user-스코프 구독. 활성 = `expires_at > now()` |
| `byeolmaru_checkins` (신규) | `user_id · checkin_date DATE · PRIMARY KEY(user_id, checkin_date)` | 출석(전 유저 습관 + 보상 카운트) |
| `users.byeolmaru_trial_started_at` (신규 컬럼, TIMESTAMPTZ NULL) | — | 3일 체험 1회성 시작 시각 |

- 재사용(신규 아님): `star_balances` · `star_transactions` · `charge_stars`/`spend_stars` RPC · `lib/stars` 래퍼.
- 🔴 `users(id)` 참조 FK 는 **`ON DELETE CASCADE` 명시**(AGENTS.md — 미명시 시 탈퇴가 23503 으로 차단).
- 신규 테이블은 `ENABLE RLS`(기본 권한이 닫혀 있어도 이중 방어). 신규 RPC 는 REVOKE 3종 + service_role GRANT.

## 9. 계측

계획 ④ 이벤트 재사용: `byeolmaru_day_selected` · `slot_clicked` · `no_profile` · `need_login`.

② 추가(§8 부모 스펙의 "블러 노출 → CTA 클릭 → 구독 시작" 퍼널) — `lib/analytics/ui-events.ts` allowlist 에 추가:
- `byeolmaru_gate_shown` — 블러(잠금 영역) 노출, 리딩/일자당 1회(재노출마다 찍으면 과대집계 — ④의 리딩당 1회 규율 동일)
- `byeolmaru_trial_started` — "3일 무료 체험 시작" 클릭
- `byeolmaru_subscribe_clicked` — 구독 CTA 클릭
- `byeolmaru_subscribe_completed` — 구독 결제 완료(meta: stars)
- `byeolmaru_checkin` — 출석 버튼(meta: streak)
- `byeolmaru_crosssell_clicked` — 추천 카드 클릭(meta: product)

어드민 집계(`/admin/free/byeolmaru`)에 구독 퍼널 섹션은 이 이벤트가 쌓인 뒤 별도 추가(② 범위 밖, 후속).

## 10. 화면 구성 순서 (별마루 세로 스택)

1. 헤더(별마루 · 오늘 간지)
2. **출석 체크인 버튼 / 스트릭** (신규)
3. 30일 캘린더 그리드 (①)
4. 오늘 상세 카드 — 정적 해석 + 개인화(자격 시 전문 / 비자격 시 시안 C 블러 + CTA) ← **핵심 전환**
5. 앞으로 30일 흐름 (①)
6. **별콩이 추천 카드**(자사 크로스셀) (신규)
7. 우리 사이 · 시뮬 슬롯 (①)
8. (구독 D-3 배너는 만료 임박 시 상단 고정)

## 11. 폐지 연동 (⑤ 참조)

`one_card`(10별) 폐지는 **별마루 배포와 동시**(무료 원카드가 대체, §6). `good_days`(35별) 폐지·구독 흡수도 동시. 이 문서(②)에서 구현하지 않고 ⑤에서 배포 직전에 스위치. ② 설계는 그 전제(원카드·택일이 별마루 안에 있음)를 가정한다.

---

## 12. 미결 / 구현(plan) 에서 확정

1. **개인화 서술 엔드포인트의 현재 위치** — 오늘 상세의 LLM 서술이 이미 어느 라우트에서 생성되는지 확인 후 게이트 삽입 지점 확정. (없으면 신규 라우트, 있으면 `entitled` 가드만 추가.)
2. **첫 줄 정적 문장 뱅크** — ⑥ 전이면 룰 폴백 1줄로 시작. ⑥에서 일진 조각 뱅크로 교체.
3. **크로스셀 로테이션 룰의 상품 매핑** — 축↔상품 대응표는 구현 시 확정(초기엔 사주 리포트·타로 2종 + 시즌으로 시작).
4. **D-3 배너 카피 / 출석 진행 UI 문구** — 카피 라이팅은 구현 시.
