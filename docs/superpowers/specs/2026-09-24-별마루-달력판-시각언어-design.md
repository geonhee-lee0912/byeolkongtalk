# 별마루 달력 판 — 시각 언어 재설계 (2026-09-24)

허브(`/byeolmaru`) 달력 판 **전체**. 두 표면(7일 스트립 · 월간 격자)을 한 설계로 잡는다.

> **개정 이력.** 1차 설계는 "스트립 = 막대 높이 / 격자 = 양방향 채도"였고 dev 에 배포까지 갔다. 실물을 보고 사용자가 기각했다 — *"차이가 이해가 안 갈 것 같다. 한 달치는 색이 진하면 좋은 건지 뭔지 모르겠다."* 정확한 지적이다. **양방향 채도의 근본 결함은 "진하다"가 두 방향을 동시에 뜻한다는 것**이고, 막대 높이도 "높다=좋다"를 학습해야만 읽힌다. 2차 설계는 **점수를 숫자로 직접 보여준다.**

## 1. 왜 (실물 감사, 375×812 구독자 계정)

| # | 결함 | 근거 |
|---|---|---|
| ④ | **오늘이 시각적 1순위가 아니다** | 톤 색면이 위계를 이긴다. 9/24(무난)보다 9/23(잘 맞는 날·금색)이 강해 보였다 |
| ⑤ | **칸 2/3이 같은 색** | 5,400칸: normal **64%** · caution 19% · good 17%. 마크 없음 65% |
| ⑥ | **칸이 좁다** | 실측 스트립 **35×101px** · 격자 **41×41px** |
| ⑦ | **마크의 뜻이 어디에도 없다** | 범례가 셀 칩과 같은 모양·같은 글자라 반복일 뿐 |
| ⑨ | **신호가 뭘 뜻하는지 학습이 필요하다** | 2차 추가. 색 농도·막대 높이는 규칙을 아는 사람만 읽는다 |

⑥ 보충: WCAG 2.5.8(AA) 최소 타깃은 24×24px이라 **규격 위반은 아니다.** 44px는 HIG·Material 권장치이고 실제 문제는 옆 칸 오타.

## 2. 되살리지 말 것 (재검증 완료)

- **스트립 범위(지난 3 + 오늘 + 앞 3)는 자의적이지 않다.** [`strip.ts`](../../../lib/byeolmaru/strip.ts) `STRIP_LENGTH = STRIP_PAST_DAYS + 1 + FUTURE_REPORT_DAYS`. 미래 칸 수는 리포트 생성 가능 일수(3)와 반드시 같아야 한다 — 어긋나면 "흐려서 눌러본 칸"이 `out_of_range`로 거절된다.
- **과거 칸이 "그날은 리포트를 안 받았어"로 가는 건 정책이다** ([`report-date.ts`](../../../lib/byeolmaru/report-date.ts) — 소급 생성 금지).
- **"이번 주 월~일 고정"은 이미 기각된 안이다** (요일 기준이면 흐린 칸이 월 6개~토 1개로 출렁인다).
- **격자 셀에 동물을 넣지 않는다.** P5 가 42px 칸에 4겹을 넣었다가 *"제일 큰 요소(동물)가 의미를 안 담고 진짜 내용이 제일 약했다"*며 뺐다. 🔴 단 **스트립에는 동물이 돌아온다**(2차) — 거긴 칸이 두 배 넓고, 이제 제일 큰 요소가 **점수 숫자**라 P5 가 걸렸던 구조가 아니다.
- **원점수(raw score)를 화면에 쓰지 않는다** — §4.

## 3. 역할 분담

| | 답하는 질문 | 주 신호 | 보조 |
|---|---|---|---|
| 7일 스트립 | 오늘 뭐지? / 앞뒤 며칠은? | **점수 숫자** | 면 색(톤) · 마크 칩 · 동물 |
| 월간 격자 | 이번 달 어느 날이 눈여겨볼 날인가 | **점수 숫자** | 면 색(찾기) |

🔴 **숫자는 "얼마나", 색은 "찾기".** 색이 정확한 값을 말하려 들면 학습이 필요해진다(1차 실패). 색은 훑을 때 시선을 끄는 역할만 하고, 판독은 숫자가 한다.

🔴 **마크는 스트립에만.** 격자 44px 칸에 날짜·숫자·칩 3층을 넣으면 숫자가 죽고, 숫자 색으로 마크를 인코딩하는 안은 대비가 깨진다(§7 계산). 격자는 "언제", 스트립은 "오늘 근처 + 왜".

## 4. 눈금 = 모집단 백분위 0~100

🔴 **원점수를 그대로 쓰면 안 된다.** 모집단 중앙이 56점이라 대부분의 날이 "56"으로 뜨고, 그건 학교 점수 프레임에서 낙제로 읽힌다 — 실제로는 딱 평균인 날인데.

앵커는 **12,960칸 실측**(60갑자 교차 표본 × 30일):

```
p0=12  p5=32  p10=38  p20=46  p30=48  p40=51  p50=56
p60=58 p70=63 p80=68  p90=73  p95=78  p100=92
```

- 표시값 = `Math.round(scorePercentile(score) * 100)` — `lib/byeolmaru/calendar-visual.ts` 의 `scorePercentile` 재사용(계약 테스트 있음)
- **고정 스케일**이다 — 같은 점수는 언제나 같은 표시값. 주 안에서 min~max 를 늘리는 상대 스케일은 나쁜 주와 좋은 주를 똑같아 보이게 해서 기각
- `day-score.ts` 가중치가 바뀌면 앵커 표를 다시 뽑을 것

⚠️ 백분위는 정의상 **절반이 50 미만**이다. 낮은 숫자를 매일 보여주는 것이 "불안 자극 금지" 원칙에 닿을 수 있다는 점을 사용자에게 알렸고, 이해도를 얻는 대가로 감수하기로 결정했다.

## 5. 표면 A — 7일 스트립

```
오늘 · 내 결대로 가는 날                      3일 연속 들르는 중
┌─────┬─────┬─────┬───────────┬─────┬─────┬─────┐
│  월  │  화  │  수  │     목     │  금  │  토  │  일  │  ① 요일 10px
│  21 │  22 │  23 │     24    │  25 │  26 │  27 │  ② 날짜 12px
│  ●  │  ●  │  ●  │     ●     │  ●  │  ●  │  ●  │  ③ 동물 14px
│  64 │  64 │  86 │     66    │  40 │  40 │  70 │  ④ 점수 17px bold
│     │ 채움 │ 척척 │           │     │ 삐걱 │ 설렘 │  ⑤ 마크 칩 9px
└─────┴─────┴─────┴───────────┴─────┴─────┴─────┘
```

🔴 **오늘은 폭과 배경만 다르다. 내부 구성품 크기는 7칸 전부 동일하다** — 오늘만 키우면 다섯 줄이 가로로 안 맞아 판이 어긋나 보인다(사용자 지적).

| | 값 |
|---|---|
| 트랙 | 8 (오늘 `span 2`) — 기존 레이아웃 복귀 |
| 칸 | 일반 38px · 오늘 76px |
| 칸 패딩 | `10px 0 8px` · 줄 간격 `gap 4px` |
| 요일 / 날짜 / 동물 / 점수 / 칩 | 10 / 12 / 14 / 17 bold / 9 |
| 오늘 | `#5A3E8C` 면 + 흰 글자 (대비 8.4) |
| 마크 없는 날 | 칩 자리에 **15px 스페이서** — 행 정렬 유지 |

- 🔴 `잔잔`(신호 없음 라벨)은 **기각됐다.** 65%에 뜨는 칩이 나머지 넷을 덮는다. 빈 자리 + 스페이서로 간다
- 미래 잠긴 칸(비구독)은 점선 유지. 점수 자리는 비운다 — 없는 걸 있는 척하지 않는다

## 6. 표면 B — 월간 격자

```
이번 달 · 잘 맞는 날 11일 · 23일                        ▾
 일   월   화   수   목   금   토      ← 토·일 lilac-deep
        1    2    3    4    5        날짜 10px 옅게
       50   50   50   52   42        점수 16px bold
```

| | 값 |
|---|---|
| 칸 | 43.9 × 43.9 정사각 (main `p-4` → 판 `p-3` → `gap 2px`) |
| 날짜 | 10px, `rgba(122,107,160,.6)` — 좌표라 뒤로 물린다 |
| 점수 | 16px bold, `#5A3E8C` (금색 칸은 `#412402`) |
| 오늘 | `#5A3E8C` 면 + 흰 글자 |
| 면 색 | 양방향 채도 — 보라 `0.11~0.30` / 금색 `0.45~0.65` |
| 마크 칩 · ✦ 별 글리프 · 하단 범례 | **전부 없음** |

- 🔴 채도 상한을 1차(보라 0.55 / 금 0.95)보다 낮췄다 — 숫자가 주 신호가 됐으니 면은 약해도 되고, 진한 면 위에서 숫자 대비가 깎이는 걸 막는다. `#5A3E8C` on 보라 0.30 = **6.29**, `#412402` on 금 0.65 = **10.09**
- 🔴 **알파 바닥 0.11 은 유지**한다 — 판이 흰색(`PANEL_BG`)이라 그 아래로 내려가면 칸이 사라진다. 두 번 되돌린 이력이 `CalendarGrid.tsx` 주석에 있다
- ✦ 별을 빼는 이유: 숫자가 `88` 이면 이미 좋은 날이라고 말한다. 중복

## 7. 마크 칩 — 솔리드

셀 배경·글자 색에 좌우되지 않도록 **칩 자체가 색면**을 갖는다.

| 마크 | 배경 | 글자 | 대비 |
|---|---|---|---|
| 설렘 | `#E8C26A` (gold 토큰) | `#412402` | 8.36 |
| 척척 | `#2A6B62` | `#ffffff` | 6.22 |
| 삐걱 | `#73264A` | `#ffffff` | 9.98 |
| 채움 | `#6B4BA8` | `#ffffff` | 6.57 |

칩 규격: `font 9px` · `line-height 12px` · `padding 2px 5px 1px` · `radius 8px`

🔴 **설렘만 밝고 글자가 어두운 건 의도다.** 넷 다 흰 글자로 통일하려면 설렘의 명도를 `L ≤ 0.183` 까지 내려야 하는데(흰 글자 AA 하한), 그 지점(`#8F6710`)에서 **삐걱과 상호대비가 1.96 으로 붙는다** — 지금 값은 5.87 이다. "밝은 금색 + 흰 글자"는 존재하지 않는 조합이다. 골드+어두운 글자는 이 앱이 "잘 맞는 날" 칸에서 이미 쓰는 패턴이다.

🔴 옛 `MARK_COLOR` + `MARK_TINT`(연한 틴트 배경 + 고정 어두운 글자)는 이 표로 **대체**된다. 틴트 4종은 서로 너무 비슷했다.

## 8. 1차에서 걷어낼 것

- `barHeightPx` · `barColor` 와 스트립 막대 렌더 전부
- 격자 ✦ 별 글리프
- 격자 마크 칩(이미 없음) · 하단 범례(이미 제거됨)
- `cellTint` 의 옛 알파 범위(보라 0.55 / 금 0.95)

`scorePercentile` 과 앵커 표는 **그대로 쓴다** — 2차의 눈금이 곧 그 함수다.

## 9. 구현 순서

1. `calendar-visual.ts` — 막대 제거, `scoreDisplay(score)` 추가, `cellTint` 알파 범위 조정, 칩 팔레트 `MARK_CHIP` 추가
2. `day-label.ts` — `MARK_COLOR`/`MARK_TINT` → `MARK_CHIP`(배경·글자 쌍) 교체. 소비처는 `DayStrip`·`DayDetailCard`·`PairDayDetailCard`
3. `DayStrip.tsx` — 막대 제거, 동물·오늘 2배 폭 복귀, 점수 숫자, 솔리드 칩, 내부 크기 통일
4. `CalendarGrid.tsx` — ✦ 제거, 날짜 축소 + 점수 숫자
5. 실물 검증

## 10. 검증

1. `npx tsc --noEmit` · `npm run build` · 유닛 전체
2. 375×812 구독자(`11111111-1111-4111-8111-111111111111`)
   - 스트립 다섯 줄이 7칸에 걸쳐 **가로로 한 선에** 서는가
   - 칸 폭 실측 — 스트립 일반 38 / 오늘 76 / 격자 43.9
   - 격자에서 무난한 날 칸이 흰 판 위에서 사라지지 않는가
   - 마크 없는 주에서 칸 높이가 균일한가
   - 칩 4종이 서로 구분되는가 (특히 설렘↔삐걱)
3. 비구독 — 미래 3칸 점선, 점수 자리 비어 있음
4. 게스트(`EmptyMonthShell`) 렌더
5. 상세 카드(`DayDetailCard`)의 마크 칩이 새 팔레트로 바뀌었는가
