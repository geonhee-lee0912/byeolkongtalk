## 1. 왜

가입 1명을 데려오는 값(~₩380)이 가입 1명당 매출(~₩230)보다 크다. 광고를 키울수록 손해가 커진다 — 10-04~09 실측: 광고비 2.1배 → 가입 1.46배 → 매출 그대로. 고칠 수 있는 손실 하나가 입구의 로그인 문턱이다.

prod 실측(09-13~10-10, 인스타 인앱 = 유료 유입 대부분, 지인·봇 제외):
- 홈 태그를 누르자마자 로그인 화면이 뜬다. 이 화면을 본 1,292명 중 **30% 는 카카오에서 돌아오지 않았다**(버튼을 안 눌렀거나 카카오 화면에서 나감 — 지금은 둘을 못 가른다). 4% 는 돌아왔지만 실패(아무 안내 없이 홈으로). 64% 로그인
- 유료 방문자의 ~28% 가 이 화면에서 나간다 ≈ 광고비의 ~28%
- 인앱 67.5% vs 일반 브라우저 76.6%(n=47) — 차이 미유의. 기술 고장보다 '로그인 자체를 안 함'
- 로그인 화면엔 "먼저 인사부터 할까?" + 기록 저장 안내뿐 — **첫 풀이가 무료라는 말이 없다**

방향: 로그인을 '가장 궁금한 순간'(뽑은 카드를 본 직후)으로 옮긴다.

## 2. 범위

**안**: 홈 태그 → 고민 → 메뉴(또는 스프레드 고르기) → 뽑기 → **카드 공개 + 로그인 창** → 로그인 뒤 자동 이어가기 · 진행 저장(로그인·결제·나중에) · 로그인 실패 안내 · 다시 온 회원 안내 · 고민 화면 위기 배너 · 계측 · 반반 판정 도구

**밖**: 이미 로그인한 회원 흐름 · 광고 랜딩 `/start` · 연애 상담 `/relationship` · 사주 운세 구매 · 별마루 로그인 · 로그인 전 AI 풀이(필요하면 이 판정 뒤) · 옛 로그인 화면 문구 개선(판정 동안 대조군 고정) · 서버측 진행 저장 · 다른 브라우저로 돌아오는 OAuth(csrf) 개선(~2%)

## 3. 새 흐름 (로그인 안 한 방문자 · 새 흐름 그룹)

1. **홈 태그** → 로그인 화면 없이 `/concern`. 다음 버튼 근처에 작은 안내: "풀이는 카카오로 3초 시작하면 바로 볼 수 있어"
2. **`/tarot`** — 판정 승자 화면(메뉴판 또는 스프레드 고르기). 가격은 '가입 선물 15별을 막 받은 신규 회원' 기준(§3-1)
3. **`/tarot/draw`** — 뽑기 의식 그대로 → 완료 → **카드 공개**: 슬롯의 카드가 앞면으로 뒤집히고 카드 이름·정/역 표시. 의미·키워드는 보여 주지 않는다(궁금증 유지)
4. 공개 ~1초 뒤 **로그인 창**(아래에서 올라오는 시트, 카드는 뒤에 보인다)
   - 제목 "카드는 뽑혔어 ✨" · 본문 "이 카드가 '{고민 앞 20자}…'에 뭐라고 하는지, 별콩이가 바로 풀어줄게"
   - 버튼 [카카오로 3초 시작] · 그 아래 "뽑은 카드는 그대로 이어져"
   - 가격 줄: 선물로 되는 상품 = "첫 풀이는 가입 선물로 무료" / 넘는 상품 = "가입 선물 15별 + ⭐N만 더 (₩X)"
   - 작은 줄: "이미 가입했다면 남은 별로 이어져 (가입 선물은 처음 한 번)"
   - [나중에 할래] → 시트만 닫고 카드는 화면에 남김 + 하단 고정 버튼 "로그인하고 풀이 보기"(시트 다시 열기)
5. **카카오 왕복 뒤 `/tarot/draw?resume=1`** 로 돌아와 버튼 없이 이어간다
   - 저장된 진행을 복원 → 지금의 '뽑은 뒤' 단계(지갑 → 가격 → 바로 풀이 / 확인 팝업 / 충전)를 그대로 탄다
   - 신규 가입(15별): 메뉴판이 승자 + 맛보기(동의 있음) = 바로 풀이 / 옛 화면이 승자 = 확인 팝업 한 번
   - 선물을 넘는 상품: 확인 팝업(잔액 부족) → 충전 시트(모자란 만큼 기본 — 잔액 맞춤 ②) → 결제 다녀와도 진행 복원
   - 다시 온 회원 + 별 부족: §4
   - 로그인 실패: §5-4
   - 신규 가입이면 막지 않는 토스트 "가입 선물 15별 받았어"
6. **홈 이어가기**: 저장된 진행이 있으면(7일 안) 홈 태그 위에 한 줄 "아까 뽑은 카드가 기다리고 있어 → 이어서 보기" → `/tarot/draw?resume=1`

문구는 전부 초안 — 구현 계획 단계에서 사용자 검수.

### 3-1. 로그인 전 가격 표시

- 표시용 지갑 = `{ balance: WELCOME_BONUS_STARS, giftUnused: true, menuArm: menuArmOf(null) }` + `guest: true`
- 메뉴판이 승자: `priceLine`(`lib/tarot/menu-price.ts`) 그대로 쓰되 guest 면 "선물로 무료" → "가입 선물로 무료", "선물 쓰면 ⭐N만 더" 옆에 "(₩X)"
- 옛 화면이 승자(`SpreadPicker`): "⭐N별" 아래 guest 한 줄 — N ≤ 15 "가입 선물로 무료" / 넘으면 "가입 선물 + ⭐(N−15)만 더 (₩X)"
- ₩X = 모자란 만큼을 덮는 가장 작은 진열 패키지 값 — 잔액 맞춤 ②와 같은 규칙(그 함수를 쓴다)
- 서버 가격은 손대지 않는다. `MENU_AB` 를 승자로 고정한 뒤라 로그인 전후 가격이 같다 → expectedCost 409 가 안 난다

## 4. 다시 온 회원 (결정 A)

- 실측: 로그인 화면을 거쳐 로그인한 930건 중 98건(10.5%)이 기존 회원 재로그인. 그중 86% 가 별 15 미만(1~14 가 70명)
- 복원(resume) 경로의 '뽑은 뒤' 단계에서 `잔액 < 가격` 이고 `giftUnused === false` 면 확인 팝업에 "다시 와줘서 반가워! 가입 선물은 처음 한 번뿐이라 ⭐N이 더 필요해" + 충전(모자란 만큼 기본). 카드는 그대로
- 돈 흐름은 지금과 같다(무료 지급 없음)

## 5. 구조

### 5-1. 스위치와 그룹

- `lib/tarot/entry-ab.ts`(순수·클라 안전) — `ENTRY_AB: "old" | "split" | "new"`, 기본 **"old"** · `entryArmOf(anonId)` = 끝 글자가 `02468ace` 면 "new", 아니면 "old"(메뉴판 판정과 같은 모양, 저장하지 않음)
- 🔴 **가드**: `MENU_AB === "split"` 이면 `entryArmOf` 는 항상 "old". 반반 중엔 로그인 전 가격(옛 그룹)과 로그인 뒤 가격이 어긋난다. 계약 테스트로 고정
- 그룹 전달: `/api/stars/balance` 비로그인 응답에 `entryArm` 추가 — 서버가 `byeolkong_anon_id` 쿠키로 계산. 홈은 로그인 안 한 방문자일 때 마운트 즉시 지갑을 읽는다. 못 읽었거나 응답 전에 태그를 눌렀으면 옛 흐름(분석은 배정 기준 — 노출 어긋남은 `home_tag_clicked.armKnown` 으로 잰다)
- 뽑기 화면의 공개 + 로그인 창은 `isGuest && entryArm === "new"` 일 때만. 그 밖의 비로그인(옛 흐름 그룹이 세션 만료 등으로 들어온 경우)은 지금 동작 그대로 — 대조군 불변
- `proxy.ts` 는 건드리지 않는다

### 5-2. 진행 저장

- localStorage `byeolkong:pending_draw` = `{ v: 1, emotion, concern, spreadType, spreadCategory, consented?, drawnCards, savedAt }`
- 쓰기: 뽑기 완료 시 — 비로그인은 공개 직전, 회원은 충전 시트로 갈 때
- 읽기: `/tarot/draw` 마운트 — `?resume=1` 이거나 지금 선택(spreadType·concern)과 일치하면 의식을 건너뛰고 공개 / '뽑은 뒤' 단계로
- 지우기: 대화로 넘어갈 때(`goToReading`) · 7일 경과 · 로그아웃·탈퇴
- 복원 시 기존 sessionStorage 키(`TAROT_SPREAD_KEY`)를 다시 채워 기존 코드 경로를 그대로 탄다
- 회원의 충전 왕복 복원(결제 뒤 '다시 뽑기' 제거)도 이 장치 — `ENTRY_AB === "old"` 동안엔 꺼 두고, `"split"`·`"new"` 에선 회원 전원에게 켠다(회원은 입구 반반 대상이 아니라 두 그룹에 똑같이 적용 — 판정을 기울이지 않는다)

### 5-3. 화면 부품

- `CardReveal` — 앞면 뒤집기(`getCardImagePath`)
- `LoginSheet` — 카카오 버튼 = `/api/auth/login/kakao?next=` + encode(`/tarot/draw?resume=1`). 콜백의 성공 리다이렉트는 `new URL(next)` + `searchParams.set` 이라 `&login=success&welcome=1` 이 붙는다(확인함)
- `StarConfirmModal` — '다시 온 회원' 한 줄 변형(§4)

### 5-4. 로그인 실패

- 콜백 `failRedirect`: `next` 가 `/tarot/draw` 로 시작할 때만 그 `next` 로 `login=fail&reason=…` 를 붙여 보낸다. 그 밖(옛 흐름 포함)은 지금처럼 홈 — 대조군 불변
- 뽑기 화면이 `login=fail` 을 읽어 "로그인이 안 됐어 — 다시 눌러줘" + 시트 다시 열기 + 이벤트

### 5-5. 위기 배너

- `lib/sensitive.ts` 는 Anthropic SDK·service 클라를 import 해서 화면에서 못 쓴다 → 정규식(PATTERNS·`detectSensitiveSync`)을 순수 모듈 `lib/sensitive-patterns.ts` 로 옮기고 `lib/sensitive.ts` 가 다시 export(서버 동작 불변)
- `/concern` 에서 고민 입력이 high 매치면 `SafetyBanner`(HOTLINES)를 그 자리에 띄운다 — 진행은 막지 않는다. **스위치와 무관하게 회원·비회원 모두**(위기 대응은 기다리지 않는다)
- AI 2차 판정은 지금처럼 로그인 뒤 첫 대화에서

## 7. 판정 — 입구 반반 (2026-10-11 사용자 결정)

- **그룹**: 익명 쿠키 끝 글자 짝 = 새 흐름 / 홀 = 옛 흐름(지금 prod — 로그인 화면 문구까지 판정 동안 고정)
- **창**: `ENTRY_AB="split"` prod 배포 시각부터 14일, 창 끝 + 48시간 뒤 실행
- **대상**: 창 안에 첫 PV 가 생긴 익명 방문자 중 첫 PV 가 `utm_source='meta'` · 첫 PV 비로그인 · 봇 제외 · 나중에 지인 6명 user_id 로 이어지는 anon 제외
- **주 지표 ①**: 방문자당 신규 가입률(48시간 안에 그 anon_id 가 신규 계정으로 로그인). 기준 ~50%, 2주면 그룹당 ~370명 → +10%p 를 ~80% 로 가려낸다
- **주 지표 ②(안전장치)**: 방문자당 48시간 매출(가입 후 48시간 결제 ÷ 방문자)
- **결정 규칙**('확실히' = 부트스트랩 95% 구간이 0 을 안 걸침)
  - 가입이 확실히 + 이고 매출이 확실히 − 가 아니면 → 전원 새 흐름
  - 가입이 확실히 − 이거나 매출이 확실히 − 면 → 옛 흐름 유지
  - 걸치면 → 1주 연장(최대 3주). 그래도 걸치면 가입 평균이 높은 쪽(매출이 확실히 − 인 쪽은 제외)
- **보조·진단**: 로그인 창 노출 → 카카오 클릭 → 가입 · 옛 화면의 클릭 vs 카카오 이탈 · 단계별 이탈(고민 → 메뉴 → 뽑기 → 공개) · 비싼 상품 고른 사람의 결제 · 다시 온 회원 · 나중에 → 이어가기 · 가입당 첫 결제율(희석 예상 — 판정 아님)
- **엿보기 금지**: 창 중엔 숫자를 보고 멈추지 않는다. 멈추는 건 고장 — `pending_draw_missing` 이 이어짐 · 한쪽만 가입 0 이 2일+ · `login_fail_shown` 이 한쪽에 몰림 · PRICE_CHANGED 409 발생. 감시 = `scripts/entry-ab-daily-check.sql`(매일 1번)
- **판정 도구**: `scripts/entry-ab-verdict.sql` + 부트스트랩(메뉴판 판정과 같은 방식)

## 8. 일정·배포

- **지금(10-12~)**: dev 에 구현, `ENTRY_AB="old"`. 다른 작업과 prod 에 같이 나가도 사용자 화면은 그대로 — 켜지는 건 측정 이벤트(`home_tag_clicked`·`login_kakao_clicked{login_page}`)와 위기 배너뿐
- 회원 충전 왕복 복원도 `"old"` 동안엔 꺼 둔다 — 메뉴판 판정 창 안에서 결제 흐름을 바꾸지 않는다
- **켜기**: 메뉴판 판정(10-25 21:29 이후) → `MENU_AB` 승자 고정 배포와 같이 또는 바로 뒤에 `ENTRY_AB="split"`. 판정이 연장되면 같이 밀린다. prod 는 사용자 go
- 판정 중 광고 소재·예산 변경 OK(반반이라 공정). 예산을 크게 줄이면 표본 부족 → 연장
- 판정 뒤 정리 배포: 진 쪽 코드 제거

## 9. 테스트·검증

- **유닛**: `entryArmOf`(규칙 · MENU_AB split 가드) · pending draw 저장/복원/만료/불일치 · guest 가격 줄(메뉴판·옛 화면, ₩X) · 실패 리다이렉트(next 가 draw 일 때만) · `sensitive-patterns` 이동 뒤 기존 감지 결과 동일 · ui-events 계약
- **dev 브라우저 E2E**(로컬에서 스위치를 split/new 로): 비로그인 태그 → 고민 → 메뉴 → 뽑기 → 공개 → 시트 / 세션 주입으로 '로그인 뒤 복귀' 재현(`?resume=1` + 쿠키) → 맛보기 바로 풀이 · 비싼 상품 충전 시트 / 결제 왕복 복원 / 로그인 실패 안내 / 나중에 → 홈 이어가기 / 위기 배너 / 다시 온 회원 문구
- **실기기**: 인스타 인앱 → 카카오 → 복귀(prod 켜기 직전, 가능하면 dev 에서)

## 10. 알고 가는 것

- 다른 브라우저로 돌아오면 csrf 검사로 로그인이 실패한다(~2%). 진행은 원래 브라우저에 남아 '홈 이어가기'로만 회복
- localStorage 가 지워지면 진행이 사라진다 → `pending_draw_missing` 으로 잰다
- 고민 원문이 기기에 최대 7일 남는다(로그아웃·탈퇴 시 삭제)
- 로그인 전 화면은 판정 승자 화면이어야 한다. `SpreadPicker` 에는 "메뉴판이 이기면 이 파일을 지운다" 주석이 있다 — 어느 쪽이 이겨도 §3-1 표시가 붙게 구현하고, 진 쪽은 판정 뒤 정리
- 새 흐름 그룹의 가입자에는 '가볍게 들어온 사람'이 섞여 가입당 지표가 낮아지는 게 정상이다 — 판정은 방문자 기준
