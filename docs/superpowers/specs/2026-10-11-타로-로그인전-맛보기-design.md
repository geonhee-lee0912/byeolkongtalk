## 1. 왜

가입 1명을 데려오는 값(~₩380)이 가입 1명당 매출(~₩230)보다 크다. 광고를 키울수록 손해가 커진다 — 10-04~09 실측: 광고비 2.1배 → 가입 1.46배 → 매출 그대로. 고칠 수 있는 손실 하나가 입구의 로그인 문턱이다.

prod 실측(09-13~10-10, 인스타 인앱 = 유료 유입 대부분, 지인·봇 제외):
- 홈 태그를 누르자마자 로그인 화면이 뜬다. 이 화면을 본 1,292명 중 **30% 는 카카오에서 돌아오지 않았다**(버튼을 안 눌렀거나 카카오 화면에서 나감 — 지금은 둘을 못 가른다). 4% 는 돌아왔지만 실패(아무 안내 없이 홈으로). 64% 로그인
- 유료 방문자의 ~28% 가 이 화면에서 나간다 ≈ 광고비의 ~28%
- 인앱 67.5% vs 일반 브라우저 76.6%(n=47) — 차이 미유의. 기술 고장보다 '로그인 자체를 안 함'
- 로그인 화면엔 "먼저 인사부터 할까?" + 기록 저장 안내뿐 — **첫 풀이가 무료라는 말이 없다**

방향: 로그인을 '가장 궁금한 순간'(뽑은 카드를 본 직후)으로 옮긴다.

## 2. 범위

**안**: 홈 태그 → 고민 → 메뉴(또는 스프레드 고르기) → 뽑기 → **카드 공개 + 로그인 창** → 로그인 뒤 자동 이어가기 · 진행 저장(로그인·결제·나중에) · 로그인 실패 안내 · 다시 온 회원 안내 · 고민 화면 위기 배너(새 흐름만 — §5-5) · 계측 · 반반 판정 도구

**밖**: 이미 로그인한 회원 흐름 · 광고 랜딩 `/start` · 연애 상담 `/relationship` · 사주 운세 구매 · 별마루 로그인 · 로그인 전 AI 풀이(필요하면 이 판정 뒤) · 옛 로그인 화면 문구 개선(판정 동안 대조군 고정) · 서버측 진행 저장 · 다른 브라우저로 돌아오는 OAuth(csrf) 개선(~2%)

## 3. 새 흐름 (로그인 안 한 방문자 · 새 흐름 그룹)

1. **홈 태그** → 로그인 화면 없이 `/concern`. 다음 버튼 근처에 작은 안내: "풀이는 카카오로 3초 시작하면 바로 볼 수 있어"
2. **`/tarot`** — 판정 승자 화면(메뉴판 또는 스프레드 고르기). 가격은 '가입 선물 15별을 막 받은 신규 회원' 기준(§3-1)
3. **`/tarot/draw`** — 뽑기 의식 그대로 → 완료 → **카드 공개**: 뽑은 카드가 앞면으로 차례로 나타나고(페이드 인 — 뒤집기 아님) 자리 이름·카드 이름·정/역을 보여 준다. 의미·키워드는 보여 주지 않는다(궁금증 유지). 2장 이상은 풀이 화면처럼 3열(5장 3+2 · 6장 3+3 · 7장 3+3+1 — 관계 5장도 풀이 화면의 전용 배치가 아니라 3+2)
4. 공개가 끝나면(1장 ≈0.9초 ~ 7장 ≈2초) **로그인 창**(아래에서 올라오는 시트, 카드는 뒤에 보인다)
   - 제목 "카드는 뽑혔어 ✨" · 본문 "이 카드가 '{고민 앞 20자}…'에 뭐라고 하는지, 별콩이가 바로 풀어줄게"
   - 버튼 [카카오로 3초 시작] · 그 아래 "뽑은 카드는 그대로 이어져"
   - 가격 줄: 선물로 되는 상품 = "첫 풀이는 가입 선물로 무료" / 넘는 상품 = "가입 선물 15별 + ⭐N만 더 (X원부터)"
   - 작은 줄: "이미 가입했다면 남은 별로 이어져 (가입 선물은 처음 한 번)" · 약관 동의 줄 "시작하면 이용약관과 개인정보처리방침에 동의한 것으로 간주돼."(`/login` 과 같은 문구 — 로그인 입구가 하나 더 생긴 것이다)
   - [나중에 할래](바깥 탭·Esc 도 같다) → 시트만 닫고 카드는 화면에 남김 + 하단 고정 버튼 "로그인하고 풀이 보기"(시트 다시 열기)
   - (구현: 이 버튼 줄(+ "처음부터 다시 뽑기")은 공개가 끝난 뒤에만 보이고 하단 탭 바로 위에 붙는다(sticky) — 7장 판·작은 화면에서 탭 아래로 밀리던 것)
5. **카카오 왕복 뒤 `/tarot/draw?resume=login`** 로 돌아와 버튼 없이 이어간다(이어가기 주소는 들어온 길을 가른다 — `resume=login|payment|home`)
   - 저장된 진행을 복원 → 공개가 끝나면 지금의 '뽑은 뒤' 단계(지갑 → 가격 → 바로 풀이 / 확인 팝업 / 충전)를 그대로 탄다
   - 신규 가입(15별): 메뉴판이 승자 + 맛보기(동의 있음) = 바로 풀이 / 옛 화면이 승자 = 확인 팝업 한 번
   - 선물을 넘는 상품: 확인 팝업(잔액 부족) → 충전 시트(모자란 만큼 기본 — 잔액 맞춤 ②) → 결제 다녀와도 진행 복원(`resume=payment`)
   - 다시 온 회원 + 별 부족: §4
   - 로그인 실패: §5-4
   - 신규 가입이면 막지 않는 토스트 "🎁 가입 선물 별 15개 받았어"
6. **홈 이어가기**: 저장된 진행이 있으면(7일 안) 홈 태그 위에 한 줄 "아까 뽑은 카드가 기다리고 있어 / 이어서 볼래?" → `/tarot/draw?resume=home`

문구는 전부 초안 — 사용자 검수는 구현 뒤 화면으로 한다(계획 Task 15). 숫자(15·가격·금액)는 문구에 박지 않고 상수·함수에서 계산한다.

### 3-1. 로그인 전 가격 표시

- 표시용 지갑 = `guestWallet(arm)`(`lib/tarot/guest-price.ts`) = `{ balance: WELCOME_BONUS_STARS, isGuest: true, giftUnused: true, menuArm: arm, entryArm: "new" }` — arm 은 지갑 응답의 `menuArm`. `/tarot` 는 `isNewFlowGuest`(새 흐름 비로그인)일 때만 이 지갑으로 그린다 — 옛 흐름 비로그인이 직접 들어와도 지금 prod 그대로(대조군 불변)
- 메뉴판이 승자: `priceLine`(`lib/tarot/menu-price.ts`)이 그 지갑을 받아 — 맛보기 "가입 선물로 무료" · 유료는 큰 글씨 `⭐P` + 작은 줄 "가입 선물 + ⭐N만 더 (X원부터)". 비교 시트도 같은 줄. 선물 배너는 비로그인에게 "🎁 가입하면 별 15개 선물 — 첫 질문은 공짜야"(회원은 "가입 선물 별 15개 — …")
- 옛 화면이 승자(`SpreadPicker`): "⭐N별" 아래 같은 한 줄 — N ≤ 15 "가입 선물로 무료" / 넘으면 "가입 선물 + ⭐(N−15)만 더 (X원부터)"
  - 🔁 **2026-10-25 변경(사용자)**: 카드 한 줄(`guestShortLine`)에서 "(X원부터)" 를 뺐다 — 320px 카드에서 "1,000원부/터" 처럼 단어 중간에서 끊겼다. 금액은 로그인 창 줄(`guestSheetLine`)에만 남는다. 같은 배포에서 입구 판정 창을 다시 시작한다(`2026-10-25-타로-원투카드-마무리-안내줄-design.md` §10)
- X원 = 모자란 별을 덮는 가장 작은 충전 시트 패키지의 값 — 첫 충전 보너스 포함(신규 회원의 첫 결제). 잔액 맞춤 ②와 같은 칸·보너스 규칙(`minTopUpWon` → `lib/recharge-default.ts` 의 `sheetPackages`·`receivedStars`)이고, 시트 칸으로 못 덮으면 금액을 뺀다. 사용자 화면의 금액 관례가 `4,900원`(충전 시트·상점)이라 `₩` 가 아니라 "원"
- 로그인 창 가격 줄(`guestSheetLine`): "첫 풀이는 가입 선물로 무료" / "가입 선물 15별 + ⭐N만 더 (X원부터)"
- 서버 가격은 손대지 않는다. `MENU_AB` 를 승자로 고정한 뒤라 로그인 전후 가격이 같다 → expectedCost 409 가 안 난다

## 4. 다시 온 회원 (결정 A)

- 실측: 로그인 화면을 거쳐 로그인한 930건 중 98건(10.5%)이 기존 회원 재로그인. 그중 86% 가 별 15 미만(1~14 가 70명)
- 복원(resume) 경로의 '뽑은 뒤' 단계에서 `잔액 < 가격` 이고 `giftUnused === false` 면 확인 팝업(`StarConfirmModal` 의 `extra` 칸)에 "다시 와줘서 반가워! 가입 선물은 처음 한 번뿐이라 별 N개가 더 필요해" + 충전(모자란 만큼 기본). 카드는 그대로. 들어온 길이 `login`·`home` 일 때만 — 결제 복귀(`payment`)는 제외
- 돈 흐름은 지금과 같다(무료 지급 없음)

## 5. 구조

### 5-1. 스위치와 그룹

- `lib/tarot/entry-ab.ts`(순수·클라 안전) — `ENTRY_AB: "old" | "split" | "new"`, 기본 **"old"** · `entryArmOf(anonId)` = 끝 글자가 `02468ace` 면 "new", 아니면 "old"(메뉴판 판정과 같은 모양, 저장하지 않음)
- 🔴 **가드**: `MENU_AB === "split"` 이면 `entryArmOf` 는 항상 "old". 반반 중엔 로그인 전 가격(옛 그룹)과 로그인 뒤 가격이 어긋난다. 계약 테스트로 고정
- 새 장치(진행 저장·회원 충전 왕복 복원)가 켜지는 조건 = `entryFeaturesOn()` = `ENTRY_AB≠"old"` **그리고** `MENU_AB≠"split"`. 꺼져 있으면 뽑기 화면은 복원·이어가기·실패 표시를 하지 않고, 홈은 저장된 판을 지운다(롤백 안전 — 켰다가 되돌린 기기에 고민 원문이 무기한 남지 않게)
- '새 흐름 비로그인' 판정은 `isNewFlowGuest(지갑)` = `isGuest && entryArm === "new"` 하나 — 홈·`/tarot`·메뉴판 가격 줄·뽑기 화면이 같이 쓴다
- 그룹 전달: `/api/stars/balance` 응답에 `entryArm` 추가 — 비로그인은 서버가 `byeolkong_anon_id` 쿠키로 계산, 회원은 늘 "old". 홈은 마운트 즉시 지갑을 읽는다(`useWallet("home")`). 못 읽었거나 응답 전에 태그를 눌렀으면 옛 흐름(분석은 배정 기준 — 노출 어긋남은 `home_tag_clicked.armKnown` 과 홈의 `wallet_fetch_failed` 로 잰다). 새 흐름으로 보낸 방문자는 홈이 sessionStorage(`ENTRY_FLOW_KEY`)에 표시해 고민 쓰기가 안내 한 줄·위기 배너를 띄운다(로그인한 뒤엔 무시)
- 뽑기 화면의 공개 + 로그인 창은 `isNewFlowGuest` 일 때만. 그 밖의 비로그인(옛 흐름 그룹이 세션 만료 등으로 들어온 경우)은 지금 동작 그대로 — 대조군 불변
- `proxy.ts` 는 건드리지 않는다

### 5-2. 진행 저장

- localStorage `byeolkong:pending_draw` = `{ v: 1, emotion, concern, spreadType, spreadCategory, consented?, drawnCards, savedAt }` (`lib/tarot/pending-draw.ts`)
- 쓰기: 비로그인은 새로 뽑은 판을 공개 직전에(복원한 판은 다시 쓰지 않는다), 회원은 충전 시트를 열 때. 7일은 마지막 저장부터 — 복원만으로는 늘지 않는다
- 읽기: `/tarot/draw` 마운트 — 주소의 `?resume=login|payment|home`(`resumeHref`·`parseResume`)이거나 지금 선택(spreadType·concern)과 일치하면 의식을 건너뛰고 공개 / '뽑은 뒤' 단계로. 모양이 맞는 저장만 쓴다: 동의는 boolean · 뽑은 장수 = 스프레드 장수 · 스프레드·카테고리(서버와 같은 7종)·감정 태그는 현행 값만 — 어긋나면 지우고 없는 것으로 친다(결제까지 마친 뒤 서버 400 막다른 길 방지)
- 지우기: 대화로 넘어갈 때(`goToReading`) · '처음부터 다시 뽑기' · 7일 경과 · 로그아웃·탈퇴 · 새 장치가 꺼진 채 홈에 올 때(§5-1)
- 복원 시 기존 sessionStorage 키(`TAROT_SPREAD_KEY`)를 다시 채워 기존 코드 경로를 그대로 탄다
- 회원의 충전 왕복 복원(결제 뒤 '다시 뽑기' 제거)도 이 장치 — `entryFeaturesOn()` 이 거짓인 동안(`ENTRY_AB === "old"` 이거나 메뉴판 반반 중)엔 꺼 두고, 켜지면 회원 전원에게 켠다(회원은 입구 반반 대상이 아니라 두 그룹에 똑같이 적용 — 판정을 기울이지 않는다)

### 5-3. 화면 부품

- `CardReveal` — 앞면을 카드마다 조금씩 늦춰 페이드 인(`getCardImagePath`). 공개가 끝나면 `onRevealed` 를 한 번 부른다(뽑기 화면이 그때 로그인 창을 올리거나 복원한 판을 이어 간다)
- `LoginSheet` — 카카오 버튼 = `/api/auth/login/kakao?next=` + encode(`/tarot/draw?resume=login`). 콜백의 성공 리다이렉트는 `new URL(next)` + `searchParams.set` 이라 `&login=success&welcome=1` 이 붙는다(확인함)
- `StarConfirmModal` — `extra` 칸에 '다시 온 회원' 한 줄(§4)

### 5-4. 로그인 실패

- 콜백 `failRedirect`(`lib/auth-redirect.ts`): `next` 가 정확히 `/tarot/draw` 이거나 `/tarot/draw?` 로 시작할 때만 그 `next` 로 `login=fail&reason=…` 를 붙여 보낸다. 그 밖(옛 흐름 포함)은 지금처럼 홈 — 대조군 불변
- 뽑기 화면이 `login=fail` 을 읽어 "로그인이 안 됐어 — 다시 눌러줘" + 시트 다시 열기 + 이벤트
- 복귀 주소 처리(구현): `AuthBootstrap` 은 `/tarot/draw` 의 콜백 주소 정리를 건너뛴다 — 로그인 복귀한 뽑기 화면은 공개가 끝나면 바로 `router.push("/tarot/reading")` 을 내는데, 그 push 가 응답을 기다리는 사이 `router.replace` 가 오면 라우터가 대기 중인 push 를 버려 '잠시만…' 에 갇힌다(`/start` 와 같은 이유)
- 대신 뽑기 화면이 `history.replaceState(window.history.state, …)` 로 `login`·`welcome`·`migrated`·`reason` 을 직접 지운다(알림은 한 번만 — 새로고침에 실패 안내·토스트가 다시 뜨지 않게). `resume` 은 새로고침 복원용으로 남기고, 풀이로 떠나기 직전·'처음부터 다시 뽑기' 때 지운다(뒤로 왔을 때 표시만 남아 '저장 없음' 고장 신호가 오탐으로 찍히지 않게). 대가: 라우터는 이 정리를 모른다 — `useSearchParams()`·canonicalUrl 은 이 화면을 떠날 때까지 옛 쿼리라, 이 화면에 `router.refresh()` 처럼 라우터 상태를 바꾸는 걸 넣으면 주소가 되돌아와 콜백 표시가 다시 뜬다(state 는 null 로 덮지 않고 그대로 넘긴다 — Next 라우터 상태가 history.state 에 있어 지우면 뒤로 가기가 깨질 수 있다)

### 5-5. 위기 배너

- `lib/sensitive.ts` 는 Anthropic SDK·service 클라를 import 해서 화면에서 못 쓴다 → 정규식(PATTERNS·`detectSensitiveSync`)을 순수 모듈 `lib/sensitive-patterns.ts` 로 옮기고 `lib/sensitive.ts` 가 다시 export(서버 동작 불변). 그 모듈은 아무것도 import 하지 않는다(계약 테스트 — 서버 전용 코드가 브라우저 번들로 딸려 오지 않게). 화면은 `concernSafetyMatch`(정규식 확신 high 만)를 쓴다

## 7. 판정 — 입구 반반 (2026-10-11 사용자 결정)

- **그룹**: 익명 쿠키 끝 글자 짝 = 새 흐름 / 홀 = 옛 흐름(지금 prod — 로그인 화면 문구까지 판정 동안 고정)
- **창**: `ENTRY_AB="split"` prod 배포 시각부터 14일, 창 끝 + 48시간 뒤 실행
- **대상**: 창 안에 첫 PV 가 생긴 익명 방문자 중 첫 PV 가 `utm_source='meta'` · 첫 PV 비로그인 · 봇 제외 · 나중에 지인 6명 user_id 로 이어지는 anon 제외
- **주 지표 ①**: 방문자당 신규 가입률(48시간 안에 그 anon_id 가 신규 계정으로 로그인). 기준 ~50%, 2주면 그룹당 ~370명 → +10%p 를 ~80% 로 가려낸다
- **주 지표 ②(안전장치)**: 방문자당 48시간 매출 `rev48` = 그 익명 쿠키로 첫 방문 후 48시간 안에 로그인한 계정(새로 가입했든 기존 회원이든)이 그 48시간 안에 낸 결제 합 ÷ 방문자 — 로그인 안 했으면 0
- **결정 규칙**('확실히' = 부트스트랩 95% 구간이 0 을 안 걸침)
  - 가입이 확실히 + 이고 매출이 확실히 − 가 아니면 → 전원 새 흐름
  - 가입이 확실히 − 이거나 매출이 확실히 − 면 → 옛 흐름 유지
  - 걸치면 → 1주 연장(최대 3주). 그래도 걸치면 가입 평균이 높은 쪽(매출이 확실히 − 인 쪽은 제외)
- **보조·진단**: 로그인 창 노출 → 카카오 클릭 → 가입 · 옛 화면의 클릭 vs 카카오 이탈 · 단계별 이탈(고민 → 메뉴 → 뽑기 → 공개) · 비싼 상품 고른 사람의 결제 · 다시 온 회원 · 나중에 → 이어가기 · 가입당 첫 결제율(희석 예상 — 판정 아님)
- **엿보기 금지**: 창 중엔 숫자를 보고 멈추지 않는다. 멈추는 건 고장 — `pending_draw_missing` 이 이어짐 · 한쪽만 가입 0 이 2일+ · 새 그룹의 로그인 왕복 실패율이 기준선보다 크게 높은 날이 이어짐 · 옛 그룹이 새 흐름 전용 화면을 봄(`arm_leak` — 공개·로그인 창·고민 쓰기 위기 배너) · PRICE_CHANGED 409 가 배포 24시간 뒤에도 이어짐. 감시 = `scripts/entry-ab-daily-check.sql`(매일 1번 — 정의·기준은 그 파일 머리가 정본)
  - 로그인 실패는 '한쪽에 몰림'이 아니라 **새 그룹 안의 왕복 실패율**: `login_roundtrip` = 실패 ÷ (실패 + 성공 복귀), 기준선 ≈6%(= §1 의 4/(4+64)). 사용자가 카카오에서 취소한 `access_denied` 는 따로 센다. `login_fail_shown` 은 새 흐름 로그인 창 경로에서만 찍혀 옛 그룹은 실패해도 이벤트가 없다 — 그룹끼리 비교하면 늘 한쪽에 '몰려' 보인다
  - PRICE_CHANGED 는 배포 직후 낡은 번들이 내는 정상 409(지인 6명 제외)라 24시간 뒤(`after_24h`)부터만 고장으로 읽는다. 메뉴판 쪽 409 와 구분하지 못해서 `MENU_AB` 를 먼저 고정한다
  - 진단(멈춤 신호 아님): `exposure` — 새 그룹 방문자가 홈에서 새 흐름을 못 탄 만큼(지갑 응답 전 탭 · 지갑 실패 폴백 · 홈 지갑 실패) 노출이 줄어 있다

- 새 흐름 그룹의 가입자에는 '가볍게 들어온 사람'이 섞여 가입당 지표가 낮아지는 게 정상이다 — 판정은 방문자 기준
- 고치지 않은 작은 것:
  - 탈퇴 후 재가입자에게 가입 토스트가 틀릴 수 있다(콜백 `welcome=1` 은 `users` 행 신규 기준이라 가입 선물을 이미 받은 카카오 계정에도 붙는다 — `/start` 와 같은 기존 의미)
  - 충전 왕복으로 저장된 회원 판을 `home` 으로 다시 열어도 '다시 온 회원' 줄이 뜬다
  - 다른 탭으로 결제 복귀하면 '이어서 깊게'의 부모 연결이 안 옮겨진다(가격은 같다)
  - 켜는 배포 직후 옛 번들 탭은 로그인 창은 뜨지만 홈 이어가기 줄은 안 뜰 수 있다
