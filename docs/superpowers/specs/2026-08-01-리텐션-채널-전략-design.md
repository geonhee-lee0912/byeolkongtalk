# 리텐션 상품(E3·E4) — 채널·구조 전략

**작성** 2026-08-01 · **상태** 구조·방향 확정 · **채널은 실측 대상**(추측으로 확정 불가)
**맥락** T1 신상품 설계. E3(운세 캘린더)·E4(편지 교환)를 **개별 상품이 아니라 "리텐션 레이어"**로 함께 본 결과. 탭 배치는 하단탭 IA 세션.

## 한 줄

리텐션 = **부를 수단(채널) + 돌아올 이유(콘텐츠)**. E3·E4는 이 레이어의 조각이며, **공통 알림 채널 하나를 공유**한다. 병목은 콘텐츠가 아니라 **채널의 opt-in 전환**이고, 완벽한 채널이 없어 **실측으로 확정**한다.

## 구조 — 리텐션의 두 조각

- **부를 수단(채널)** — 앱 밖에서 유저를 다시 불러오는 신호
- **돌아올 이유(콘텐츠)** — 돌아와서 볼 것 (좋은날·편지·데일리·미열람 결과)

**돌아온 뒤 진열**은 이미 IA 스펙 §3 **홈 오늘 블록**이 설계해둠(좋은날·편지·이어가기·데일리 한 자리). 그래서 새로 정할 건 주로 **"밖에서 부르는 수단"**.

## 병목 — opt-in 전환 (+ 채널 선택도 고민 포인트)

재방문 실패의 원인은 *"볼 게 없어서(콘텐츠)"가 아니라 "부를 방법이 없어서(채널)"* — IA 스펙 §배경. 더 정확히는 **모든 0원 채널이 유저의 능동적 opt-in(권한·홈추가·구독)을 요구하고 그 전환율이 낮다**(웹푸시 opt-in ~6%). 채널이 없는 게 아니라 **문을 열게 만드는 게 어렵다**.
- ⚠️ 단 채널 선택 자체도 무시 못 함(2026-08-01 사용자) — 채널마다 마찰·도달이 달라 opt-in 난이도가 갈린다.

## 채널 — 웹푸시 제외, 3후보 실측

**웹푸시 제외** — iOS는 "홈 화면 추가"(PWA 수동 설치) 없이는 불가. 우리 타겟(여성 다수 → iOS 비중 추정 높음)엔 실효성 낮음. (⚠️ iOS/Android 실비율은 확인 항목)

**완벽한 채널이 없다 — 웹 서비스(네이티브 앱 없음)의 구조적 한계.** 3후보 전부 약점이 있어 **추측 대신 실측으로 확정**한다(캘린더·메일 0원, 알림톡 8원 — 저볼륨이라 비용은 결정 요인 아님).

| 채널 | 강점 | 치명 약점 |
|---|---|---|
| **캘린더 구독**(webcal) | 0원·iOS OK·opt-in 1회로 자동 갱신·**iOS에서 설치 없이 네이티브 알림 얻는 유일 경로** | **타겟이 캘린더 알림에 반응할지 미검증**(구독 캘린더 알림 기본 꺼짐 잦음) |
| **이메일** | ~0원·콘텐츠 자유·수집 쉬움(카카오서) | **오픈율 낮음**(운세 메일 = 스팸함 직행) |
| **카카오 알림톡** | 도달·열람 최고(카톡) | 전화번호 **미수집**(수집 선결) + **정보성만**(마케팅 금지) |

> webcal 구독은 **메일을 거치지 않는다**(링크 클릭 → 캘린더 앱이 서버 이벤트 직접 구독). 단 "메일에 .ics 초대 첨부" 방식은 가능하나 메일 오픈이 선결.

## E3·E4 엮기 — 공통 채널 레이어

- **좋은날(E3)** = 날짜 정해짐 → 캘린더 최적
- **편지(E4)** = **"도착 예정일이 정해진" 구조로 설계하면** 좋은날과 똑같이 캘린더를 탄다. E4 미결이던 "왕복 주기"가 곧 캘린더 이벤트 → **E3·E4가 한 인프라 공유**(사용자가 말한 "엮기"의 실체)
- 즉시성 필요분(편지 방금 도착 등)만 알림톡(정보성) 보조

## 채널별 역할 분담 (잠정)

- **마케팅성 재방문**(좋은날·이벤트) → 캘린더 (유저가 구독한 거라 제약 없음)
- **정보성 즉시 알림**(편지 도착·예약 결과) → 알림톡 (정보성이라 제약 회피 + 도달 최고)
- 메일 → 오픈율 때문에 후순위(영수증·백업)

## 확인·실측 항목

1. **iOS/Android 실비율** — 웹푸시 완전 제외 근거 (계측 조회)
2. **카카오 OAuth 전화번호 scope** 추가 가능 여부·동의율 — 알림톡 선결
3. **알림톡 정보성 경계** — "편지 도착"이 정보성으로 통과되는지
4. **채널별 복귀율/오픈율 실측** — 좋은날 리포트에 얇게 붙여 A/B (되는 걸 확대, 안 되면 접기)

## 기각·보류

- 웹푸시 — iOS 실효성 낮아 제외(Android 비율 크면 재고)
- "채널 하나로 다 커버" 단정 — 완벽한 채널 없음이 결론, 실측이 답
- 각 상품(좋은날 리포트·편지) 콘텐츠 형태 — 구현 스펙에서
- 탭 배치·정본 지면 — 하단탭 IA 세션
