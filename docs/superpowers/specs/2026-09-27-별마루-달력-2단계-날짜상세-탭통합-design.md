# 별마루 달력 2단계 — 날짜 상세 탭 통합 (2026-09-27)

1단계(`2026-09-26-별마루-달력-무료화-단순화-design.md`) §8 이 예고한 작업. 그 절의 조사 결과가 이 스펙의 출발점이고, 여기서 **결정**으로 굳힌다.

## 1. 왜

**날짜를 고르면 그날의 사주·타로·우리를 한 자리에서 오갈 수 있어야 한다.** 지금은 못 한다.

| 입구 | 지금 도달하는 곳 |
|---|---|
| 달력 칸 클릭 | `/byeolmaru/saju?date=X` — **사주뿐** |
| 허브 목록 3행 | `/byeolmaru/{saju,tarot,woori}` — 각 화면의 **오늘뿐** |

그래서 9/20 을 눌러 사주를 본 뒤 "그날 타로는?" 으로 가려면 상세 카드 안의 링크를 타고 나가야 하고, **"우리"는 과거로 갈 길이 아예 없다**(`pair-narrative` 라우트에 `?date=` 가 없다).

부수 효과로 중복도 줄어든다 — 세 View 가 각자 `/api/byeolmaru/calendar` 를 부르고(우리는 2번) `BackHeader`·`useByeolmaruSubscribe` 도 각자 갖고 있다. 다만 **중복 제거는 목적이 아니라 결과다**. 판단이 갈릴 땐 "오가기"를 지킨다.

## 3. 구조

```
app/byeolmaru/day/page.tsx              신설 — Suspense + DayTabsBridge
components/byeolmaru/DayTabsBridge.tsx  신설 — useSearchParams 로 ?date ?tab 파싱
components/byeolmaru/DayTabsView.tsx    신설 — 껍데기
  ├ BackHeader                (하나)
  ├ 탭 3개                     (사주 / 타로 / 우리)
  ├ GET /api/byeolmaru/calendar  ← 이 화면에서 유일한 호출
  └ 활성 탭의 View 에 data 를 prop 으로 주입

app/byeolmaru/saju/page.tsx   → 리다이렉트 스텁
app/byeolmaru/tarot/page.tsx  → 리다이렉트 스텁
app/byeolmaru/woori/page.tsx  → 리다이렉트 스텁
```

🔴 **`page.tsx` 에 Suspense 경계가 필요하다** — `useSearchParams` 를 쓰는 클라 컴포넌트는 경계가 없으면 빌드가 *"missing suspense boundary with useSearchParams"* 로 실패한다. 그리고 **fallback 에 완전한 뷰를 쓰면 안 된다** — 정적 프리렌더가 fallback 을 셸로 굳혀 그 인스턴스도 마운트→fetch 를 한 번 타고, 이어서 실제 인스턴스가 또 fetch 한다(기존 `saju/page.tsx` 주석의 실측: 캘린더 4회). 가벼운 로딩 문구를 쓴다.

### 3-1. 세 View 에 가하는 수술 — 두 군데씩

1. **`data` 옵셔널 prop** — 받으면 자기 `/api/byeolmaru/calendar` fetch 를 건너뛴다. 안 받으면 지금처럼 스스로 부른다(경로가 하나뿐이라 실제로는 항상 받지만, 옵셔널로 두면 이 변경이 기존 동작을 깨지 않는다).
2. **`BackHeader` 제거** — 껍데기가 그린다. 스텁이 리다이렉트라 **View 는 항상 껍데기 안에서만** 렌더되므로 조건부 분기가 필요 없다.

`useByeolmaruSubscribe` 는 각 View 에 남긴다. 탭은 한 번에 하나만 활성이고, 훅을 껍데기로 올리면 세 View 의 시그니처를 전부 바꿔야 해서 A′ 의 "수술 면적 최소" 원칙에 어긋난다.

### 3-2. 탭은 lazy + keep-alive

- 처음 연 탭만 마운트한다. **안 연 탭은 마운트 자체를 안 하므로 초기 비용은 지금과 같다.**
- 한 번 연 탭은 `display:none` 으로 살려둔다.

🔴 **언마운트하면 안 되는 이유**: 오갈 때마다 리포트를 다시 부르고(캐시 히트라도 왕복은 난다) 선택 상태·스크롤이 초기화된다. 목적이 "오가기"인데 오갈 때마다 리셋되면 의미가 없다.

⚠️ `display:none` 인 탭도 DOM 에 남으므로 **숨은 탭의 `PaywallCut` 이 `byeolmaru_gate_shown` 을 다시 찍지 않도록** 주의한다 — 그 이벤트는 마운트 시 1회 발화이고 keep-alive 에서는 마운트가 한 번뿐이라 자연히 1회다. 되레 **탭을 닫았다 여는 반복으로 중복 발화하던 위험이 사라진다.**

## 4. 선행 — "우리"에 날짜 얹기

이게 없으면 2번 탭까지만 목적을 달성한다.

### 4-1. 라우트

`app/api/byeolmaru/pair-narrative/route.ts` 에 `?date=` 추가 + `reportDatePolicy(date, todayKst)` 적용. 사주 `daily-report` 와 **같은 패턴**이다.

| 날짜 | 정책 |
|---|---|
| 과거 | `cache_only` — 그날 받은 것만. 없으면 "그날은 리포트를 안 받았어" |
| 오늘 | `generate` — 캐시 히트면 그대로, 없으면 생성(자격·하루 상한 검사) |
| 미래 | `out_of_range` — "그날 아침에 열려." |

🔴 **캐시 조회는 자격 게이트보다 앞에 둔다** — 1단계에서 거짓 페이월 4건을 고치며 세운 원칙이다(`d716acd`·`84b90a0`·`11642fd`). 안 그러면 만료 직후 유저가 **그날 아침에 받은 글을 손에 쥔 채 페이월을 본다**.

### 4-2. 그날 본 상대 찾기

신설: `getPairNarrativeByDate(userId, dateStr)`

- `(user_id, narrative_date)` 로 조회한다. 인덱스 `idx_byeolmaru_pair_narrative_user (user_id, narrative_date DESC)` 가 **이미 있다** — 마이그레이션 불필요.
- PK 가 `(user_id, partner_profile_id, narrative_date)` 라 **같은 날 두 상대의 행이 있을 수 있다**(상대 교체가 무료이고 하루 상한은 "새 상대 1명"이라 교체 후 생성이 가능하다). 그때는 `created_at` 최근 것.
- 기존 `getCachedPairNarrative(userId, partnerId, dateStr)` 는 **그대로 둔다** — 오늘 경로(상대가 정해진 상태)가 계속 쓴다.

### 4-3. 화면

`WooriTodayView` 가 `?date=` 를 받는다. 🔴 **과거 날짜엔 `CurrentPartner`(지금 걸어둔 상대)가 아니라 그날 상대를 표시한다** — 안 그러면 B 의 이름 아래 A 의 글이 뜬다.

## 5. 탭 상태와 URL

- `?tab=saju|tarot|woori`, 없거나 모르는 값이면 `saju`.
- `?date=` 없으면 오늘.
- 전환은 `router.replace` — 주소는 바뀌어 복사·공유가 되고, 기록은 안 쌓여 **뒤로가기 한 번에 달력으로** 나간다.

🔴 **`tab` 값을 화이트리스트로 검증할 것.** 신뢰 못 할 쿼리로 config 를 조회하다 터진 prod 크래시가 이 저장소에 있다(`RECO_DISPLAY[product]` → `undefined.label`, 2026-08-02). 모르는 값은 조용히 `saju` 로 떨어뜨린다.

### 5-1. 리다이렉트 스텁

| 기존 | 이동 |
|---|---|
| `/byeolmaru/saju?date=X` | `/byeolmaru/day?date=X` (tab 생략 = 사주) |
| `/byeolmaru/tarot?date=X` | `/byeolmaru/day?date=X&tab=tarot` |
| `/byeolmaru/woori` | `/byeolmaru/day?tab=woori` |

🔴 **쿼리를 통째로 보존한다** — 카카오 공유 링크가 `utm_source=byeolmaru_tarot&utm_medium=share` 를 달고 온다(`DailyCardBlock.tsx`). 어트리뷰션이 스텁에서 끊기면 공유 유입이 전부 direct 로 잡힌다.

새로 만드는 공유 링크는 `/byeolmaru/day?date=…&tab=tarot` 를 가리키게 바꾼다.

## 6. 계측

의미가 유지되는 것 — 손대지 않는다:

- `byeolmaru_free_item_clicked(meta.item)` — 목록 3행. href 만 바뀌고 세는 대상은 같다
- `byeolmaru_day_selected(meta.offset, tone, subjectKind, surface)` — 달력 칸
- `byeolmaru_gate_shown(meta.slot)` — `saju_report`/`tarot_rich`/`woori_30d` 로 세 상품을 이미 가른다

**신설: `byeolmaru_day_tab_changed`** `meta:{from, to, offset}`

🔴 **이게 이 통합의 성패를 재는 유일한 지표다.** 없으면 "날짜 상세까지 온 사람이 다른 탭으로 얼마나 넘어가나"를 영영 못 읽고, 그러면 통합이 실패해도 알 수가 없다. `offset`(오늘로부터의 일수)을 같이 실어 **과거 날짜에서의 탭 이동**과 오늘에서의 이동을 가른다.

⚠️ **판독 경계** — `byeolmaru_free_item_clicked(item="tarot"/"woori")` 자체는 **안 내려앉는다**(목록 3행이 그대로 그 이벤트를 찍는다). 바뀌는 건 **도달 경로가 둘이 된다**는 것이다 — 목록에서 직접 들어오는 길에 더해, "사주 탭에서 타로 탭으로 전환"이라는 길이 새로 생긴다(예전엔 상세 카드 링크로 화면을 나가야 했다). 그러니 배포 후 타로·우리 **도달 총량**은 `free_item_clicked` + `day_tab_changed(to=…)` 를 **합쳐** 읽고, `free_item_clicked` 단독 추세를 도달로 오독하지 말 것.

## 7. 범위 밖

- **탭 순서·디자인의 재설계** — 사주/타로/우리 순서는 허브 목록과 같게 둔다.
- **상대 미등록자에게 우리 탭 숨기기** — 이 지면의 철학은 "입구는 열어두고 도착지가 상태를 처리한다"다(허브 목록의 `woori` 행도 조건 없이 보인다). 탭도 3개 고정.
- **결과 화면 디테일 개선 · 구독/비구독 비교** — 사용자가 2단계 *다음*으로 예고한 별도 작업.

## 8. 검증

### 8-1. 자동

- `tsc` clean · `next build` exit 0 (라우트 표에 `ƒ Proxy` 유지)
- 유닛 전량 통과. 🔴 `find` 에 `-not -path "*/node_modules/*"` 를 쓸 것 — `./node_modules/*` 만 빼면 `.claude/worktrees/*/node_modules/` 의 zod 테스트 303건이 거짓 실패한다
- `reportDatePolicy` 를 pair 경로에도 적용했으므로 관련 유닛 추가

### 8-2. 실물 (dev, 375×812)

**목업을 만들지 않는다** — 이 저장소는 목업 대체물에 두 번 속았다.

| # | 확인 | 계정 |
|---|---|---|
| 1 | 달력 칸 → 사주 탭이 열리고 **그 칸의 날짜**가 맞다 | 구독 `11111111…` |
| 2 | 탭 3개를 오가도 **캘린더 재호출 0회** — 진입 시 1회만(네트워크 탭) | 〃 |
| 3 | 탭을 오갔다 돌아와도 **선택 상태·스크롤이 유지**된다 | 〃 |
| 4 | 뒤로가기 **한 번**에 달력으로 나간다(탭 3번 전환 후) | 〃 |
| 5 | 과거 날짜 × 우리 탭 — **그날 본 상대**가 뜬다 | 〃 |

### 8-3. 배포

- `origin/dev` 푸시는 사용자 확인 후.
- 🔴 **prod(main) 배포는 하지 않는다** — 사용자가 명시할 때까지.
- **마이그레이션 없음** (인덱스가 이미 존재한다).
