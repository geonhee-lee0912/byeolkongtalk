# 별마루 ③ 우리 오늘 — 설계

> 상위 정본 = `2026-08-31-별마루-리텐션허브-design.md` §7. 이 문서는 §7이 "전략 확정, 구현 디자인 미정"으로 남긴 부분을 확정한다. 브레인스토밍 2026-09-05. ② = `2026-09-04-별마루-2-구독게이트-design.md`.

## 1. 목표 & 히어로

- **무료 = 나의 오늘 / 구독 = 나 + 그 사람의 오늘.** 상대를 걸어두면 매일 둘 사이 흐름을 본다 → 1회성 궁합과 달리 **매일 볼 이유**. 관측 수요 76%(재회·걔 속마음)에 정면.
- 전제는 실측 뒷받침(§7): 8월 self 162명 중 **95명(59%)이 상대 등록·전원 생년월일**. 새 행동을 만드는 게 아니라 이미 쌓이는 데이터에 목적지를 주는 것.
- 🔴 **남은 미검증(히어로 리스크)**: "그걸 매일 보는 게 돈 낼 이유가 되는가" — 별마루 전체 리스크와 동일. 완화 = 정적 오서링(⑥)을 뒤에 둬 히어로가 안 서면 손실을 끊는다.

## 2. 범위 (MVP)

- **B 스코프**: 상대별 **우리 30일 캘린더** + 오늘 상세. "오늘 한 장"(A)은 30일의 **오늘 셀**로 자동 포함 → 한 벌 코드로 A+B.
- **포함**: 나/우리 토글 · 우리 판정(C, §7) · 상대 인라인 등록/관리(§6) · 구독 게이트=완전 블러(§4) · 별콩 서술(§8) · 계측(§9).
- **제외(v1)**: 택일(`good_days` 전 기간 구매 0으로 반증, 부록 성격 — 수요 재확인 시 후속) · 스레드/시뮬 진입(백로그 #14 → 타로톡/사주 이전 예정).

## 3. 화면 구성

- 캘린더 **한 벌 + 상단 선택 토글**: `나`(기본) · 등록한 상대들 · `＋`.
  - `나` = 현행 나의 오늘(무료·모두). 상대 선택 = 우리 오늘(구독).
  - **그리드·상세 컴포넌트 재사용**, "대상"만 `나` ↔ `나×상대`로 교체.
- **토글 노출은 전원 · 동작은 자격 기준**: `나`는 모두 무료. 상대 선택 시 — 구독자 = 우리 오늘 실렌더 / 비구독자 = 완전 블러 + 구독(3일 체험) CTA. 상대 담기/관리(`＋`)는 구독 전용(§6).
- 상대 0명 **구독자** = `나` + `＋ 상대 걸어두기`(등록 유도). **비구독자** = `나`(무료) + 잠긴 "우리 오늘" 티저(구독 유도). 어느 쪽이든 **나만 보는 사람도 완전한 경험**(강제 아님).
- 우리 상세 카드: 우리 tone/score + 오늘 태그 + "너희 결" 배경 + 서술(구독) / 완전 블러 + 3일 체험 CTA(비구독).
- 🔴 회귀 주의: `isToday`/KST 사슬은 나의 오늘과 동일 제약(상위 스펙 "회귀 표면" 참조) — 우리 캘린더도 같은 `kstDate`/`fmtDate` 짝을 쓴다.

## 4. 접근 모델 & 게이트

- **비구독자 = 우리 오늘 완전 블러**(구독유도용). 상대 등록·조회 불가. ②-a의 "첫 줄 맛보기(시안 C)"와 달리 여기선 **통짜 잠금**(사용자 결정 2026-09-05).
- **구독자 = 열림.** ②-a `lib/byeolmaru/entitlement.ts`가 surface-agnostic → 우리 오늘도 자격자만 실렌더, 비자격은 블러+CTA(3일 체험). `PremiumBlock` 패턴 재사용.
- 🔑 **설계 원칙: 인물 데이터를 구독 상태에 절대 묶지 않는다.** 구독은 자동갱신 없는 30일 기간권이라 해지→재구독 갭이 정상 → 그 사이/이후에도 등록 상대는 유지된다(§5로 자동 충족).

## 5. 데이터 모델

- **인물 정본 = `user_profiles`** (단일 창고). 우리 사이·궁합·`/api/profiles`·별자리 등록이 전부 여기 `relation_type`만 다르게 쌓인다. `GET /api/profiles` = 본인 전원 목록 + 사주 계산.
  - → "다른 곳에서 등록한 상대"·"사주 프로필에서 가져오기"는 **별도 import 기능 불필요** = 같은 창고를 읽는 것.
- **우리 오늘 watch = 신규 얇은 링크 테이블 `byeolmaru_watch`**: `(user_id, profile_id → user_profiles.id, created_at)`. **데이터가 아니라 링크**("이 상대를 우리 오늘에서 본다"). partner 데이터는 계속 `user_profiles` → §7 "상대 데이터 4번째 장소 금지" **준수**.
  - `relationships` **재사용 안 함**: ① 스레드/시뮬의 테이블이고 곧 타로톡으로 이전(백로그 #14)이라 얽히면 지저분 ② 옛 50별 슬롯·일일턴·패스·rolling_summary baggage → 별마루 가격을 얹으면 **한 테이블 두 가격 규칙**(버그 온상) ③ 따로 = 깨끗한 소유권.
  - 신규 테이블이라 기존 watch 0 → **grandfather 불필요.** 기존 상대(95명 등)는 `user_profiles`에서 **추천으로 떠서 골라 담는다**(오래된 옛 상대를 강제로 안 띄워 관련성↑).
- 🔴 내 프로필 조회는 **반드시 `is_primary = true`** — `user_profiles`는 본인 전용이 아니라 상대(partner) 행이 같은 `user_id`로 들어온다. 안 하면 상대 사주가 내 캘린더로 샌다(상위 스펙 리뷰가 배포 전 잡은 사고 계열).

## 6. 상대 관리 (재화)

- **여러 명 가능.** 구독자: **2명 무료 + 3번째부터 1명당 5별**(`byeolmaru_watch` 행 수 기준, 서버 권위). 비구독자: 담기 불가(완전 블러).
- **5별 근거**: 구독 자체가 20별(`BYEOLMARU_SUBSCRIPTION.cost`)이라 추가 상대는 작은 애드온이어야 함 — 답변추천(`SIM_SUGGEST_COST=5`) 티어 = 구독의 1/4. 원가는 nano+캐시라 ~0, 게다가 우리가 **원하는 행동(여러 명 담기=연료)**이라 마찰 최소화. (구)`SLOT_COST=50`(relationships)은 /relationship 잔존용이라 **안 건드림**.
- 담기 UI(인라인): "이미 아는 사람"(`user_profiles` 추천, 재입력 0) 고르기 / "새로 등록"(모달 → `POST /api/profiles`). 3번째부터 `StarConfirmModal`로 5별 확인(②-a 결제 패턴).

## 7. 판정 로직 — C 하이브리드 (룰 100%, LLM 0)

재료: `dayFactors(A,D)`·`dayFactors(B,D)`(각자 오늘) × `pairRelation(A,B)`(고정 궁합) × 일진 D(천간·지지·오행). A=나(is_primary), B=상대.

**우리 score(0~100) = 3층:**
1. **각자 오늘 base** — 두 `dayFactors`를 blend(연애축 가중 여지) → 부드러운 일간 변화 + "누가 리드"(개인 점수 차).
2. **관계 촉발/충돌**(D가 두 일주를 건드림): 끌림↑ = D천간 × A/B 일간 **천간합**(+) · 결속 = D지지 × A/B 일지 **육합**(+) · 삐걱 = D지지 × A/B 일지 **육충**(−). primitive 재사용(`heavenlyCombo`·`earthlySixCombo`·`earthlySixClash`).
3. **정적 궁합 baseline** — `pairRelation`의 끌림(천간합)·결속(육합)·연월조화 강하면 관계 자체가 따뜻 → 전 날짜에 작은 상수 리프트(잘 맞는 커플 달력은 전반적으로 따뜻, 그 위에 일진이 출렁).

**출력(셀·상세):**
- 우리 tone(good/normal/caution) + score
- 오늘 태그: 끌림↑ · 결속 · 삐걱 주의 · 네가/걔가 리드
- "너희 결"(고정 배경): 십신 라벨(`labelAtoB`/`labelBtoA`) · 끌림 · 결속 · 연월조화
- 개인 캘린더의 love/money/work 3축과 달리 둘 사이엔 **단일 우리-score + 관계 태그**로 간다.

**구현**: 신규 순수 함수(가칭 `lib/byeolmaru/pair-day.ts`) + 유닛. 가중치는 `day-score.ts`처럼 **상수 = 정본 · 전부 튜닝 대상**(초기값은 근사, 실데이터로 조정). `Record<ElementRelation, number>` 강제(삼항 체인 금지 — 새 멤버 조용한 0점 방지, 상위 스펙 리뷰 교훈).

## 8. 서술 (LLM, 구독 전용)

- ②-a `app/api/byeolmaru/narrative` 패턴 재사용: nano `generateOnce`, **비자격 미호출**(원가 0), 캐시 키 = (self, partner, day).
- 톤: 별콩 코어(반말·단정 금지·매턴 질문 금지). "너희 결" + 오늘 태그(§7 출력)를 근거로 둘 사이 하루를 서술.
- 비구독 = 서술 미생성 + 완전 블러 + 3일 체험 CTA.

## 9. 계측 (배포와 동시 — 나중이면 첫 7일이 빈다)

신규 `ui_events`(비-PII, `lib/analytics/ui-events.ts` allowlist):
- `byeolmaru_partner_selected`(토글에서 상대 선택)
- `byeolmaru_watch_add`(담기 — meta: 기존 pick / 신규 등록)
- `byeolmaru_watch_limit`(2명 초과 = 5별 지불 트리거 도달)
- `byeolmaru_watch_purchase`(5별 결제 완료)
- `byeolmaru_subscribe_from_woori`(우리 오늘 블러 CTA 경유 구독)

핵심 지표: 우리 오늘 도달 → 담기 → (비구독은) 구독 전환 · 상대 수 분포 · 우리 오늘 D1~D7 재방문. 어드민 = `/admin/free/byeolmaru`(④) 확장.

## 10. 미해결 / 리스크

- 🔴 **히어로 미검증** — "매일 볼 이유가 되나". 노출 실험으로 해결 안 됨(구형태 실패 ≠ 신형태 예측). 의식적으로 받아들이고 ⑥ 후순위로 완화.
- score 가중치 실데이터 튜닝 필요(초기값은 근사).
- 택일 v1 제외(수요 재확인 시 부록으로 부활 가능).
