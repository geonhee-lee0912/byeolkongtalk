# 앱 결제(②) 설계 — 앱 안 별 충전을 애플·구글 결제로

- 상위 설계: `specs/2026-10-12-앱-전환-design.md` §5 ② (스토어 소모성 상품 · 서버 검증 · 환불 회수 · 첫충전 보너스 적용 · 앱 안 토스 숨김)
- 왜: 별은 디지털 재화라 앱 안에서 팔려면 애플 심사 지침 3.1.1·구글 결제 정책상 스토어 결제여야 한다. 지금 앱(웹뷰)에선 토스 결제창이 그대로 떠서 이대로 제출하면 반려 유력
- 운영자 결정(2026-11-23): **직접 구현**(RevenueCat 안 씀 — 처리위탁 추가 없음) · **가격 = 웹과 같게** · **환불된 별은 남은 만큼만 회수**

## 1. 범위

웹에서 돈을 받는 곳은 **별 패키지 결제 하나뿐**이다(별마루 구독·운세·타로는 별 소비). 입구는 둘:
- 상점 `app/shop/page.tsx` — 5종
- 충전 시트 `components/upsell/RechargeSheet.tsx` — 3종(`lib/recharge-default.ts` `SHEET_PACKAGE_IDS`), 별이 모자란 7개 화면에서 뜬다

**앱(웹뷰) 안에서만** 이 둘이 토스 대신 스토어 결제를 쓴다. 웹 브라우저는 그대로 토스.

빠지는 것: 정기 구독(없음) · 구매 복원(소모성이라 해당 없음) · 한국 대체 결제(애플 26%·별도 바이너리) · 앱 출시 전 옛 앱 호환(설치 0대).

## 2. 상품·가격

| 패키지(`lib/constants.ts` `STAR_PACKAGES`) | 별 | 웹 가격 | 스토어 상품 ID |
|---|---|---|---|
| star_10 | 10 | ₩1,000 | `star_10` |
| star_30 | 30 | ₩2,800 | `star_30` |
| star_70 | 70 | ₩5,900 | `star_70` |
| star_150 | 150 | ₩11,000 | `star_150` |
| star_300 | 300 | ₩19,900 | `star_300` |

- 두 스토어 모두 **소모성(consumable)**. 상품 ID 는 패키지 id 그대로(애플·구글 같게) — 서버가 상품 ID → 패키지로 바로 찾는다
- 가격은 웹과 같게. **애플 원화 가격 단계에 ₩2,800·₩11,000 이 있는지 미확인** — 상품 만들 때 App Store Connect 가격 화면에서 보고, 없으면 가장 가까운 단계를 운영자에게 묻는다. 구글은 금액을 직접 적는다
- 앱 화면의 가격 글자는 **스토어가 돌려준 현지 가격 문자열**을 쓴다(우리 상수 아님 — 애플 요구·단계 차이 대비). 별 수는 우리 상수
- 첫충전 보너스(별의 20%, 1인 1회 `bonus_claims`)는 **웹과 같은 규칙·같은 원장**으로 준다 — 웹에서 받았으면 앱에선 없다
- 수수료 15%(애플 Small Business Program · 구글 15% 구간)를 전제. 매출 기록은 손님이 낸 금액(총액), 수수료는 어드민에서 따로 보인다(§6)

## 3. 흐름

```
웹(상점·충전 시트, 앱 안)            앱(mobile)                         서버
 '구매' 누름 ── iap.buy{productId} ─▶ 스토어 결제창(StoreKit 2 / Play Billing)
                                     ├ 취소·실패 ─ iap.result{ok:false, reason} ─▶ 웹: 조용히 닫음/안내
                                     └ 성공(거래 정보) ── POST /api/payment/iap (앱 토큰) ─▶ 검증 → payments 행 → charge_stars → 첫충전 보너스
                                       ◀── {balance, stars, bonus} ──────────────────────┘
                                       거래 마무리(애플 finishTransaction / 구글 consume) — 서버가 성공을 준 뒤에만
 ◀── iap.result{ok:true, balance, bonus} ─ 
 웹: 잔액 갱신·완료 진동(기존 appHaptic)
```

- **서버가 권위**: 앱이 보낸 건 거래 식별자뿐. 서버가 스토어에 직접 물어 확인한다
  - 애플: 거래 ID → App Store Server API `Get Transaction Info`(앱 결제 키로 인증) → 서명된 거래(JWS)를 애플 루트 인증서로 검증(`@apple/app-store-server-library`) → 번들 ID·상품 ID·환경(운영=Production, dev=Sandbox 허용)·환불 여부 확인
  - 구글: 구매 토큰 → Google Play Developer API `purchases.products.get`(서비스 계정) → 구매 상태 PURCHASED·패키지명·상품 ID 확인 → 별 지급 뒤 서버에서 `consume`(소비 = 확인 처리 겸함. 3일 안에 안 하면 구글이 자동 환불)
- **멱등**: `payments.pg_tid` 유니크(`idx_payments_pg_tid`)에 `apple:<transactionId>` / `google:<orderId>`. 같은 거래가 다시 오면 기존 결과를 돌려준다(재시도·앱 재실행에서 안전). `charge_stars` 는 payment_id 로 이미 멱등
- **끝나지 않은 거래**: 앱 실행·로그인 때 스토어의 미완료 거래를 다시 서버로 보낸다(멱등이라 중복 지급 없음) → 성공하면 마무리. 결제는 됐는데 앱이 죽은 경우를 메운다
- **로그인 안 됨**: 앱 상점은 로그인한 사람만 결제 버튼(지금 웹과 같음). 거래를 받은 회원 = 앱 토큰의 회원. 결제 중 로그아웃하면 다음 로그인 회원에게 가지 않도록 — 미완료 거래 재전송은 **로그인한 회원 + 스토어 계정 토큰(appAccountToken/obfuscatedAccountId 에 회원 id 해시)** 이 맞을 때만
- 실패 분류는 토스 3분류를 따른다: 손님 취소(warn 아님, 기록 안 함) / 스토어·서버 검증 실패(error) / 경합(멱등 성공)

## 4. 환불 → 별 회수 (남은 만큼만)

- 애플: App Store Server Notifications v2 `REFUND` → `POST /api/payment/iap/apple/notify` (서명 검증)
- 구글: 실시간 개발자 알림(RTDN, Pub/Sub 푸시) `voidedPurchaseNotification` → `POST /api/payment/iap/google/notify` (Pub/Sub 푸시 인증 토큰 검증)
- 처리: `pg_tid` 로 결제를 찾아 `status='refunded'` + 회수. **회수량 = 그 결제로 준 별 + 그 결제에 붙은 첫충전 보너스**, 잔액이 모자라면 **0 까지만** 빼고 모자란 양을 기록
- 새 DB 함수 `clawback_stars(p_user_id, p_amount, p_payment_id)` — `SECURITY DEFINER` + `REVOKE … FROM PUBLIC, anon, authenticated` + service_role 만. `min(잔액, 요청량)` 을 빼고 `star_transactions`(type `refund`, payment_id `clawback:<결제 id>` — 같은 환불 알림이 두 번 와도 한 번만)에 남기고 `{clawed, shortfall}` 을 돌려준다
- `payments` 에 칸 2개: `stars_clawed_back int`, `clawback_shortfall int` (어드민에서 덜 회수된 환불·반복 계정이 보이게)
- 첫충전 보너스 수령 기록(`bonus_claims`)은 지우지 않는다 — 환불했다고 보너스를 다시 받지 않게
- 웹 토스 환불(어드민)의 별 처리는 바꾸지 않는다(범위 밖 — 지금도 회수 안 함)

## 5. 앱 안 화면

- 상점·충전 시트는 `useAppInfo`(앱이면 플랫폼·버전)로 갈린다. 앱이면: 패키지 카드의 가격 = 스토어 가격 문자열, 버튼 = `iap.buy`. 스토어 가격을 아직 못 받았으면 버튼 대기
- 앱 안에서 **토스 결제창·"웹에서 사면 …"·웹 결제 안내를 보이지 않는다**(애플 3.1.1 — 외부 결제 유도 금지)
- 결과: 성공 = 기존 결제 완료 화면 흐름(잔액·첫충전 보너스 안내·진동) / 취소 = 아무 말 없이 / 실패 = "결제를 마치지 못했어 — 돈이 나갔다면 앱을 다시 열면 별이 들어와"(미완료 거래 재전송이 메운다)
- 브리지 메시지 추가(형식 버전 `BRIDGE_VERSION` 은 올리지 않는다 — 새 type 만 더한다, 앱 ① 규칙): 웹→앱 `iap.products{ids}`·`iap.buy{productId}`, 앱→웹 `iap.products{items:[{id, price}]}`·`iap.result{…}`

## 6. 어드민

- `payments.pg_provider` 'apple' / 'google' 로 나뉜다. 매출 화면에 결제 수단별 줄 + 스토어 수수료(15% 상수, 한 곳에 정의) 추정 줄
- 환불·덜 회수된 양이 보이는 줄. 집계는 SQL RPC 로(AGENTS '어드민 집계')

## 7. 서버 비밀값 (운영자 → Vercel, 값은 채팅에 쓰지 않는다)

`APPLE_IAP_KEY_ID` · `APPLE_IAP_ISSUER_ID` · `APPLE_IAP_PRIVATE_KEY`(앱 결제 키 .p8) · `APPLE_APP_ID`(앱의 숫자 ID — 운영 거래 검증에 필수) · `GOOGLE_PLAY_SERVICE_ACCOUNT`(JSON) · `GOOGLE_PUBSUB_PUSH_EMAIL`·`GOOGLE_PUBSUB_AUDIENCE`(환불 알림 인증). 없으면 앱 결제 라우트만 503(웹·토스 무관). `lib/env.ts` 선택 목록 + `/api/health`

## 8. 순서 (따로 올리는 단위)

1. **마이그레이션 PR** — `clawback_stars` + `payments` 칸 2개(반대편 리뷰 + Claude 리뷰 + 운영자 승인, 카나리아 401)
2. **서버 PR** — 확인 라우트·환불 알림 2개·회수·어드민(env 없으면 꺼진 채). 가짜 스토어 응답으로 라우트 테스트(중복·경합·환불 두 번·잔액 부족)
3. **웹 PR** — 앱 안 상점·충전 시트 분기 + 브리지
4. **앱 PR** — 결제 라이브러리(Expo SDK 58 에 맞는 것 — `expo-iap` 유력, 버전 문서로 확인) + 미완료 거래 재전송
5. **실기기 샌드박스** [로컬에서] — 애플 샌드박스 계정·구글 라이선스 테스터로 구매·취소·앱 죽이기·환불 알림. 출시 전 앱 빌드 1회(알림·화면 실기기 확인과 같이)

## 9. 확인 못 한 것

- 애플 원화 가격 단계에 ₩2,800·₩11,000 이 있는지 — 공식 표상 ₩400~20,000 은 ₩100 단위라 둘 다 있을 것(유력), 콘솔 화면 확인 전
- 한국에서 구글 수수료 15% 가 기존 방식 그대로인지(2026 년 일부 나라만 체계 변경 안내)
- `expo-iap`(6.5.1, StoreKit 2·Play Billing 9) 의 Expo SDK 58 호환 — 예제가 SDK 57 이라 미확인. 계획 Task 7 첫 단계가 관문
- 구글 '개인' 계정이면 비공개 테스트 12명 × 14일이 필요하다 — 앱 결제가 든 빌드로 시작해야 실사용 테스트가 된다
