# 별자리(byeoljari) 데이터 + 라우트 — P2 설계 (2026-08-15)

상위 스펙 `2026-08-15-별-인연-별자리-지도-design.md`의 서브프로젝트 **P2**. 데이터 계층(신규 테이블 · claim RPC) + 라우트/API 뼈대까지. **별자리 SVG · 상징 형상 · 성장형 · 줌 렌더는 P3**, 무료→유료 다리는 P5.

## 0. 배경

- 상위 스펙 §2(위치 = `/fortune` 무료 서브) · §5(바이럴 루프) · §6(비로그인/로그인 깔때기) · §8(프라이버시)의 구현부.
- **기존 테이블 전부 `user_id NOT NULL FK`** → 게스트가 생일조차 저장 불가. 선례 `survey_responses`(nullable `user_id` + `anon_id` + JSONB)가 "게스트가 로그인 없이 쓰고 나중 귀속"을 이미 함 → 그 패턴 계승.
- **P1 `pairRelation` 궁합 엔진 완료**(`lib/saju/pairing.ts`, dev) → P2 조회 API가 소비.

## 1. 목표 & 비스코프

**목표:** 비로그인 생성·참여·공유가 DB에 안전히 흐르고, 로그인 시 claim으로 소유가 이전되며, 조회 API가 P1 궁합 결과를 그래프 데이터로 반환하는 데까지.

**비스코프 (P3/P5):**
- 별자리 SVG · 상징 형상 라이브러리 · 성장형 빈자리 · 줌 · "남이 보는 나" 렌더 — **P3**.
- 별콩이 톤 실제 카피 문구 조립 — **P3**.
- 무료→유료(궁합·기질) 다리 — **P5**.
- P2 페이지는 입력폼·리스트 수준의 최소 뼈대(P3가 시각을 채움).

## 2. 네이밍

- slug `byeoljari`, 기능명 **"별자리"**. 라우트 `/fortune/byeoljari`.
- 테이블·컬럼은 영문 `star_maps` / `star_map_members` (코드 일관성).

## 3. 라우트 & API

**페이지:**
- `/fortune/byeoljari` — 내 별자리(있으면) 또는 만들기. 비로그인 공개(fortune 탭이 이미 무가드).
- `/fortune/byeoljari/[shareId]` — 카톡 공유 링크로 온 게스트 랜딩. noindex.

**API** (전부 `getServiceSupabase()` service_role, `anon_id`/`user_id`는 **서버 `getSession()`에서만** 파생 — 클라 전송값 불신):
- `POST /api/fortune/byeoljari` — 지도 생성. `creator_anon_id` 귀속 + `share_id` 발급 + 호스트 자기 별(member, `is_host`) 생성.
- `GET /api/fortune/byeoljari/[shareId]` — 지도 + 멤버 + **쌍별 `pairRelation` 그래프** 반환. **무인증**(공유용). `birth_date` 등 PII 미반환(계산 결과·라벨만). `compat_visible` 옵트인 반영.
- `POST /api/fortune/byeoljari/[shareId]/join` — 게스트 참여. 생일 입력 → member 추가(`member_anon_id` 귀속). 중복 참여(같은 anon_id) 방지/갱신.
- `POST /api/fortune/byeoljari/claim` — 로그인 콜백 후 자동 호출. `claim_star_maps(anon_id, user_id)` RPC 위임.

## 4. 데이터 모델 (신규 2 테이블)

```
star_maps
  id              UUID PK DEFAULT gen_random_uuid()
  share_id        TEXT UNIQUE NOT NULL          -- 짧은 코드(URL), 형식은 §8
  owner_user_id   UUID REFERENCES users(id) ON DELETE CASCADE   -- nullable: claim 전 NULL
  creator_anon_id TEXT NOT NULL                 -- 만든 브라우저 쿠키
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()

star_map_members
  id              UUID PK DEFAULT gen_random_uuid()
  map_id          UUID NOT NULL REFERENCES star_maps(id) ON DELETE CASCADE
  display_name    VARCHAR(50) NOT NULL
  birth_date      DATE NOT NULL                 -- 비공개(계산 전용), 응답에 미반환
  birth_time      TIME                          -- nullable = 시간 모름(일지 지표엔 무관)
  relation_type   VARCHAR(20) NOT NULL          -- CHECK: 'friend','lover','acquaintance','senior' (친구/연인/지인/상사)
  member_anon_id  TEXT                          -- 넣은 사람(nullable: 호스트 대리입력 가능)
  is_host         BOOLEAN NOT NULL DEFAULT false
  name_public     BOOLEAN NOT NULL DEFAULT false -- 옵트인: 이름 공개(기본 별만)
  compat_visible  BOOLEAN NOT NULL DEFAULT false -- 옵트인: 다른 게스트에게 내 궁합 공개(기본 호스트만)
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
```

- **RLS**: 두 테이블 `ENABLE ROW LEVEL SECURITY` + 정책 0(deny-all) + `REVOKE ALL … FROM PUBLIC, anon, authenticated` + `GRANT ALL … TO service_role`. 마이그레이션 `<ts>_star_maps.sql`.
- 사주 계산은 **조회 시 `birth_date`로 `calcSaju` 재계산**(캐시 여부는 §8 열린 결정). `gender`는 `calcSaju` 시그니처상 필요하나 일간·일지 지표엔 무관 → 게스트에게 안 물어보고 기본값(`"other"`).

## 5. claim 메커니즘 (게스트 → 호스트 소유 이전)

- `claim_star_maps(p_anon_id TEXT, p_user_id UUID)` **SECURITY DEFINER RPC** (`REVOKE … FROM PUBLIC, anon, authenticated` + `GRANT … TO service_role`): `creator_anon_id = p_anon_id AND owner_user_id IS NULL`인 지도를 `owner_user_id = p_user_id`로 UPDATE. per-anon advisory lock으로 원자화.
- 호출 시점: 카카오 로그인 콜백 성공 직후 서버가 현재 세션의 `anon_id` + 새 `user_id`로 자동 호출(추가 UI 없음).
- 코드베이스에 anon→user claim 선례 없음 = **신규 로직** (SECURITY DEFINER는 `create_relationship` 패턴 참고).

## 6. 게스트 보관 & 프라이버시

- **생일 보관 = 원본 `DATE` 저장 · 계산에만 · 응답/노출 0 · 호스트가 지도 삭제 가능**(사용자 확정 (a)). 프라이버시는 저장이 아니라 **응답에서 막음**(GET이 PII 미반환).
- **옵트인 3단 (member, 보수적 기본):** `name_public`(별만 vs 이름) · `compat_visible`(호스트만 vs 전체) · 생일 항상 비공개.
- 🔴 **비로그인 소실 한계 UI 명시 (사용자 지시):** `anon_id` 쿠키 기반이라 **다른 기기/브라우저 로그인 · 쿠키 삭제 시 자동 승계 실패**(데이터는 DB 잔존 · `share_id` 링크 접근은 유지 · '내 것' 연결만 실패). 페이지에 안내 문구 필수(예: "로그인하면 이 별자리를 영구 보관해요 · 안 하면 이 기기에서만 볼 수 있어요"). 같은 기기는 쿠키 유지라 정상 승계.

## 7. 공유 인프라 재사용

- 공유-읽기: `GET …/[shareId]`가 `app/api/readings/[id]/public` 패턴(무인증·service_role·PII 미반환·`has_sensitive` 차단) 계승.
- 동적 OG: `app/api/og/*`의 `ImageResponse` 패턴으로 별자리용 OG 이미지(빈 자리 노출 = "채워줘" 썸네일). rate-limit 재사용.
- 카톡: `lib/kakao-share.ts` `shareToKakao` 그대로.

## 8. 열린 결정 (plan에서 확정)

- **`share_id` 형식** — 짧은 코드(nanoid ~8자, URL 친화) vs UUID. 추측성/충돌 고려.
- **saju 캐시** — member에 계산 결과 캐시 컬럼(JSONB)을 둘지, 조회 시 매번 `calcSaju` 재계산할지.
- **claim 타이밍 구현** — 로그인 콜백에 훅을 어디에 걸지(`lib/session.ts`/OAuth 콜백 라우트).
- **음력 입력** — 게스트 입력에 음/양력 선택을 줄지(마찰↑) vs 양력 고정.
- **중복 참여** — 같은 `member_anon_id`가 다시 join 시 갱신 vs 새 member vs 차단.
- **비로그인 소실 안내 문구** 최종 카피(P3 톤과 함께).
