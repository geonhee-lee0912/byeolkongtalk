# 별자리(byeoljari) 렌더 + 두 뷰 — P3 설계 (2026-08-16)

상위 스펙 `2026-08-15-별-인연-별자리-지도-design.md`의 서브프로젝트 **P3**. P2(데이터·라우트·`pairRelation` 그래프 API)가 만든 `nodes/edges/triads`를 **시각(별자리)으로 렌더**한다. 넓게 뷰(관계망) ↔ 줌 ↔ 1:1 뷰, 상징 형상, 성장형, 별콩이 카피, SEO까지 = 상위 스펙 §2·§4의 **풀 비전(C)**. 바이럴 초대·게이팅은 P4, 무료→유료 다리는 P5.

## 0. 배경 / 입력

- P2 조회 API(`GET /api/fortune/byeoljari/[shareId]`)가 반환하는 계약을 소비한다:
  - `nodes[]`: `{ id, name(옵트인 시만·아니면 null), isHost, relationType, element(오행), compatVisible }`
  - `edges[]`: `{ a, b, element(관계 5분류), labelAtoB, labelBtoA, heavenlyCombo, sixCombo }` — 호스트가 끼거나 양쪽 `compat_visible`일 때만 포함(P2가 필터)
  - `triads[]`: `{ element, memberIds[] }` — 3인 삼합 클러스터. `memberIds`는 같은 일지 멤버가 여럿이면 3 초과 가능(렌더는 `length===3` 가정 금지)
- 렌더는 룰 100%·LLM 0(상위 스펙 §3). 카피 문구도 룩업 테이블.

## 1. 목표 / 비스코프

**목표:** P2 그래프를 별콩이 세계관의 별자리로 그려, 넓게(관계망)·좁게(1:1) 두 뷰로 탐색·공유 가능하게. 도령 "평면 한 장"과 갈라지는 **줌 되는 진짜 관계망**을 시각으로 실현.

**비스코프:**
- 바이럴 초대 링크·"채워줘" 카톡·N명 게이팅·콕집기 → **P4**
- 무료→유료(궁합·기질) 다리 → **P5**
- 형상 실루엣 **에셋의 최종 완성도**(전문 일러/AI 파이프라인) → 별도 제작 트랙(스펙엔 규칙·경계만)
- 카피 **실제 문구 테이블** → 구현 시 채움(스펙엔 원칙·구조)

## 2. 렌더 아키텍처 — 관계망 우선 + 형상 은은 (핵심 결정)

형상을 전면에 세우는 안(형상 우선)은 실증 결과 **모바일에서 별·관계선과 엉키고 작아져** 기각. 이 서비스의 핵심 가치는 "진짜 관계망"이므로 무게중심을 관계에 둔다:

- **주인공 = 관계망** (오행별 노드 + 관계선 + 삼합 + 빈자리) — 진하고 또렷
- **상징 형상 = 뒤 배경의 아주 연한 실루엣**(opacity ~0.08~0.1) — "무슨 별자리(청룡 등)"라는 정체성·무드만 은은히. 별은 관계 기반으로 배치(형상 윤곽에 억지로 맞추지 않음)

> 상위 스펙이 형상 아키텍처로 남긴 A(관계망 우선)/B(형상 우선)/C(절충) 중, 실증을 거쳐 **A에 가까운 "관계망 우선 + 형상 은은 배경"**으로 확정. B/강한 C는 모바일 부담으로 폐기.

### 에셋 / 코드 경계

| 요소 | 담당 |
|---|---|
| 형상(동물 실루엣) 이미지 | **에셋**(일러/AI) — 15종, 투명 PNG, 은은한 오행 틴트, 화면에선 낮은 opacity |
| 형상별 "별이 놓일 윤곽 path" 데이터 | **데이터**(수작업 정의) — 인원만큼 별을 분포시킬 곡선 |
| 밤하늘 배경 · 노드(별/원) · 관계선 · 삼합 · 천간합 · 빈자리 · 라벨 · 줌 · 1:1 · 관계필터 · 카피 | **코드** |

**핵심:** 일러로는 형상(동물)만 뽑고, 별·선·배경·인터랙션은 전부 코드. 별 위치는 형상 윤곽 path 위에 **참여 인원만큼 동적 분포**(고정 앵커 개수 아님).

## 3. 시각 시스템 (실증 확정)

- **배경:** 진한 밤하늘 `#1F1735`(별콩 `night` 정본). 지도 비율 **정사각(1:1)**.
- **오행색(노드·선) — "발광 소프트" 팔레트** (별콩이 파스텔은 밤하늘 위 칙칙해 기각, 발광 젬톤 채택):
  - 목 `#4FD6B8` · 화 `#FF8A6B` · 토 `#FBC94D` · 금 `#EDE6D6` · 수 `#8AB4F8`
  - ⚠️ 기존 `ELEMENT_COLORS`(밝은 카드 UI용)와 별개인 **별자리 전용 팔레트**. 정본 통일(SajuBoard 회귀) 여부는 열린 결정(§11).
- **노드 = 순수 별 또는 순수 원**(절대 합치지 않음 — 별을 원이 감싸는 halo 금지):
  - **별**(둥근 꼭지, `stroke-linejoin:round`로 통통하게) = 참여자·호스트
  - **원**(채운) = 나(뷰어) — 관계망에서 즉시 식별
  - **호스트** = 제일 큰 별 + 중심 위치 + 이름 라벨(별도 모양·테두리 없음)
  - **빈자리** = 점선 원(골드)
  - 색은 별·원 자체에 오행색으로 칠함(링 아님)
- **삼합** = 3노드 골드 삼각(반투명 채움 + 굵은 골드 선). 별자리의 "심장".
- **천간합/육합** = 케미 스파크/결속선(엣지 배지·선 처리).
- **형상 실루엣** = 오행 신수(§4)를 연한 면으로 뒤에.

## 4. 상징 형상 라이브러리 — 오행 신수 × 진화

**매핑 규칙:** 그룹의 **지배 오행(최빈 오행)** = 신수 계열, **인원** = 진화 단계 + (윤곽 path 위) 별 개수.

**진화 = 소동물 → 중간(독립 형상) → 신수** (각 단계가 다른 형상이라 "도감 수집" 재미. 신수의 축소판이 아님):

| 오행 / 신수 | 소(~5명) → 중(~10명) → 대(~15명, 신수) |
|---|---|
| 목 / 청룡 | 청개구리 → 이무기 → 청룡 |
| 화 / 봉황 | 반딧불이 → 공작 → 봉황 |
| 토 / 기린 | 옥토끼 → 사슴 → 기린 |
| 금 / 백호 | 흰 담비 → 눈표범 → 백호 |
| 수 / 현무 | 해마 → 가오리 → 현무 |

- **성장형:** 티어별로 형상이 진화(포켓몬식). **진화 임계 = 5·10·15명**(5명=소동물 완성 → 10명=중간 → 15명=신수 완성). 격하감 없이 "자라는/진화하는" 긍정 프레이밍. 완성 순간 가벼운 축하 + 다음 예고("○명 더 오면 ○○로"). 15명 초과는 신수 완성 상태 유지(별만 추가).
- **MVP 형상 개수:** 5신수 × 3단계 = 15종이 목표. **MVP는 중간 단계 5개부터** 제작 후 확장(상위 스펙 §10 "소수로 시작").
- **에셋 형태:** 화면 전면이 아니라 **은은한 배경**이라 단순 실루엣으로 충분(디테일 과하면 모바일 부담). 실증한 "미니멀 플랫 실루엣(A)"이 배경용으로 적합(라인아트는 연하게 하면 안 보여 배경엔 부적합).

## 5. 두 뷰 + 줌

- **넓게 뷰(별자리):** 정사각 관계망. 호스트 중심 + 오행색 관계선 + 삼합 강조 + 형상 은은 배경 + 빈자리. 단톡방 통째 공유용.
- **줌 전환:** 별 하나 탭 → 그 사람 중심으로 **줌인 → 1:1 뷰**. `← 별자리로`로 복귀. (도령 "평면 한 장" 대비 차별 = 줌 되는 지도.)
- **1:1 뷰(좁게):** 나 ↔ 상대. 구성:
  - 오행 관계(생아/아생/극아/아극/비화) 한 줄
  - **양방향 십신** 두 칸: "내가 보는 상대"(`labelAtoB`) / **"상대가 보는 나"(`labelBtoA`) = 골드 강조** ← §2 차별점 "남이 보는 나"
  - 천간합/육합 배지(케미)
  - 별콩이 한 줄 카피
  - 개인 카드 공유(P4 연동)

## 6. 관계 필터

관계분류(친구/연인/지인/상사) 칩으로 **특정 관계만 강조, 나머지는 dim**(opacity↓). 관계망이 복잡할수록(다인원) 부분 탐색에 유용. 코드로 선택 상태 → 비해당 노드/선 opacity 낮춤.

## 7. 인원 스케일 대응

인원이 많아질 때(15명+) 복잡도·엉킴을 관리:

1. **관계선은 전체 쌍(n²)을 절대 그리지 않음** — 호스트 중심(star) + 특수 관계(삼합·천간합·육합)만. 15명이어도 선 ~15+α.
2. **줌/팬** — 축소 상태선 별·형상만, 확대하면 이름·상세.
3. **관계 필터**(§6)로 부분 보기.
4. **별 크기·선 굵기 인원 적응**(많을수록 작게).
5. 극단(예 30명+) = 상한 캡 또는 오행별 소성좌 분할 — 후속(§11).

## 8. 별콩이 카피 (원칙·구조만, 문구는 구현)

- P1 `TEN_GOD_LABEL` 10종 라벨을 시작점(예: 정관→"든든한 지원군"). 오행 관계 5분류 + 십신 10 + 관계분류 4의 조합으로 문구 조립.
- **관계분류(친구/연인/지인/상사)는 문구 톤만 조정**(같은 십신이라도 연인/상사 톤이 다름).
- 화법은 **코어 페르소나 준수**: 단정적 예언 금지 · 흐름/가능성/선택 · 불안 자극 금지 · 따뜻한 마무리. 실제 문구 테이블은 구현 시.

## 9. SEO

- `/fortune/byeoljari`(만들기·설명 페이지) = **색인 O**(로그인 없는 인터랙티브 도구 엔드포인트, 상위 스펙 §0).
- 개인 별자리 `/fortune/byeoljari/[shareId]` = **noindex**(P2에서 이미 설정, 공유 전용).

## 10. 프라이버시 옵트인 (보수적 기본)

상위 스펙 §8·P2 스키마(`name_public`/`compat_visible`)대로:
- 이름 비공개(별만) · 내 궁합은 호스트만(전체 게스트 아님) · 생일 항상 비공개(GET이 PII 미반환)
- 게스트 참여 시 체크박스로 옵트인(P2 join API가 이미 두 플래그 수신)

## 11. 열린 결정 (플랜에서 확정)

- **형상 윤곽 path 정의 방식** — 형상 에셋에 별 배치용 곡선을 어떻게 데이터화(SVG path 좌표? 정규화 곡선?).
- **줌 구현** — CSS transform 트랜지션 vs 라우트 전환 vs SVG viewBox 애니.
- **다인원 캡 수치·소성좌 분할** 트리거(15명=신수 완성 이후, 예 30명+).
- **별자리 전용 오행 팔레트 vs 정본 통일** — 새 팔레트를 별자리에만 둘지, `ELEMENT_COLORS` 정본까지 바꿀지(SajuBoard 회귀 QA 동반).
- **에셋 제작 파이프라인** — 15종 실루엣을 higgsfield/일러 중 무엇으로, 어느 순서로.
- **MVP 렌더 우선순위** — 넓게 뷰·1:1·줌·필터·형상·성장형 중 첫 배포에 무엇까지.

## 12. 폴백

형상(은은 배경)조차 구현 부담이 크거나 엉키면 **형상 없이 순수 관계망**으로 폴백(형상은 후속 레이어). 관계망·1:1·줌은 형상과 독립적으로 성립.
