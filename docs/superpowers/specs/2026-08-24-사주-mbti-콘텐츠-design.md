# 사주 MBTI — 콘텐츠 집필 설계 (하위 프로젝트 C)

> 하위 프로젝트 **C(콘텐츠 집필)**. A(축 매핑)·B(문항→자아유형+일치율)는 구현 완료.
> 원 기획서: `~/Downloads/saju-mbti-test-기획정리.md`(§4 16유형 매트릭스·§5 오행). 작성 2026-08-24.

## 1. 목표 · 범위

16유형 매트릭스(기획서 §4 확정)를 토대로 결과에 쓰일 **정적 텍스트 콘텐츠**를 집필한다. 순수 데이터·LLM 0(별자리 지도 노선, A·B와 동일).

- **범위**: ① 16유형 본문 해석문 ② 오행 질감 모듈 5종 ③ 일치율 밴드 서사 3종 ④ 카드 문안(밈 부제·공유 문구). 한자 낙관·캐릭터·오행 컬러는 기획서 §4·§5 확정값 재사용.
- **비범위**: 결과 화면 **렌더·비주얼 시스템**(오각차트·낙관 도장·오행 80색 변주·애니메이션·%막대)=D. 입력 순서·퍼널·공유 기능 구현=E. §6의 결과 흐름은 콘텐츠 구조를 규정하므로 여기서 확정하되, 렌더는 D.
- **의존**: B의 `selfType`/`matchRate`, A의 `paljaType`(`code`·`element`)이 이 콘텐츠의 키를 만든다. 콘텐츠는 그 키로 조회되는 표시층.

## 2. 확정 결정

| 결정 | 값 |
|---|---|
| 보이스 | **하이브리드** — 본문 해석=별콩이 톤(따뜻·차분·신비·장난기), 밈 부제·공유 문구=위트 레이어 |
| 본문 구조 | **스탠다드** — 밈 부제 · 한 줄 정의 · 성격(3~4문장) · 빛 · 그림자(출구 有) · 연애 · 궁합 · [팔자 한정]오행 한 줄 |
| 결과 흐름 | **리빌-라스트** — 상단 팔자 히어로 → 본문 설명 → 하단 자아 갭 리빌(일치율) |
| 자아 카드 | **별도 풀 카드 없음** — 하단 리빌에서 유형명+갈린 축+밴드 서사만(탭 시 같은 16풀 재사용) |
| 저장 | **타입 안전 TS 모듈** `lib/saju-mbti/content.ts` + 계약 테스트 |
| 오행 | 팔자 카드에만 한 줄(자아엔 오행 없음, B 결정). 오행별 고정 형용사(16×5=80을 21로 커버) |
| 일치율 | **극 일치 수 0~4**(B 결정) → 4=천명/2~3=절충/0~1=거스름. ⚠️기획서 §7 "%차이 평균"은 B에서 폐기 |

## 3. 보이스 규칙 (불변식)

- **본문 해석(성격·빛·그림자·연애) = 별콩이 톤**: ①단정적 예언 금지("~인 쪽이야", "~인 편이야" 관찰형) ②1인칭 `내가 보기엔`, 2인칭 `너`(반말) ③불안 자극·운명론 협박 금지 ④따뜻한 마무리 ⑤장난기는 절제.
- **밈 부제·공유 문구 = 위트 레이어**: MBTI 밈 문법("특징: …", "십중팔구 너") 계승, 펀치·공유력 우선.
- **원칙② (거스름=주체성)**: 일치율 밴드에서 팔자를 "진짜 너"라 우기지 않는다. 팔자=씨앗/타고난 결, 자아=네가 살아낸 너. 거스름은 열등이 아니라 "스스로 다시 쓴" 주체성.
- **그림자(약점)는 출구와 함께**(원칙 완충): 결점을 박제하지 말고 "~해도 돼"로 문을 연다.

## 4. 콘텐츠 모델 (TS)

```ts
import type { FiveElement } from "@/lib/saju/elements";
import type { MatchBand } from "./match.ts";

export type Code16 = string; // 4자 한글코드. 계약 테스트가 16 완결성·유효성 검증(A·B 방식)

export interface CompatEntry { code: Code16; reason: string } // reason=밈 한 줄
export interface TypeContent {
  hanja: string;        // 陰柔印生 (기획서 §4)
  character: string;    // 우렁각시
  memeSubtitle: string; // 위트
  oneLiner: string;     // 별콩이 한 줄
  personality: string;  // 3~4문장
  light: string;        // 빛(강점)
  shadow: string;       // 그림자(출구 有)
  love: string;         // 연애·관계
  compat: { fits: CompatEntry[]; clashes: CompatEntry[] }; // fits 1~2, clashes 1
  shareText: string;    // 공유 문구(위트)
}
export const TYPE_CONTENT: Record<Code16, TypeContent>;     // 16

export interface ElementModule { texture: string }          // 오행 질감 한 줄
export const ELEMENT_MODULE: Record<FiveElement, ElementModule>; // 5 (목화토금수)

export interface MatchNarrative { title: string; body: string }
export const MATCH_NARRATIVE: Record<MatchBand, MatchNarrative>; // 천명/절충/거스름
```

## 5. 16유형 본문 — 칸별 스펙 + 캔버스 완본

각 칸의 분량·역할(캔버스=우렁각시 음유인생, 승인됨):

- **memeSubtitle**(위트): 몰래 다 차려놓고 생색은 0. 남들 다 자는데 부엌 불 켜져 있으면 십중팔구 너.
- **oneLiner**(별콩이): 티 없이 다 해두고 슬며시 물러나는, 소리 없는 다정.
- **personality**(3~4문장): 너는 앞에 나서서 판을 쥐기보다 뒤에서 필요한 걸 미리 채워두는 쪽이야. 시끌벅적한 자리보다 마음 맞는 몇과의 깊은 온기를 더 오래 기억하고, 돈 되는 일보다 '의미가 남는 일'에 손이 먼저 가지. 내가 보기엔 네 다정함은 소리가 없어서 티가 안 날 뿐, 사라지는 게 아니라 더 오래 스며드는 쪽이야.
- **light**(1~2줄): 남이 놓친 빈자리를 먼저 보는 눈. 곁에 있으면 어느새 삶이 정돈돼 있어.
- **shadow**(1~2줄, 출구): 다 해주고 "나 여기 있어"는 삼키는 편이라, 알아주지 않으면 혼자 서운함이 고여. 티 내는 건 지는 게 아니야 — 네 몫도 소리 내어 챙겨도 돼.
- **love**(2~3문장): 좋아하면 말보다 챙김이 먼저 나가. 상대의 빈틈을 조용히 메우는 연애를 하는데, 문제는 그걸 상대가 다 눈치채진 못한다는 거야. 한 번씩 웃으며 "이거 내가 해준 거야" 생색도 내봐 — 그게 관계를 더 단단하게 해.
- **compat**: fits=[도깨비(양강재생) "네가 조용히 판을 깔면 걔가 시끌벅적 터뜨려. 티 안 나는 손 + 티 나는 손."] · clashes=[구미호(음강인단) "둘 다 속으로만 굴리다 오해 적립. '말을 해야 알지'가 평생 숙제."]
- **shareText**(위트): 나 우렁각시래. 넌 뭐 나옴? 👀

**나머지 15유형**: 기획서 §4의 캐릭터·밈 부제를 앵커로 같은 칸 규격·같은 보이스로 집필(플랜에서 생산). 궁합 fits/clashes는 **큐레이션**(축 상보/충돌을 서사로), 계약 테스트가 코드 유효성 검증.

## 6. 결과 흐름 (리빌-라스트 — D 핸드오프)

콘텐츠 구조를 규정하므로 여기서 확정. 렌더는 D.

1. **상단 (클린·임팩트)**: 팔자 유형만 — 낙관(한자) + 캐릭터 + 오행 표기 + `oneLiner` + `memeSubtitle` 칩 + 하단 유도 티저.
2. **본문 (타고난 너)**: `personality` · `light`/`shadow` · `love` · `compat` · 오행 `texture`(팔자 한정).
3. **하단 리빌 (페이오프)**: "그런데, 네가 문항에서 답한 너는—" → 자아 유형명(제비 등) → **4축 비교**(`matchRate.perAxis`로 갈린 축 표시) → 일치율 밴드(`MATCH_NARRATIVE`) → 원칙② 서사. `perAxis`로 "어긋난 축: 음양" 동적 한 줄 가능(D 선택).
4. 공유/저장.

> 자아는 여기서 **유형명 + 갈린 축 + 밴드 서사**만. 별도 풀 카드 없음 → 스크롤 단축. 상단 캡처 공유 대비 D가 밴드를 이미지에 조합.

## 7. 오행 모듈 5종 (팔자 한정, 오행별 고정)

16 뼈대에 얹는 **질감 형용사 한 줄**. 오행별 고정이라 어느 유형에 붙어도 읽히게(범용). 기획서 §5 방향 재작성:

- **火**(캔버스): 잠잠하다가도 아끼는 것 앞에선 앞뒤 없이 확 타오르는 불씨를 품은 쪽이야.
- **木**(청록) / **土**(황) / **金**(백·은) / **水**(흑·남): 각 한 줄로 집필(木=명분·방향이 서야 곧게 뻗는 / 土=내 사람에게 묵직하게 오래가는 / 金=원칙을 벼려 맺고 끊는 / 水=소리 없이 스며드는). ⚠️水는 음유인생 뼈대와 겹치므로 "이중으로 깊은"식 공명으로.

## 8. 일치율 밴드 3종 (원칙②)

밴드당 1개 공통 서사(유형 무관). 별콩이 톤 + 주체성 프레이밍:

- **천명 (4/4)** title "천명대로 사는 자": 네가 아는 너와 타고난 너가 네 축에서 그대로 포개졌어. 억지로 꾸민 게 아니라 결대로 살아온 거야. 이런 사람은 드물어 — 애써 되려 하지 않아도 이미 제자리에 있는 셈이지.
- **절충 (2~3/4)** title "절충하며 사는 자"(캔버스): 타고난 결과 네가 만든 너가 몇 군데는 겹치고 몇 군데는 어긋나. 세상 대부분이 여기야. 어긋난 축이야말로 네가 살면서 스스로 고쳐 쓴 자리 — 타고난 걸 그냥 따르지 않고 네 방식으로 조율해 온 흔적이야.
- **거스름 (0~1/4)** title "팔자를 거스르는 자": 타고난 결과 네가 사는 방식이 거의 반대야. 근데 이건 틀린 게 아니라, 넌 팔자를 그냥 받지 않고 스스로 다시 쓴 거야 — 씨앗은 이렇게 심겼는데 넌 다른 꽃을 피우기로 한 거지. 가장 주체적인 자리가 여기 있어.

## 9. 카드 문안

- **밈 부제**: 유형별 1개(§5 `memeSubtitle`). 기획서 §4 부제를 다듬어 앵커.
- **한자 낙관**: `hanja`(기획서 §4 확정). 렌더는 D(도장 스타일).
- **공유 문구**: 유형별 1개(§5 `shareText`). "나 ○○래, 넌?" 유도.

## 10. 검증 (성공 기준)

- **계약 테스트**(`content.test.ts`): ①`TYPE_CONTENT` 키가 16개·전부 유효 코드(A·B가 만드는 코드 집합과 일치) ②각 유형 8칸 비어있지 않음 ③`compat.fits`/`clashes`의 모든 `code`가 유효 16코드 ④`ELEMENT_MODULE` 5개(목화토금수) ⑤`MATCH_NARRATIVE` 3밴드. 렌더 검증은 D.
- **파일럿(범위 밖)**: 실사용자 체감 정확도는 B §7 파일럿과 함께. 여기선 구조·보이스 완결성만.

## 11. 후속

- **D 결과화면**: 리빌-라스트 렌더·4축 %막대·오각차트·낙관·오행80색·공유이미지. (별도 spec→plan)
- **E 플로우**: 사주 입력↔12문항 순서·퍼널·공유 기능. (별도 spec→plan)
