# 별마루 Phase 5 — 화면·UX 전면 개편 (design)

작성 2026-09-12. 정본 `2026-09-07-별마루-개편-무료허브-design.md` 의 §10 **4단계 밖에 얹는 5단계**.
Phase 1~4a 로 기능은 다 지어졌고(4b 초대 = 백로그), P5 는 **기능을 전부 보존한 채 화면·정보구조·동선만 다시 짠다.**

> 스코프 = **별마루 3화면 한정** (`/byeolmaru`, `/byeolmaru/saju`, `/byeolmaru/woori` + 모달).
> 홈·2탭·마이는 건드리지 않는다.

---

## 1. 왜 (문제)

지금 별마루는 **모든 블록이 똑같은 `rounded-2xl bg-cream-warm p-4` 박스**를 `space-y-4` 로 쌓은 화면이다. 보더·그림자·일러스트·호버·모션이 없고 구분은 이모지 하나뿐이라 **위계가 존재하지 않는다.** 같은 앱의 홈(`app/page.tsx`)은 그라데이션 아이콘 타일 + PNG 일러스트 + 해시태그 칩 + 호버를 쓰는데, 별마루만 한 단계 아래에 머물러 집 안에서 혼자 톤이 다른 방이 됐다. Phase 3~4 에서 "비주얼 과투자 금지, 폴리시는 P5"로 의도적으로 미룬 결과다.

화면 문제 외에 **설계 구멍 세 개**가 이번 개편 과정에서 드러났다.

1. **비구독자 첫 화면에 구독할 이유가 없다.** 무료가 30일 달력을 전부 보고, 잠금은 인연 탭을 눌러야 나온다. 상대를 안 담은 사람은 그 탭에 갈 일이 없다. 스펙 §11 "페이월 균일 리스크"가 이 모양으로 나타났다.
2. **유료 가치에서 breadth 축이 사실상 없다.** 무료가 이미 30일 등급을 다 보므로 구독은 "LLM 서술 깊이" 하나로 얇아진다.
3. **출석 보상이 필요한 쪽과 받는 쪽이 반대다.** 환급은 구독자 전용인데 구독자는 이미 다 열려 있어 매일 올 이유가 없고, 매일 올 이유가 필요한 비구독자는 아무것도 못 받는다. 게다가 지급이 구독 만료 후 lazy 라 체감이 30일 뒤다.

## 2. 원칙

- 기능은 전부 보존한다. 재설계 대상은 **화면·정보구조·동선**이다.
- 디자인 정본은 `app/globals.css` `@theme` 토큰. **새 색을 만들지 않는다.**
- 페이월은 **배너가 아니라 콘텐츠의 연장**으로만 존재한다. 이 서비스에서 배너형 업셀은 역사적으로 안 먹혔다(C3 인챗 업셀 미작동, 낙수 회수 19~22%).
- 자물쇠(🔒)를 쓰지 않는다. 잠긴 것이 아니라 **아직 안 온 것**으로 표현한다.

**확정 사항**

- **달력이 히어로.** 사용자 판단("달력이 확실히 임팩트 있다"). 30일 그리드를 허브에 바로 펼친다. 스펙 §4 의 "홈엔 이번 주 미니 프리뷰(7일 점)"는 **폐기** — 미니 프리뷰는 임팩트를 죽인다.
- **무료 목록은 2탭(`/fortune`) 리스트와 동형.** 가로 행 카드 = 아이콘 타일 + 라벨 + 가격/상태 칩 + 태그라인 + 해시태그. 사용자 요구("무료 상품들은 다른 탭의 목록과 같은 형태면 좋겠어").
- **목록은 3종** — 오늘 타로 · 사주 MBTI · 별 인연 지도. **우리 오늘 줄은 제거**하고 달력 탭으로 들어간다(§8).
- **오늘 사주도 목록에 없다.** 달력 판 자체가 진입점이다.

### 3-1. 아이콘

`public/icons/fortune/` 에 **`saju_mbti.webp` · `byeoljari.webp` · `daily.webp` · `compat.webp` 가 이미 있다.** 오늘 타로만 신규가 필요한데, 그것도 새로 뽑지 않는다 — **타일 자리에 카드 이미지를 직접 넣는다**(§12).

## 4. 비주얼 — 라이트 B

다크 톤(밤하늘 판)도 검토했으나 **라이트 채택**(사용자 결정). 라이트로 가면 "잘 맞는 날이 어둠 위에서 발광하던 효과"를 잃으므로, **판 안에 명암을 만들어 보상**한다.

| 요소 | 값 |
|---|---|
| 판 배경 | `linear-gradient(160deg, #FFFBF2, #EFE6FA)` + `1px rgba(184,168,216,.35)` 보더 + 부드러운 그림자 |
| 오늘 히어로 | 배경에 녹이지 않고 **골드 타일로 띄운다** (`#FFF3D6 → #F2D78A`, 그림자). 라이트에선 이래야 오늘이 산다 |
| 잘 맞는 날 | `#E8C26A` 솔리드 + 그림자 |
| 무난한 날 | **순백 `#fff`** ← 판 안에 명암을 만드는 핵심 |
| 챙길 날 | `rgba(255,255,255,.45)` + 옅은 보더 |
| 오늘 칸 | `0 0 0 2px #5A3E8C` + `scale(1.07)` |
| 안 온 날 | `rgba(255,255,255,.28)` + 점선 보더 + 옅은 점(자물쇠 금지) |
| 목록 카드 | 흰 배경 + **좌측 4px 컬러 바** + 큰 타일(48px) + 그림자. 오늘 타로만 골드 바 |
| 섹션 타이틀 | 골드 3px 바 + 골드 밑줄 |

⚠️ 판 안의 흰 칸과 아래 목록의 흰 카드가 섞여 보일 수 있다. 목록 카드의 좌측 컬러 바와 그림자가 구분자 역할을 하도록 유지할 것.

## 5. 하루 이름 다변화 — 십신 10종

**문제:** 30일 달력이 `잘 맞는 날 / 무난한 날 / 살짝 챙길 날` 3종뿐이라 평평하다.

**실측(전수 7,200 케이스 = 나 120명[일간10×일지12] × 일진 60갑자):**

| 그날 오행이 내게 | 좋은 날 | 챙길 날 |
|---|---|---|
| 없음 | 30일 중 7.9일 | 1.0일 |
| 부족 | 7.8일 | 4.8일 |
| 보통 | **1.9일** | 5.6일 |
| 과다 | **0.6일** | **12.8일** |

30일엔 다섯 오행이 6일씩 섞이므로 **보통 사람은 좋은 날 3~5일 · 챙길 날 5~7일 · 나머지 20일 안팎이 전부 "무난한 날"**이다.
→ **쪼갤 대상은 좋은 날이 아니라 무난한 날 20일이다.**

**채택 = 십신(`tenGod()`) 기반 하루 이름.**

- 십신은 지금 점수가 쓰는 `elementRelation`(5종)을 **음양으로 쪼갠 것**이다(생아=정인·편인, 아극=정재·편재 …). 즉 **판정을 전혀 안 건드리고 정확히 2배로 갈린다. 재튜닝 불필요 · 추가 계산 0 · 무회귀.**
- 일진 천간은 10일 주기라 **30일이면 십신 10종이 정확히 3일씩** 들어온다(실측 10.0% 균등).

| 십신 | 하루 이름(초안) | 십신 | 하루 이름(초안) |
|---|---|---|---|
| 정인 | 날 감싸주는 결 | 정재 | 차곡차곡 쌓는 날 |
| 편인 | 생각이 깊어지는 결 | 편재 | 판을 벌이기 좋은 날 |
| 비견 | 내 결대로 가는 날 | 정관 | 자리가 잡히는 날 |
| 겁재 | 티격태격 붙는 날 | 편관 | 긴장이 도는 날 |
| 식신 | 여유가 도는 날 | 상관 | 끼가 튀는 날 |

- 기존 `TEN_GOD_LABEL` 은 **사람용**(별자리 지도)이라 그대로 쓰지 않는다. **날짜용 10줄 + 그 이름에 붙는 한 줄 10개**를 새로 저작한다. 그게 전부다.
- **본문 뱅크(⑥ `skeleton-lines.json`, `tone × relation` 45개)는 건드리지 않는다.** 이름은 히어로, 본문은 그 아래라 자리가 달라 어긋나 보이지 않는다.
- **칸에는 원인 마크**를 붙인다: `✧` 천간합 · `◇` 육합 · `△` 충 · `＋` 빈 곳 채움. 우리 오늘 셀의 `✨끌림 🔗결속`과 **같은 어법**이라 두 탭이 한 문법을 쓴다.
- 톤 3단(색)은 **무회귀로 유지**한다.

**기각:** 축(연애/돈/일) 기반 라벨 — 실측상 **좋은 날의 78%가 love 로 쏠려** 다변화가 안 된다(love 축만 천간합 +25 · 육합 +18 을 받는데 그 둘이 점수를 good 으로 미는 힘이기도 하다).
**기각(보류):** 가중치 재튜닝으로 좋은 날 종류 늘리기 — ⑥ 뱅크 45개 문구 재검수가 따라오고 기존 등급 숫자가 바뀐다. 실사용 데이터 후 별건.

## 6. 무료선 변경 — 채워지는 이번 달

🔴 **이 절은 정본 스펙 §5 의 무료선("무료 = 30일 등급 캘린더")을 변경한다.**

**바뀌는 것**

- 달력 범위: `오늘부터 앞으로 30일` → **이번 달(1일~말일)**. `buildCalendar` 변경.
- **무료 = 지나간 날 + 오늘.** 안 온 날은 보이지만 내용이 없다(옅은 점 + "그날이 오면 열려").
- **구독 = 앞당겨 보기.** 안 온 날을 지금 전부 펼친다.
- **과거는 자동으로 열린다**(방문 여부 무관). 가입 이전 날짜도 칠해져 있다.

**근거**

- 구독이 파는 것이 "잠긴 콘텐츠"가 아니라 **"앞당겨 보는 권리"**가 된다. 무료 유저도 하루에 한 칸씩 결국 30일을 다 받는다 — 시간으로 내느냐 별로 내느냐의 차이라 인색하지 않다.
- **매일 와야 할 이유**가 생긴다(사용자 판단: "내일 이걸 보기 위해 또 들어오는 좋은 리텐션").
- **breadth 축이 유료 가치로 살아난다**(§1 문제 2 해소).
- **되돌리기 방향이 유리하다.** 30일을 다 준 뒤 줄이면 뺏는 것이라 반발이 크지만, 조여놨다가 푸는 건 쉽다. 데이터가 0인 지금은 되돌리기 쉬운 쪽에 선다.

**과거 자동 개방을 택한 이유(방문한 날만 채우는 스탬프 방식 기각):** 9월 20일 가입자의 첫 화면이 "놓친 날" 투성이가 되면 첫인상이 나쁘다. 지나간 운세는 상품 가치가 낮아 무료로 줘도 손해가 없고, 스탬프 감각은 출석 스트릭이 이미 따로 재고 있어 중복이다.

**기각:** "오늘만 무료 + 달력은 오늘부터 30일" — 자물쇠 29개짜리 회색 격자가 되어 히어로가 죽고, 내일 와도 칸이 하나 옮겨갈 뿐 **쌓이는 게 없어 리텐션 장치로도 약하다.**

## 7. 결과 전달 — 요약은 안, 전문은 밖

분량 편차가 크다: 무료 상세 ~450자 vs 유료 `DailyReportCard` **~2,100자**(일진 히어로 + 총평 + 5섹션).

**확정: 두 탭 모두 "두툼한 요약 + 별도 페이지".**

- 허브 = 오늘 히어로(이름 + 마크 + 한 줄) + "자세히 보기 →"
- 전문 = `/byeolmaru/saju?date=` · `/byeolmaru/woori` (현 구조 유지, 껍데기만 개편)

**기각:** 전부 허브 인라인(허브가 4.5화면이 되고 무료 목록이 유료 리포트 아래 3.5화면 밑으로 파묻혀 "무료 전부의 집"과 자기모순) · 바텀시트(2,100자 스크롤 두 겹 + 뒤로가기·딥링크 신규 구현. 별마루 실사용이 0이라 "날짜 훑기" 가설에 선지불하는 셈. `byeolmaru_day_selected` 의 `offset` 계측이 이미 있으니 노출 후 `offset≠0` 비율을 보고 나중에 얹으면 되고, 나→다 방향이 그 반대보다 싸다).

## 8. 우리 오늘 — 달력 탭으로 통합 + 분량 확장

**통합.** 목록의 "우리 오늘" 줄을 없애고, 달력 판 상단 **칩 행(`나` / `지민 연애` / `＋`)**으로 올린다. 상대 칩을 누르면 달력이 통째로 우리 버전이 된다. 칩 색·판 강조는 관계 유형 색(`DOLL_COLORS`, P4-a 에서 이미 `watch.status` 로 저장 중)을 재사용한다. 셀에는 `✨끌림 🔗결속` 태그가 그대로 뜬다.

- 상대 0명이면 칩 자리에 **`＋ 인연 걸어두기`**(금색 점선). 비어 있는 게 아니라 "여기 사람을 걸 수 있다"가 보이게 — 초대 루프 입구.
- **비구독 인연 달력도 §6 과 같은 규칙을 쓴다 — 지나간 날 + 오늘 무료, 안 온 날은 구독.** 그래야 무료선이 두 탭에 걸쳐 **한 문장**("무료는 지나간 날과 오늘, 구독은 앞당겨 보기")이 된다.
  ⚠️ 현재 서버는 비자격 pair 에 `cells: [todayCell]` **1칸만** 내려준다(`calendar/route.ts:107`). 이 계약을 **"이번 달 1일~오늘"**로 넓혀야 한다. `buildPairCalendar` 는 룰 100%라 칸이 늘어도 **원가는 0**이다. (상대를 담기 전 날짜도 생일만 있으면 계산된다.)
- 🔴 **`/byeolmaru/woori` 는 어떤 하단탭도 활성이 아닌 페이지가 아니다** — 달력 탭에서 진입하므로 별마루 탭이 유지된다.

**분량 확장.** 현재 우리 오늘은 정본 스펙 §5 의 depth 원칙("무료 = 유료의 진짜 20~30% taste")을 **스스로 어기고 있다.**

| | 현재 | P5 목표 |
|---|---|---|
| 오늘 사주 | 무료 450자 / 유료 2,100자 = **21%** ✅ | 유지 |
| 우리 오늘 | 무료 **1문장 ~50자** / 유료 ~600자 = **8%** ❌ | 무료 **~350자** / 유료 **~1,200자** = 29% |

- 무료 350자 = 톤 × `끌림/결속/삐걱/리드` × 관계유형 조합의 **정적 뱅크**(원가 0). `getPairStaticLine` 을 대체.
- 유료를 오늘 사주와 같은 2,100자로 키우지 않는다 — 구독자가 하루 4,200자를 받으면 둘 다 안 읽고, 오늘 사주가 "오늘의 본편"이라는 위계도 사라진다.

🔴 **`pair-narrative` 일별 캐시 신설 (필수).** `daily-report` 는 `byeolmaru_daily_report` 로 (유저, 날짜) 캐시가 있는데 `pair-narrative` 에는 **캐시가 없어 호출할 때마다 nano 를 새로 돌린다.** P5 에서 조건이 셋 다 나빠진다: ①서브페이지 → 허브 첫 화면 ②상대 칩 전환마다 재생성(`WooriTodayView` effect) ③분량 2배. `(유저, 상대, 날짜)` 캐시를 `daily-report` 패턴 그대로 복제한다. 마이그레이션 1장.

## 9. 페이월 — 맥락 분산

**원리: 한 곳에 모으지 않는다. 각 콘텐츠 옆에 그 콘텐츠의 다음 단계만 붙인다.**

| 자리 | 미끼 |
|---|---|
| 나 탭 달력 아래 | **오늘 사주 리포트** — 분량 칩 `약 2,100자` + 5섹션 이름(재물·직장·애정·건강·학업) + **실제 첫 줄 + 페이드** |
| 인연 탭 | **우리 오늘 30일** — 무료 오늘을 먼저 다 주고, 안 온 날이 시각 증거가 됨 |
| 오늘 타로 화면 | 카드 밑 깊은 해석 티저 (`PremiumBlock` 이 이미 하는 일) |
| 구독 시트 | **전체 가치 3종 + 가격을 여기서 크게, 딱 한 번** |

**미끼는 둘이다**(사용자 결정) — 우리 오늘뿐 아니라 **사주 리포트의 "더 길고 정확한 내용"**도 대등한 미끼다. 그래서 "길다·정확하다"를 말이 아니라 **증거로** 보여준다: 분량 칩(2탭의 `FORTUNE_LENGTH_HINT` 관행 재사용) + 5섹션 이름 + 실제 첫 줄. 첫 줄은 **위 무료 요약을 이어받아** 쓴다("위에서 본 '잘 맞는 날'이 왜 그런지부터—") → 무료→유료가 한 흐름으로 읽힌다.

**톤.** `🔒 구독` 자물쇠를 없애고 **"별콩이가 더 깊이 읽어줄게" + 작은 `구독` 배지**. 화법은 별콩이, 유료라는 사실은 배지가 명확히 남긴다.
**CTA.** 전부 **"3일 무료로 열어보기"** — 잠금이 아니라 열쇠. 시트 하단 "체험 중엔 별이 안 나가".
**가격 노출 2단.** 허브 CTA 밑에 작게 `체험 끝나면 20별 / 30일`, 구독 시트에서 크게.

**타이밍: 항상 노출 + 제한 둘.**
- 비로그인 구경 모드에선 **숨긴다**(공유 유입 첫인상 보호, 정본 §7 Loop 1 목적과 충돌 방지).
- 생일 미입력(`no_profile`)에게도 **숨긴다**(아직 볼 게 없는 사람).
- → 미끼를 보는 사람은 **이미 자기 달력을 무료로 받아본 사람**이라 광고가 아니라 맥락의 연장이 된다. 두 조건 다 기존 상태값이라 구현 비용 0.
- **거절하면 그날은 접힌다** (CTA 닫기 → 당일 미노출).

**기각:** 잠긴 3줄 카탈로그 진열 — ①잠금이 무료와 같은 분량(3 vs 3)으로 서면 "반은 못 쓰는 앱"으로 읽혀 정체성이 반으로 깎이고 ②잠긴 줄은 눌러도 안 열려 같은 옷을 입힌 게 배신이 되며 ③A 엔 맛이 있는데 B 엔 설명만 있다.
**기각:** 골드 배너 카드 — 형태가 목록과 달라 광고로 읽히고 눈이 건너뛴다.

## 10. 출석 재정의 — 별 환급 폐지

🔴 **`ATTENDANCE_REWARD_STARS`(10별) 지급을 폐지한다.**

- 새 설계에서 출석의 보상은 **그날의 운세**다(달력 칸이 열린다). 별 환급은 중복이다.
- 기존 구조는 거꾸로였다 — 환급은 구독자 전용인데 구독자는 이미 다 열려 있고, 매일 올 이유가 필요한 비구독자는 못 받았다.
- 체감이 30일 뒤다(`grantDueReward` 는 *만료된* 구독을 훑는다).
- 무료 별은 원가의 87%를 먹은 레버다. 줄이는 방향이 맞다.
- 부수 효과: 구독 **실부담이 10별 → 20별**이 된다(사실상 가격 정상화).

**정리 대상:** `ATTENDANCE_THRESHOLD` · `ATTENDANCE_REWARD_STARS` · `grantDueReward` · `byeolmaru_subscriptions.reward_granted_at` · `getAttendanceState` 의 `daysThisSub`/`threshold`.
**별마루가 prod 에 없어 기존 지급 이력 정리 문제가 없다**(`origin/main` 에 `app/byeolmaru` 자체가 없음 — 확인함).

**대체 표시:** 출석 스트립 = **"이번 달 12칸 채움 · 7일 연속"** — 달력 채움 진행. 별 얘기 없음. 스트릭(`computeStreak`)은 표시용으로 유지.

## 11. 재화

- **별마루 구독 20별 / 30일 유지.** 인상하면 전환 장벽이 급등한다(사용자 판단).
- 🔴 **웰컴 보너스 20 → 15** (`WELCOME_BONUS_STARS`).
  - 현재 **웰컴 20 = 구독 20** 이 정확히 일치해 **가입만 하면 웰컴 별로 한 달 구독을 살 수 있다.** 그 사람의 첫 달은 매출 ₩0인데 nano 원가는 30일치가 나간다.
  - 15로 내리면 구독에 **최소 1회 충전**이 걸리는데 **구독 가격은 그대로**라 체감 인상이 0이다.
  - **3일 무료 체험이 따로 있어 체험 장벽은 여전히 0.** 웰컴으로 구독을 사게 두는 건 체험이 아니라 한 달 무상 제공이다.
  - 원카드(10)·투카드(15)·3천자 리포트(15)는 여전히 웰컴으로 살 수 있어 **첫 경험은 안 막힌다.**
  - 적자 진단 격자가 이미 "웰컴 15"로 확정했으나 코드는 20이다 — 새 결정이 아니라 **밀린 집행**이다.
  - ⚠️ **별마루 밖 전 상품에 파급된다.** 상수 한 줄이지만 P5 구현 범위에 넣을지 별건 배포로 뺄지는 착수 시 결정한다.

## 12. 상태별 화면

| 상태 | 달력 판 | 목록 | 페이월 |
|---|---|---|---|
| **비로그인 구경** | **안 칠해진 이번 달**(날짜만) + "네 생일만 있으면 이 칸이 다 칠해져" + 카카오 CTA | MBTI·별자리를 **위로** (로그인 없이 되므로 먼저 맛보게) | **숨김** |
| **생일 미입력** | 동일 + 생일 입력 CTA | 동일 | **숨김** |
| **처음 온 사람** | 이번 달 과거 칠해짐 + 오늘 + `＋ 인연 걸어두기` 칩 | 3종, 타로 = 카드 뒷면 + `오늘 아직` | 노출 |
| **매일 오는 사람** | + 상대 칩 | 타로 = **뽑은 카드 앞면** + `별 · 뽑음` | 노출(거절 시 당일 접힘) |

- 비로그인 히어로를 비우지 않고 **"안 칠해진 달력"**으로 채운다. 가짜 데이터가 아니라 진짜 빈 상태라 정직하고, "내 칸이 비어 있다"가 그 자체로 로그인 유인이 된다. 개인화 0(정본 §11 리스크 5 준수).
- **오늘 타로의 목록 행 타일에 카드 이미지를 직접 넣는다.** 안 뽑음 = 뒷면(`CARD_BACK_IMAGE`), 뽑음 = 뽑은 카드 앞면(`getCardImagePath`). 2탭 동형을 유지하면서 "오늘 뽑았나"라는 데일리 라이브 성격이 한 줄에서 살아난다. **신규 아이콘 제작 불필요.**

## 13. 계측

기존 이벤트 유지 + 다음을 추가/활용한다.

- `byeolmaru_day_selected` 의 **`offset≠0` 비율** — 바텀시트(§7 기각안) 재검토 관문.
- 미끼 노출/클릭을 자리별로 구분(`meta.slot` = `saju_report` / `woori_30d` / `tarot_rich`) — 어느 미끼가 파는지.
- 페이월 당일 접힘(닫기) 비율.
- 달력 "앞당겨 보기" CTA → 체험 시작 → 구독 전환 퍼널.

## 14. 단계 분해

각 단계는 독립 배포 가능. 단계별로 plan → subagent-driven 구현 사이클.

- **P5-1 판정·라벨** — 십신 하루 이름 10종 + 한 줄 10개 저작 · 원인 마크 · `DayCell` 에 factors 실어 내리기 · 실제 일진 30일로 라벨 빈도 재측정.
- **P5-2 달력 범위·무료선** — `buildCalendar` 를 이번 달로 · 안 온 날/지나간 날 상태 · 구독 = 앞당겨 보기 · **비자격 pair 응답을 1칸 → 이번 달 1일~오늘로 확대**(§8) · 출석 환급 폐지 및 스트립 대체.
- **P5-3 허브 재조립** — 라이트 B 달력 판 · 오늘 히어로 · 인연 칩 통합 · 무료 목록 3종(2탭 동형) · 상태별 4화면.
- **P5-4 페이월·구독 시트** — 맥락형 미끼 3자리 · 톤/CTA 교체 · 가격 2단 노출 · 타이밍 제한 2 + 당일 접힘 · 계측.
- **P5-5 우리 오늘 분량** — 무료 정적 뱅크 ~350자 저작 · 유료 프롬프트 ~1,200자 · **`pair-narrative` 일별 캐시(마이그레이션)**.
- **(별건) 웰컴 15** — 상수 한 줄. 파급이 별마루 밖이라 배포 시점을 따로 정한다.

## 15. 리스크 · 미검증

1. 🔴 **오행 과다 유저의 달력이 온통 챙길 날이다.** 실측 — 좋은 날 0.6일 / 챙길 날 12.8일. "네 한 달은 대체로 조심할 날"이라는 메시지가 되어 **별콩이 화법(불안 자극 금지)과 정면 충돌**한다. P5 범위 밖일 수 있으나 노출 전에 판단이 필요하다.
2. **무료선 변경이 유입을 해칠 수 있다.** "무료로 다 보는 곳"인데 달력 절반이 안 온 날이다. 과거 자동 개방과 자물쇠 금지로 완화했지만 **공유 유입 첫인상은 실측으로만 안다.**
3. **리텐션 가설이 미검증이다.** "가리면 매일 온다"는 별마루 실사용이 0이라 가설일 뿐이다.
4. 🔴 **구독 원가를 아직 재지 않았다.** 구독자 1명이 하루 nano 3회(리포트 + 우리오늘×상대수 + 타로), 상대 3명이면 하루 5회 · 월 150회. 20별(≈₩1,860, 30별 팩 기준) 안에 들어오는지 **실측이 필요**하다. `WATCH_FREE_SLOTS 2 + 추가 5별` 구조가 상대수 폭주를 막는 방어벽으로 작동한다.
5. **`monthly`(20별, 5,000자) 잠식.** 구독도 20별인데 같은 "이번 달" 축을 본다. 성격은 다르지만(월 단위 서사 vs 일 단위 흐름) 유저가 구분하기 어렵다. → 노출 후 최우선 관측.
6. **타로톡 원카드(10별) 잠식.** 구독에 매일 800자 리치 해석이 들어가면 "원카드를 왜 사?"가 생길 수 있다. 역할은 다르다(고민 기반 상담 vs 랜덤 오늘 한 장). 구독에서 타로 해석을 빼는 안은 **미채택** — 구독 가치가 얇아진다. → 관측.
7. **라벨 빈도는 조합 전수 기준이다.** 천간합·육합·충은 60갑자 중 특정 짝일 때만 나오므로 실제 달력에선 더 드물다. **구현 시 실제 일진 30일로 다시 재야 한다.**
