## 1. 목표

앱(`mobile/`, Expo SDK 58 웹뷰 한 장) 안에서 보이는 화면이 웹사이트처럼 보이지 않게 한다. 애플 심사 가이드라인 4.2(웹을 그대로 감싼 앱은 거절)에 맞서는 근거를 화면으로 만든다. 푸시·네이티브 로그인·인앱결제에 더해 "앱다운 화면"을 소명 자료에 넣는다.

**끝났다는 기준**
- 개발용 앱(아이폰·안드로이드)에서 다음이 모두 동작한다(§11 확인).
  - 탭 첫 화면과 하위 화면의 헤더가 앱식이다.
  - 앱에서는 푸터가 없다.
  - 화면이 OS별 방식으로 쌓이고 빠진다.
  - 시트를 끌어내려 닫을 수 있고, 안드로이드 뒤로 버튼은 시트만 닫는다.
  - 작은 동작 7가지가 들어갔다.
  - 새 앱 아이콘과 상태바 아이콘이 보인다.
- 웹(브라우저)은 지금과 똑같이 보인다.

**이 일에서 하지 않는 것**
- **전체 디자인 다듬기:** 화면이 AI 같거나 서둘러 만든 듯 보이는 것을 고치는 일은 별도 일로 뺐다. 알림 시트·카드·설정 같은 새 화면도 그 일에 포함되고, 웹도 같이 바뀐다. 이 일이 끝난 뒤 ROADMAP 의 다음 줄에서 한다.
- **네이티브 화면 스택:** 하위 화면마다 웹뷰를 쌓는 방식은 하지 않는다. 심사에서 막히면 그때 올린다(§11).
- **안드로이드 예측 뒤로 가기:** 뒤로 제스처 중 이전 화면 미리보기는 웹뷰가 지원하지 않아 하지 않는다.
- **스플래시 화면 그림:** 지금 그대로 둔다.
- **화면 구성:** 하단 탭의 구성과 어떤 화면에서 탭을 숨기는지는 지금 그대로 둔다.

## 3. 앱 모드 — 첫 화면이 그려지기 전에 정한다

**문제:** 지금 웹은 마운트한 뒤에야 앱 안인지 안다(`lib/use-app-info.ts`). 이대로 헤더를 바꾸면 웹 헤더가 한 번 보였다가 앱 헤더로 바뀐다.

**방식**
- 루트 레이아웃 `<head>` 의 인라인 스크립트 한 줄이 앱 안인지 판단해 `<html>` 에 두 속성을 붙인다.
  - 붙이는 속성: `data-app` 과 `data-platform="ios|android"`
  - 1차 근거: 앱이 문서 시작 전에 넣는 `window.__BYEOLKONG_APP__`
  - 2차 근거: UA 의 `ByeolkongApp/` 표식. 안드로이드는 문서 시작 전 주입이 인라인 스크립트보다 늦을 수 있다(확인 못 함). UA 는 첫 요청부터 붙어 있으니 둘 중 하나만 맞아도 앱으로 본다
  - 판단 규칙: 지금 `lib/app-context.ts` `getAppInfo` 와 같다
- 웹과 앱에서 달라지는 부분은 **둘 다 그려 두고 CSS 로 하나를 숨긴다.**
  - 숨기는 규칙: `html[data-app] .web-only{display:none}` · `html:not([data-app]) .app-only{display:none}`
  - 이렇게 하면 서버가 앱 여부를 몰라도 된다
  - 그래서 루트 레이아웃이 요청 헤더를 읽지 않는다. 읽으면 모든 화면이 동적 렌더로 바뀌고, 정적인 설명 페이지(SEO)까지 느려진다
- 화면마다 동작이 달라야 하는 곳(진동, 시트 뒤로 가기 등)은 지금처럼 `useAppInfo()` 를 쓴다.

## 4. 헤더

**탭 첫 화면** — `/` 타로톡 · `/fortune` 사주 운세 · `/byeolmaru` 별마루 · `/shop` 별콩 상점 · `/mypage` 마이
- 왼쪽에 화면 제목(굵게, 22px 안팎), 오른쪽에 별 잔액 칩 하나를 둔다. 로고·프로필 칩은 앱에서 뺀다(마이 탭과 겹친다).
- 비로그인이면 별 잔액 대신 '로그인'을 둔다(지금 웹 헤더와 같다).

**하위 화면** — 그 밖의 모든 화면
- 왼쪽에 `‹`, 가운데에 제목을 둔다. 오른쪽은 비운다.
- 제목은 경로 → 제목 표 하나에서 정한다(`lib/app-shell/titles.ts`, 접두사 일치). 표에 없으면 '별콩톡'.
- 상품 설명 같은 동적 화면은 접두사 단위로 묶어 부른다(예: `/fortune/…` → '사주 운세').

**`‹` 의 동작**
- 앱 안 기록이 있으면 뒤로 간다.
- 없으면 그 화면이 속한 탭 첫 화면으로 간다. 딥링크·알림으로 하위 화면이 바로 열렸을 때가 이 경우다.

**겹치는 자체 헤더 정리**
- 지금 하위 화면 16곳쯤이 자기 '← 돌아가기' 줄이나 제목 줄을 갖고 있다. 예: `components/byeolmaru/BackHeader.tsx`, `/mypage/notifications`, `/mypage/support`, `/terms`, `/tarot/result`.
- 앱에서는 이 줄들을 `web-only` 로 숨긴다. 본문 제목(h1)이 헤더 제목과 같은 말이면 앱에서 숨기고, 다르면 둔다. 1단계에서 16곳을 다 본다.

**상태바**
- 상태바와 헤더는 같은 cream 단색으로 이어 경계가 보이지 않게 한다. 앱 쪽 `SafeAreaView` 배경이 이미 cream 이다.
- 앱 헤더는 반투명(`bg-cream/85` + 흐림)이 아니라 단색으로 둔다. 스크롤할 때 상태바와 색이 어긋나지 않게 하기 위해서다.

## 5. 작은 동작 7가지

| # | 동작 | 방식 | 어디서 |
|---|---|---|---|
| ① | 글자 길게 누르기 | 앱에서는 기본으로 선택을 막는다(`user-select:none`, `-webkit-touch-callout:none`). **상담 답변 말풍선과 결과 본문**에는 `selectable` 을 달아 복사를 허용한다 | 웹 CSS |
| ② | 링크 길게 누르기 미리보기 | 끈다(`allowsLinkPreview={false}`, 아이폰) | 앱 |
| ③ | 누를 때 회색 번쩍임 | `-webkit-tap-highlight-color:transparent`. 버튼·탭·카드는 누르는 동안 살짝 작아지고 옅어진다(`active:scale-[.97]`) | 웹 CSS |
| ④ | 당겨서 새로고침 | **탭 첫 화면 5개에서만** 웹뷰를 다시 읽는다. 아이폰은 웹뷰 기본 기능(`pullToRefreshEnabled`)을 앱이 현재 주소를 보고 켜고 끈다. 안드로이드는 그 기능이 없어 웹이 탭 첫 화면에 당김 표시를 그린다(§7 메시지로 앱에 새로고침을 청한다) | 앱 + 웹 |
| ⑤ | 탭 다시 누르기 | 지금 탭을 다시 누르면 맨 위로 부드럽게 올라간다 | 웹 |
| ⑥ | 진동 | 탭 전환·카드 뽑기·결제 완료 세 순간만 가볍게 울린다. 웹이 앱에 메시지(§7)를 보내고 앱이 `expo-haptics` 로 울린다 | 앱 + 웹 |
| ⑦ | 안전 영역·상태바 | 지금처럼 앱이 노치·홈 바 영역을 비운다. 색만 §4 대로 맞춘다 | 앱 |

- ⑥ 의 `expo-haptics` 는 새 의존성이다. 설치는 에이전트가 직접 하지 않는다(AGENTS.md). 4단계 계획에서 운영자 손 또는 init 절차로 넣는다.

## 6. 화면 전환 — OS별 쌓기 흉내

**도구:** Next 16 의 `experimental.viewTransition`(React `<ViewTransition>`)
- View Transitions 를 지원하지 않는 기기(아이폰 iOS 18 미만 등)에서는 애니메이션 없이 지금처럼 바로 바뀐다.
- 이 스위치는 `next.config` 전역 설정이다. 그래서 웹에서는 CSS 로 모든 전환 애니메이션을 끈다(`html:not([data-app]) ::view-transition-group(*) {animation:none}`).

**움직임**

| | 아이폰 | 안드로이드 |
|---|---|---|
| 하위 화면으로 들어가기 | 새 화면이 오른쪽에서 덮는다. 아래 화면은 왼쪽으로 1/3 밀리며 어두워진다(약 0.35초) | 새 화면이 살짝 아래에서 떠오르며 나타난다(약 0.3초) |
| `‹` 버튼 | 반대로 움직인다 | 반대로 움직인다 |
| OS 뒤로(아이폰 왼쪽 끝 밀기 · 안드로이드 뒤로 버튼) | **애니메이션 없음.** 웹뷰가 이미 손가락을 따라 진짜로 움직인다(`allowsBackForwardNavigationGestures`, 지금 켜져 있음). 겹치면 두 번 움직인다 | 반대로 움직인다(`‹` 와 같다). **4단계 빌드부터** — 그 전엔 즉시 바뀐다(아래 "1단계 실측") |
| 탭 바꾸기 | 즉시 | 즉시 |

**방향 정하기 (1단계 구현, 2026-11-07)**
- 방향은 `<html data-nav>` 값 하나로 정한다(`components/layout/AppNavDirection.tsx`, 판정은 `lib/app-shell/nav-direction.ts`). 값이 없으면 움직이지 않는다 — 화면 이동이 아닌 React 트랜지션이 미끄러지지 않게.
  - 링크 클릭(캡처 단계): 같은 사이트 링크면 `forward`, 하단 탭·별 잔액 칩(`data-nav="tab"`)이면 `tab`(즉시).
  - 기록 뒤로(popstate): 아이폰은 `‹` 로 간 것만 `back`, 손가락 뒤로 가기는 `none`. 안드로이드는 `back`.
- 링크 이동은 React `<ViewTransition update="app-nav">`(AppShell)이 연 전환에 위 값으로 움직임을 고른다. 웹에서는 `update="none"` 이라 전환 자체가 열리지 않는다.

**1단계 실측 (2026-11-07, 데스크톱 크롬 — 아래 미확인 ① 의 답)**
- React 는 popstate 이동에 `<ViewTransition>` 을 걸지 않는다(링크 이동만 `startViewTransition` 호출, `history.back` 은 0회).
- 직접 연 `document.startViewTransition` 도 그 콜백 안에서 `history.back` 이 일어나면 "Transition was aborted because of invalid state" 로 중단된다.
- 그래서 `‹` 는 지금 화면을 복제한 덮개를 헤더·탭바 아래에 두고, 뒤로 간 뒤 덮개를 밀어낸다(아이폰: 오른쪽으로 빠지며 아래 화면이 왼쪽 1/3 에서 밝아지며 들어옴 · 안드로이드: 아래로 가라앉으며 사라짐).
- 안드로이드 하드웨어 뒤로는 앱이 웹뷰 `goBack` 을 바로 불러 이 길을 못 탄다. 4단계에서 앱이 웹에 뒤로를 청하게 바꾼다(§7 `ui.back` 확장).

**한계 (흉내라서 생기는 것)**
- 화면 두 장이 실제로 살아 있지 않다. 직전 화면을 찍은 사진이 움직인다.
- 뒤로 가면 이전 화면을 새로 그린다. 스크롤 위치·입력 중인 글이 남는지는 확인 못 했다. 1단계 실기기 확인표 D7 에서 보고, 깨지는 화면이 있으면 그 결과를 운영자에게 가져온다.
- 확인 못 함: 아이폰 손가락 뒤로 가기가 SPA 이동(`pushState`)에도 사진을 보여 주는지 — 1단계 실기기 확인표 D5 에서 본다.

## 7. 웹 ↔ 앱 메시지 추가

`lib/app-bridge/protocol.ts` 에 더한다. 지금 규칙을 그대로 따른다: 웹 → 앱은 `postToApp`, 앱 → 웹은 `byeolkong:app` CustomEvent, 토큰은 절대 싣지 않는다.

| 방향 | 이름 | 뜻 |
|---|---|---|
| 웹 → 앱 | `ui.overlay` (open \| closed) | 시트·팝업이 열려 있다/닫혔다. 앱이 안드로이드 뒤로 버튼 처리에 쓴다 |
| 앱 → 웹 | `ui.back` | 안드로이드 뒤로 버튼이 눌렸고 시트가 열려 있다. 웹이 맨 위 시트를 닫는다 |
| 웹 → 앱 | `ui.haptic` (light \| success) | 진동 한 번 |
| 웹 → 앱 | `ui.refresh` | 새로고침해 달라(안드로이드 당겨서 새로고침) |

- 지금 `WebToAppMessage.payload` 는 빈 객체 고정이다. 값을 싣는 메시지는 이번에 처음 생긴다. 파싱은 지금처럼 허용 목록으로 하고, 모르는 값은 버린다.
- **옛 앱 대비:** 이 메시지들을 아는 앱만 `AppInfo.caps` 에 `ui` 를 싣는다. 웹은 `hasCap(app, "ui")` 일 때만 보낸다. 2·3단계는 4단계 빌드 전에 dev 에 들어간다. 그동안 지금 깔린 개발용 앱에서는 시트 모양만 바뀌고, 안드로이드 뒤로 버튼은 지금처럼 화면을 뒤로 보낸다.
- 안드로이드 뒤로 버튼 처리: 앱 `BackHandler` 는 바로 답해야 해서 웹에 물어볼 수 없다. 그래서 웹이 미리 알려 둔 `ui.overlay` 상태를 보고 정한다.
  - 열려 있으면 `ui.back` 을 보내고 앱이 소비한다.
  - 닫혀 있으면 지금처럼 웹뷰 뒤로 또는 앱 닫기.
  - 로그인 덮개 중에는 지금처럼 무시한다.

## 8. 공통 시트 틀

`components/common/Sheet.tsx`(아래에서 올라오는 시트)와 `components/common/Dialog.tsx`(가운데 확인창) 둘을 만든다. 지금 시트·팝업 25개쯤을 이 둘로 옮긴다.

**Sheet**
- 손잡이를 둔다.
- 아래에서 올라오는 움직임과 뒤 화면 어둡게를 둔다. 아이폰·안드로이드 같은 움직임이다.
- 손잡이·머리 부분을 끌어내려 닫는다. 일정 거리나 속도를 넘으면 닫히고, 아니면 제자리로 돌아온다.
- 뒤 화면 스크롤을 잠근다.
- 바깥을 누르면 닫는다. 닫으면 안 되는 시트는 `dismissible={false}` 를 준다.
- 안전 영역(홈 바) 여백을 둔다.

**Dialog**
- 모양은 지금 확인창들 그대로 두고, 여는 법과 닫는 법만 통일한다.

**둘 다**
- 열릴 때 `ui.overlay open`, 닫힐 때 `closed` 를 보낸다(§7).
- 여러 개가 겹치면 맨 위 하나만 `ui.back` 으로 닫는다. 열린 것들을 쌓아 두는 작은 스택을 하나 둔다.
- 웹(브라우저)에서는 끌어내리기·손잡이 없이 지금 보이는 모양과 같게 그린다. 앱 전용 꾸밈은 `app-only` 또는 `useAppInfo` 로만 붙인다.

**옮기는 순서**
- 2단계: 틀을 만들고 → `RevisitSheet`(알림)를 옮긴다.
- 3단계: 나머지를 옮긴다. 판정 보호 화면에 닿는 시트(`tarot/LoginSheet`, `upsell/RechargeSheet`, `start/WelcomeStarsModal`)도 dev 에서는 옮긴다. 운영 배포는 판정이 끝나고 운영자 "go" 뒤에만 한다.

**알림 화면 (2단계)**
- `RevisitSheet` 의 시트를 공통 틀로 옮긴다.
- 결과 안의 카드와 `/mypage/notifications` 는 새 헤더(§4)에 맞춰 겹치는 제목 줄을 정리한다.
- 칩·버튼·글자 같은 꾸밈은 다음 일(디자인 다듬기)에서 고친다. 시안(`2026-11-06-앱-알림-시안.html`)은 그때까지 임시 정답이다.

## 9. 푸터·약관

- `Footer` 를 앱에서 숨긴다(`web-only`). 홈·마이 두 곳이다. 웹 푸터의 '타로 가이드' 링크는 SEO 때문에 웹에 그대로 둔다.
- 마이 맨 아래에 앱 전용 한 줄 '약관·사업자 정보'를 둔다. 누르면 새 하위 화면 `/mypage/legal` 이 열린다.
  - 사업자 정보 7줄: 지금 푸터와 같은 내용이다.
  - 이용약관·개인정보처리방침·환불정책 세 링크를 둔다.
- 비로그인은 마이를 못 열지만 로그인 화면에 약관·개인정보 링크가 이미 있다. 결제는 로그인 뒤에만 된다.
- 확인 못 함: 전자상거래법의 사업자 정보 표시 위치를 앱에 어디까지 요구하는지. 원문을 대조하지 않았다(유력 판단).

## 10. 아이콘

**앱 아이콘 — 별콩이 얼굴**
- 별콩이 머리 그림(`public/byeolkong-head.png` 의 캐릭터)을 보라 밤하늘 배경(night 계열)에 꽉 차게 올린다.
- 홈 화면 크기에서 뭉개지지 않게 귀걸이 같은 잔장식은 덜어 낸 단순한 판으로 만든다.
- 규격 — 아이폰: 1024×1024, 배경을 채운 불투명 PNG
  - 지금 `mobile/assets/icon.png` 은 500px 에 모서리가 투명이다(2026-11-07 픽셀 확인). 아이폰에서는 투명한 곳이 검게 칠해지고 스토어 제출 때 걸린다.
- 규격 — 안드로이드: adaptive icon 전경 `adaptive-icon.png` 1024px. 얼굴을 가운데 안전 영역(지름 66%) 안에 두고, 배경색은 night 계열로 맞춘다.
- 만드는 법: 그림 생성 도구를 쓴다. **생성 전에 대상·스타일·프롬프트를 운영자와 먼저 맞추고** 돌린다. 웹 파비콘(`app/icon.png`)은 이번에 바꾸지 않는다. 맞출지는 디자인 다듬기 일에서 정한다.

**안드로이드 상태바 아이콘 — 4꼭지 별**

## 12. 제약

- **운영 배포 금지:** 입구 판정 창이 끝나고(2026-11-10 18:57 KST 이후) 운영자가 "go" 할 때만 한다. 이 일의 변경은 dev 에만 들어간다.
- **판정 보호 화면:** 판정 창 동안 로그인·첫 화면·타로 첫 구매의 **운영** 코드를 바꾸지 않는다. 홈 헤더·푸터, 로그인 시트 이전은 dev 에서만 하고 앱에서만 달라진다. 웹 모양은 그대로다.
- **전역 스위치:** `next.config` 의 `viewTransition` 스위치는 다음 운영 배포에 함께 실린다. 웹에서는 CSS 로 애니메이션을 끄지만 전역 설정이 바뀌는 것은 사실이라, 운영 배포 PR 의 영향 범위에 적는다.
- **공개 저장소:** 키·풀 UUID·사업 숫자를 쓰지 않는다.
