## 2. 코드 사실

- `result_viewed_at` 을 쓰는 곳은 **단 하나** — `app/api/readings/[id]/route.ts:73` POST. 소유권 검증 + 최초 1회만 기록(재방문 미덮어씀). 로직에 결함 없음.
- 호출부도 정상: `app/tarot/result/page.tsx:96`(소유자 분기 `isOwner` 로 공유 링크 폴백과 구분) · `app/(consultations)/saju/result/page.tsx:81`. 둘 다 데이터 로드 성공 후 fire-and-forget.
- **종료 후 UI = 수동 `<Link>`**: `app/tarot/reading/page.tsx:1019` · `app/(consultations)/saju/reading/page.tsx:641`. 자동 `router.push` 도, 타이머도, 인터스티셜도 없다. 화면엔 "별콩이의 풀이가 마무리됐어 ✨" + [결과 보기 →] 버튼뿐.
- ⚠️ **AGENTS.md 의 "reading [END] → result 자동 이동" 은 스테일**(Phase 5 e2 항목). 실제로 자동 이동하는 유일한 갈래는 reco 직행(`saju/reading/page.tsx:399` `router.replace`)이었고, 그건 P2-6 으로 중단됐다.

**함의**: `result_viewed_at` 은 "결과를 봤나"가 아니라 **"버튼을 눌렀나"** 를 재고 있다. 지표 해석 시 이 정의를 기억할 것.

## 4. 미열람군은 누구인가 (열람군 대조)

| 지표 | 열람 288 | 미열람 68 | 해석 |

## 7. day 14 픽스 후보 (지금 배포 금지)

우선순위순. 전부 **퍼널 지표를 직접 움직이므로 판정 창 중간 배포 불가**.

1. **`[END]` 후 자동 이동** (효과 최대, 위험 최소) — `setIsEnded(true)` 직후 짧은 지연(마지막 응답을 읽을 시간) 후 `router.push('/…/result?id=')`. 수동 버튼은 폴백으로 유지. ⚠️ 지연 없이 즉시 밀면 마지막 한마디를 못 읽고 튕겨나가는 역효과 가능 → 2~3초 + "결과로 넘어갈게" 안내, 또는 유저가 스크롤/탭하면 취소.
2. **결과를 별도 화면이 아니라 스레드 하단에 인라인** — 근본 해법이지만 공유·OG·이어가기 진입점이 result 페이지에 묶여 있어 범위가 크다. 사이클 단위 설계 필요.
3. **btn_finish 눌렀을 때 확인 없이 result 로 직행** — 이미 "마무리" 의도를 명시한 군이라 중간 화면이 불필요. 41건(미열람 60%)을 정조준.

**측정 방법**: 픽스 후 같은 3쿼리 재실행(스크립트는 이 문서 §8). btn_finish 미열람률 21.8% → 5% 이하가 성공선.
