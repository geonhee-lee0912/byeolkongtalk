# 앱 ① 껍데기 + 로그인 — 상세 설계

- 날짜: 2026-10-12
- 상태: 사용자 검토 대기 → 승인 시 writing-plans
- 상위 설계: `specs/2026-10-12-앱-전환-design.md` (D3-1 React Native(Expo) + 웹뷰 · D3-2 토큰 인증 처음부터 · D8 카카오 + 애플 로그인)
- 이 문서의 범위: 하위 프로젝트 ① — 앱 껍데기, 웹 ↔ 앱 연결, 로그인(카카오·애플), 토큰 인증, 계정 구조 변경

---

## 1. 목표

1. iOS·Android 앱이 웹뷰로 byeolkongtalk.com 을 띄우고, 웹 기능이 앱 안에서 그대로 동작한다.
2. 앱에서는 카카오(카카오톡 앱 로그인)와 애플 로그인으로 가입·로그인한다. 웹에도 애플 로그인을 추가한다.
3. 앱 쪽(React Native) 코드는 토큰으로 서버를 부를 수 있다. ②(결제 확인)·③(알림 기기 등록)과 나중의 앱 화면이 이 토큰을 쓴다.
4. 계정 구조가 카카오 전용에서 '로그인 수단 여러 개'로 바뀌고, 기존 회원·보너스 기록·탈퇴가 그대로 이어진다.

**비목표(①에서 안 함)**: 스토어 결제(②), 푸시(③), 웹의 앱 설치 안내·메타 SDK(④), 스토어 제출(⑤), 앱 전용 화면(출시 후), 카카오·애플 계정 병합, 유니버설 링크(공유 링크로 앱 열기 — 범위는 ④에서 결정).

## 2. 현재 구조 (2026-10-12 코드 확인)

- **웹 로그인**: `app/api/auth/login/kakao`(state nonce 쿠키 + 카카오 리다이렉트) → `app/api/auth/kakao`(콜백). 콜백이 회원 찾기·만들기와 신규 가입 처리를 전부 한다.
  - 신규 가입 처리: `users` insert → `user_acquisition`(acq 쿠키 또는 page_views 복구) → `star_balances` 0 → 웰컴 별(`bonus_claims` 의 `kakao_id_hash` 로 1회 청구) → 메타 CAPI `CompleteRegistration`
  - 마지막에 `setUserCookie(res, userId)` 후 `next?login=success(&welcome=1)` 로 리다이렉트
- **세션**: `lib/session.ts` — `byeolkong_user_id` 쿠키에 `users.id` UUID 원문(무서명, 설계상 의도 · 형식 검증만), 어드민만 HMAC 토큰. `getSession()` 은 쿠키만 읽는다.
- **카카오 토큰은 서버에 저장하지 않는다**(콜백에서 한 번 쓰고 버림). 탈퇴의 unlink 는 어드민 키 + 카카오 회원번호로 한다(`lib/kakao.ts` `unlinkKakao`).
- **카카오 ID 를 읽는 곳**: `users.kakao_id`(BIGINT UNIQUE NOT NULL) · 콜백 · `app/api/auth/withdraw` · `app/api/payment/confirm`(첫충전 보너스 해시) · `app/api/stars/first-charge-status` · `app/api/auth/me` · 어드민 회원 화면 2개(재가입 판정 해시) · `app/api/admin/users`
- **해시 원장**: `bonus_claims(kakao_id_hash, bonus_type)` · `account_withdrawals(kakao_id_hash)` — 둘 다 `sha256(String(kakao_id))`
- **로그인 진입점 3곳**: `app/login/page.tsx` · `app/start/page.tsx` · `app/tarot/draw/page.tsx`(로그인 전 맛보기 시트). 전부 `/api/auth/login/kakao?next=...` 로 이동한다.
- 루트 `tsconfig.json` 의 `include` 가 `**/*.ts` 라서, 하위 폴더에 앱 코드를 두면 웹 타입 검사에 섞인다.

## 3. 저장소 구조

- 같은 저장소에 `mobile/` 폴더를 만든다(Expo, TypeScript). 앱 라이브러리 목록(`mobile/package.json`)은 웹과 분리한다.
- 웹 도구에서 제외한다: 루트 `tsconfig.json` `exclude` 에 `mobile` 추가 · `.vercelignore` 에 `mobile/` 추가(웹 배포 업로드에서 뺌).
- **공용 코드**: 웹과 앱이 함께 쓰는 순수 TypeScript 모듈만 공유한다. ①에서는 웹 ↔ 앱 메시지 형식 하나다(`lib/app-bridge/protocol.ts`, next·서버 의존 금지). 앱은 Metro `watchFolders` 로 루트의 이 파일을 가져온다.
- 리포가 **공개**다 → 애플 키(.p8)·토큰 비밀값·Vercel 우회 값은 절대 커밋하지 않는다(서버는 Vercel env, 앱은 EAS env).

## 4. 앱 껍데기

- **웹뷰**: `react-native-webview` 로 기준 주소를 연다. UA 끝에 `ByeolkongApp/<버전> (<ios|android>)` 를 붙인다(`applicationNameForUserAgent`). 문서가 뜨기 전에 `window.__BYEOLKONG_APP__ = { version, platform }` 를 주입한다.
- **앱 변형 2벌**(`app.config.ts`, 환경 변수 `APP_VARIANT`)

  | 변형 | 번들 ID(예시) | 기준 주소 | 카카오 앱 |
  |---|---|---|---|
  | development | `com.byeolkongtalk.app.dev` | dev.byeolkongtalk.com (또는 로컬) | 카카오 dev 앱 |
  | production | `com.byeolkongtalk.app` | byeolkongtalk.com | 카카오 prod 앱 |

  dev 사이트는 Vercel 접근 보호가 걸려 있다 → 첫 주소에 Vercel 우회 쿼리(`x-vercel-protection-bypass` + `x-vercel-set-bypass-cookie=true`)를 붙여 쿠키로 통과한다. 우회 값은 개발용 빌드에만 넣는다.
- **링크 규칙** (`onShouldStartLoadWithRequest`)
  1. 우리 도메인의 로그인 시작 주소(`/api/auth/login/kakao`, `/api/auth/login/apple`) → 이동을 막고 네이티브 로그인을 실행한다(`next` 쿼리를 그대로 가져감). **기존 로그인 버튼 3곳을 고치지 않아도 된다.**
  2. 우리 도메인의 `/api/auth/logout` → 앱 로그아웃 절차(§7-4)를 먼저 하고 이어서 로드한다.
  3. 그 밖의 우리 도메인 → 웹뷰 안에서 연다.
  4. 다른 http(s) 사이트 → 앱 안 브라우저(`expo-web-browser`)로 연다.
  5. 앱 호출 주소(`kakaolink:`·`kakaotalk:`·`intent:`·`tel:`·`mailto:` 등) → OS 에 넘긴다(`Linking.openURL`). 카카오톡 공유가 앱에서 동작하려면 필요하다.
- **딥링크**: 앱 주소 체계 `byeolkong://open?path=<내부 경로>`. 앱이 받으면 웹뷰를 그 경로로 연다(③의 알림 클릭이 쓴다). 내부 경로는 웹의 `safeNextPath` 와 같은 규칙으로 검증한다.
- **오프라인**: 첫 로드가 실패하면 앱 화면으로 "연결이 끊겼어" + 다시 시도 버튼을 보여 준다.
- **안드로이드 뒤로 가기**: 웹뷰 기록이 있으면 뒤로, 없으면 앱 종료 확인.
- **시작 화면**: Expo 스플래시(별콩이 이미지)를 웹뷰 첫 화면이 뜰 때까지 유지한다.

## 5. 웹 ↔ 앱 메시지 (`lib/app-bridge/protocol.ts`)

- 형식: `{ v: 1, type, payload }`. 앱은 메시지를 보낸 페이지 주소가 우리 도메인일 때만 받는다.
- ①에서 쓰는 메시지

  | 방향 | type | 언제 |
  |---|---|---|
  | 웹 → 앱 | `auth.loggedOut` | 웹에서 탈퇴를 마쳤을 때(로그아웃은 링크 규칙 2가 처리) |
  | 앱 → 웹 | (주입 값) `window.__BYEOLKONG_APP__` | 문서 시작 시. 웹이 앱 안인지 판단하는 1차 근거 |

- 결제(②)·알림(③) 메시지는 각 단계에서 이 파일에 추가한다.
- **앱 토큰은 어떤 메시지로도 웹에 넘기지 않는다.**

## 6. 웹 쪽 변경

- `lib/app-context.ts`(가칭): 브라우저에서는 `window.__BYEOLKONG_APP__` 또는 UA 의 `ByeolkongApp/` 로, 서버에서는 요청 UA 로 앱 안인지 판단한다.
- `lib/analytics/pageview.ts` `detectBrowserEnv`: UA 에 `ByeolkongApp/` 가 있으면 `"app"` 을 맨 먼저 돌려준다. 어드민 트래픽에서 앱을 따로 보게 된다.
- **애플 로그인 버튼**: 로그인 진입점 3곳에 카카오 버튼 아래 "Apple로 계속하기"를 추가한다(`/api/auth/login/apple?next=...`).
  - 보이는 조건: 웹 브라우저 + iOS 앱. **안드로이드 앱에서는 숨긴다**(애플 지침 4.8 은 iOS 에만 적용되고, 안드로이드에는 네이티브 애플 로그인이 없다).
  - 버튼 근처에 "기존 회원은 카카오로 로그인" 안내를 둔다(계정 2개가 생기는 걸 줄임).
  - 웹에 버튼을 보이는 스위치(`APPLE_LOGIN_WEB`)는 **10-25 메뉴판 판정 뒤**에 켠다. 그 전에도 iOS 앱(내부 테스트)에서는 보인다.
- **탈퇴 화면**: 탈퇴가 성공하면 앱 안일 때 `auth.loggedOut` 을 보낸다.

## 7. 로그인과 토큰

### 7-1. 공통 가입 처리 모듈 (`lib/auth/sign-in.ts`)

지금 카카오 콜백 안에 있는 회원 찾기·만들기와 신규 가입 처리를 이 모듈로 옮긴다. 네 경로(카카오 웹 · 카카오 앱 · 애플 웹 · 애플 앱)가 모두 이걸 부른다.

```
signIn({ provider, providerUserId, nickname?, profileImg?, request, appleRefreshToken?, appleClientId? })
  → 로그인 수단으로 회원 찾기
     ├─ 있음: 닉네임·프로필(카카오만)·last_login 갱신
     └─ 없음: users insert → user_identities insert → user_acquisition → star_balances
              → 웰컴 별(로그인 수단 해시로 1회) → CAPI CompleteRegistration
  → { userId, isNewUser }
```

- 카카오 웹 콜백의 겉 동작(리다이렉트·쿠키·state 처리·KOE320 무해 처리)은 바꾸지 않는다. 안쪽만 이 모듈을 부르게 바꾼다.
- 애플 회원 닉네임: 애플이 첫 로그인 때만 이름을 준다. 없으면 `별콩이_` + 무작위 4자리.
- 애플 로그인은 **이름만 요청하고 이메일은 요청하지 않는다**(우리는 이메일을 쓰지 않는다 — 수집 최소화).

### 7-2. 로그인 수단 해시 (`lib/auth/identity-hash.ts`)

- 카카오: `sha256(String(kakaoId))` — **지금 값 그대로**라 기존 `bonus_claims`·`account_withdrawals` 기록과 이어진다.
- 애플: `sha256("apple:" + sub)` — 카카오 값과 겹치지 않게 접두를 붙인다.
- 저장 칸은 기존 `kakao_id_hash` 를 그대로 쓴다(이름만 남은 칸 — 마이그레이션에서 주석으로 의미를 바꿔 적는다). 칸 이름을 바꾸면 배포 순서 사고 위험이 있어서다.

### 7-3. 앱 로그인 흐름

```
[웹뷰] 로그인 버튼 → /api/auth/login/kakao?next=X 로 이동 시도
[앱]   이동을 막음 → 네이티브 로그인
         카카오: 카카오톡 앱 로그인 → 카카오 액세스 토큰
         애플:   무작위 nonce 생성 → 애플 로그인(sha256(nonce) 전달) → identityToken + authorizationCode
       → POST /api/auth/app/kakao   { accessToken, platform }
         POST /api/auth/app/apple   { identityToken, authorizationCode, nonce, fullName?, platform }
[서버] 제공자 확인 → signIn() → 앱 토큰 발급 + 교환 코드 발급
       ← { accessToken, accessExpiresAt, refreshToken, handoffCode, isNewUser }
[앱]   토큰을 기기 보안 저장소(expo-secure-store)에 보관
       웹뷰를 /api/auth/app/handoff?code=…&next=X 로 연다
[서버] 교환 코드 소비 → setUserCookie() → X?login=success(&welcome=1) 로 리다이렉트
```

- **카카오 토큰 확인**: `GET kapi.kakao.com/v1/user/access_token_info` 로 토큰의 `app_id` 가 우리 카카오 앱(`KAKAO_APP_ID`)인지 확인한 뒤 `GET /v2/user/me` 로 회원번호·닉네임을 받는다. 다른 앱에서 발급된 토큰은 거절한다. 카카오 토큰은 서버에 저장하지 않는다(애플 지침 5.1.1(v)).
- **애플 토큰 확인**: identityToken(JWT)을 애플 공개키(JWKS)로 검증한다. 발급자 `https://appleid.apple.com`, 대상(aud) = 앱 번들 ID(웹은 Services ID), 만료, nonce(`sha256(앱이 보낸 nonce)` 일치)를 확인한다. 통과하면 authorizationCode 를 애플 토큰 주소에 교환해 **애플 리프레시 토큰**을 받아 암호화 저장한다(탈퇴 때 revoke 하려면 필요하다).
- 서명·검증은 `jose` 라이브러리를 쓴다(JWT 검증·ES256 서명을 직접 구현하지 않는다).
- 로그인 직후 리다이렉트 쿼리(`login=success`, `welcome=1`)는 웹 콜백과 같게 맞춘다 → 기존 `AuthBootstrap` 처리와 로그인 전 맛보기의 이어하기(`next` 의 `resume=login`)가 그대로 동작한다.

### 7-4. 앱 토큰 규칙

| 항목 | 규칙 |
|---|---|
| 액세스 토큰 | 1시간. HMAC 서명(`APP_ACCESS_TOKEN_SECRET`, 어드민 비밀값과 분리). 내용: 회원 ID·만료·종류·버전 |
| 리프레시 토큰 | 90일. 무작위 32바이트. DB 엔 해시만 저장. **쓸 때마다 새것으로 교체**(같은 '기기 묶음' 안에서) |
| 재사용 감지 | 이미 교체된 리프레시 토큰이 다시 오면 그 기기 묶음의 토큰을 전부 폐기한다 |
| 교체의 원자성 | `UPDATE … SET rotated_at = now() WHERE token_hash = $1 AND rotated_at IS NULL AND revoked_at IS NULL AND expires_at > now() RETURNING …` 한 문장으로 동시 요청을 막는다 |
| 교환 코드 | 60초 · 1회용 · 해시 저장 · 같은 방식의 조건부 UPDATE 로 소비 |
| 앱 실행 시 | 리프레시로 토큰을 갱신하고, **교환 코드를 새로 받아 웹뷰 첫 주소로 연다**(`POST /api/auth/app/handoff-code`). 웹뷰 쿠키가 지워졌어도 매번 맞춰진다 |
| 로그아웃 | 앱이 `POST /api/auth/app/logout` 으로 그 기기 묶음을 폐기 → 보안 저장소 비움 → 웹뷰가 `/api/auth/logout` 을 열어 쿠키 정리 |
| 탈퇴 | 서버가 회원을 지우면 토큰 행도 함께 지워진다(FK CASCADE). 이미 나간 액세스 토큰은 최대 1시간 남지만 회원 행이 없어 쓸 데가 없다 |
| 속도 제한 | 앱 로그인·토큰 갱신·교환 코드 주소에 IP 기준 속도 제한을 건다 |

- **`getSession()` 확장**: 요청에 `Authorization: Bearer <액세스 토큰>` 이 있고 검증을 통과하면 그 회원으로 본다. 없으면 지금처럼 쿠키를 읽는다. 둘 다 있으면 토큰이 우선한다(앱 쪽 호출은 명시적이다). Next 16 의 `headers()` 도 async 이므로 모든 호출처는 지금처럼 `await getSession()` 그대로다.
- 앱 쪽 호출은 쿠키를 쓰지 않는다(React Native 의 fetch 쿠키 저장소는 웹뷰와 별개다).

### 7-5. 웹 애플 로그인

```
GET  /api/auth/login/apple?next=X
       → state("{nonce}|{next}") + nonce 쿠키(SameSite=None; Secure — 애플이 form_post 로 돌아오는 교차 사이트 POST 라 Lax 쿠키는 안 실려 온다)
       → appleid.apple.com/auth/authorize (client_id=Services ID, response_mode=form_post, scope=name)
POST /api/auth/apple/callback   (code, id_token, state, user)
       → state 확인 → id_token 검증(aud = Services ID) → code 교환(애플 리프레시 토큰) → signIn()
       → setUserCookie() → 303 으로 X?login=success(&welcome=1)
```

- 실패하면 카카오와 같은 `loginFailRedirectUrl` 규칙으로 돌려보낸다.

## 8. 계정 구조 (마이그레이션)

모든 새 표는 RLS 를 켜고 정책 없이(서비스 역할만) 쓴다. `users(id)` 를 참조하는 FK 는 전부 `ON DELETE CASCADE`. SECURITY DEFINER 함수는 만들지 않는다(만들게 되면 `REVOKE … FROM PUBLIC, anon, authenticated` 셋 다).

```sql
-- 로그인 수단
create table user_identities (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  provider text not null check (provider in ('kakao','apple')),
  provider_user_id text not null,              -- 카카오 회원번호(문자열) / 애플 sub
  apple_client_id text,                        -- 애플 토큰을 발급한 client_id(번들 ID 또는 Services ID) — revoke 때 필요
  apple_refresh_token_enc text,                -- 암호화 저장(APPLE_TOKEN_ENC_KEY)
  created_at timestamptz not null default now(),
  last_login_at timestamptz,
  unique (provider, provider_user_id)
);
create index on user_identities(user_id);

-- 기존 카카오 회원 옮겨 담기
insert into user_identities (user_id, provider, provider_user_id, created_at)
select id, 'kakao', kakao_id::text, created_at from users;

-- 애플 회원은 kakao_id 가 없다
alter table users alter column kakao_id drop not null;

-- 앱 리프레시 토큰
create table app_refresh_tokens (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references users(id) on delete cascade,
  family_id uuid not null,                     -- 기기 로그인 1회 = 묶음 1개
  token_hash text not null unique,
  platform text check (platform in ('ios','android')),
  created_at timestamptz not null default now(),
  expires_at timestamptz not null,
  rotated_at timestamptz,
  revoked_at timestamptz
);
create index on app_refresh_tokens(user_id);
create index on app_refresh_tokens(family_id);

-- 교환 코드(웹뷰 쿠키 발급용)
create table app_handoff_codes (
  code_hash text primary key,
  user_id uuid not null references users(id) on delete cascade,
  is_new_user boolean not null default false,
  expires_at timestamptz not null,
  used_at timestamptz,
  created_at timestamptz not null default now()
);
```

- `bonus_claims.kakao_id_hash`·`account_withdrawals.kakao_id_hash` 는 칸 이름 그대로 두고 `COMMENT ON COLUMN` 으로 '로그인 수단 해시'라고 적는다(§7-2).
- **전환기**: 카카오 회원은 `users.kakao_id` 도 계속 채운다(되돌리기 안전판). 읽기는 전부 `user_identities` 로 옮긴다. `users.kakao_id` 칸 삭제는 출시 후 별도 정리 작업으로 한다.
- 오래된 교환 코드·만료 토큰 정리는 ③에서 만드는 cron 에 얹는다(①에서는 쌓여도 무해한 양이다).

## 9. 카카오 ID 를 읽던 곳 바꾸기

| 위치 | 바꾸는 것 |
|---|---|
| `app/api/auth/kakao` (웹 콜백) | 안쪽을 `signIn()` 으로 교체. 겉 동작 불변 |
| `app/api/auth/withdraw` | 로그인 수단별로 끊기: 카카오 → 지금처럼 unlink, 애플 → 애플 revoke. **토큰이 있는데 revoke 가 실패하면 탈퇴를 멈추고 503**(카카오와 같은 규칙). 애플 토큰이 없으면(교환 실패로 못 받은 경우) 로그를 남기고 진행. `account_withdrawals` 에는 그 회원의 로그인 수단 해시를 남긴다 |
| `app/api/payment/confirm` · `app/api/stars/first-charge-status` | 첫충전 보너스 해시를 `identity-hash` 로 계산 |
| `app/api/auth/me` · `app/api/admin/users` · 어드민 회원 화면 2개 | 로그인 수단(카카오/애플)을 보여 주고, 재가입 판정을 로그인 수단 해시로 |

## 10. 환경 변수

| 위치 | 이름 | 용도 |
|---|---|---|
| 서버(Vercel) | `APP_ACCESS_TOKEN_SECRET` | 앱 액세스 토큰 서명 |
| 서버 | `KAKAO_APP_ID` | 카카오 토큰의 `app_id` 대조 |
| 서버 | `APPLE_TEAM_ID` · `APPLE_KEY_ID` · `APPLE_PRIVATE_KEY` | 애플 client_secret(ES256) 서명 — revoke·code 교환 |

| 앱(EAS) | `EXPO_PUBLIC_BASE_URL` · 카카오 네이티브 앱 키 · (개발용만) Vercel 우회 값 | 변형별 설정 |

3. Expo 계정 만들기(무료) — 빌드·배포용
4. Vercel env 등록 후 재배포, `/api/health` 확인

## 12. 테스트와 완료 기준

**자동 테스트** (`node --import tsx --test`, 기존 방식)
- 액세스 토큰 발급·검증·만료·위조 거절
- 리프레시 교체, 재사용 감지 시 묶음 폐기, 동시 갱신 두 요청 중 하나만 성공
- 교환 코드 1회 사용·60초 만료
- 카카오 토큰 확인: `app_id` 불일치 거절(가짜 응답)
- 애플 identityToken 검증: 서명·aud·iss·만료·nonce 각각 틀린 경우 거절(테스트용 키)
- 로그인 수단 해시: 카카오 해시가 **기존 공식과 같은 값**인지(기존 보너스 기록 호환), 애플 해시와 겹치지 않는지
- `signIn()`: 신규·기존 회원, 웰컴 별 1회, 카카오 웹 콜백의 겉 동작 불변
- 링크 규칙·딥링크 경로 검증(순수 함수)

**실기기 확인** (아이폰·안드로이드)
- 카카오로 가입 → 웰컴 별 → 웹뷰 로그인 상태 → 로그아웃 → 다시 로그인(웰컴 별 중복 없음)
- (아이폰) 애플로 가입·로그인·로그아웃
- 탈퇴: 카카오 회원·애플 회원 각각, 탈퇴 후 앱 토큰으로 호출 실패
- 앱을 껐다 켜도 로그인 유지, 웹뷰 쿠키를 지워도 다시 맞춰짐
- 로그인 전 맛보기 → 로그인 → 이어하기가 그대로 동작
- 카카오톡 공유, 외부 링크, 안드로이드 뒤로 가기, 오프라인 화면

**웹 회귀**
- 웹 브라우저의 카카오 로그인·신규 가입·웰컴 별·유입 기록·CAPI 가 그대로다
- 애플 버튼 스위치를 끈 상태에서 웹 화면 변화가 없다

**완료 기준**: 위 항목 통과 + 개발용 앱을 실기기에 설치해 대표님이 직접 확인

## 13. 배포 순서와 시점

1. 마이그레이션(로그인 수단 표·옮겨 담기·kakao_id NOT NULL 해제·토큰 표) — 기존 동작에 영향 없음
2. 서버: `signIn()` 추출(웹 콜백 동작 불변) · 새 주소들 · `getSession()` 토큰 지원 · 탈퇴 변경 · 웹 애플 로그인(버튼 스위치 꺼짐)
3. 웹: 앱 판단 · `browser_env` 'app' · 메시지 형식 · 탈퇴 메시지 · 애플 버튼(스위치 꺼짐)
4. 앱: Expo 프로젝트 · 웹뷰 · 링크 규칙 · 네이티브 로그인 · 토큰 보관·갱신 · 딥링크 · 오프라인 · 뒤로 가기
5. 실기기 확인

- dev 에는 바로 올린다. prod 배포는 대표님이 명시적으로 지시할 때만 한다.
- **10-23 12:36(소재 판정 끝)·10-25 21:29(메뉴판 판정) 전에는 웹 화면에 보이는 변화를 prod 에 내보내지 않는다.** 애플 버튼 스위치는 그 뒤에 켠다. 서버 주소·DB 변경은 화면에 안 보이므로 일정 제약이 없다.

## 14. 알려진 한계와 나중 일

- 안드로이드 앱에는 애플 로그인이 없다 → 아이폰에서 애플로 가입한 사람이 안드로이드로 옮기면 앱에서 로그인할 수 없다(웹 브라우저에서는 가능). 수요가 보이면 웹 애플 로그인을 앱에서 여는 방식을 추가한다.
- 한 사람이 카카오·애플로 계정을 2개 만들 수 있다 → 안내 문구로 줄이고, 병합은 수요를 보고 나중에.
- 탈퇴 직후 최대 1시간 동안 이미 나간 액세스 토큰이 남는다 → 회원 행이 없어 실제로 쓸 데가 없다. 더 엄격하게 하려면 토큰 확인 때 회원 존재를 조회한다(요청마다 DB 1회).
- 카카오 네이티브 로그인 라이브러리(`@react-native-seoul/kakao-login` 후보)의 Expo 호환 방식은 계획 단계에서 확정한다.
- `users.kakao_id` 칸 정리, 오래된 토큰·코드 정리는 별도 작업.
