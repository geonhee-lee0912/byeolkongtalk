# 사주 MBTI — 문항 → 자아 유형 + 일치율 설계 (하위 프로젝트 B)

> 하위 프로젝트 **B(문항 확정 → 자아 유형)** + 그 산출물로 가능해지는 **일치율(A+B)** 만 다룬다.
> A(축 매핑)는 완료. C(콘텐츠)·D(결과화면)·E(플로우)는 각자 별도 스펙.
> 원 기획서 §6(12문항 초안·가중치): `~/Downloads/saju-mbti-test-기획정리.md`. 작성 2026-08-23.

## 1. 목표 · 범위

문항 12개 답 → **자아 유형**(4축 2분법, A와 동일 포맷) 산출 + **일치율**(자아 vs 팔자 극 일치)까지. 순수·결정론·LLM 0.

- **입력**: 12문항 각 선택지 id (4지선다).
- **출력**: 축별 `AxisResult`(A의 타입 재사용) × 4 + 16 한글코드 + 일치율 밴드(팔자와 함께).
- **비범위**: 16유형/오행/일치율 **본문 콘텐츠**(C), 결과 화면·%막대 렌더(D), 입력 순서·라우트·공유(E). 자아 유형엔 **오행 없음**(오행 주기질은 사주 쪽 전용).

## 2. 3원칙 (설계 불변식 — "내 성격 아닌데" 방어)

1. **자아 축은 영원히 무보정.** 자아 극 = 문항 원점수 높은 쪽. 16유형 분포가 쏠려도 **가중치로 output을 보정하지 않는다**(그 순간 답↔유형이 어긋남). 분포 조정은 오직 **문항/선택지 내용**(선택지 매력 균등화)으로.
2. **팔자 카피는 "진짜 너"라고 우기지 않는다.** 팔자 = 씨앗/타고난 결, 자아 = 네가 만든 너. "거스르는 자"는 열등이 아니라 **주체성 서사**. (실행은 C, 여기선 원칙만 고정.)
3. **경계선은 %막대로 완충.** 51:49도 극 라벨은 박히지만 결과 화면 축별 %막대(D)가 "거의 반반"을 눈으로 보여줘 라벨 폭력성을 완충.

## 3. 자아 유형 산출

- **채점**: 각 문항 선택지는 극 가중치를 가짐 — 주축 +2, 일부 부축 +1 흘림. 예(원 기획서): `③ 살 것만 사서 빠른 이탈 〔음+2, 재+1〕`. 8개 극(양/음·강/유·재/인·생/단) 누적 집계.
- **축별 판정** (음양 예):
  ```
  frontScore = 양 누적, backScore = 음 누적
  pole = frontScore > backScore ? "양" : frontScore < backScore ? "음" : <동점 폴백 §4>
  raw  = frontScore − backScore              // + = 앞극
  pct  = frontScore / (frontScore + backScore) × 100   // 원점수 비율, 표시 전용
  ```
- **출력 형태**: A의 `AxisResult{raw, pct, pole}` 재사용. `code` = 4축 극 이어붙임(음양·강유·재인·생단), A와 동일 규칙.
- ⚠️ **pct 의미가 A와 다르다**: 자아 pct = **원점수 비율**, 팔자 pct = **인구 백분위**. 둘 다 "앞극 쪽 %"로 표시는 되지만 **일치율 계산엔 pct를 쓰지 않는다**(§5, 극만 사용). 크기 비교(|자아pct − 팔자pct|) 금지.

## 4. 동점 처리

축 전체점(부축 흘림 포함)이 front == back 동점이면 → 그 축 **전용 3문항의 주축 다수결**로 폴백. 3문항 각각 한쪽 극에 +2 하므로 3-0 또는 2-1 → **항상 결판**(홀수). 자의적 코인플립 없음. self-report 충실.

## 5. 일치율 (A+B 통합)

- **극 일치 기반**(크기 아님): 4축 각각 자아 극 == 팔자 극인지 세어 `matchCount ∈ 0..4`.
- **밴드**: `4 → 천명대로 사는 자 / 2~3 → 절충하며 사는 자 / 0~1 → 팔자를 거스르는 자`.
- 화면(D)엔 축별로 자아·팔자 %막대를 나란히 — 극 일치 여부 + 근소차를 시각화(일치율 산술과 별개).
- 산출물: `{ matchCount, band, perAxis: [{axis, selfPole, paljaPole, agree}] }`.

## 6. 문항 검수 1라운드 (원안 유지 + 3곳)

원 기획서 §6 12문항 초안을 데이터로 옮기되:
1. **Q9 극단성 완화** — "십 년 농사 vs 도 닦자"는 인생결단급이라 답 쏠림 위험. 딜레마 강도를 다른 문항과 맞춰 재작성(재/인 축 신호는 유지).
2. **선택지 매력 균등** — 원칙①의 유일한 분포 레버. 한쪽 극 선택지만 매력적이지 않게 문안 다듬기.
3. **부축 흘림 pool 재계산** — 부축 +1 흘림 합이 축별 총점 pool(음양14·강유14·재인13·생단13)을 실제로 맞추는지 검산, 어긋나면 흘림 재배치.
- **선택지 셔플**: 렌더 시 4선택지 위치 랜덤화(①②=한쪽 극 패턴 노출 방지). **점수는 위치가 아니라 선택지 id(정체성)에 고정**.

## 7. 검증 (성공 기준)

- **단위 테스트**: 채점 누적·축 판정·동점 3문항 폴백·코드 조립·일치율 매핑(0~4→밴드). 고정 답안 세트로 기대 유형 검증.
- **밸런스 시뮬**(진단): 무작위 응답 대량 → 자아 16유형 분포 확인. ⚠️구조적 쏠림 시 **문항/선택지 내용으로만** 교정(가중치로 output 보정 금지 — 원칙①). 시뮬은 채점 구조 균형을 보는 것이지 "체감 정확도"를 보는 게 아님.
- **실사용자 파일럿**: 지인 몇 명에게 돌려 "네 자아유형 맞아?" 체감 확인 — "내 성격 아닌데" 방어의 **마지막 관문**. 파일럿 실패 시 원칙① 하에 문항 내용만 수정.

## 8. 코드 구조

- `lib/saju-mbti/questions.ts` — 12문항 데이터(문항 텍스트·선택지 id·극 가중치). 셔플은 렌더 계층(D)에서, 데이터는 정렬 원본.
- `lib/saju-mbti/self-type.ts` — `selfType(answers: string[]): { axes, code }` (답 id 배열 → 자아 `AxisResult`×4 + 코드). 동점 폴백 포함.
- `lib/saju-mbti/match.ts` — `matchRate(self, palja): { matchCount, band, perAxis }` (자아·팔자 극 비교).
- A의 `constants.ts`(`Pole`/`AxisKey`/`POLES`)·`mapping.ts`(`PaljaType`) 재사용. 순수·결정론.
- 밸런스 시뮬: `scripts/saju-mbti-selftype-sim.mjs`(무작위 응답 → 분포, dev 툴).

## 9. 확정 결정 요약

| 결정 | 값 |
|---|---|
| 일치율 비교 | 극(極) 일치 수 0~4 → 밴드 (크기 차 아님) |
| 밴드 컷 | 4=천명 / 2~3=절충 / 0~1=거스름 |
| 자아 pct | 원점수 비율(표시 전용), 무보정 |
| 동점 | 축 3문항 주축 다수결 폴백 |
| 문항 | §6 원안 + 검수 1라운드(Q9·매력균등·pool 재계산·셔플) |
| 자아 오행 | 없음(사주 전용) |
