## 3. 설계

### 3-1. 구매 일수 — `lib/byeolmaru/subscribe-offer.ts` `subscriptionPurchaseDays` (순수 함수 · 유닛 테스트)

| 단계 | 판정(computeEntitlement 결과) | p_days | 체험 기록 |
|---|---|---|---|
| 체험 전 | 비자격 · trialUsed=false | 30 + 3 = **33** | 성공 뒤 `trial_started_at = now`(startTrial 그대로 — NULL 일 때만) |
| 체험 중 | reason=trial | 30 + **남은 체험(시간 기준 올림)** | — |
| 체험 후 | 비자격 · trialUsed=true | 30 | — |
| 구독 중 | reason=subscription | **409 `already_subscribed` · 차감 없음**(`alreadySubscribedUntil` — 응답에 지금 만료 `expiresAt`) | — |

- 경계: 남은 71.9h → 3일 · 0.1h → 1일 · 정확히 48h → 2일. 올림이라 남는 몇 시간은 유저 몫이다
- RPC `purchase_byeolmaru_subscription` 은 `GREATEST(활성 만료, now()) + p_days` 그대로다. 체험은 구독 행이 아니라 RPC 가 모르므로, 남은 체험을 TS 가 일수에 더한다
- 구독 중 = 409(사용자 확인 2026-10-12, 원래는 '30일 이어 붙이기'였다): 구독자 화면엔 연장 버튼이 없다 → 구독 중 구매는 사실상 전부 **낡은 화면**(같은 날짜 화면의 다른 탭에 남은 버튼 — 다른 탭에서 막 샀다)에서 온다. 그대로 두면 20별을 또 빼고 30일을 이어 붙였다. 클라는 "이미 구독 중이야 — M월 D일까지"를 띄우고 화면을 새로 읽는다. 서버는 warn `ALREADY_SUBSCRIBED:`(설계된 정상 신호)
- 체험 전 구매에 체험을 기록하는 이유: 안 하면 33일이 끝난 뒤 '3일 무료 체험'이 다시 뜬다(trialUsed=false)
- ⚠️ 부작용: 체험 전·중에 산 구독 행은 30일보다 길다(최대 33일) — 어드민 구독 기간·방문일 분모가 그만큼 늘어난다. 체험 전 구매자는 `trial_started_at ≈ 구독 started_at`(수 초 차)로 가려진다

### 3-2. 노출

| 단계 | 자리 | 내용 | surface |
|---|---|---|---|
| 체험 전 | 절단선 캡션(주 버튼은 체험 그대로) | "체험 끝나면 20별 / 30일 · 바로 구독하면 체험 3일 + 30일 →" | `cut` |
| 체험 중 | 유료 리포트 바로 아래(세 탭) — `TrialSubscribeNudge` | "체험 D-{n}야. 지금 구독해 두면 체험 끝난 다음부터 30일 이어서 받아." · [이어서 구독하기 · 20별] · "자동결제 아니야 — 20별 한 번이면 끝." | `report_end` |
| 체험 후 | 허브 배너 · 절단선 · 받은 글 아래 안내 | 기존 그대로 | `banner` · `cut` · `kept_report` |

- 넛지 조건 `entitled && !subscriptionExpiresAt`(= 체험 중). 금색·자물쇠·'끝나면 못 봐' 금지(페르소나 원칙) — 보조 스타일 한 줄 + 버튼 하나, 화면당 하나
- D-N 은 HubBanner 와 같은 계산(올림·최소 1) — `daysLeft` 하나를 둘이 같이 쓴다
- 구독 확인창 부제는 단계별: 체험 전 "체험 3일 + 30일" / 체험 중 "체험 끝난 다음부터 30일" / 체험 후 지금 문구

### 3-3. 충전하고 돌아오기

- 잔액 부족 → 확인창 [별 충전하러 가기] 와 서버 402 **둘 다** 그 자리 `RechargeSheet`(need=20 · 잔액 전달 · source `byeolmaru_subscribe`). FortunePurchasePanel 관례대로 열릴 때만 마운트
- returnTo = 지금 경로 + `bm_sub=<surface>`. 결제 성공 → /shop 이 returnTo 로 돌려보냄 → 돌아온 화면이 **자격을 읽은 뒤 한 번만** 확인창을 다시 열고 표시를 주소에서 지운다
  - 주소 정리는 `history.replaceState(history.state, "", …)` — null 로 덮지 않는다(첫 로드에 Next 의 `__NA` 상태가 지워진다) · `router.replace` 금지(대기 중인 이동을 버린다)
  - 이미 구독 중이면 안 연다(다른 탭에서 샀을 수 있다)
  - **잔액이 20 이상일 때만 연다**(2026-10-12, `shouldResumeSubscribe`) — 결제 실패·취소 뒤 /shop 의 '← 대화로 돌아가기'도 같은 returnTo(표시 포함)로 와서, 열면 같은 '별이 부족해' 창이 또 떴다. 표시는 열든 안 열든 지운다

## 4. 같이 고친 구멍 3개

1. **연타 이중 차감** — 확인·체험 시작에 ref 동기 잠금(state 만으론 같은 틱 연타를 못 막는다) + 버튼 '여는 중…' + 진행 중 확인창 닫기 막음
2. **충전 후 미복귀** — §3-3
3. **500 미로깅** — `subscription.ts` 가 에러를 돌려주고 라우트가 402 외 실패를 `logError`(402 는 설계된 정상 신호라 안 남긴다)

덤: 구독 뒤 `byeolkong:balance-updated` — 다른 구매 경로와 같이 헤더 잔액이 바로 줄어든다. 성공만이 아니라 결과를 모르는 실패(시간 초과·연결 끊김·5xx)·409 뒤에도 보낸다 — 서버엔 이미 20별이 빠졌을 수 있다(`syncEntitlement`).

### 4-1. 서버 쪽 중복 방어 — 구독 중이면 409(2026-10-12 구현)

- 실측으로 구멍이 하나 더 나왔다(10-11 E2E·검토): 날짜 상세(`DayTabsView`)는 자격을 진입 때 한 번 받고 연 탭을 살려 두는데, 체험·구독 성공은 그 탭만 새로 고쳤다 → **다른 탭은 낡은 자격** — 사주 탭에서 체험을 시작해도 타로 탭엔 '3일 무료로 열어보기', 한 탭에서 구독한 뒤 다른 탭의 남은 [구독하고 매일 보기]를 누르면 **20별 또 차감 + 30일 이어 붙이기**
- 서버: 구독 라우트가 RPC 전에 자격을 보고 **구독 중이면 차감 없이 409 `already_subscribed`**(§3-1). 순차 중복(앞 요청 커밋 뒤 도착 — 연타·두 탭·실패 뒤 재시도)이 전부 여기서 막힌다
- 화면: 체험·구독의 성공·409·실패·시간 초과 뒤 `window` 에 `byeolmaru:entitlement-changed` → `DayTabsView` 가 캘린더를 **한 번** 다시 받아 열린 탭 전부에 내려준다(누른 탭의 새로 읽기와 합쳐진다 — 탭 오가기엔 요청 0). 다시 받기가 5xx·본문 깨짐·본문 없는 404 면 지금 화면을 그대로 둔다(덮으면 세 탭이 '못 펼쳤어'가 된다 — 낡은 버튼은 409 가 막는다). 허브(`ByeolmaruHub.reloadAfterChange`)도 같은 규칙(`acceptReloadedCalendar`) — 오프라인에서 배너의 체험·구독을 눌러도 허브가 통째로 에러로 바뀌지 않는다(첫 진입 로딩 실패는 그대로 에러)
- 시간 제한: 체험·구독 요청 15초(처리 중엔 확인창을 못 닫아 응답이 안 오면 갇힌다). 넘으면 잠금을 풀고 `failed{status:"timeout"}` + 화면 새로 읽기 + 짧은 안내. 연결 끊김·5xx 뒤에도 새로 읽는다(서버엔 반영됐는데 응답만 잃었을 수 있다 — iOS 앱 전환 등)
  - 🔴 **구독의 시간 초과 안내는 재시도를 권하지 않는다**: "응답이 늦어서 결과를 아직 몰라. 이미 구독됐을 수 있으니, 잠시 뒤 화면을 새로 불러와서 구독 상태부터 확인해줘." — 첫 요청이 서버에서 아직 안 끝났으면 바로 다시 누른 요청은 409 판정(RPC 잠금 밖)을 지나 20별을 또 뺄 수 있다. 연결 끊김·5xx·체험 시작(1회성이라 재시도가 늘 안전) 문구는 그대로
- 서버: 구독 라우트만 자격을 **엄격하게** 읽는다(`getEntitlementStrict`) — DB 에러면 던져 500 `purchase_failed` + logError(차감 전이라 별은 그대로). 느슨한 `getEntitlement`(캘린더·리포트 — 동작 그대로)는 supabase-js 가 일시 실패를 `{error}` 로 돌려줄 때 '구독 없음'으로 읽어, 구독자도 409 를 지나 20별이 또 빠지고 체험을 쓴 유저는 33일 + 체험 재기록이 됐다. users 행이 없는 쿠키(탈퇴 등)는 에러가 아니라 체험 전·구독 없음(`.maybeSingle()`)
- **남는 구멍 = 두 기기 '동시' 구매**(둘 다 커밋 전에 자격을 읽는다) — 막으려면 판정을 RPC 안 `FOR UPDATE` 잠금 아래로 옮겨야 한다(SQL 변경). 규모(4주 구매 1건 안팎)에서 이득이 작아 그대로 두고, 판독 SQL 의 `broken_double_row`·`broken_extension`(구독 중에 산 행)으로 감시한다 — 한 줄이라도 나오면 그때 넣는다

## 5. 계측

- 새 `byeolmaru_subscribe_offer_shown{surface, phase, slot?}` — 구독 선택지가 그려질 때 마운트당 1회(체험 전 링크·체험 중 넛지·체험 후 배너/절단선/받은 글 안내 전부)
- `byeolmaru_subscribe_clicked` · `byeolmaru_subscribe_completed` 에 `surface`·`phase`(+ completed 는 재오픈 구매면 `resumed:true`)
  - completed 의 `phase`·`days` 는 **서버가 판정한 값**(구독 라우트 응답 — 2026-10-12~). clicked 의 phase 는 누른 순간 화면이 안 단계라 둘이 다를 수 있다
- 새 `byeolmaru_subscribe_failed{status: 402|409|500|기타 숫자|"network"|"timeout", surface, phase}` — 409 = 낡은 화면의 구독을 서버가 막음(차감 없음 · 고장 아님), "timeout" = 15초 무응답(2026-10-12~)
- 충전 시트 source `byeolmaru_subscribe` — `paywall_shown{surface}`·`recharge_sheet_opened{source}` 둘 다 **Meta AddToCart 에서 제외**(`rechargeCapiEventId`)
- 기존 `byeolmaru_gate_shown` 은 추세 잇기용으로 그대로
- ⚠️ `byeolmaru_trial_started` 는 잠금 때문에 events 수가 줄어든다(실인원 불변) — **배포 전후 events 수 비교 금지**
- 판독: `scripts/byeolmaru-subscribe-offer-check.sql`(읽기 전용 · `params.deploy_at` 필수). 어드민 `admin_byeolmaru_funnel` 은 이벤트 4개 고정이라 새 이벤트를 안 본다 — 이 판독은 SQL 로 한다

## 6. 성공 기준 (배포 후 4주 · 실인원 · 지인 6명 제외)

- 체험 중 노출 ~40명 중 클릭 0 → **상품·가격**
- 클릭은 있는데 충전에서 멈춤 → **현금 장벽**
- 구매 4명+ → **유지**
- 기대치는 4주 구매 1건 안팎(0건 확률 ~30%) — 0건으로 실패를 단정하지 말고 **막힌 단계**로 판정한다
- 즉시 조치 고장: 구독 500 1건 · 완료 이벤트인데 구독 행 없음 · 같은 유저 1분 안 구독 행 2개 · 구독 중에 산 행(`broken_extension` — 409 가 막았어야 하는 구매)

## 7. 배포·확인

- prod 는 메뉴판 판정 뒤 사용자 go. 배포 시각을 판독 SQL `params.deploy_at` 에 넣는다
- 배포 뒤 사용자 실결제 1회 확인(prod 구매 경로는 한 번도 실행된 적 없다): 잔액 부족 → 충전 시트 → 토스 결제 → 별마루 복귀 → 구독창 자동 재오픈 → 구독 → 20별 차감(헤더) → 배너 '구독 중 · D-N'
