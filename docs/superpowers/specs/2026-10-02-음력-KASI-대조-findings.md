# 음력 — 한국천문연구원(KASI) vs tyme4ts 전수 대조 (2026-10-02)

> 출발점: `2026-10-02-음력-무효날짜-design.md` §8-2 "추정·미검증 — tyme4ts 는 중국 농력 기준". 이 문서는 그 추정을 실측으로 판정한다. **결정: A안(KASI 표 정본화)** — §6. 절입 1시간(§4)은 미결정.

## 1. 결론

- **확인됨.** tyme4ts(앱 엔진, 1.5.2 고정)는 중국 농력이다. 1900~2050 에서 한국 음력(KASI)과 **64개월의 양력 날짜가 다르다** — 하루 밀림 62개월 + 한 달 통째 밀림 2개월(2012·2017 윤달 위치 차이).
- 원인은 하나 — **기준 시간대**. 합삭(새 달)·중기(윤달 판정)가 베이징시 23시대 = KST 0시대에 걸리면 날짜가 갈린다. 129개 불일치 행 전부 이것으로 설명된다(§3).
- 앱 영향(날짜 단위, `calcSaju` 실측): 1900~2050 한국 실존 음력일 55,134일 중
  - **1,857일(3.37%) 조용히 틀린 사주** — 전부 일주 틀림, 그중 월주 115일·연주 7일도 틀림. (시각을 알면 시주 천간도 일간 따라 틀림)
  - **121일(0.22%) 한국엔 있는데 앱이 막음**(폼에 없음 / 서버 400) — 2012 윤3월·2017 윤5월 전체 + 61개 달의 30일
  - 121일 한국엔 없는데 앱이 받음(2012 윤4월·2017 윤6월 + 62개 달의 30일)
  - prod 실재 범위 1959~2015 만 보면: 20,819일 중 639일(3.07%) 틀림 · 50일 막힘
- **prod 현재 영향 0행** — 음력 입력 프로필 25행(본인 12) 중 불일치 구간 해당 0 → 묶인 reading 도 0(§5).
- 같은 원인의 **별건**: 양력 입력도 절입(월·연주 경계)을 베이징시로 판정한다 → 절입 직전 1시간(KST) 출생은 월주(입춘이면 연주도)가 다음 것으로 나온다(§4).

## 2. 출처 · 방법

**출처 = KASI 천문우주지식정보 음양력 변환** (https://astro.kasi.re.kr/life/pageView/8) 이 쓰는 공개 GET 엔드포인트. 2026-10-02 조회.

| 엔드포인트 | 용도 | 비고 |
|---|---|---|
| `GET /life/lunc/between?start_yyyy=1900&end_yyyy=2050&mm=MM&dd=01&isLeap=0\|1` | 음력 MM월 1일의 양력 날짜(연도 범위 전체) | **`isLeap` 서버 의미 0=평달·1=윤달**(페이지 라벨과 반대) — 응답 `LUNC_LEAP_MM`(평/윤)으로 판정. 12개월×평/윤 = **24회 호출로 전체 수신** |
| `GET /life/lunc?yyyy=&mm=&dd=` | 음력→양력 단건(평·윤 둘 다 반환) | 2017-05-01 → 평 2017-05-26 / 윤 2017-06-24 확인 |
| `GET /life/lunc/getMaxDate` | 범위 끝 | 양력 2050-12-31 = 음력 2050-11-18 → **2050년 12월은 KASI 범위 밖** |
| `GET /kor/life/pageView/7?yyyy=&mm=` | 월별천문현상(합삭 시각 KST) | 메커니즘 1차 확인용 2개월만 |

응답 필드: `LUNC_YYYY/MM/DD`·`LUNC_LEAP_MM` 음력 · `SOLC_YYYY/MM/DD` 양력 · **`LUNC_EN_DD` 그달 일수** · `LUNC_ILJIN` 일진.

공식 OpenAPI 는 공공데이터포털 "한국천문연구원_음양력 정보"(https://www.data.go.kr/data/15012679/openapi.do, 서비스키 필요 — `.env.local` 에 없음)로, 같은 데이터다.

**검증 단계**
1. KASI 1,867개월(1900-01 ~ 2050-11, 윤달 56개) — 각 달 `1일 + 일수 = 다음 달 1일` 체인 끊김 **0**.
2. tyme4ts: `LunarYear.getMonths()` 로 같은 표(1,868개월) — 체인 끊김 0. (조사 스크립트만 tyme4ts 직접 호출, 앱 코드 아님)
3. 정답 쪽 검증: KASI 날짜를 양력으로 넣은 `calcSaju` 일주 = KASI `LUNC_ILJIN` — **1,867/1,867 일치**. 같은 1일을 음력으로 넣은 앱 결과는 1,801/1,865 일치 + 2개월 막힘 → 차이 64개월이 §1 과 정확히 같다.
4. 날짜 단위 영향: KASI 실존 음력일 55,134일 전부를 워크트리 `lib/saju/calc.ts` 의 `calcSaju`/`canCalcSaju` 에 넣어 정답(같은 날의 KASI 양력일)과 연·월·일주 비교(시각 모름 = 0시, 앱과 같은 처리).

## 4. 별건 — 절입 1시간 (양력 입력 포함)

tyme4ts 는 절기 시각도 베이징시로 낸다. 앱은 입력 시각(KST)을 그대로 비교한다.

- 2024 입춘: 같은 순간 = 08:27 UTC = **KST 17:27**(한국 공지) = 베이징 16:27. 앱은 **16:27 에 연·월주를 바꾼다** — 실측: KST 16:26 → 계묘년 을축월 / 16:28 → 갑진년 병인월. 즉 KST 16:27~17:27 출생은 갑진년 병인월로 틀린다(정답 계묘년 을축월).
- 해마다 절 12개 × 1시간 → **시각을 아는 출생의 약 0.14%** 가 월주 틀림(입춘 창이면 연주도). 음력 표 문제와 달리 양력 입력(다수)에 걸린다.
- prod 영향은 미측정(별도 조회 필요). 판정 근거: tyme4ts 계산 + KASI 합삭 1차 자료로 확인한 +1시간 관계. KASI 절기 시각 1차 자료(공공데이터포털 특일정보 API)는 서비스키가 없어 미조회 — 한국 공지 시각은 2차 자료(언론·위키) 기준.
