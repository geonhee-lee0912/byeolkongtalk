# 우리 사이 탭 · 연애 시뮬레이션 상세 설계

**작성** 2026-08-03 · **상태** 브레인스토밍 1차 확정 (세부 이월 명시)
**선행** `2026-08-01-연애-시뮬레이션-형태-design.md`(상품 형태) · `2026-08-02-하단탭-IA-통합-design.md`(§3탭) · `2026-07-27-e1-ia-content-hierarchy-design.md`(§4 파일 프레임·3화자)
**맥락** T1 게이트 **최대 작업**. 이 문서 = 우리 사이 탭(파일 허브 + 시뮬 + 스레드)의 화면·과금 구체화.
**⚠️ 선행 스펙에서 오너 결정으로 뒤집은 것 2건** 있음 — §6 참조(형태 스펙의 "단발 고정가 폐기"·"무료 체험 전제"를 뒤집음).

## 한 줄

밤에 **인형을 안고 마음을 털어놓듯**, 유저가 그린 그 사람의 초상화(=인형)를 상대로 난감한 상황을 연습하고, 곁의 별콩이가 통찰을 건네는 상품. 파는 것은 인형이 아니라 **별콩이와 함께하는 경험**(대화 한 판 + 코칭).

## 1. 정체 — "밤에 인형을 안고 털어놓는 것" (정본, 맨 앞 고정)

3화자를 이 은유로 세운다. 별콩이는 상대를 **연기하지 않는다.**

| 자리 | 정체 |
|---|---|
| **유저** | 밤에 인형을 안고 마음을 털어놓는 사람 |
| **상대 인형** (민준이) | 유저가 그린 초상화 = 별콩이가 데려다 준 오브젝트. **진짜 걔가 아님.** 차갑고 회피하고 화낼 수 있음 |
| **별콩이 🌙** | 인형이 아니라 **너**를 지켜보는 곁의 수호자. 코어 페르소나 그대로. 연기 안 함 |

이 은유가 E6 리스크를 한 번에 푼다:

1. **별콩이 코어 안 깨짐** — 차가운 건 인형이지 별콩이가 아니다. 별콩이는 끝까지 따뜻한 관찰자(코어 편집 0)
2. **안전** — 위기 신호 뜨면 별콩이가 **인형을 내려놓고** 바로 곁으로. 연기 중이 아니라 원래 관찰자라 개입이 자연스럽다(`lib/sensitive.ts` high → 역할극 중단)
3. **거울 프레임** — "인형"은 그 자체로 *"진짜 걔가 아니라 내 마음속 상(像)"* 이라 예측 오해가 원천 차단(정확도 0 문제 소멸)
4. **세계관 정합** — "밤에 인형 안고 털어놓기" = 별의 수호자·밤·위로라는 별콩이 정체성과 딱 맞음. **인형놀이 = 매직 서클의 원형**

## 2. 뼈대 — 파일 허브 + 시뮬 + 스레드 (E1 §4 계승)

```
/relationship  = 파일 허브 (한 화면)
  ├── 미등록 → 상단이 입력창 / 등록 → 그 자리가 파일 카드 (화면 전환 없음)
  ├── [시뮬레이션] → 밤 무대 (3화자, 독립 화면)
  └── [별콩이랑 얘기] → 대화 스레드 (현행 + ⚡ 스킬 4종)
```

- **콜드스타트를 별도 화면으로 두지 않는다** — E1 §4의 "미등록/등록후"는 같은 라우트의 두 상태. 등록 = "다음 화면 이동"이 아니라 **"상단이 입력창→파일 카드로 채워지는 것"**
- 파일 허브 = 상품 나열 ❌ = **사람 프로필**. 아래는 카탈로그가 아니라 딱 2개(시뮬·얘기) + 무료 후크 자리
- **동선**: 등록 → 시뮬 체험 → 디브리핑 → 허브에 "보낼 말" 적립 → 스레드로 깊이

## 3. 콜드스타트 + 입력 범위 (무발화 직격)

- **게이트(필수)**: 이름 + 관계(썸·연인·짝사랑·이별·기타). 이것만으로 시작
- **옵션(선택, 시작 안 막음)**: 상대 생일(→사주·궁합 열림) · MBTI · 한 줄 성격
- **점진 보강**: 안 받은 정보는 시뮬 중 별콩이가 물어 채운다 = **공동창작으로 초상화가 두꺼워짐**(리텐션 심장). 앞단에서 다 받으면 이 서사가 죽으므로 **필수 게이트 금지**
- ⚠️ 입력 선요구가 무발화 14/15의 직접 원인 + E6 최대 리스크(등록 마찰 재발). 필수 게이트는 그 지뢰
- **신규 필드**: MBTI (코드에 0건). 사주·성격은 기존 `user_profiles`(partner) 활용
- **재조정 여지**: 페르소나(상대 인형 화자) 구현하며 입력 범위 다시 볼 수 있음(오너, 2026-08-03)

## 4. 시뮬 한 판의 흐름

배경 톤을 스레드(크림)와 **확 다른 밤의 무대**로 바꿔 화자 혼동을 물리적으로 차단.

**① 상황 고르기**
- **구체 상황 카드 + 자유 입력**(템플릿이 주, 자유가 보조). 백지 입력이 무발화 원인이라 구체 카드로 첫 마찰 제거
- **"무게 분류(가벼움/중간/무거움)"는 삭제** — 그건 내부 설계 개념이지 유저 대면 라벨이 아니다. 유저는 자기 상황을 찾지 무게를 고르지 않는다
- 상황은 **관계별로** 다름(썸→연락·데이트·고백 / 연인→서운함·화해 / 이별→재회·마지막 / 짝사랑→다가가기). 목록 구성은 이월(§8)

**② 3화자 대화 (밤 무대)**
- **상단 프레임 고지**(제품 발화): *"별콩이가 민준이 인형을 데려왔어. 진짜 걔가 아니라 네 마음이 그린 민준이야."*
- 상대 = **인형으로 시각화**(사람 아님 신호), 별콩이 개입 = **채팅 버블이 아니라 노트**(지켜보는 사람 신호)
- **자유 대화가 기본** — 미연시식 A/B/C 선택지 ❌(= "정답 고르기 = 공략" = 스펙이 기각한 승리목표형 게임화). 정답 있는 선택지는 대상화·판타지 머신으로 미끄러진다
- **말문 도우미(💭)** = 미연시 선택지와 다름: 정답 없음 · 안 써도 됨 · 고르면 내 말로 다듬음. **유저가 "💭 별콩이 도움" 버튼을 누를 때만** 제공(자동 노출 ❌). → 이 버튼이 곧 **코칭**(§5, 별 소모): 가벼운 말문 트기부터 깊은 통찰까지 한 버튼
- **턴 한도 = 고민톡(타로/사주 chat)과 동일** — 자연 수렴(`[END]`) + abs-cap 방식 재사용(무한 대화 방지 = 원가 경계)
- **[정리하기] = "인형 내려놓고 정리"** = 디브리핑 트리거이자 유저가 언제든 빠져나오는 문(위기 시 서버가 누르는 문도 같음)

**③ 디브리핑**
- 별콩이 복귀(관찰자 → 곁) → 통찰(*"넌 먼저 물러서는 버릇이 보였어"* = 관찰형, 예측 ❌) → **"보낼 말"** 한 문장 → 파일에 적립
- ⚠️ **유료 판이라도 디브리핑까지 반드시 포함**(E1 §4 안전 제약 — 인형 침묵으로 끝나면 최악, 특히 이별 코호트)

## 5. 과금 (스레드=패스 / 시뮬=판 고정가 / 코칭=별도 별)

"패스·스레드 존폐 재검토"의 답 = 없애지도 통합하지도 않고 **각 상품 성격에 맞게 분리.**

| 상품 | 방식 | 상세 |
|---|---|---|
| **연애 상담(스레드)** | **패스** (기존 그대로) | 지속 대화 성격 → 기간제. 무료 인트로 3턴 → 패스 30·60·100별 → 하루 캡 뒤 5별=+5턴. `passes.ts` 재사용 |
| **시뮬레이션** | **판 고정가 X별** | 한 판 세션 성격 → 한 판 = 한 상황, 턴 한도까지, 디브리핑 포함 = X별 |
| **별콩이 코칭(💭)** | **별도 별** | §4의 "💭 별콩이 도움" 버튼 = 코칭(말문 트기~전략~통찰). 연애 스킬(`RELATIONSHIP_SKILLS` 45/40/40/30)처럼 부를 때 별 소모 |

- **무료 첫 판 폐지** → **웰컴 20별**(`WELCOME_BONUS_STARS`)이 흡수. **X < 20** 이어야 신규가 웰컴 별로 첫 판을 체험. 명시적 무료 트랙 없이 기존 재화로 체험을 대신
- 별 잔액은 항상 `lib/stars` 래퍼 경유(트랜잭션) — RPC 직접 호출 금지(AGENTS.md)

## 6. 선행 스펙에서 뒤집은 결정 (근거 기록 — 나중에 판단 자료)

| 뒤집은 것 | 형태 스펙 원안 | 이번 결정 | 근거 / 화해 |
|---|---|---|---|
| **과금 단위** | "상황 단발 고정가 **폐기**", 대화 진행형(continuation+extend) | **판 고정가 X별** | 원가 통제(턴 한도) · 유저 이해 쉬움("한 판=X별") · 상점 상품화. 스펙이 걱정한 "반복 노동"은 **같은 상황 리셋을 강제 안 하면** 안 생김(다른 상황=정상 소비) |
| **무료 체험** | 무료 인트로 전제(형태 스펙·E1 §4 동선의 심장) | **무료 첫 판 폐지** | 린 검증(일단 유료로 구매 비율 관측 → 무료 체험 도입 여부 결정) · 무료별 원가 부담. 웰컴 20별이 사실상 체험 재화 |

⚠️ **무발화 직격책 약화 주의** — E1 §4는 "등록 직후 첫 행동을 결제가 아니라 무료 한 판으로" 만드는 게 무발화 14/15 대응이었다. 무료 폐지는 첫 행동을 결제(웰컴 별 차감)로 바꾼다. **웰컴 별 흡수가 이 완충을 얼마나 대신하는지 = 배포 후 첫 관측 지표.** 구매 비율이 무너지면 "명시적 무료 체험" 부활을 최우선 검토.

## 7. 신규 vs 기존 (구현 범위)

- **신규 구현**: 파일 허브 화면 · 시뮬 전체(상황 선택·3화자 무대·디브리핑) · **MBTI 필드** · 상대 인형 화자 페르소나 · 코칭(💭) 별 소모 액션 · 판 고정가 결제
- **기존 재사용**: 패스·스레드·스킬 4종(`skills.ts`) · 관계 memory(`memory.ts`) · SSE · continuation · 웰컴 별 · 고민톡 턴 한도/수렴 로직 · `user_profiles`(partner) · `lib/stars`

## 8. 보류 — 이어서 (다음 브레인스토밍 라운드)

의도적 이월(빈 placeholder 아님). 형태·과금 뼈대가 섰으니 그 위에서 채운다.

- **상황 목록 구성** — 관계별(썸/연인/짝사랑/이별)로 어떤 상황 카드들을 둘지
- **게임성 장치** — 형식만 살리는 연출(판·"다시"·카드) 구체. 승리 목표는 금지 유지
- **코호트 취급** — 이별·짝사랑의 시뮬을 어떻게(위기 신호 최다 코호트, 안전 우선)
- **가격 구체값** — 시뮬 X별(단 X<20) · 코칭 별 단가. 코드 상수가 정본
- **갈래 지도 재정의** — 형태 스펙의 "갈래 = 갈라진 가지 기록"은 진행형 과금 전제였다. **판 고정가로 오며 과금 포인트가 아니게 됨** → 산출물/기록으로서 어떤 형태일지(또는 폐기) 재검토 필요
- **미등록 허브 아래 처리** — 입력창 아래를 ⓐ 잠금+티저 / ⓑ 입력창만 / ⓒ 시뮬 하나 미리보기 중 무엇으로(내 추천 ⓒ 결, 미확정)
- **명칭 통일** — "리허설"(E1 §4 내부어) → 유저 대면 **"시뮬레이션"**. 문서·코드 반영
