## 한 줄

밤에 **인형을 안고 마음을 털어놓듯**, 유저가 그린 그 사람의 초상화(=인형)를 상대로 난감한 상황을 연습하고, 곁의 별콩이가 통찰을 건네는 상품. 파는 것은 인형이 아니라 **별콩이와 함께하는 경험**(대화 한 판 + 코칭).

## 1. 정체 — "밤에 인형을 안고 털어놓는 것" (정본, 맨 앞 고정)

3화자를 이 은유로 세운다. 별콩이는 상대를 **연기하지 않는다.**

| 자리 | 정체 |
|---|---|
| **유저** | 밤에 인형을 안고 마음을 털어놓는 사람 |
| **상대 인형** (민준이) | 유저가 그린 초상화 = 별콩이가 데려다 준 오브젝트. **진짜 걔가 아님.** 차갑고 회피하고 화낼 수 있음 |
| **별콩이 🌙** | 인형이 아니라 **너**를 지켜보는 곁의 수호자. 코어 페르소나 그대로. 연기 안 함 |

이 은유가 E6 리스크를 한 번에 푼다:

1. **별콩이 코어 안 깨짐** — 차가운 건 인형이지 별콩이가 아니다. 별콩이는 끝까지 따뜻한 관찰자(코어 편집 0)
2. **안전** — 위기 신호 뜨면 별콩이가 **인형을 내려놓고** 바로 곁으로. 연기 중이 아니라 원래 관찰자라 개입이 자연스럽다(`lib/sensitive.ts` high → 역할극 중단)
3. **거울 프레임** — "인형"은 그 자체로 *"진짜 걔가 아니라 내 마음속 상(像)"* 이라 예측 오해가 원천 차단(정확도 0 문제 소멸)
4. **세계관 정합** — "밤에 인형 안고 털어놓기" = 별의 수호자·밤·위로라는 별콩이 정체성과 딱 맞음. **인형놀이 = 매직 서클의 원형**

## 2. 뼈대 — 파일 허브 + 시뮬 + 스레드 (E1 §4 계승)

```
/relationship  = 파일 허브
  ├── 미등록 → 상단이 입력창 / 등록 → 그 자리가 파일 카드 (화면 전환 없음)
  ├── (1:N) 상대가 여럿이면 파일 허브가 "상대 목록"이 됨 → 상대 선택 → 그 사람 파일
  ├── [시뮬레이션] → 밤 무대 (3화자, 독립 화면)
  └── [별콩이랑 얘기] → 대화 스레드 (현행 + ⚡ 스킬 4종)
```

- **콜드스타트를 별도 화면으로 두지 않는다** — 등록 = "다음 화면 이동"이 아니라 **"상단이 입력창→파일 카드로 채워지는 것"**
- 파일 허브 = 상품 나열 ❌ = **사람 프로필**. 아래는 카탈로그가 아니라 딱 2개(시뮬·얘기) + 무료 후크 자리
- **동선**: 등록 → 시뮬 체험 → 디브리핑 → 허브에 "보낼 말" 적립 → 스레드로 깊이

## 3. 콜드스타트 + 입력 범위 (무발화 직격)

- **게이트(필수)**: 이름 + 관계(썸·연인·짝사랑·이별·기타). 이것만으로 시작
- **옵션(선택, 시작 안 막음)**: 상대 생일(→사주·궁합 열림) · MBTI · 한 줄 성격
- **점진 보강**: 안 받은 정보는 시뮬 중 별콩이가 물어 채운다 = **공동창작으로 초상화가 두꺼워짐**(리텐션 심장). 앞단에서 다 받으면 이 서사가 죽으므로 **필수 게이트 금지**
- ⚠️ 입력 선요구가 무발화 14/15의 직접 원인 + E6 최대 리스크(등록 마찰 재발)
- **신규 필드**: MBTI (코드에 0건). 사주·성격은 기존 `user_profiles`(partner) 활용
- **재조정 여지**: 페르소나 구현하며 입력 범위 다시 볼 수 있음(오너, 2026-08-03)

## 4. 대상 관리 — 1:N · 상태 변화 · 슬롯

현재 `route.ts:77` 는 `// v1 단일 관계`(유저당 1명). → **1:N 으로 전환.**

- **같은 사람, 관계 변화** (썸→연인→이별): `status`만 변경, **같은 파일 유지**(기록 이어짐). 현행 PATCH 그대로
- **다른 사람으로 교체**: 덮어쓰면 이전 상대 기록이 오염됨(현행 결함). → **상대별 파일(1:N)** 로 나란히 보존. 파일 허브가 "상대 목록"(1뎁스 추가)
- **관계 슬롯 (과금)**:
  - **1번째 상대 = 무료 슬롯**(진입 보장 = 무발화 영향 0)
  - **2번째부터 = 슬롯을 별로 구매**(영구 보유, 이별해도 파일 보존)
  - 상점의 별 상품에 "관계 슬롯"이 추가되는 것과 연결
- **데이터**: `relationships` 유저당 N행 허용(현재 단일 제약 해제). 슬롯 수 = 결제로 게이트

## 5. 시뮬 한 판의 흐름

배경 톤을 스레드(크림)와 **확 다른 밤의 무대**로 바꿔 화자 혼동을 물리적으로 차단.

**① 상황 고르기**
- **구체 상황 카드 + 자유 입력**(템플릿이 주, 자유가 보조). 백지 입력이 무발화 원인이라 구체 카드로 첫 마찰 제거
- **"무게 분류(가벼움/중간/무거움)"는 삭제** — 내부 설계 개념이지 유저 대면 라벨이 아니다. 유저는 자기 상황을 찾지 무게를 고르지 않는다
- 상황은 **관계별로** 다름(썸→연락·데이트·고백 / 연인→서운함·화해 / 이별→§6 / 짝사랑→다가가기). 목록 구성은 이월(§11)

**② 3화자 대화 (밤 무대)**
- **상단 프레임 고지**(제품 발화): *"별콩이가 민준이 인형을 데려왔어. 진짜 걔가 아니라 네 마음이 그린 민준이야."*
- 상대 = **인형으로 시각화**(사람 아님 신호), 별콩이 개입 = **채팅 버블이 아니라 노트**(지켜보는 사람 신호)
- **자유 대화가 기본** — 미연시식 A/B/C 선택지 ❌(= "정답 고르기 = 공략" = 스펙이 기각한 승리목표형 게임화)
- **말문 도우미(💭)** = 유저가 **"💭 별콩이 도움" 버튼을 누를 때만** 제공(자동 노출 ❌). 정답 없음·안 써도 됨·고르면 내 말로 다듬음. → 이 버튼이 곧 **코칭**(§8, 별 소모): 말문 트기부터 깊은 통찰까지
- **턴 한도 = 고민톡(타로/사주 chat)과 동일** — 자연 수렴(`[END]`) + abs-cap 재사용(무한 대화 방지 = 원가 경계)
- **[정리하기] = "인형 내려놓고 정리"** = 디브리핑 트리거이자 유저가 언제든 빠져나오는 문(위기 시 서버가 누르는 문도 같음)

**③ 디브리핑**
- 별콩이 복귀 → 통찰(관찰형, 예측 ❌) → **"보낼 말"** 한 문장 → 파일에 적립
- ⚠️ **유료 판이라도 디브리핑까지 반드시 포함**(E1 §4 안전 제약 — 인형 침묵으로 끝나면 최악)

## 6. 코호트 취급 — 이별·짝사랑 (안전 직결)

이별/짝사랑은 **가장 절실**(수요의 큰 축)이면서 **위기 신호 최다** 코호트. **막지 않되 코칭 방향과 안전으로 지킨다.**

- **재회는 적극 돕는다** — "재회하고 싶은 마음"은 핵심 니즈. 막고 훈계하면 판단 안 하는 별콩이가 아니라 **꼰대**가 된다. "재회 조르기 금지" 같은 상황 차단은 **하지 않음**
- 위험 관리는 **상황 차단이 아니라 두 가지로**:
  1. **단정적 헛된 희망 금지** (화법 원칙) — *"이렇게 하면 100% 돌아와"* ❌ / *"걔 마음은 걔 몫, 네가 할 수 있는 걸 해보자"* ⭕
  2. **위기 신호 감지** — `lib/sensitive.ts` 상시. high → 인형 내려놓고 별콩이 복귀 + hotline(기존 재사용)
- **매달림 등 건강하지 않은 방식**도 막지 않되, 별콩이가 **판단 없이 부드럽게 건강한 방향 제안**(강요 ❌)
- **짝사랑**도 같은 결(집착 강화 방지). 세부 프리셋은 이월(§11)

## 7. 파일 축적 — 갈래 지도 재정의

원래 형태 스펙의 "갈래 = 갈라진 가지 기록"은 **진행형 과금 전제**였다. 판 고정가로 오며 갈래(분기)는 과금 포인트가 아니게 됐고, "같은 상황 다른 갈래로 또"는 기각된 리셋 반복이 된다. → **"분기(옆)"가 아니라 "쌓임(위)"으로 재정의.**

- **ⓐ 판 아카이브** = 그 사람과 해본 시뮬 판들의 히스토리(각 판 = 상황 + "보낼 말"). **= reading 데이터의 "그 사람 필터 뷰"**. 시뮬 판을 reading으로 저장하면 보관함엔 "시뮬" 종목으로, 파일 허브엔 "그 사람" 필터로 자동으로 들어감 — **새로 만드는 게 아님**(E1 §5: 정본 데이터 하나·진입 슬롯 여럿·복제 아님). 보관함 세분화(마이 작업)에 "시뮬" 종목이 추가되는 것과 같은 일
- **ⓑ 초상화 지도** = 판들을 가로질러 별콩이가 뽑은 종합(그 사람 성향 + 너의 패턴). **초상화가 두꺼워짐**(시뮬 스펙 리텐션 심장). **이것만 신규 추가분**

## 8. 과금

각 상품 성격에 맞게 분리 — "패스·스레드 존폐"의 답 = 없애지도 통합하지도 않음.

| 대상 | 방식 | 상세 |
|---|---|---|
| **연애 상담(스레드)** | **패스** (기존) | 지속 대화 → 기간제. 무료 인트로 3턴 → 패스 30·60·100별 → 하루 캡 뒤 5별=+5턴. `passes.ts` 재사용 |
| **시뮬레이션** | **판 고정가 X별** | 한 판 = 한 상황, 턴 한도까지, 디브리핑 포함 |
| **별콩이 코칭(💭)** | **별도 별** | §5의 "💭 별콩이 도움" 버튼 = 코칭. 스킬(`RELATIONSHIP_SKILLS` 45/40/40/30)처럼 부를 때 소모 |
| **관계 슬롯** | **별도 별** | 2번째 상대부터 슬롯 개방(§4). 1번째 무료 |

- **무료 첫 판 폐지** → **웰컴 20별**(`WELCOME_BONUS_STARS`)이 흡수. **X < 20** 이어야 신규가 웰컴 별로 첫 판 체험
- 별 잔액은 항상 `lib/stars` 래퍼 경유(트랜잭션) — RPC 직접 호출 금지(AGENTS.md)

## 9. 선행 스펙에서 뒤집은 결정 (근거 기록)

| 뒤집은 것 | 원안 | 이번 결정 | 근거 / 화해 |
|---|---|---|---|
| **과금 단위** | "단발 고정가 폐기", 진행형 | **판 고정가 X별** | 원가 통제(턴 한도)·유저 이해·상점 상품화. "반복 노동"은 같은 상황 리셋을 강제 안 하면 안 생김 |
| **무료 체험** | 무료 인트로 전제(무발화 직격책) | **무료 첫 판 폐지** | 린 검증(유료로 구매 비율 관측 → 무료 체험 도입 결정)·원가. 웰컴 별이 체험 대신 |

⚠️ **무발화 직격책 약화 주의** — 무료 폐지는 첫 행동을 결제(웰컴 별 차감)로 바꾼다. **웰컴 별 흡수가 이 완충을 얼마나 대신하는지 = 배포 후 첫 관측 지표.** 구매 비율 무너지면 "명시적 무료 체험" 부활 최우선 검토.

## 10. 신규 vs 기존 (구현 범위)

- **신규 구현**: 파일 허브 화면 · **1:N 데이터 모델**(relationships 단일 제약 해제) · **관계 슬롯**(개방 결제) · 시뮬 전체(상황 선택·3화자 무대·디브리핑) · **MBTI 필드** · 상대 인형 화자 페르소나 · 코칭(💭) 별 소모 · 판 고정가 결제 · **초상화 종합**(ⓑ)
- **기존 재사용**: 패스·스레드·스킬 4종 · 관계 memory · SSE · continuation · 웰컴 별 · 고민톡 턴 한도/수렴 · `user_profiles`(partner) · `lib/stars` · `lib/sensitive` · **reading 저장/보관함**(시뮬 판 = reading)
