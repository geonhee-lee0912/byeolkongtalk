### 확정
- **이번 사이클: 웰컴 20별 동결.** 7/22 변경(30→20) 직후 재변경은 전환 퍼널 판독 오염 (findings 가 "6개 변경 중첩으로 인과 판정 포기"라 한탄한 실수 반복 금지). 무료 발행 총량은 광고 감액이 자동 축소 — 단 유입이 효율 소재 집중으로 ~70% 유지되므로 ⅓까진 안 줄어든다 (월 무료 원가 ~₩114k → **~₩70~80k** 어림).

## 3. 인프라 — dev Supabase 브랜치 완전 삭제 + 로컬 전환 (+₩38k/월)

결정: **C안 (완전 삭제)**. 세션-온리 운용(A) 대신 최대 절감 선택 — 코드/스키마 검증은 로컬로 동등하게 가능(마이그레이션 replay 로 22001 류 버그 동일 포착), 상실하는 것은 실환경(폰·HTTPS·카카오 공유·Vercel 런타임) 검증이며 이는 prod 배포 후 스모크로 대체.

### 전환 순서 (역순 금지)
1. **이번 사이클 픽스를 dev 브랜치에서 마지막 검증 → prod 배포 완료까지 dev 유지**
2. 로컬 Supabase(Docker) 셋업: `supabase start` + 마이그레이션 replay (`supabase db reset`)
3. `.env.local` 을 로컬 Supabase URL/키로 전환 (QA 하네스 포함)
4. 카카오 dev 앱에 `http://localhost:3000/api/auth/kakao` redirect URI 등록
5. dev Supabase 브랜치 삭제
6. 이후 dev.byeolkongtalk.com 은 DB 없는 상태 — Vercel dev 도메인/env 정리는 선택 (방치 무해, 접속 시 에러만)

### 삭제 후 워크플로우 변화
- 검증: 로컬(`next dev` + 로컬 Supabase) → prod 배포 → **prod 스모크** (`/api/health` + 핵심 라우트 + 실기기 확인). 기존 "dev push → dev 사이트 검증" 단계 소멸.
- 마이그레이션: git dev push 시 sync 대상 없음(무해) → main 머지 시 prod 적용 (기존과 동일). **prod 첫 적용이 되므로 additive 원칙 준수 + main Workflow logs 확인 습관 유지.**
- 유지 인프라: Vercel Pro $20(상업 이용 필수) + Supabase Pro $25 + 도메인. **고정 인프라 ≈ ₩64k/월.**

## 5. 판정 구조 — day 4/7/14/28 스냅샷 + 사전 결정 트리 (재측정: 픽스 prod 배포일 = day 0)

### 압축 원리 (왜 2주 단순 대기가 아닌가)
1. **선행지표**: 실측상 결제는 리딩 #1~#2 에서만 발생(직행 중앙 4.3분) → **D3 매출/가입**이 성숙 LTV 의 유효한 선행지표. 성숙 LTV 는 후행 검증만.

3. **하네스 선검증**: 페르소나 픽스(P1)는 QA 하네스로 day 0 에 기계 검증 — "적용됐는가"는 prod 트래픽을 기다릴 필요 없음.
