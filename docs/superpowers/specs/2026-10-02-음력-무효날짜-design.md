# 음력 무효 날짜 — 설계 (2026-10-02)

> 생년월일 폼이 **음력에 없는 날짜**(30·31일, 없는 윤달)를 고를 수 있게 두고, 서버는 그걸 **저장한 뒤에** `calcSaju` 에서 터진다. 폼과 서버를 둘 다 막고, 혹시 남은 깨진 행이 목록 전체를 죽이지 않게 한다.
> 사용자 확정(2026-10-02): 방향 = 폼 + 서버 둘 다 · 폼의 음력 정보 = 정적 표 + 계약 테스트 · 윤달 UI = 체크박스 유지(있는 달에만) · GET 목록 행 단위 방어 = 포함 · 저장 안 하는 검증기 2개 = 포함 · dev DB 재현 = 검증 전용 테스트 유저로.

## 0. 왜 하는가

엔진이 2026-08-23(`08b26c28`) manseryeok → tyme4ts 로 바뀌면서, 없는 음력 날짜에 **throw** 하게 됐다(manseryeok 은 조용히 틀린 사주를 냈다). 폼과 서버 검증은 그 전제를 따라오지 않았다.

- 폼(`components/saju/SajuInputForm.tsx:79-83`)의 일 목록은 **양력 월 길이** 기준이다. 주석 "음력은 라이브러리가 알아서 처리"는 manseryeok 시절 것이라 지금은 틀렸다. "윤달이야"는 음력이면 **항상** 체크할 수 있다.
- 서버 `validateProfile`(`lib/saju/profile-input.ts:25`)은 형식만 본다(정규식·플래그 타입).
- 고치지 않으면 — 깨진 행 하나가 생긴 유저는 **스스로 고칠 길이 없다**: GET `/api/profiles` 가 목록 전체 500 → 마이페이지에 내 사주가 사라지고 "내 사주 입력" → POST → 409 반복. 생일 벽 팝업(`BirthPromptButton`)도 조회 실패 시 self=null 로 열려 같은 409 루프.

## 1. 성공 기준

1. 폼에서 **엔진이 계산 못 하는 날짜를 고를 수 없다**(음력 그달 실제 일수, 그해 실제 윤달).
2. 서버는 계산 못 하는 생일을 **저장 전에** 400 으로 거른다 — 생일을 쓰는 6경로 전부.
3. 혹시 깨진 행이 있어도 GET 목록은 200 이고, 그 행은 `saju: null` 로 보여 [생일 추가하기] → PATCH 로 복구된다.
4. 양력·정상 음력 입력의 동작은 **불변**이다.

## 2. 현황 실측 (2026-10-02)

**직접 실행**
- `calcSaju` throw: 음력 1996-01-30 `illegal day 30 in 农历丙子年正月` · 01-31 · 1996 윤3월 `illegal leap month 3 in lunar year 1996`. 1996-01-29 정상. **무효 양력(2023-02-29 `illegal solar day`)도 throw** — 폼은 막지만 서버 정규식은 통과시킨다. `calcDaeun` 도 같은 입력에서 같이 throw.
- 1900~2026 윤달 있는 해 **47번**, 해마다 한 달뿐 → "윤달이야"가 유효한 (년,월) = 1,524 중 47.
- `user_profiles.birth_date` 는 **`DATE`** 다(`20260605000000_saju_core.sql:15`). 실존 음력일의 **0.37%(172일, 전부 음력 2/29·2/30)** 는 그레고리력에 없는 Y-M-D 라 저장 불가. 지금 폼(양력 일수)은 이미 이 날을 안 보여준다 → 현상 유지.
- tyme4ts 를 클라에 실으면 `LunarYear`·`LunarMonth` 만 import 해도 **~70KB gzip**(트리셰이킹 안 됨, `sideEffects` 미선언). 지금 tyme4ts 를 클라에 싣는 건 사주 MBTI 하나뿐.
- 데이터: **dev** 프로필 9 / 음력 0. **prod** 프로필 738 / 생일 733 / 음력 25 / 윤달 플래그 0 → 25행 전부 운영과 같은 경로(`profileRowToSajuInput → calcSaju`)로 통과, **깨진 행 0**. `error_logs` 에 관련 메시지 0건(단 profiles POST/PATCH throw 와 사주 MBTI 클릭 throw 는 원래 로그를 안 남기는 경로라 "아무도 안 맞았다"는 증명 못 함).

## 4. `lib/saju/lunar-table.ts`

```ts
/** 그해 윤달 월(1~12). 없으면 0. 표 범위(1900~2100) 밖도 0. */
export function lunarLeapMonth(year: number): number;
/** 음력 그달 일수(29|30). 없는 달(윤달 아닌데 isLeap, 표 범위 밖)은 0. */
export function lunarMonthDays(year: number, month: number, isLeap: boolean): number;
/** 폼이 보여줄 마지막 날. 양력 = 그 월 일수. 음력 = min(음력 그달 일수, 같은 숫자 월의 양력 일수) —
 *  뒤쪽은 birth_date 가 DATE 컬럼이라서(음력 2/30 은 저장 불가). isLeap 은 그해 윤달이 그달일 때만 적용. */
export function maxBirthDay(year: number, month: number, isLunar: boolean, isLeap: boolean): number;
```

- 표 형식: 연도당 `[윤달 월(0=없음), 대소월 문자열]`. 문자열은 그해 달 순서대로(윤달은 그 월 바로 뒤) `'1'`=30일 · `'0'`=29일 — 12자 또는 13자. 인덱스 = 연도 − 1900, 줄마다 연도 주석.
- 표는 tyme4ts 를 직접 부르지 않고 **`canCalcSaju` 로 찔러서** 얻는다(AGENTS.md: tyme4ts 직접 호출 금지). 탐침은 계약 테스트 안에만 있다 — 별도 생성 스크립트는 두지 않는다.
- 생성·재생성: 계약 테스트가 어긋나면 **1900~2100 전체 표 리터럴을 실패 메시지에 찍는다**. 처음 만들 때도, tyme4ts 업그레이드로 어긋날 때도 그 블록을 그대로 붙여넣으면 된다.
- 범위 1900~2100: 폼 연도 범위(1900~올해)를 74년 덮고, 저장 안 하는 검증기 2개의 상한(2100)과 같다. 범위 밖 음력은 `lunarMonthDays` = 0 → `maxBirthDay` = 0(폼은 그 해를 보여주지 않는다).

## 5. 폼

- 일 목록 = `1..maxBirthDay(year, month, calendar === "lunar", isLeapMonth)`. 기존 "일이 월말보다 크면 자동 보정"(렌더 중 `setDay`)을 그대로 쓴다 → 저장된 무효 날짜를 미리 채워도 마지막 날로 내려간다.
- 윤달: `const leapAvailable = calendar === "lunar" && lunarLeapMonth(year) === month`. 체크박스는 **생년월일 줄 바로 아래**, `leapAvailable` 일 때만 렌더. 문구 "윤달이야" 그대로. `isLeapMonth && !leapAvailable` 이면 렌더 중 `setIsLeapMonth(false)`(자동 해제 — 다시 그달로 와도 체크된 채 나타나지 않게).
- 제출값은 지금처럼 `isLeapMonth: calendar === "lunar" ? isLeapMonth : false`.
- `SajuInputForm:80` 의 틀린 주석은 새 규칙 설명으로 바꾼다. 같은 파일의 다른 manseryeok 언급(7행 시진 주석)은 손대지 않는다.

## 6. 서버

### 6-1. `canCalcSaju` (`lib/saju/calc.ts`)

```ts
/** calcSaju 가 이 입력을 계산할 수 있는가. 없는 음력 날짜(30·31일·없는 윤달)·없는 양력 날짜면 false. 저장 전 검증용. */
export function canCalcSaju(input: SajuInput): boolean; // try { calcSaju(input); return true } catch { return false }
```

### 6-2. `validateProfile` — 반환 직전, `birthDate !== null` 일 때 순서대로

| # | 검사 | 실패 코드 |
|---|---|---|
| ① | `isValidBirthDate(birthDate)` (`lib/byeoljari/validate.ts` 재사용) — DATE 컬럼에 들어가는 Y-M-D 인가 | `invalid_birth_date` |
| ② | `birthTime !== null` 이면 `isValidBirthTime(birthTime)` (같은 파일) | `invalid_birth_time` |
| ③ | `canCalcSaju(profileRowToSajuInput({ birth_date, birth_time, is_lunar_input, is_leap_month, gender }))` | 음력 `invalid_lunar_date`(신규) / 양력 `invalid_birth_date` |

- ②가 있는 이유: `"24:00"`·`"99:99"` 는 정규식 `^\d{2}:\d{2}$` 를 통과하고 `calcSaju` 에서 터진다 — ②가 없으면 ③이 시각 오류를 날짜 오류로 잘못 이름 붙인다.
- ③을 `profileRowToSajuInput` 으로 만드는 이유: 읽는 쪽과 **같은 변환**이라 "검증 통과 ⇒ 읽을 때 안 터짐"이 성립한다.
- strict·optionalBirth 두 모드 공통. 생일 null 은 건너뛴다.

### 6-3. 저장 안 하는 검증기 2개

`/api/consultations/saju/calc` `validateInput` · `/api/fortune/create` `validateSajuInput` 끝에 `canCalcSaju` — 실패 시 음력 `invalid_lunar_date` / 양력 `invalid_day`(두 검증기의 기존 어휘 `invalid_year/month/day` 에 맞춤). 결과: 500 → 400, consultations 의 `error_logs` 오염 중단.

### 6-4. GET 목록 방어

`lib/saju/profile-input.ts`:

```ts
/** 저장된 행 → 사주. 생일 없으면 { saju: null, error: null }, 계산 실패면 { saju: null, error }. */
export function profileRowToSaju(row: {
  birth_date: string | null;
  birth_time: string | null;
  is_lunar_input: boolean;
  is_leap_month: boolean;
  gender: string;
}): { saju: SajuResult | null; error: unknown };
```

GET `/api/profiles` 는 행마다 이걸 쓰고, `error` 가 있으면 `logError(error, { route: "/api/profiles", userId, extra: { stage: "profile_saju", profileId } })` 후 `saju: null` 로 내려준다. 마이페이지는 `self && !self.saju` 를 이미 "생일을 알려주면 사주도 보여줄게" + [생일 추가하기](PATCH)로 그리므로 화면 수정은 없다.

- 라우트 안에 직접 쓰지 않고 lib 로 빼는 이유: 리포에 라우트 테스트·모듈 모킹 관례가 없다(`app/**/*.test.ts` 0개) — 테스트 가능한 자리에 둔다.
- POST/PATCH 응답의 `serializeProfile` 은 그대로 — 직전에 ③을 통과한 행이다.

### 6-5. 그대로 두는 것

- 모달 문구(전부 "저장을 못 했어…" 범용). 폼이 막으므로 400 은 캐시된 옛 번들·직접 호출만 맞는다.
- 별마루 5라우트·연애 채팅·`/api/fortune/create` 프로필 경로의 읽기 — 이미 logError 500 이거나 별 차감 전이고, 가드 + 깨진 행 0 이라 도달 불가.

## 8. 범위 밖 · 알려진 한계

1. 음력 2/29(평년)·2/30 은 입력 불가 — `DATE` 컬럼(현상 유지, 실존 음력일의 0.37%). 저장 형식을 바꾸는 건 읽는 쪽 전부가 걸린 별건.
2. **추정·미검증**: tyme4ts 는 중국 농력 기준이라 한국천문연구원 음력과 다른 해가 있을 수 있다(예: 2017 윤달 — tyme4ts 6월, 한국은 윤5월로 알려짐). 맞다면 그해 음력 입력의 변환 자체가 어긋난다. 별건.
3. `lib/byeoljari/validate.ts` 머리 주석("calcSaju 는 out-of-range 에 throw 하지 않고…")은 manseryeok 시절 기준이라 틀렸다 — 언급만, 손대지 않는다.
4. 모달별 400 전용 문구, 사주 MBTI `onBirthDone` 의 try/catch — 폼이 막으므로 하지 않는다(YAGNI).
