## 1. 왜

가입자당 매출을 광고비(가입 1명 ₩391)보다 크게 만드는 게 목표다. 지금은 ₩139(48시간, 최고였을 때도 ₩239).

prod 실측(지인 6명 제외):
- **결제의 75%는 첫 상품을 고르는 순간 일어난다.** 08-24~10-02 가입 첫 타로 984명 중 웰컴 별을 넘는 상품을 고른 58명은 전원 그 자리에서 결제했고, 웰컴 별로 공짜 리딩을 한 926명은 그 뒤 2%만 결제했다.
- **웰컴 별로 살 수 있는 최대치가 표준이 된다.** 웰컴 15 → 투카드(15별) 70%.
- **결제는 거의 전부 "모자란 만큼을 덮는 최소 패키지"다.** ₩1,000 결제의 86%가 부족분 10별 이하. 결제자당 매출이 ~₩3,000 에 묶인 이유.
- **깊은 상품을 고르는 사람은 가격에 둔감했다.** 더 내야 할 돈이 ₩1,000→₩2,800(2.8배)이 돼도 프리미엄 첫 선택 5.7%→4.9%(통계적 차이 없음). 웰컴 30→20 의 가입당 매출 +72% 도 결제 1건이 커져서였다.
- 경쟁사(헬로우봇 등)는 "카드 몇 장"이 아니라 **"이름 붙은 질문 하나"**를 판다. 최소 결제 ₩3,300~4,400.

방향: 타로톡을 **질문 메뉴판**(질문마다 맛보기 → 3장 → 깊게)으로 바꾸고, 별 가격·패키지를 그 사다리에 맞춘다. 사주는 미끼 가격, 별마루는 가격 유지.

## 4. 타로톡 흐름

```
홈 (질문 10개)  →  고민 쓰기 (지금 그대로)  →  질문 메뉴판 (3~4개)  →  카드 뽑기  →  대화
                                                  └ 유료 상품은 비교 창에서 결정
```

- 메뉴판은 `/tarot`(지금의 스프레드 고르기 화면) 자리를 대체한다. URL·세션 저장 키(`TAROT_SPREAD_KEY`, `byeolkong:pending_consultation`, `byeolkong:continuation`)는 유지.
- **대화까지의 단계 줄이기**:
  - 맛보기 카드를 누르면 바로 카드 뽑기로 간다(시작 버튼 없음). 카드에 가격(또는 "선물로 무료")이 이미 적혀 있으므로 그 탭을 **가격 동의**로 본다.
  - 유료 상품은 비교 창의 "이걸로 볼래"가 가격 동의를 겸한다.
  - 동의한 선택은 세션 저장값에 `consented: true` 로 실어 보낸다. 카드 뽑기 화면은 `consented` 이고 잔액이 충분하면 **확인 팝업 없이 바로 대화로** 간다.
  - **잔액이 모자라면 지금처럼 카드를 뽑은 뒤** `StarConfirmModal`(잔액 부족) → 충전 시트. 이 자리는 그대로 둔다 — 지금 결제가 일어나는 자리이고 `paywall_shown`(Meta AddToCart)의 원천이다.
  - 서버는 늘 권위다: 대화 시작 시 잔액이 모자라면(다른 탭에서 썼다 등) 지금처럼 402 → 잔액 부족 모달.

## 5. 질문 메뉴판

### 5-1. 구성 규칙
- 질문마다 **맛보기(1장) · 3장 · 깊게(질문 전용 5~6장)**, 속마음·재회만 **끝까지(7장)** 추가 → 상품 32개. 전부 기존 스프레드 재포장(부록 A).
- 깊게 상품에 "별콩이 추천" 리본. 위에서부터 맛보기 → 3장 → 깊게 → 끝까지 순.
- 상품 카드 = 이름 · 카드 자리 칩(`getPositionLabels(spread, category, tag)`) · 가격 줄(5-3).
- 카탈로그는 새 모듈 하나(`lib/tarot/menu.ts`)에 데이터로 둔다: `{ key, tag, tier: 'teaser'|'mid'|'deep'|'full', spreadType, name, oneLiner }`. 가격은 `SPREAD_INFO` 에서, 카드 자리는 `getPositionLabels` 에서 가져온다(중복 정의 금지).
- 상품 식별은 리딩의 `(emotion_tag, spread_type)` 조합으로 복원된다 → **DB 마이그레이션 없음**.
- 예전 `TAG_SPREADS` 에만 있던 스프레드(readiness_6, chakra_7, 일부 태그의 potential_7 등)는 메뉴에서 빠진다. 엔진·예전 리딩은 그대로.

### 5-2. 비교 창 (유료 상품을 누르면)
- 맛보기와 이 상품을 나란히: **보는 질문 수와 카드 자리 이름**, 첫 풀이 분량(대략), 대화 길이(자연 마무리 턴).
  - 분량·턴 근거(prod 9월~ 중앙값): 1장 ~810자·8턴 / 3장 ~2,040자·10턴 / 5장 ~3,500자·13턴 / 7장 ~4,700자·17턴. 화면엔 "~800자" 처럼 반올림해 보여주고, 턴은 `WRAP_THRESHOLDS[spread].hardCapTurn` 을 쓴다.
- 가격 줄(5-3) + [이걸로 볼래 →] + "맛보기부터 해볼래".
- 3장(mid)과 깊게(deep)의 차이가 "질문 3개 vs 5개"로 분명히 보이게 — 깊게 갈 사람이 3장으로 내려오는 걸 막는 장치(가격 차가 ₩1,000 vs ₩4,900 로 크다).

### 5-3. 가격 표시 규칙
- **`giftUnused`** = 그 유저가 별을 한 번도 쓴 적 없음(`star_transactions` 에 `type='spend'` 행 0). `/api/stars/balance` 응답에 필드로 추가한다.
- 맛보기: `giftUnused && balance ≥ 15` → **"선물로 무료"** / 그 외 → "⭐15".
- 유료 상품: `giftUnused` → "⭐P · 선물 쓰면 ⭐(P−15)만 더" / 그 외 `balance < P` → "⭐P · ⭐(P−balance)만 더" / `balance ≥ P` → "⭐P · 지금 잔액으로 바로".
- 메뉴판 맨 위 배너: `giftUnused` 일 때만 "🎁 가입 선물 별 15개 — 첫 질문은 공짜야".
- 홈 큰 카드(속마음·재회) 한 줄: 비로그인 또는 `giftUnused` → "🃏 첫 질문은 공짜 · 깊게 보기까지 4가지" / 그 외 → "🃏 맛보기부터 깊게 보기까지 4가지".

## 6. 맛보기 끝 — "이어서 깊게"

- **언제**: 맛보기(one_card) 리딩이 [END] 로 끝난 뒤. 두 자리 — ① 대화 화면 마지막 답 아래, [결과 보기 →] 위(작은 카드) ② 결과 화면(지금 `RechargeBlock` 자리의 맨 위).
- **무엇**: 같은 질문의 깊게 상품 카드 자리를 펼쳐 보여준다. 첫 자리는 "지금 마음 ✓"(방금 본 한 장), 나머지는 이름 + 🔒. 아래에 **"이 고민 이어서 다섯(여섯) 장으로 · ⭐55"** 버튼.
- **가격 = 정가**(이어가기 할인 없음, 사용자 확정). 맛보기 → 이어서 깊게 = 처음부터 깊게와 같은 돈이어야 "맛보기부터 하고 이어가는 게 싸다" 우회로가 안 생긴다.
- **경로**: 기존 tarot-fresh 이어가기를 그대로 쓴다 — `byeolkong:continuation = { previousReadingId, mode: 'fresh' }` + `byeolkong:pending_consultation = { emotion, concern }` + 스프레드 선택(깊게 스프레드, `consented: true`)을 심고 **카드 뽑기로 바로**. 서버(`/api/consultations/tarot`)가 부모 소유권·비민감·[END] 를 검증하고, chat 라우트가 부모 요약을 주입한다(지금 동작).
- 민감(`has_sensitive`) 리딩에는 보여주지 않는다(지금 이어가기와 같은 규칙).
- 결과 화면의 기존 "이 고민 다시 뽑기"는 맛보기 리딩에선 두 번째 줄로 내려가고, 하드코딩된 `newCostLabel="⭐10~"` 는 "⭐15~" 로 고친다(맛보기 리딩이 아닌 결과 화면도 같은 문구).
- 대화 **도중**에는 지금 있는 "한 장 더"만 둔다(깊게 제안을 대화 안에 넣지 않는다 — 사용자 확정).

## 9. 판정과 되돌리기 — 반반 무작위 비교 (2026-10-09 사용자 결정)

배포 전후 비교 대신 **가입자를 반반 무작위로 나눠** 옛 타로톡(지금 prod)과 새 메뉴판을 같은 기간에 비교한다. 광고가 어떤 사람을 데려오든 두 그룹에 똑같이 섞이므로 차이가 곧 메뉴판 효과다. 우리 쪽 변화 없이도 가입당 매출이 흔들리는 일(09-20 ×0.58, 08-02 주 1주 반토막)이 메뉴판이 노리는 크기(×2.8)와 같은 급이라 전후 비교로는 못 가린다. 판정 중에 광고 소재·구조를 바꿔도 판정이 깨지지 않는다(→ '광고 구조 동결' 조항은 없앤다).

- **그룹**: user_id 마지막 글자가 짝수(`0 2 4 6 8 a c e`)면 메뉴판, 홀수면 옛 타로톡. 저장하지 않고 계산한다(SQL: `position(right(id::text,1) in '02468ace') > 0`). 기존 유저도 같은 식으로 나뉜다. 실측 균형: 전체 1,403 : 1,386 · 09-01 이후 가입 544 : 555. 나누는 범위는 §9-1.
- **판정 창**: 배포 시각부터 14일 동안 가입한 사람, 창 끝 + 48시간 뒤 실행. 지인 6명 제외. 모집단 = 그 기간 가입 전원(광고·오가닉·소재 무관 — 무작위라 섞여도 공정). 메타 가입만 따로 보는 건 보조.
- **주 지표**: 가입당 48시간 매출, 메뉴판 그룹 − 옛 그룹, 부트스트랩 95% 구간.
- **결정 규칙** (2026-10-09 사용자 확정):
  - 구간이 0 위 → 전원 메뉴판 / 0 아래 → 전원 옛 타로톡(메뉴판 철회)
  - 0 을 걸침 → 1주 연장(최대 3주). 3주에도 걸치면 평균이 높은 쪽
- **깊은 상품 가격 되돌리기**: 메뉴판 그룹의 2주 **깊은 상품(5~7장) 첫 결제 매출 합 < ₩5,600** 이면 깊은 상품 별 가격만 40·45 / 55 로 되돌린다(원래 ₩11,200 — 노출이 절반이라 절반으로 조정, 2026-10-09 사용자 확정). 주 판정과 따로 본다.
- **보조 지표**: 48시간 결제율 · 결제 1건당 금액 · 최대 결제자 몫(8월 판정이 고래 1명에 뒤집힌 전례) · 첫 리딩 전 결제(메뉴판은 맛보기가 선물로 무료라 뜻이 달라 진단용만).
- **진단 지표**(그룹별): 첫 선택 분포(맛보기/3장/깊게/끝까지) · 맛보기 → 유료 전환(48시간) · 이어서 깊게 노출 → 클릭 → 결제 · 충전 결제 1건당 금액 · 10칸 비중 · 사주 단품 판매 수 · 사주 → 타로 교차 · 별마루 구독.
- **정밀도**: 가입당 48시간 매출 평균 ₩131 · 표준편차 ₩750(09-20 이후 메타 가입 476명) → 2주(그룹당 ~190명)면 약 2.6배 차이부터, 3주면 약 2.3배 가려낸다. ×1.5 같은 작은 효과는 못 잡는다.
- **엿보기 금지**: 2주 전엔 숫자가 앞서든 뒤지든 멈추지 않는다. 일찍 멈추는 건 **고장**일 때만 — 그룹 가격과 실제 차감이 다름 · 한쪽만 에러가 몰림 · 한쪽만 결제 0 이 이어짐. 감시 = `scripts/menu-ab-daily-check.sql`(매일 1번, 배포 시각 입력).
- **끄는 스위치**: `MENU_AB = 'split' | 'menu' | 'legacy'` — 'menu'·'legacy' 면 전원 한쪽. 상수라 바꾸면 재배포(prod 는 사용자 go).
- **교란**: 10-09 한글날 연휴·②(10-05 배포)·광고 변화는 두 그룹 공통이라 차이에 안 섞인다. 어드민 화면 숫자는 판정 동안 두 그룹이 섞여 나온다 — 판독은 SQL 로.
