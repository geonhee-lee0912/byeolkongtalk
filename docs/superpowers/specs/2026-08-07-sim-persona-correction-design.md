# 연애 시뮬 인형 페르소나 교정 설계

**작성일:** 2026-08-07
**상태:** 설계 확정(브레인스토밍) → 구현 플랜 대기

## 목표

연애 시뮬레이션 대화 중 유저가 "내 상대는 이런 페르소나가 아닌데?"라고 느낄 때,
**인형 대사 단위 피드백(👍/👎)**으로 교정하고 그 내용을 **상대 성격 프로필에 영구 반영**한다.
결과적으로 시뮬이 상대를 점점 더 정확히 아는 도구가 된다.

## 배경 (현행 구조)

- 시뮬 인형 = "네 마음속 상대". `buildDollSystemMessage`가 매 `say` 턴마다 조립:
  코어(`doll_partner.md`) + 상황 seed + **상대 프로필 라인**(`formatPartnerForDoll` = 관계·MBTI·성격) + 라이트 컨텍스트.
- 상대 성격의 원천 = `user_profiles.personality`(`relationships.partner_profile_id`로 연결).
  이 값은 **연애 상담 스레드·궁합·시뮬이 공유하는 단일 원천**이다.
- 즉 인형은 유저가 등록한 성격으로 빚어진다 → 성격이 부실/부정확하면 인형도 어긋난다.
  교정이 곧 프로필 보강이 되는 구조.

## 핵심 UX 흐름

1. 인형 대사(`SimBubble`) 각각 하단에 작은 **👍 / 👎** 버튼.
2. **👎(달라)**: 인라인 입력 *"실제 상대는 어떤 사람이야? (예: 사실 낯을 많이 가려)"* → 보내기. **입력 필수.**
3. **👍(맞아)**: 인라인 입력 *"어떤 점이 걔다웠어? (건너뛰기 OK)"* → 보내기. **입력 선택**(스킵 시 '이 반응 맘에 듦'만 기록).
4. 전송 → 상대 성격에 **즉시 반영** → *"반영했어 🌙 다음부터 그렇게 반응할게"* 짧은 확인.
5. 인형은 **다음 `say` 턴부터** 갱신된 성격으로 반응(직전 대사 재생성 안 함 — 오너 결정 2026-08-07).

## 반영 / 전파

- **저장:** `user_profiles.personality`에 즉시 append. 형식 = 기존 성격 + `\n· {note}`.
  입력 프롬프트를 '성격 서술'로 유도해(👎/👍 문구) 프로필 화면에도 자연스럽게 읽히도록 한다.
- **인형 반영:** 코드 변경 최소 — `loadSim`이 `personality`를 조회하고 `buildDollSystemMessage`가 이미 주입 중.
  피드백으로 `personality`가 갱신되면 **다음 턴 시스템 메시지가 자동으로 새 값을 읽는다.**
- **전파:** `personality`가 연애 상담 스레드·궁합·다음 시뮬의 공통 원천이므로 **별도 배선 없이 전파**된다.

## 유저 안내 (기능 발견)

- **별콩이 프레임 노트(진입 시) 한 줄:** "인형이 실제 걔랑 다르게 굴면 대사 밑 👍👎로 알려줘 — 내가 더 걔답게 만들어줄게."
- **무대 미니 안내(목록형·은은):** `👍 맞아요 · 👎 달라요` — 초반에 짚어주되 과하지 않게.
- 대사의 👍/👎 버튼 자체가 발견을 유도.

## 데이터 / API

- **`POST /api/relationship/sim/feedback`** (신규 라우트, non-stream JSON)
  - body: `{ simReadingId: string, kind: "up" | "down", note?: string }`
  - 검증: 세션 소유권(`reading.user_id === userId`, `consultation_type === 'relationship_sim'`),
    `relationships.partner_profile_id` 존재.
  - `kind: "down"` → `note` 필수. `kind: "up"` → `note` 선택.
  - `user_profiles.personality` append 후 update.
  - 응답: `{ success: true, personality: string }`(클라 갱신용) 또는 실패 시 4xx/5xx.
  - rate-limit: 기존 sim 라우트와 동일 정책 준용.
- **소유권/프로필 로드**는 `sim/chat`의 `loadSim`과 겹치므로 공용 헬퍼로 추출하거나 최소 복제.

## 엣지 케이스

- **상대 프로필 미등록**(`partner_profile_id` 없음): 교정 버튼 **숨김** + 짧은 안내("상대 프로필을 등록하면 교정할 수 있어"). 실사용에선 대부분 등록되어 있음.
- **재피드백:** 같은 대사에 여러 번 허용(누적). 1회 제한하지 않음.
- **민감/위기 턴:** 위기 시엔 인형을 내려놓고 별콩이가 복귀하므로(인형 대사 아님) 그 메시지엔 👍/👎 없음. 인형 대사(`skill_key IS NULL`)에만 버튼.
- **personality 노출:** 마이페이지·프로필 상세에 그대로 보이므로 성격 서술 유도로 자연스럽게 유지.

## MVP 제외 (YAGNI)

- 교정 되돌리기(undo), 피드백 히스토리 화면.
- `personality` 길이 자동 요약(haiku) — 서술이 짧아 당장 불필요. 누적이 커지면 후속.
- 👍 강화의 정교한 가중치 처리 — 단순 append로 충분.
- 대사별 피드백 서버 기록(`message_id` 연동) — 클라 로컬 상태로 "피드백함" 표시. 서버 기록은 후속.

## 성공 기준

- 👎 교정 후 인형이 **다음 턴에 반영된 성격**으로 반응한다(QA 하네스로 검증).
- `user_profiles.personality`가 실제 갱신되어 **마이페이지·다음 시뮬에서 확인**된다.
- 프로필 미등록 상대는 교정 버튼이 숨겨진다.
- 유저가 진입 멘트/미니 안내로 기능을 인지한다.
