## 1. 배경 · 목적

무료 서비스 3종(오늘의 운세·별 인연 별자리·사주 MBTI) 중 **별자리 어드민**은 이미 dev 완료(퍼널 대시보드 `/admin/free/byeoljari`, RPC 5종·ACL 검증됨). **MBTI 어드민은 아직 없다.**

핵심 제약: **MBTI 는 서버 기록이 0**이다 — 생일은 브라우저 `calcSaju` 로컬 계산, 상태는 `sessionStorage`, 공유 링크는 비-PII 결과코드(`?r=`). 그래서 오늘 측정 가능한 신호는 `/fortune/saju-mbti` 로의 `page_views`(방문·UV)뿐이고, 전 플로우(intro→quiz→birth→result)가 한 URL이라 "시작 vs 완료 vs 공유"조차 못 가린다.

전략 입력값(`woori-sai-tab-usage-2026-08-24`): 무료 상품은 결제 깔때기가 **아니다**(무료→결제는 역인과). 무료의 정당한 목표는 **바이럴 획득 + 리텐션**. MBTI 는 공유형=바이럴 도구다. 따라서 MBTI 어드민은 byeoljari 의 결제 퍼널을 그대로 베끼는 게 아니라 **바이럴 확산 + 참여 품질**을 잰다.

동시에 사용자 요청: 두 어드민(별자리·MBTI) 모두 **가입에서 끝내지 말고 "가입 → 상품 구매"까지** 볼 것. 이건 단위경제(LTV ≥ CAC)를 재는 축이라 중요하다. "상품" = **운세/타로 상품(별 소모)** + **별 상품(충전=매출)** 둘 다.

**이 스펙의 목표:**
1. MBTI 에 비-PII 계측을 심어 참여·바이럴을 측정 가능하게 만든다.
2. `/admin/free/saju-mbti` 종합 대시보드를 만든다(byeoljari 대칭).
3. 두 어드민 공통으로 "가입 코호트 → 구매 여정(별 충전 + 운세/타로 상품 소비)"을 붙인다.

## 3. 프라이버시 결정 (확정)

MBTI 계측을 심으면 "서버 전송 0" 포스처가 **"비-PII 분석만 전송"**으로 바뀐다. 정확히:

| 데이터 | 서버 전송 |
|---|---|
| 생일 원본 | ❌ 안 감 — 브라우저 `calcSaju` 로컬 계산 (불변) |
| 퍼널 이벤트(started/birth/completed/shared/shared_view/retry) | ✅ 신규 |
| 결과 유형코드(팔자·자아·밴드·오행) | ✅ 신규 — `meta`, **비-PII**(유형 카테고리, 생일로 역산 불가) |
| `anon_id`/`user_id` | ✅ 이미 page_views 가 전송 중 |

**판정:** 이건 `page_views`(경로+anon_id, 무-PII)와 **동일한 급의 익명 분석**이다. 생일=PII 는 여전히 안 가므로 새 동의 의무가 생기지 않는다. 개인정보처리방침의 분석/쿠키 조항이 page_views 를 이미 커버하므로 MBTI 이벤트도 같은 우산 아래 든다.

- ⚠️ 구현 전 확인: 유저 노출 문구(처리방침·고지)에 "MBTI 서버 전송 0"을 **명시**한 텍스트가 있는지 grep(`saju-mbti`, `MBTI`) — 발견 시 "비-PII 분석 전송"으로 정합. (2026-08-29 비회원 고지 작업은 별자리 대상이었고, MBTI 컴포넌트엔 그런 유저 노출 주장 없음 — 재확인만.)

## 4. 계측 설계

### 4.1 이벤트 6종 (`lib/analytics/ui-events.ts` `UI_EVENTS` allowlist 추가)

`trackUiEvent(event, { meta })` 재사용. `/api/event` → `ui_events`(anon_id/user_id 는 서버 세션에서 추출·위조 불가). **마이그레이션 불필요**(event 는 자유 문자열, allowlist 가 게이트).

| 이벤트 | 발화 지점(파일:함수) | meta |
|---|---|---|
| `saju_mbti_started` | `SajuMbtiFlow` intro "시작하기" onClick (`setStage("quiz")`) | — |
| `saju_mbti_birth` | `SajuMbtiFlow.onQuizDone` (quiz→birth 진입) | — |
| `saju_mbti_completed` | `SajuMbtiFlow.onBirthDone` (compute 직후, 1회) | `{ palja, self, band, element }` |
| `saju_mbti_shared` | `SajuMbtiFlow.onShare` (공유 탭 = 발신 의도) | `{ palja, via: "native"\|"copy" }` |
| `saju_mbti_shared_view` | `SharedTeaser` 마운트 useEffect (유효 토큰일 때만, `content` 존재) | `{ fromPalja }` |
| `saju_mbti_retry` | `SharedTeaser` 의 "나도 해보기"(onStart 래퍼) — 결과화면 재시작과 분리 | `{ fromPalja }` |

- 퍼널(참여): `방문(page_views) → started → birth → completed`
- 퍼널(바이럴): `completed → shared → [친구]shared_view → retry → (친구)completed`
- `meta.palja`/`self` = 유형 코드(`palja.code`/`self.code`, 한글 4자, <1KB), `band` = 0~2, `element` = 오행 문자.
- ⚠️ `shared` 는 탭 시점에 발화(native share 완료 여부는 알 수 없음 — byeoljari `invite_clicks`=발신과 동일 관행).
- ⚠️ `retry` 는 `SharedTeaser` 안에서 `onStart` 를 감싸 발화(결과화면 `onRestart` 는 retry 미발화 → 이중발화 없음).

### 4.2 공유 링크 utm 어트리뷰션

`SajuMbtiFlow.onShare` 의 링크(`/fortune/saju-mbti?r=${token}`)에 **`&utm_source=saju_mbti`** 추가. 친구가 클릭 후 가입하면 기존 `AuthBootstrap → user_acquisition` 파이프로 귀속(byeoljari `utm_source=byeoljari` 와 동일). `normalizePath` 가 `?query` 를 스트립하니(`pageview.ts:18`) page_views 는 `/fortune/saju-mbti` 로 접혀 /admin/traffic 오염 없음.

- (선택) `utm_content = palja code` 도 붙이면 "어떤 유형이 가입을 데려오나"까지 가능. v1 포함하되 대시보드 노출은 후순위.

## 5. 데이터 모델 (확인됨)

- **`ui_events`**(`20260731070000`): `anon_id`, `user_id`, `event`, `reading_id`(nullable), `meta` JSONB. MBTI 이벤트의 `reading_id` 는 null(readings 행 없음).
- **`page_views`**: 방문 경로. MBTI 방문 = `path = '/fortune/saju-mbti'`.
- **`user_acquisition`**(`20260705000000`): `user_id` PK, `utm_source`. MBTI 신규 가입 = `utm_source = 'saju_mbti'`.
- **`payments`**(`20260608000000` + `20260802000000`): `user_id`(nullable, ON DELETE SET NULL), `amount_won`, `stars_given`, `package_type`, `status`('completed' 만 매출). = **별 상품(충전) = 매출**.
- **`star_transactions`**(`20260604000000`): `type`('spend' 등), `amount`, `source`(VARCHAR50), `reading_id`. spend = **운세/타로 상품 소비**. 분류기 `admin_star_spend_breakdown`(`20260731050000`) 이 이미 fortune/tarot/saju/relationship/upsell + 상품명으로 분해(free-first FIFO 무료별 귀속 포함).

## 6. RPC 설계

**공통 규칙(AGENTS.md):** 전부 `SECURITY DEFINER SET search_path = public`, `service_role` 전용(`REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated` + `GRANT ... TO service_role`). 날짜 버킷 = `(created_at AT TIME ZONE 'UTC' + interval '9 hours')::date`(KST). **이벤트 필터는 `event IN (...)` 명시 리스트**(`LIKE 'saju_mbti_%'` 금지 — `_` 가 와일드카드). page_views 어드민 제외는 **NULL(비로그인) 보존** `(user_id IS NULL OR user_id <> ALL(p_exclude))`.

### 6.1 MBTI 기본 집계 (신규 3종)

**`admin_saju_mbti_summary(p_exclude UUID[])`** → 스칼라 1행:
- `visits`(page_views path='/fortune/saju-mbti', 어드민 제외는 비로그인 NULL 보존 `(user_id IS NULL OR user_id <> ALL(p_exclude))`), `started`·`birth`·`completed`·`shared`·`shared_view`·`retry`(ui_events, `count(*) FILTER (WHERE event=...)`), `utm_signups`(user_acquisition utm_source='saju_mbti', `<> ALL(p_exclude)`).
- 앱에서 파생: 완료율(completed/started)·문항→생일 이탈·공유율(shared/completed)·도착전환(retry/shared_view).

**`admin_saju_mbti_type_dist(p_exclude UUID[])`** → long 포맷 rows `(kind, key, cnt)`:
- `kind` ∈ {`palja`,`band`,`element`}, `key` = `meta->>'palja'` 등, completed 이벤트 대상. 앱에서 16유형·밴드3·오행5 로 렌더.

**`admin_saju_mbti_trend(p_since TIMESTAMPTZ, p_exclude UUID[])`** → long 포맷 `(bucket, kind, cnt)`:
- `kind` ∈ {`visits`,`started`,`completed`,`shared`,`retry`}, KST 일별. page_views + ui_events UNION.

### 6.2 공용 구매 여정 인프라

**`admin_star_spend_breakdown` 일반화(핵심):**
- 기존 4-arg `(p_since, p_until, p_exclude, p_fortune_types)` 를 **DROP** 후 5-arg `(..., p_users UUID[] DEFAULT NULL)` 로 재생성. `win` CTE 에 `AND (p_users IS NULL OR t.user_id = ANY(p_users))` 추가. 분류 사다리는 **한 줄도 안 바꾼다**(검증된 SSOT — 복제 금지 = 드리프트 방지).
- 기존 호출부(`/admin/analytics` products 화면)는 named args 4개 → PostgREST 가 `p_users=NULL` 기본값으로 해소(변경 불필요, 단 확인).
- 코호트 뷰는 `p_users = 코호트`, `p_since` = 서비스 시작(넉넉히) 또는 30일, `p_until = NULL`.

**`admin_cohort_payments(p_users UUID[])`** → rows `(package_type, payers, revenue_won, stars_given)`:
```
SELECT coalesce(package_type,'(없음)'), count(DISTINCT user_id),
       sum(amount_won)::BIGINT, sum(stars_given)::BIGINT
FROM payments
WHERE status='completed' AND user_id = ANY(p_users)
GROUP BY 1 ORDER BY 3 DESC;
```
앱에서 합산 → 코호트 결제자·매출·ARPU. (코호트 스코프라 NULL 익명분은 의도적으로 제외 — §8 캐비엇.)

### 6.3 코호트 resolver (신규 2종)

**`admin_byeoljari_cohort_users(p_exclude UUID[])`** → `SETOF UUID`:
- 기존 `admin_byeoljari_summary` 의 코호트 정의(utm `byeoljari` ∪ 참여자 `member_anon_id`↔page_views 브리지)와 **동일한 user_id 집합**을 목록으로 반환. 검증: `count(*) == summary.cohort_size`(dev 대조).

**`admin_saju_mbti_cohort_users(p_exclude UUID[])`** → `SETOF UUID` = 다음 UNION(− p_exclude):
1. utm 가입: `user_acquisition WHERE utm_source='saju_mbti'`
2. 로그인 완료자: `ui_events WHERE event='saju_mbti_completed' AND user_id IS NOT NULL`
3. anon 브리지: `ui_events(event='saju_mbti_completed', anon_id NOT NULL)` → `page_views` 조인해 같은 anon_id 의 `user_id IS NOT NULL`
- 정의: "MBTI 에 닿은 뒤 가입 상태가 된 유저"의 상한 근사(신규 획득 + 기존 참여 혼합). ④가입 섹션은 utm(순수 신규)을 따로 표시해 구분.

> ⚠️ 구매 여정은 윈도우가 아니라 **코호트 전 기간 LTV** — `p_since` 는 앱 데이터 이전 고정 하한(예: `'2026-01-01'`)을 넘겨 코호트의 모든 결제·소비를 잡는다(30일 창 아님). `admin_star_free_attribution` 은 어차피 유저별 전체 원장을 걸으므로 무료별 귀속은 정확하다.

### 7.2 byeoljari ④결제 확장

기존 유지(코호트 결제자·결제율·매출·ARPU·생성→첫결제 중앙). **추가**: 별 패키지 분포(`admin_cohort_payments`) + 운세/타로 상품 소비(`admin_star_spend_breakdown` with `p_users = admin_byeoljari_cohort_users`). 섹션명 "④ 결제 → 구매 여정"으로 확장.
